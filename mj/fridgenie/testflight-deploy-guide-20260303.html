1 Prerequisites Check사전 준비 확인

Verify these before starting:

Xcode Version

Xcode 버전

You need Xcode 15+ (ideally latest). Check in terminal:

Xcode 15 이상 필요 (최신 버전 권장). 터미널에서 확인:

Apple Developer 계정

유료 Apple Developer 멤버십 ($99/년)이 활성화되어 있는지 확인. 무료 계정으로는 TestFlight 사용 불가.

→ Check at developer.apple.com/account

→ developer.apple.com/account에서 확인

Xcode Signed In

Xcode 로그인

Open Xcode → Settings (⌘,) → Accounts tab. Your Apple ID should be listed with "Apple Development" and "Apple Distribution" certificates.

Xcode → Settings (⌘,) → Accounts 탭. Apple ID가 "Apple Development"와 "Apple Distribution" 인증서와 함께 표시되어야 함.

📸 You should see your Apple ID with your Team "7373NYW784" and role listed as "Agent" or "Admin". 📸 Apple ID와 Team "7373NYW784"가 표시되고 역할이 "Agent" 또는 "Admin"으로 나와야 합니다.

사진 라이브러리 권한 추가

영수증 스캔을 위해 사진 라이브러리 접근 권한이 필요합니다. ios/Runner/Info.plist에 추가:

2 Signing & Certificates서명 & 인증서

Let Xcode handle it (Automatic Signing)

Xcode가 자동으로 처리하게 하기 (자동 서명)

  1. Open the iOS project in Xcode: Xcode에서 iOS 프로젝트 열기: 
    cd ~/Projects/fridgenie
open ios/Runner.xcworkspace
    ⚠️ Always open .xcworkspace, NOT .xcodeproj! Flutter uses CocoaPods which requires the workspace. ⚠️ 항상 .xcworkspace를 열어야 합니다. .xcodeproj 아님! Flutter는 CocoaPods를 사용하므로 workspace 필수.
  2. In the left sidebar, click Runner (the blue project icon at the very top). 왼쪽 사이드바에서 Runner (맨 위의 파란 프로젝트 아이콘) 클릭.
  3. Select Runner under TARGETS → Signing & Capabilities tab. TARGETS에서 Runner 선택 → Signing & Capabilities 탭.
  4. Check ✅ "Automatically manage signing". ✅ "Automatically manage signing" 체크.
  5. Set Team to your team (ID: 7373NYW784). Select it from the dropdown. Team을 본인 팀 (ID: 7373NYW784)으로 설정. 드롭다운에서 선택.
  6. Verify Bundle Identifier is com.fridgenie.app. Bundle Identifier가 com.fridgenie.app인지 확인.
📸 You should see a green checkmark with "Signing Certificate: Apple Development: [your name]" and a valid provisioning profile. No red errors. 📸 녹색 체크마크와 "Signing Certificate: Apple Development: [이름]" 및 유효한 프로비저닝 프로파일이 표시되어야 합니다. 빨간 에러 없어야 함.
💡 What Xcode does automatically: Creates a development certificate, an App ID, and a provisioning profile. For distribution, it'll create a distribution certificate when you archive. You don't need to touch the Apple Developer portal manually! 💡 Xcode가 자동으로 하는 것: 개발 인증서, App ID, 프로비저닝 프로파일 생성. 배포용 인증서는 아카이브할 때 자동 생성됩니다. Apple Developer 포털을 직접 건드릴 필요 없어요!

Important: Check BOTH configurations

중요: 두 가지 설정 모두 확인

Make sure signing is set for both Debug and Release. Click "Build Settings" tab → search "signing" → verify team is set for both.

Debug와 Release 모두 서명이 설정되어 있는지 확인. "Build Settings" 탭 → "signing" 검색 → 두 가지 모두 팀 설정 확인.

3 App Store Connect SetupApp Store Connect 설정

Create your app in App Store Connect

App Store Connect에서 앱 생성

  1. Go to appstoreconnect.apple.com → sign in. appstoreconnect.apple.com → 로그인.
  2. Click "Apps" → blue "+" button → "New App". "Apps" 클릭 → 파란 "+" 버튼 → "New App".
  3. Fill in the form: 양식 작성:
    • Platform: iOS
    • Name: Fridgenie
    • Primary Language: English (U.S.) or Korean또는 한국어
    • Bundle ID: com.fridgenie.app (select from dropdown — it appears after Xcode registers it)(드롭다운에서 선택 — Xcode가 등록한 후 나타남)
    • SKU: fridgenie-001 (any unique string, internal use only)(아무 고유 문자열, 내부 용도)
    • User Access: Full Access
  4. Click "Create". "Create" 클릭.
⚠️ Bundle ID not showing in dropdown? Go back to Xcode, make sure signing succeeded (Step 2), then try again. Xcode auto-registers the App ID with Apple. It may take a minute to appear. ⚠️ 번들 ID가 드롭다운에 안 나타나나요? Xcode로 돌아가서 서명이 성공했는지 확인 (2단계), 그다음 다시 시도. Xcode가 App ID를 Apple에 자동 등록합니다. 나타나는 데 1분 정도 걸릴 수 있음.
💡 You do NOT need to fill in app descriptions, screenshots, or pricing right now. Those are only needed for App Store release. For TestFlight, just creating the app entry is enough! 💡 앱 설명, 스크린샷, 가격 설정은 지금 안 해도 됩니다. App Store 출시 때만 필요. TestFlight에는 앱 항목 생성만으로 충분!

5 Building the Archive아카이브 빌드

Prepare & Build

준비 & 빌드

Step A: Clean & Get Dependencies

A단계: 클린 & 의존성 설치

cd ~/Projects/fridgenie
flutter clean
flutter pub get
cd ios
pod install --repo-update
cd ..

Step B: Set the build number

B단계: 빌드 번호 설정

In pubspec.yaml, check your version line:

pubspec.yaml에서 version 줄 확인:

version: 1.0.0+1

Format: version_name+build_number. Each TestFlight upload needs a unique build number. Start with +1.

형식: 버전이름+빌드번호. TestFlight 업로드마다 고유한 빌드 번호 필요. +1부터 시작.

Step C: Build the release IPA

C단계: 릴리스 IPA 빌드

flutter build ipa --release

This runs flutter build ios + creates an archive. Wait for it to complete (2–5 minutes).

flutter build ios + 아카이브 생성을 수행합니다. 완료까지 2–5분 대기.

💡 Alternative: Build from Xcode directly
1. In Xcode, set the device to "Any iOS Device (arm64)" at the top (NOT a simulator)
2. Menu: Product → Archive
3. Wait for the build to complete
4. The Organizer window opens automatically when done 💡 대안: Xcode에서 직접 빌드
1. Xcode 상단에서 기기를 "Any iOS Device (arm64)"로 설정 (시뮬레이터 아님)
2. 메뉴: Product → Archive
3. 빌드 완료 대기
4. 완료되면 Organizer 창이 자동으로 열림
📸 After archiving, the Xcode Organizer window opens showing your archive with the app name, version, date, and a "Distribute App" button on the right. 📸 아카이브 후 Xcode Organizer 창이 열리며 앱 이름, 버전, 날짜가 표시되고 오른쪽에 "Distribute App" 버튼이 있습니다.
6 Common Build Issues & Fixes자주 발생하는 빌드 문제 & 해결

❌ "No signing certificate" / "No provisioning profile"

→ Go to Xcode → Signing & Capabilities → uncheck then re-check "Automatically manage signing". Select your team again.

→ Xcode → Signing & Capabilities → "Automatically manage signing" 체크 해제 후 다시 체크. 팀 다시 선택.

❌ CocoaPods could not find compatible versions

cd ios
rm Podfile.lock
pod install --repo-update

❌ The sandbox is not in sync with the Podfile.lock

cd ios
pod install

❌ Minimum deployment target issues

Open ios/Podfile and make sure the platform line is:

ios/Podfile을 열어서 platform 줄 확인:

platform :ios, '15.0'

Also check in Xcode: Runner target → Build Settings → search "iOS Deployment Target" → set to 15.0+.

Xcode에서도 확인: Runner target → Build Settings → "iOS Deployment Target" 검색 → 15.0+ 설정.

❌ Module 'xxx' not found

flutter clean
flutter pub get
cd ios && pod install --repo-update && cd ..
flutter build ipa --release

❌ Archive fails with "Provisioning profile doesn't include signing certificate"

→ Xcode → Settings → Accounts → select your team → click "Download Manual Profiles" or "Manage Certificates" → make sure you have an "Apple Distribution" certificate.

→ Xcode → Settings → Accounts → 팀 선택 → "Download Manual Profiles" 또는 "Manage Certificates" 클릭 → "Apple Distribution" 인증서 확인.

❌ Build succeeds but archive is greyed out

→ Make sure device is set to "Any iOS Device (arm64)", not a simulator. Archive is disabled when targeting a simulator.

→ 기기가 "Any iOS Device (arm64)"로 설정되어 있는지 확인. 시뮬레이터 타겟이면 Archive 비활성화됨.

⚠️ Nuclear option: If nothing works, try deleting the build folder and derived data: 
flutter clean
rm -rf ios/Pods ios/Podfile.lock
rm -rf ~/Library/Developer/Xcode/DerivedData
flutter pub get
cd ios && pod install --repo-update && cd ..
flutter build ipa --release
 ⚠️ 최후의 수단: 아무것도 안 되면 빌드 폴더와 derived data 삭제: 
flutter clean
rm -rf ios/Pods ios/Podfile.lock
rm -rf ~/Library/Developer/Xcode/DerivedData
flutter pub get
cd ios && pod install --repo-update && cd ..
flutter build ipa --release

From Xcode Organizer

Xcode Organizer에서

옵션 A: flutter build ipa 후

Flutter tells you where the archive is. Open it:

Flutter가 아카이브 위치를 알려줍니다. 열기:

Organizer가 열립니다. 또는 Xcode → Window → Organizer.

옵션 B: 커맨드 라인으로 직접 업로드

(The Xcode GUI method below is easier for first-timers.)

(처음이라면 아래 Xcode GUI 방법이 더 쉬움.)

Distribute via Xcode Organizer (Recommended)

Xcode Organizer로 배포 (권장)

  1. In Organizer, select your archive → click "Distribute App". Organizer에서 아카이브 선택 → "Distribute App" 클릭.
  2. Select "TestFlight & App Store" → Next. "TestFlight & App Store" 선택 → Next.
  3. Select "Upload" (not Export) → Next. "Upload" 선택 (Export 아님) → Next.
  4. Leave all checkboxes as default (Include bitcode, Upload symbols, Manage signing automatically) → Next. 체크박스 기본값 유지 → Next.
  5. Select "Automatically manage signing" → Next. "Automatically manage signing" 선택 → Next.
  6. Review the summary → click "Upload". 요약 확인 → "Upload" 클릭.
  7. Wait for upload to complete (1–5 minutes depending on internet). You'll see a success message. ✅ 업로드 완료 대기 (인터넷 속도에 따라 1–5분). 성공 메시지 표시. ✅
📸 After successful upload, you'll see "Your binary has been uploaded" with a green checkmark. The build will appear in App Store Connect within 5-15 minutes. 📸 업로드 성공 시 "Your binary has been uploaded"와 녹색 체크마크 표시. 5-15분 내에 App Store Connect에 빌드가 나타남.
⚠️ After upload, Apple processes the build. This takes 5–30 minutes. You'll get an email when it's ready (or if there are issues). Check App Store Connect → TestFlight tab to see the status. ⚠️ 업로드 후 Apple이 빌드를 처리합니다. 5–30분 소요. 준비되면 (또는 문제 있으면) 이메일이 옵니다. App Store Connect → TestFlight 탭에서 상태 확인.
8 TestFlight ConfigurationTestFlight 설정

Set up testers & groups

테스터 & 그룹 설정

Compliance (Export Regulations)

규정 준수 (수출 규정)

When your build appears in TestFlight, you'll see a yellow "Missing Compliance" warning. Click "Manage" next to it.

빌드가 TestFlight에 나타나면 노란색 "Missing Compliance" 경고가 보입니다. 옆에 "Manage" 클릭.

  • Question: "Does your app use encryption?" → Select "Yes" (because HTTPS/TLS counts)질문: "Does your app use encryption?" → "Yes" 선택 (HTTPS/TLS도 암호화에 해당)
  • Then: "Does your app qualify for any exemptions?" → Select "Yes" (standard HTTPS exemption)그다음: "Does your app qualify for any exemptions?" → "Yes" 선택 (표준 HTTPS 면제)
💡 Pro tip: To skip this every time, add this to your Info.plist: 
<key>ITSAppUsesNonExemptEncryption</key>
<false/>
This tells Apple your app only uses standard HTTPS encryption. 💡 프로 팁: 매번 이 과정을 건너뛰려면 Info.plist에 추가: 
<key>ITSAppUsesNonExemptEncryption</key>
<false/>
앱이 표준 HTTPS 암호화만 사용한다고 Apple에 알려줍니다.

Internal Testing (Fastest — no review needed!)

내부 테스트 (가장 빠름 — 심사 불필요!)

  1. App Store Connect → your app → TestFlight tab.App Store Connect → 앱 → TestFlight 탭.
  2. Under "Internal Testing" on the left, click "+" to create a group (e.g., "Dev Team").왼쪽 "Internal Testing"에서 "+" 클릭하여 그룹 생성 (예: "Dev Team").
  3. Add yourself as a tester (use the same Apple ID email).본인을 테스터로 추가 (같은 Apple ID 이메일 사용).
  4. Select the build → enable it for the group.빌드 선택 → 그룹에 활성화.
✅ Internal testers get access immediately! No beta app review needed. Up to 100 internal testers (must be part of your App Store Connect team). ✅ 내부 테스터는 즉시 접근 가능! 베타 앱 심사 불필요. 최대 100명 (App Store Connect 팀 멤버여야 함).

External Testing (For others — requires review)

외부 테스트 (다른 사람용 — 심사 필요)

If you want to invite people outside your dev team:

개발 팀 외부 사람을 초대하려면:

  1. Create an "External Testing" group."External Testing" 그룹 생성.
  2. Add testers by email or share a public link.이메일로 테스터 추가 또는 공개 링크 공유.
  3. Submit the build for Beta App Review (usually approved within 24-48 hours).빌드를 Beta App Review에 제출 (보통 24-48시간 내 승인).
  4. Fill in test info: what to test, contact email, privacy policy URL.테스트 정보 작성: 테스트 내용, 연락 이메일, 개인정보 처리방침 URL.
⚠️ For tonight, stick with Internal Testing — it's instant. You can set up external testing later. ⚠️ 오늘 밤에는 내부 테스트만 하세요 — 즉시 됩니다. 외부 테스트는 나중에 설정.

💡 No email yet? Open TestFlight directly — sometimes the app appears before the email arrives. Also check your spam folder! 💡 이메일 안 왔나요? TestFlight를 직접 열어보세요 — 이메일보다 먼저 앱이 나타나기도 합니다. 스팸 폴더도 확인!
