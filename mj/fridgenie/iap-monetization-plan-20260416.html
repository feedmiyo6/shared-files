1. How Apple Subscriptions Work (Behind the Scenes)애플 구독이 작동하는 방식 (내부 구조)

🧠 The big picture:큰 그림:
Apple is the payment processor. You set products in App Store Connect. Your app calls StoreKit to show the payment sheet. Apple charges the user. Apple sends your server a receipt to verify. You update Supabase. User gets Pro.애플이 결제 처리자입니다. App Store Connect에서 상품을 설정하고, 앱에서 StoreKit으로 결제 시트를 표시합니다. 애플이 사용자에게 청구하고, 서버에 영수증을 전송합니다. Supabase를 업데이트하면 사용자가 Pro가 됩니다.
📍 Current Fridgenie status (important):현재 Fridgenie 상태 (중요):
Fridgenie already has the free/pro gating logic and switch behavior built in app code. In other words, the beta-vs-paid mode concept is already there. What is NOT built yet is the actual Apple payment plumbing: StoreKit / Apple IAP / RevenueCat / receipt validation / restore purchases.Fridgenie에는 이미 무료/프로 게이팅 로직과 스위치 동작이 앱 코드에 구현되어 있습니다. 즉, 베타 모드와 유료 모드 개념은 이미 있습니다. 아직 구현되지 않은 것은 실제 애플 결제 연결부입니다: StoreKit / Apple IAP / RevenueCat / 영수증 검증 / 구매 복원.

Auto-Renewal (Monthly)자동 갱신 (월별)

Apple handles renewals automatically every 30 days. You don't write any code for this — Apple charges the user and sends your server a notification. Your server just needs to listen for it. If payment fails, Apple retries for up to 60 days before cancelling.애플이 30일마다 자동으로 갱신을 처리합니다. 코드를 작성할 필요가 없습니다 — 애플이 청구하고 서버에 알림을 보냅니다. 서버는 이를 수신하기만 하면 됩니다. 결제 실패 시 애플이 최대 60일간 재시도한 후 취소합니다.

3. Promo Codes — Two Completely Different Systems프로모 코드 — 완전히 다른 두 가지 시스템

This is where it gets interesting. There are TWO separate promo code systems and they serve different purposes:흥미로운 부분입니다. 두 가지 별개의 프로모 코드 시스템이 있으며 목적이 다릅니다:

System A: Apple Offer Codes (App Store Connect)시스템 A: 애플 오퍼 코드 (App Store Connect)

What it is: Apple-generated alphanumeric codes that give free/discounted access to your subscription. Redeemed directly in the App Store app.무엇인가: 구독에 무료/할인 접근을 제공하는 애플 생성 영숫자 코드. App Store 앱에서 직접 사용합니다.

Use when: Marketing campaigns, influencer codes, App Store feature negotiations, press review access.사용 시기: 마케팅 캠페인, 인플루언서 코드, App Store 피처 협상, 언론 리뷰 접근.

How it works: Generate up to 1,000 codes/quarter in App Store Connect → Share code → User opens App Store app → Taps "Redeem Gift Card or Code" → Gets subscription for free/discount.작동 방식: App Store Connect에서 분기당 최대 1,000개 코드 생성 → 코드 공유 → 사용자가 App Store 앱 열기 → "기프트 카드 또는 코드 사용" 탭 → 무료/할인으로 구독 획득.

Limitation: Codes are single-use and expire after 6 months. Apple manages everything — you just see the subscription activate.제한: 코드는 1회용이고 6개월 후 만료됩니다. 애플이 모든 것을 관리 — 구독 활성화만 확인합니다.

System B: Your Existing Fridgenie Promo Codes (Supabase)시스템 B: 기존 Fridgenie 프로모 코드 (Supabase)

What it is: Your custom promo_codes table + redeem_promo_code RPC. User enters a code in YOUR app → Supabase validates → sets subscription_tier = 'pro'.무엇인가: 커스텀 promo_codes 테이블 + redeem_promo_code RPC. 사용자가 앱에서 코드 입력 → Supabase 검증 → subscription_tier = 'pro' 설정.

Use when: Beta access, team/friend codes, internal testing, "FRIDGENIE2026" launch code, gifting Pro to early adopters.사용 시기: 베타 접근, 팀/친구 코드, 내부 테스트, "FRIDGENIE2026" 론칭 코드, 얼리 어답터에게 Pro 선물.

Important caveat: This bypasses Apple's payment system. Apple gets no cut. But Apple's rules say: you cannot use your own promo code system to give access to features that normally cost money through IAP, UNLESS it's for press/reviewers or internal testing. In practice, this is fine for beta — just don't actively advertise it as an alternative to paying.중요 주의사항: 애플의 결제 시스템을 우회합니다. 애플에 수수료가 없습니다. 하지만 애플 규정상: IAP를 통해 돈을 내야 하는 기능에 자체 프로모 코드 시스템 사용 불가 (언론/리뷰어 또는 내부 테스트 제외). 실제로 베타에서는 괜찮습니다 — 결제 대안으로 적극적으로 홍보만 하지 않으면 됩니다.

// supabase/functions/revenuecat-webhook/index.ts
// Receives: { event: "INITIAL_PURCHASE" | "RENEWAL" | "CANCELLATION", 
//             app_user_id: "supabase-user-id", ... }

Deno.serve(async (req) => {
  const body = await req.json()
  const userId = body.event.app_user_id
  const eventType = body.event.type

  const tier = ['INITIAL_PURCHASE', 'RENEWAL', 'UNCANCELLATION']
    .includes(eventType) ? 'pro' : 'free'

  await supabase
    .from('profiles')
    .update({ subscription_tier: tier })
    .eq('id', userId)

  return new Response('ok')
})

This one function handles ALL subscription state changes automatically: new purchase → pro, renewal → stay pro, cancellation → back to free after period ends.이 하나의 함수가 모든 구독 상태 변경을 자동으로 처리합니다: 신규 구매 → pro, 갱신 → pro 유지, 취소 → 기간 종료 후 free로 복귀.
