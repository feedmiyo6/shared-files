1. Overview & Philosophy1. 개요 & 철학

Core Idea:핵심 아이디어: AI doesn't generate recipes — it's a smart matchmaker. It looks at what's in your fridge, understands your taste, and finds you real recipes from real people on the internet.AI는 레시피를 생성하지 않습니다 — 똑똑한 매칭 시스템입니다. 냉장고에 뭐가 있는지 보고, 취향을 파악해서, 인터넷의 실제 레시피를 찾아줍니다.

Why This Approach Wins이 접근 방식이 좋은 이유

  • Real recipes with real reviews, real photos, real cooking times — not AI hallucinations진짜 레시피 — 실제 리뷰, 실제 사진, 실제 조리시간 (AI 환각 아님)
  • Nearly free to run — AI only generates dish names, not full recipes거의 무료 운영 — AI는 요리 이름만 생성, 전체 레시피 아님
  • Users trust it more — "4.8★ on AllRecipes with 2,000 reviews" beats "AI thinks this should taste good"사용자가 더 신뢰 — "AllRecipes에서 4.8★, 리뷰 2천개"가 "AI가 맛있을 거라고 생각함"보다 나음
  • Links open in browser → user comes back to app naturally. No lock-in anxiety.링크는 브라우저에서 열림 → 사용자가 자연스럽게 앱으로 돌아옴. 종속 불안 없음.

3. How Many Dishes? Why 8.3. 몇 개 추천? 왜 8개인가

Answer: 4 per cuisine, up to 2-3 cuisines at a time = 8-12 total.답: 요리별 4개, 한번에 2~3개 요리 = 총 8~12개.

Why Not 20?왜 20개가 아닌가?

  • Choice paralysis — Studies show 5-9 options is the sweet spot. 20 makes people scroll forever and pick nothing.선택 마비 — 연구에 따르면 5~9개가 적정. 20개는 끝없이 스크롤하고 아무것도 안 고름.
  • Mobile scrolling — 20 dishes = ~15 screen scrolls. Users give up after 3.모바일 스크롤 — 20개 = ~15번 스크롤. 유저는 3번 후 포기.
  • Quality > Quantity — 4 great matches per cuisine beats 10 mediocre ones.질 > 양 — 요리별 좋은 매칭 4개가 보통 10개보다 나음.
  • "Refresh" button — If none appeal, one tap gets 8 more. Feels like discovery, not homework."새로고침" 버튼 — 마음에 안 들면 탭 한번으로 8개 더. 탐험 느낌, 숙제 아님.

4. Image Strategy4. 이미지 전략

Recommended: Pre-cached Emoji + Lazy Web Thumbnails추천: 미리 캐시된 이모지 + 지연 로딩 웹 썸네일

The Hybrid Approach하이브리드 접근

1
Instant:즉시: Show food emoji as placeholder (🍲🍝🍛). Already in the AI response. Zero latency.음식 이모지를 플레이스홀더로 표시 (🍲🍝🍛). AI 응답에 이미 포함. 지연 없음.
2
Background:백그라운드: While user reads results, fetch thumbnail from recipe source links. Takes 0.5-2 seconds per image.유저가 결과를 읽는 동안, 레시피 출처에서 썸네일 가져오기. 이미지당 0.5~2초.
3
Fade in:페이드인: Replace emoji with real photo as it loads. Smooth transition. User barely notices the swap.로드되면 이모지를 실제 사진으로 교체. 부드러운 전환. 유저는 교체를 거의 못 느낌.
4
Cache:캐시: Store thumbnail URLs in Supabase. Next time someone searches "Kimchi Jjigae" → instant real image. Cache grows organically.썸네일 URL을 Supabase에 저장. 다음에 "김치찌개" 검색 → 즉시 실제 이미지. 캐시가 자연스럽게 증가.

Web Scraping Speed — Honest Numbers웹 스크래핑 속도 — 솔직한 수치

Method방법Speed속도Quality품질Cost비용
Recipe site meta tags (og:image)레시피 사이트 메타태그0.3-1s⭐⭐⭐⭐⭐Free무료
Google Custom Search API0.2s⭐⭐⭐⭐$5/1K
Unsplash API (fallback)Unsplash API (대안)0.3s⭐⭐⭐Free무료

Bottom line: Scraping og:image from recipe pages takes ~1 second. Since we fetch all 8 in parallel while user reads, they'll see real images within 1-2 seconds of results loading. After first fetch, it's cached forever → instant. 결론: 레시피 페이지에서 og:image 스크래핑은 ~1초. 유저가 읽는 동안 8개를 동시에 가져오므로, 결과 로딩 1~2초 내에 실제 이미지 표시. 첫 가져오기 후 영구 캐시 → 즉시.

System Flow시스템 흐름

User taps "Suggest Recipes"
         │
         ▼
┌─────────────────────────┐
│  Supabase Edge Function  │
│  (recipe-suggest)        │
└────────┬────────────────┘
         │
    1. Check cache (dish name + filters → cached results?)
    │   └── Yes → Return cached dishes (0ms AI cost)
    │   └── No ↓
    │
    2. Call GPT-4o-mini
    │   Input: inventory list + cuisine + filters
    │   Output: 8 dish objects {name, emoji, description, cook_time}

    │   └── Fetch top 4 results → extract og:image, title, rating
    │   └── Cache results in Supabase
    │
         ▼
Return to app: dishes + images + source links

🧞 The Verdict결론

This system costs almost nothing to run ($2/month at 1,000 users), gives users real recipes from trusted sources with real photos, and has a clear path to $1,500+/month revenue at 10K users. The AI is just the smart matchmaker — the internet does the heavy lifting.이 시스템은 운영 비용이 거의 없고 (1,000명에 월 $2), 실제 사진이 있는 신뢰할 수 있는 출처의 실제 레시피를 제공하며, 10K 유저에서 월 $1,500+ 수익 경로가 명확합니다. AI는 똑똑한 매칭만 — 인터넷이 무거운 작업을 담당.
