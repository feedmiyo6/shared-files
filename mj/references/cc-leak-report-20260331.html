On March 31, 2026, security researcher Chaofan Shou discovered that Anthropic's Claude Code CLI had its entire source code exposed via a source map file (.map) accidentally bundled in npm package version 2.1.88. The source map referenced an R2 storage bucket containing the full, unobfuscated TypeScript source.

2026년 3월 31일, 보안 연구원 Chaofan Shou가 Anthropic의 Claude Code CLI의 전체 소스 코드가 npm 패키지 버전 2.1.88에 실수로 포함된 소스맵 파일(.map)을 통해 노출된 것을 발견했습니다. 소스맵은 전체 비난독화 TypeScript 소스가 포함된 R2 스토리지 버킷을 참조하고 있었습니다.

Key Clarification:핵심 정리: Only the CLI tool source was leaked — NOT the Claude AI model weights, training data, or infrastructure. You cannot "run Claude" from this code. It's the interface layer, not the intelligence. CLI 도구의 소스만 유출되었습니다 — Claude AI 모델 가중치, 학습 데이터, 인프라는 유출되지 않았습니다. 이 코드로 Claude를 "실행"할 수 없습니다. 인터페이스 레이어이지 지능 자체가 아닙니다.

🧠 Top 6 Learnings for Our Development 우리 개발에 활용할 6가지 핵심 학습

HIGH IMPACT 1. Three-Layer Context Compression 1. 3단계 컨텍스트 압축 전략

Claude Code uses a sophisticated three-layer compression system to manage long sessions:

Claude Code는 긴 세션 관리를 위해 정교한 3단계 압축 시스템을 사용합니다:

  • MicroCompact — No API calls. Locally edits cached content, removes old tool outputs. Lightest, most frequent.API 호출 없음. 캐시된 콘텐츠를 로컬에서 편집, 이전 도구 출력 제거. 가장 가볍고 자주 실행.
  • AutoCompact — Triggers near context limit. 13K token buffer, generates 20K summary. Circuit breaker after 3 failures.컨텍스트 한계 근처에서 트리거. 13K 토큰 버퍼, 20K 요약 생성. 3회 실패 후 서킷 브레이커.
  • Full Compact — Compresses entire conversation. Re-injects recent files (5K/file), plans, skills. Post-compression: 50K tokens.전체 대화 압축. 최근 파일(5K/파일), 계획, 스킬 재주입. 압축 후: 50K 토큰.
Action:적용: Run /compact proactively before starting new phases. CLAUDE.md survives fully — conversation instructions don't! 새 단계 시작 전에 선제적으로 /compact 실행. CLAUDE.md는 완전히 유지됨 — 대화 중 지시사항은 유지되지 않음!
HIGH IMPACT 2. Self-Healing Memory Architecture 2. 자가 치유 메모리 아키텍처

Claude Code's memory isn't a simple store-everything system. It uses "skeptical memory":

Claude Code의 메모리는 단순히 모든 것을 저장하는 시스템이 아닙니다. "회의적 메모리"를 사용합니다:

  • MEMORY.md is a lightweight index of pointers (~150 chars/line), NOT a data storeMEMORY.md는 경량 포인터 인덱스(~150자/줄), 데이터 저장소가 아님
  • Actual knowledge distributed across topic files, fetched on-demand실제 지식은 주제 파일에 분산, 필요시 가져옴
  • Agent treats memory as a "hint" — verifies against actual codebase before acting에이전트는 메모리를 "힌트"로 취급 — 행동 전 실제 코드베이스와 검증
  • AutoDream consolidation: runs background memory maintenance (orient → gather → consolidate → prune)AutoDream 통합: 백그라운드 메모리 유지보수 실행 (탐색 → 수집 → 통합 → 정리)
Action:적용: Apply this to our MEMORY.md — keep it as a pointer index, not a data dump. Verify before acting on memory. 우리 MEMORY.md에 적용 — 데이터 덤프가 아닌 포인터 인덱스로 유지. 메모리에 따라 행동하기 전 검증.
HIGH IMPACT 3. Multi-Agent Orchestration Patterns 3. 멀티 에이전트 오케스트레이션 패턴
  • Coordinator Mode: Main agent assigns tasks to workers, workers execute in parallel코디네이터 모드: 메인 에이전트가 작업자에게 태스크 할당, 작업자는 병렬 실행
  • Permission Mailbox: Workers request permission for dangerous ops via queue권한 메일박스: 작업자가 큐를 통해 위험한 작업에 대한 권한 요청
  • Atomic Claim: createResolveOnce prevents duplicate permission handling원자적 클레임: createResolveOnce로 중복 권한 처리 방지
  • Team Memory: Shared memory space across agents팀 메모리: 에이전트 간 공유 메모리 공간
Action:적용: Use Task tool with sub-agents for all large exploration tasks. Keep main context lean. This directly applies to our Luna/Atlas/Kai/Nova agent architecture! 모든 대규모 탐색 작업에 서브 에이전트와 Task 도구 사용. 메인 컨텍스트를 가볍게 유지. 우리 Luna/Atlas/Kai/Nova 에이전트 아키텍처에 직접 적용!
MEDIUM IMPACT 4. System Prompt Engineering 4. 시스템 프롬프트 엔지니어링

Anthropic doesn't use vague instructions. Their prompts are engineered constraints:

Anthropic은 모호한 지시사항을 사용하지 않습니다. 그들의 프롬프트는 엔지니어링된 제약조건입니다:

  • Tool constraints: "Must use FileReadTool, bash not allowed"도구 제약: "FileReadTool 사용 필수, bash 불허"
  • Risk controls: "Must double-confirm before deleting"리스크 제어: "삭제 전 이중 확인 필수"
  • Output specs: "Conclusion first, then explain"출력 사양: "결론 먼저, 그 다음 설명"
  • Anti-patterns explicitly banned: No over-engineering, no hypothetical design안티패턴 명시적 금지: 과도한 설계 금지, 가상 설계 금지
Action:적용: Apply this to our CLAUDE.md files — specific constraints > vague guidance. Use "IMPORTANT" and "YOU MUST" for critical rules. 우리 CLAUDE.md 파일에 적용 — 구체적 제약 > 모호한 가이드. 중요한 규칙에 "IMPORTANT"와 "YOU MUST" 사용.
MEDIUM IMPACT 5. CLAUDE.md as Instruction Budget 5. CLAUDE.md 지시사항 예산 관리
  • LLMs reliably follow ~150-200 distinct instructionsLLM은 약 150-200개의 고유 지시사항을 안정적으로 따름
  • System prompt already uses ~50 instructions → your budget is ~100-150시스템 프롬프트가 이미 ~50개 지시사항 사용 → 당신의 예산은 ~100-150개
  • Over 200 lines = Claude starts losing/ignoring instructions200줄 초과 = Claude가 지시사항을 잃거나 무시하기 시작
  • CLAUDE.md content is prompt-cached (90% cheaper on subsequent turns)CLAUDE.md 콘텐츠는 프롬프트 캐시됨 (후속 턴에서 90% 저렴)
Action:적용: Keep CLAUDE.md under 200 lines. For each line ask: "Would removing this cause mistakes?" Use @imports for detailed docs. CLAUDE.md를 200줄 미만으로 유지. 각 줄마다 물어보기: "이걸 제거하면 실수가 생길까?" 상세 문서는 @imports 사용.
STRATEGIC 6. KAIROS: The Autonomous Daemon Future 6. KAIROS: 자율 데몬의 미래

A feature flag mentioned 150+ times — an always-on background agent mode:

150회 이상 언급된 기능 플래그 — 항상 켜져있는 백그라운드 에이전트 모드:

  • Background sessions with autonomous task handling자율 작업 처리가 가능한 백그라운드 세션
  • AutoDream: Memory consolidation while user is idle (merge observations, remove contradictions, convert to facts)AutoDream: 사용자가 유휴 상태일 때 메모리 통합 (관찰 병합, 모순 제거, 사실로 변환)
  • Forked sub-agent prevents main "train of thought" corruption포크된 서브 에이전트가 메인 "사고의 흐름" 오염 방지
Insight:인사이트: This is exactly what we're doing with OpenClaw heartbeats + cron jobs. We're already ahead of the curve! The AutoDream pattern maps perfectly to our MEMORY.md consolidation workflow. 이것은 우리가 OpenClaw 하트비트 + 크론 작업으로 하고 있는 것과 정확히 같습니다. 우리가 이미 앞서가고 있습니다! AutoDream 패턴은 우리 MEMORY.md 통합 워크플로우에 완벽하게 매핑됩니다.
