1. What is Gemma 4? Community & BenchmarksGemma 4란? 커뮤니티 반응 & 벤치마크

Google released Gemma 4 on April 2, 2026, built on the same research foundation as Gemini 3 but packaged for open distribution under Apache 2.0 — meaning you can use it commercially with no restrictions or fees.구글은 2026년 4월 2일 Gemma 4를 출시했습니다. Gemini 3와 동일한 연구 기반 위에 구축되었지만, Apache 2.0 라이선스 하에 오픈 배포되어 상업적 이용도 제한 없이 무료로 가능합니다.

🔑 Key: The 26B A4B is a Mixture of Experts model.핵심: 26B A4B는 Mixture of Experts 모델입니다.
It has 26B total parameters but only activates 4B per token — so it runs at 4B speed while producing 26B-quality output. Best bang for your buck on 24GB hardware.총 26B 파라미터를 갖고 있지만 토큰당 4B만 활성화됩니다. 즉, 4B 속도로 실행되면서 26B 품질의 출력을 냅니다. 24GB 하드웨어에서 가장 가성비가 뛰어납니다.

2. Running Gemma 4 on Mac mini (Setup Guide)Mac mini에서 Gemma 4 실행하기 (설치 가이드)

Best Tool: Ollama ✅최고의 도구: Ollama ✅

As of Ollama v0.19+, it automatically uses Apple's MLX framework on Apple Silicon — no configuration needed. Easiest path by far.Ollama v0.19+부터 Apple Silicon에서 Apple MLX 프레임워크를 자동으로 사용합니다. 별도 설정 없이 가장 쉬운 방법입니다.

Step-by-Step Setup단계별 설치 가이드

# 1. Install Ollama (use official installer, NOT Homebrew)
curl -fsSL https://ollama.com/install.sh | sh
# Or download from: https://ollama.com

# 2. Pull your model (pick based on your RAM — see table below)
ollama pull gemma4           # Default: E4B (~9.6 GB) — best for 16GB Mac mini
ollama pull gemma4:e2b       # Lightest (~7.2 GB)
ollama pull gemma4:26b       # MoE sweet spot (~18 GB) — best for 24GB Mac mini
ollama pull gemma4:31b       # Full power (~20 GB) — needs 32GB+

# 3. Run interactively
ollama run gemma4

# 4. Pass images (multimodal!)
ollama run gemma4 "What's in this image?" /path/to/photo.jpg

# 5. API access (OpenAI-compatible)
curl http://localhost:11434/api/generate \
  -d '{"model": "gemma4", "prompt": "Hello!"}'

Recommended Environment Variables (add to ~/.zshrc)권장 환경 변수 (~/.zshrc에 추가)

export OLLAMA_NUM_GPU=99          # Maximize GPU layer offloading
export OLLAMA_KEEP_ALIVE=0        # Keep model loaded between requests
export OLLAMA_HOST=0.0.0.0:11434  # Accept connections from network

Increase Context Window (default is too small!)컨텍스트 창 확장 (기본값이 너무 작음!)

# Create a Modelfile
echo "FROM gemma4
PARAMETER num_ctx 32768" > Modelfile

ollama create gemma4-32k -f Modelfile
ollama run gemma4-32k

4. Fine-Tuning & Personalization (Hermes + LoRA)파인튜닝 & 개인화 (Hermes + LoRA)

What is Hermes?Hermes란?

NousResearch Hermes refers to two things: (1) Hermes Models — fine-tuned LLMs optimized for function calling, tool use, and agentic behavior; (2) Hermes Agent (Feb 2026) — an open-source autonomous AI agent platform with persistent memory, native function calling, and the ability to export conversation trajectories for fine-tuning.NousResearch Hermes는 두 가지를 의미합니다: (1) Hermes 모델 — 함수 호출, 도구 사용, 에이전트 동작에 최적화된 파인튜닝된 LLM; (2) Hermes Agent (2026년 2월) — 영구 메모리, 기본 함수 호출, 파인튜닝용 대화 내보내기 기능을 갖춘 오픈소스 자율 AI 에이전트 플랫폼.

🚨 CRITICAL: Using a model ≠ Training a model중요: 모델 사용 ≠ 모델 훈련

Simply chatting with a local model does NOT make it smarter or more personalized over time. This is the most common misconception about local AI.로컬 모델과 그냥 대화하는 것만으로는 시간이 지나도 더 똑똑해지거나 개인화되지 않습니다. 이것이 로컬 AI에 대한 가장 흔한 오해입니다.

Action행동Does model change?모델이 변하나요?
Inference (chatting)추론 (대화하기)❌ No. Weights are frozen. Read-only.아니요. 가중치가 고정됩니다. 읽기 전용.
Fine-tuning파인튜닝✅ Yes. Weights actually update.예. 가중치가 실제로 업데이트됩니다.
RAG❌ No. Just better context injection.아니요. 더 나은 컨텍스트 주입일 뿐.
Analogy: Inference is reading someone a book — they answer from what they already know. Fine-tuning is sending them to school. More chatting ≠ more learning.비유: 추론은 책을 읽어주는 것 — 이미 아는 것으로 대답합니다. 파인튜닝은 학교에 보내는 것. 더 많이 채팅한다고 ≠ 더 많이 배우지 않습니다.

Step-by-Step: Fine-Tune with Unsloth (Recommended)단계별 가이드: Unsloth로 파인튜닝 (추천)

# 1. Install Unsloth
curl -fsSL https://unsloth.ai/install.sh | sh

# 2. Launch Unsloth Studio (web UI — easiest method!)
unsloth studio -H 0.0.0.0 -p 8888
# Open http://localhost:8888

Or via Python:또는 Python으로:

from unsloth import FastVisionModel

# Load model with 4-bit quantization (saves memory)
model, tokenizer = FastVisionModel.from_pretrained(
    "google/gemma-4-E4B-it",
    load_in_4bit=True,
)

# Add LoRA adapter
model = FastVisionModel.get_peft_model(
    model,
    r=8,           # LoRA rank
    lora_alpha=8,
    lora_dropout=0,
    bias="none",
)

# Train...
trainer.train()

# Save as GGUF for Ollama
model.save_pretrained_gguf("./my-gemma4", tokenizer,
                           quantization_method="q4_k_m")

Option A: Move LoRA Adapter Only (Small & Fast)옵션 A: LoRA 어댑터만 이동 (소형 & 빠름)

# After fine-tuning, your adapter folder is ~10–100 MB
ls ./my-gemma4-adapter/
# adapter_config.json  adapter_model.safetensors

# Copy to new machine
scp -r ./my-gemma4-adapter/ user@new-machine:~/adapters/

# ⚠️ The new machine also needs the same base model downloaded!

Option B: Export Merged GGUF (Self-Contained, Recommended)옵션 B: 병합된 GGUF 내보내기 (자급자족, 추천)

# Export merged model as single GGUF (in Python, after training)
model.save_pretrained_gguf(
    "./my-gemma4-merged",
    tokenizer,
    quantization_method="q4_k_m"
)

# Copy the .gguf file to new machine
scp ./my-gemma4-merged/*.gguf user@new-machine:~/models/

Option C: Import into Ollama on New Machine옵션 C: 새 기기의 Ollama에 가져오기

# On the new machine, after copying the .gguf file:
cat > Modelfile << 'EOF'
FROM /path/to/my-gemma4-merged.gguf
PARAMETER temperature 0.7
PARAMETER num_ctx 32768
SYSTEM "You are a helpful assistant specialized in TypeScript."
EOF

ollama create my-custom-gemma -f Modelfile
ollama run my-custom-gemma

Option D: Upload to Hugging Face (Any Machine Can Pull)옵션 D: Hugging Face에 업로드 (어디서나 당겨올 수 있음)

pip install huggingface-hub
huggingface-cli login

# Upload
huggingface-cli upload your-username/my-gemma4 ./my-gemma4-merged/ --private

# On any new machine
huggingface-cli download your-username/my-gemma4
