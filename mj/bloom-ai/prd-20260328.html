01 — Overview

What is Bloom AI? Bloom AI란?

Bloom AI is a personal study companion for high-stakes exam preparation. Users create Projects — self-contained study spaces for any subject — and Bloom provides diverse interactive learning modes, AI-powered evaluation of free-form answers, voice interaction, adaptive scheduling, and a persistent memory engine that tracks progress across every session. Bloom AI는 고위험 시험 준비를 위한 개인 학습 도우미입니다. 사용자는 어떤 과목이든 자체적인 학습 공간인 프로젝트를 생성하고, Bloom은 다양한 대화형 학습 모드, AI 기반 자유형 답변 평가, 음성 상호작용, 적응형 스케줄링, 그리고 모든 세션의 진행 상황을 추적하는 영구 메모리 엔진을 제공합니다.

02 — Core Concept

Project-Based Learning 프로젝트 기반 학습

Everything in Bloom revolves around Projects. A Project is a self-contained study space for any subject, exam, or learning goal. Each Project has its own questions, progress tracking, memory, and scheduled sessions. Bloom의 모든 것은 프로젝트를 중심으로 돌아갑니다. 프로젝트는 어떤 과목, 시험, 학습 목표에 대한 독립적인 학습 공간입니다. 각 프로젝트는 자체 문제, 진도 추적, 메모리, 예약 세션을 갖습니다.

  • Project 2: "High-Risk Obstetrics Deep Dive" — focused subset, case simulations only프로젝트 2: "고위험 산과 심화 학습" — 집중 하위 세트, 케이스 시뮬레이션만
  • Project 3: "Spanish for Medical Practice" — language learning, different modes프로젝트 3: "의료 스페인어" — 언어 학습, 다른 모드

🔧 Project Creation Flow🔧 프로젝트 생성 흐름

Users describe what they want to study in natural language. Bloom AI analyzes their input and auto-generates: 사용자가 자연어로 학습하고 싶은 내용을 설명합니다. Bloom AI가 입력을 분석하고 자동 생성합니다:

  • Topic structure (categories + subcategories)주제 구조 (카테고리 + 하위 카테고리)
  • Initial question bank (AI-generated, calibrated to domain)초기 문제 은행 (AI 생성, 도메인에 맞게 보정)
  • Suggested study schedule + recommended modes추천 학습 일정 + 추천 모드
  • Evaluation rubrics per topic주제별 평가 루브릭
  • Difficulty curve calibrated to exam date시험일에 맞춘 난이도 커브
💡 Freedom-first approach: Users don't need to know the "right" structure. They just tell Bloom what they're studying and Bloom builds the plan. They can modify everything afterward. 💡 자유 우선 접근: 사용자는 "올바른" 구조를 알 필요가 없습니다. Bloom에게 공부할 내용만 말하면 Bloom이 계획을 세웁니다. 이후 모든 것을 수정할 수 있습니다.
03 — Memory Engine

It Remembers Everything 모든 것을 기억합니다

Each user has their own AI memory space in Supabase. The Memory Engine is the core differentiator — Bloom doesn't just grade your answers, it understands your learning trajectory. 각 사용자는 Supabase에 자체 AI 메모리 공간을 갖습니다. 메모리 엔진이 핵심 차별화 요소입니다 — Bloom은 답변만 채점하는 것이 아니라 학습 궤적을 이해합니다.

🧠 What Bloom Remembers Per User🧠 Bloom이 사용자별로 기억하는 것

  • Every answer — full text, score, time taken, which key points were hit/missed모든 답변 — 전체 텍스트, 점수, 소요 시간, 맞힌/놓친 핵심 포인트
  • Learning patterns — which topics click fast vs. need repetition, best time of day, session length preferences학습 패턴 — 빨리 이해하는 주제 vs. 반복이 필요한 주제, 최적 시간대, 선호 세션 길이
  • Common mistakes — recurring gaps in knowledge, misconceptions반복 실수 — 반복되는 지식 공백, 오해
  • Growth trajectory — how scores have changed over time per topic성장 궤적 — 주제별 시간에 따른 점수 변화
  • Session continuity — "Last time you were working on X, want to continue?"세션 연속성 — "지난번에 X를 공부하고 있었는데, 계속할래요?"
  • Verbal patterns — how you explain things (voice mode), your vocabulary level언어 패턴 — 설명 방식(음성 모드), 어휘 수준

💬 Memory-Powered Feedback Examples💬 메모리 기반 피드백 예시

  • "You answered a similar placental abruption question 2 weeks ago and missed the DIC workup. This time you included it — great improvement!""2주 전에 비슷한 태반 조기박리 문제에서 DIC 검사를 빠뜨렸는데, 이번에는 포함했네요 — 훌륭한 발전!"
  • "I notice you tend to forget fetal monitoring steps when the question is time-pressured. Let's drill that in Rapid Fire mode.""시간 압박이 있는 문제에서 태아 모니터링 단계를 빠뜨리는 경향이 있네요. Rapid Fire 모드로 연습해볼까요?"
  • "Your Obstetrics scores jumped from 58% to 81% this month. Gynecologic Oncology is still at 52% — should we shift focus?""이번 달 산과 점수가 58%에서 81%로 올랐어요. 부인과 종양학은 아직 52%인데 — 초점을 바꿀까요?"

🗄️ Per-User Database Structure🗄️ 사용자별 데이터베이스 구조

Each user's data is isolated via Row-Level Security (RLS). Their entire learning history lives in Supabase, queryable by the AI during evaluations.각 사용자의 데이터는 행 수준 보안(RLS)으로 격리됩니다. 전체 학습 기록이 Supabase에 저장되며, 평가 시 AI가 쿼리할 수 있습니다.

user_memory
├── answers (every response, timestamped)
├── evaluations (AI feedback + scores)
├── learning_patterns (auto-computed insights)
├── srs_state (spaced repetition intervals)
├── session_logs (when, how long, what mode)
├── weak_areas (auto-identified gaps)
├── milestones (achievements, streaks)
└── preferences (modes, schedule, voice settings)
04 — RAG System

Bring Your Own Sources 나만의 소스 가져오기

Like NotebookLM, users can upload their own study materials as sources. Bloom ingests, chunks, embeds, and uses them for question generation, answer evaluation, and contextual references. Your sources become the foundation of your study experience. NotebookLM처럼 사용자가 자신의 학습 자료를 소스로 업로드할 수 있습니다. Bloom이 수집, 청킹, 임베딩하여 문제 생성, 답변 평가, 컨텍스트 참조에 사용합니다. 소스가 학습 경험의 기반이 됩니다.

📄 Supported Source Types📄 지원 소스 유형

  • PDFs — textbooks, guidelines, lecture slides, practice examsPDF — 교과서, 가이드라인, 강의 슬라이드, 모의 시험
  • Web URLs — articles, guidelines (ACOG bulletins, UpToDate), reference pages웹 URL — 기사, 가이드라인 (ACOG 게시물, UpToDate), 참고 페이지
  • Text/Notes — copy-paste your own notes, summaries, mnemonics텍스트/노트 — 자신의 노트, 요약, 기억법 복사-붙여넣기
  • Images — diagrams, flowcharts, clinical images for reference이미지 — 다이어그램, 플로차트, 임상 이미지 참조

🔍 RAG Pipeline🔍 RAG 파이프라인

When a source is uploaded:소스가 업로드되면:

  • 1. Parse & Extract — PDF text extraction, URL scraping, image OCR1. 파싱 & 추출 — PDF 텍스트 추출, URL 스크래핑, 이미지 OCR
  • 2. Chunk — Split into semantic chunks (512-1024 tokens) with overlap2. 청킹 — 오버랩이 있는 의미 단위 청크(512-1024 토큰)로 분할
  • 3. Embed — Generate vector embeddings (OpenAI text-embedding-3-small, ~$0.02/1M tokens)3. 임베딩 — 벡터 임베딩 생성 (OpenAI text-embedding-3-small, ~$0.02/1M 토큰)
  • 4. Store — Supabase pgvector for semantic search4. 저장 — 시맨틱 검색을 위한 Supabase pgvector
  • 5. Index — Auto-tag topics, link to project's topic tree5. 인덱싱 — 자동 주제 태깅, 프로젝트 주제 트리에 연결

💡 How RAG Enhances Every Mode💡 RAG가 모든 모드를 향상시키는 방법

  • Question Generation — generates questions directly from YOUR sources, not generic AI knowledge문제 생성 — 일반 AI 지식이 아닌 사용자의 소스에서 직접 문제 생성
  • Answer Evaluation — AI references your specific textbook/guideline when grading: "According to Williams Obstetrics Ch.35 (your source), the correct approach is..."답변 평가 — AI가 채점 시 사용자의 특정 교과서/가이드라인 참조: "Williams 산과학 35장(귀하의 소스)에 따르면..."
  • Teach-Back — evaluates your explanation against what your source materials say가르치기 모드 — 소스 자료 내용과 비교하여 설명 평가
  • Audio Briefing — summarizes YOUR sources, not generic content오디오 브리핑 — 일반 콘텐츠가 아닌 사용자의 소스 요약
  • Flashcards — auto-generated from highlighted sections of your materials플래시카드 — 자료의 하이라이트 섹션에서 자동 생성

📚 Source Management UI📚 소스 관리 UI

  • Library view showing all uploaded sources per project프로젝트별 업로드된 모든 소스를 보여주는 라이브러리 뷰
  • Source health indicator (chunks indexed, topics mapped)소스 상태 표시기 (인덱싱된 청크, 매핑된 주제)
  • Citation links in feedback — tap to jump to the source피드백의 인용 링크 — 탭하면 소스로 이동
  • Bulk upload (drag & drop on Mac, file picker on iOS)일괄 업로드 (Mac에서 드래그 앤 드롭, iOS에서 파일 선택기)
  • "Generate questions from this source" — one-tap action"이 소스에서 문제 생성" — 원탭 액션
05 — Interactive Pivoting

Your Study, Your Rules 당신의 학습, 당신의 규칙

Projects are living, adaptive plans — not rigid syllabuses. Users can pivot, adjust, skip, and refocus at any time through natural conversation with Bloom. 프로젝트는 경직된 커리큘럼이 아닌 살아있는 적응형 계획입니다. 사용자는 Bloom과의 자연스러운 대화를 통해 언제든지 방향 전환, 조정, 건너뛰기, 재집중할 수 있습니다.

💬 Natural Language Project Commands💬 자연어 프로젝트 명령

Users can say things like:사용자는 다음과 같이 말할 수 있습니다:

  • "Skip Gynecologic Oncology for now — it's low-yield for me. Focus on Obstetrics instead.""부인과 종양학은 지금 건너뛰세요 — 저한테 효율이 낮아요. 산과에 집중해 주세요."
  • "I just realized I need to study preeclampsia way more. Add extra questions on that.""전자간증을 훨씬 더 공부해야 할 것 같아요. 그 주제에 추가 문제를 넣어주세요."
  • "Change my daily count from 15 to 10 — I'm burned out this week.""일일 문제 수를 15개에서 10개로 줄여주세요 — 이번 주 지쳤어요."
  • "I want more case simulations and less flashcards.""플래시카드는 줄이고 케이스 시뮬레이션을 더 주세요."
  • "Add a new topic: Fetal Echocardiography. Here's my reference PDF.""새 주제 추가: 태아 심초음파. 참고 PDF 여기 있어요."
  • "I nailed Labor & Delivery — reduce its frequency and rotate in more Gyn Onc.""분만 & 출산은 마스터했어요 — 빈도를 줄이고 부인과 종양학을 더 넣어주세요."

🔧 How Pivoting Works🔧 방향 전환 작동 방식

  • In-session chat — a chat input at the bottom of the study screen. Type instructions anytime.세션 내 채팅 — 학습 화면 하단의 채팅 입력. 언제든지 지시 입력 가능.
  • AI parses intent — understands "skip", "focus", "add", "reduce", "change" etc.AI가 의도 파악 — "건너뛰기", "집중", "추가", "줄이기", "변경" 등 이해.
  • Confirms changes — "Got it! I'll deprioritize Gyn Onc and increase Obstetrics questions by 30%. Sound good?"변경 확인 — "알겠어요! 부인과 종양학 우선순위를 낮추고 산과 문제를 30% 늘릴게요. 괜찮나요?"
  • Updates project config — topic weights, daily set composition, mode preferences all adjust프로젝트 설정 업데이트 — 주제 가중치, 일일 세트 구성, 모드 선호도 모두 조정
  • Logged in memory — "On April 15, you asked to skip Gyn Onc. Ready to add it back?"메모리에 기록 — "4월 15일에 부인과 종양학 건너뛰기 요청. 다시 추가할 준비됐나요?"

🤖 AI Study Advisor🤖 AI 학습 어드바이저

Bloom also proactively suggests pivots based on your performance data:Bloom은 성과 데이터를 기반으로 방향 전환을 사전에 제안하기도 합니다:

  • "You've scored 90%+ on Obstetrics for 2 weeks straight. I suggest reducing it to maintenance mode and shifting focus to REI where you're at 58%.""2주 연속 산과에서 90% 이상 득점했어요. 유지 모드로 전환하고 58%인 생식내분비학에 집중하는 것을 제안합니다."
  • "Your exam is 3 months away. Based on your current trajectory, I recommend adding one case simulation per day.""시험이 3개월 남았어요. 현재 궤적을 기반으로 하루에 케이스 시뮬레이션 하나를 추가하는 것을 권장합니다."
06 — Study Modes

10 Ways to Learn 10가지 학습 방법

Not just flashcards. Bloom offers diverse, interactive formats that adapt to what each user needs. All modes contribute to the Memory Engine. 단순 플래시카드가 아닙니다. Bloom은 각 사용자에게 필요한 것에 맞는 다양하고 대화형 형식을 제공합니다. 모든 모드가 메모리 엔진에 기여합니다.

Free-Form Q&A자유형 Q&A

10 — Data Architecture

Database Schema 데이터베이스 스키마

Supabase PostgreSQL with Row-Level Security. Each user's data is fully isolated. Project-centric organization. 행 수준 보안이 적용된 Supabase PostgreSQL. 각 사용자의 데이터는 완전히 격리됩니다. 프로젝트 중심 구성. 

── Auth (Supabase Auth) ──────────────────────
  profiles              -- user profile, preferences, settings

── Projects ──────────────────────────────────
  projects              -- user's study projects (OB/GYN Board, etc.)
    ├── id, user_id, name, description
    ├── icon, color
    ├── exam_date (nullable)
    ├── daily_goal (questions per day)
    ├── difficulty_mode (auto/easy/medium/hard)
    ├── schedule_mode (balanced/cram/targeted/countdown)
    ├── notification_time
    └── created_at, updated_at

── Content ───────────────────────────────────
  topics                -- topic tree per project
    ├── id, project_id, name, parent_id
    ├── weight, description
    └── icon, sort_order

  questions             -- question bank
    ├── id, project_id, topic_id
    ├── type (free_form/case/rapid/flashcard/teach_back)
    ├── difficulty (1-5)
    ├── question_text, question_image_url
    ├── rubric (jsonb)       -- key_points, scoring criteria
    ├── model_answer
    ├── explanation
    ├── source_reference
    ├── is_ai_generated
    └── created_at

  case_scenarios        -- branching case data
    ├── id, project_id, topic_id
    ├── title, initial_prompt
    ├── branches (jsonb)     -- decision tree structure
    └── optimal_path (jsonb)

  materials             -- uploaded study documents
    ├── id, project_id, user_id
    ├── filename, storage_path
    ├── extracted_text, topic_tags
    └── questions_generated (count)

── Learning Data (per-user, RLS-protected) ───
  answers               -- every answer ever given
    ├── id, user_id, question_id, session_id
    ├── answer_text
    ├── answer_audio_url, transcription
    ├── time_taken_seconds
    └── created_at

  evaluations           -- AI feedback for each answer
    ├── id, answer_id
    ├── score (0-100)
    ├── feedback_text
    ├── key_points_hit (jsonb)
    ├── key_points_missed (jsonb)
    ├── reasoning_quality (1-5)
    ├── follow_up_question
    ├── model_used
    └── created_at

  srs_state             -- spaced repetition per question
    ├── user_id, question_id
    ├── ease_factor, interval_days, repetitions
    ├── next_review_date
    └── last_score

  study_sessions        -- session logs
    ├── id, user_id, project_id
    ├── mode (free_form/voice/case/rapid/etc.)
    ├── started_at, ended_at
    ├── questions_attempted, avg_score
    └── total_time_seconds

  learning_patterns     -- AI-computed insights
    ├── user_id, project_id
    ├── topic_mastery (jsonb)    -- per-topic scores over time
    ├── weak_areas (jsonb)       -- auto-identified gaps
    ├── best_study_time          -- when user performs best
    ├── avg_session_length
    ├── streak_current, streak_best
    └── updated_at

  daily_sets            -- pre-generated daily questions
    ├── id, user_id, project_id
    ├── date, questions (jsonb array of question_ids)
    ├── completed_count
    └── generated_at

── RAG / Sources ─────────────────────────────
  sources               -- uploaded study materials
    ├── id, user_id, project_id
    ├── type (pdf/url/text/image)
    ├── title, filename, storage_path
    ├── raw_text, chunk_count
    ├── topic_tags (auto-detected)
    ├── status (processing/ready/error)
    └── created_at

  source_chunks         -- chunked + embedded content
    ├── id, source_id
    ├── chunk_text, chunk_index
    ├── embedding (vector(1536))  -- pgvector

    └── metadata (jsonb)

  project_directives    -- user's custom pivoting instructions
    ├── id, user_id, project_id

    ├── active (boolean)
    └── created_at

  scheduled_tasks       -- cron job definitions

15 — Risks

Risks & Mitigations 리스크 & 완화

⚠️ AI Cost Overrun⚠️ AI 비용 초과

Risk: Heavy voice + case sim usage could push costs above $80/mo.리스크: 음성 + 케이스 시뮬레이션 과다 사용 시 월 $80 이상 가능.

Mitigation: (1) Smart caching — reuse eval context for similar answers. (2) Haiku/nano for non-critical paths. (3) Cache TTS audio for repeated feedback phrases. (4) In-app usage monitor with monthly budget cap. (5) ElevenLabs Starter plan ($5/mo) covers ~30K chars — enough for moderate voice usage.완화: (1) 스마트 캐싱 — 유사 답변에 평가 컨텍스트 재사용. (2) 비핵심 경로에 Haiku/nano. (3) 반복 피드백 문구에 TTS 오디오 캐시. (4) 월간 예산 상한이 있는 앱 내 사용량 모니터. (5) ElevenLabs Starter 플랜($5/월)은 ~30K 문자 제공 — 보통 음성 사용에 충분.

⚠️ Medical Accuracy⚠️ 의학적 정확성

Risk: AI-generated questions or evaluations could contain medical errors.리스크: AI 생성 문제 또는 평가에 의학적 오류 가능.

Mitigation: (1) Use Claude Sonnet (most accurate) for all evaluations. (2) Reference established guidelines (ACOG, Williams) in prompts. (3) Flag low-confidence evaluations. (4) Lucy can report inaccuracies → improves over time.완화: (1) 모든 평가에 Claude Sonnet(가장 정확) 사용. (2) 프롬프트에 확립된 가이드라인(ACOG, Williams) 참조. (3) 낮은 신뢰도 평가 플래그. (4) Lucy가 부정확성 보고 → 시간이 지나면 개선.

⚠️ Scope Creep⚠️ 범위 확대

Risk: 10 modes is ambitious. Could delay Phase 1.리스크: 10개 모드는 야심찬 목표. Phase 1이 지연될 수 있음.

Mitigation: Phase 1 = only Free-Form Q&A. Ship fast. Add modes incrementally. Each phase is independently valuable.완화: Phase 1 = 자유형 Q&A만. 빠르게 출시. 모드를 점진적으로 추가. 각 단계는 독립적으로 가치 있음.
