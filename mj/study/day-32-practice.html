Exercise 1: Hardware Inventory 실습 1: 하드웨어 인벤토리

For the following module, list every piece of hardware that synthesis will create. Count flip-flops, muxes, adders, and gates.

다음 모듈에 대해 합성이 생성할 모든 하드웨어를 나열하세요. 플립플롭, 멀티플렉서, 가산기, 게이트를 세어보세요.

module data_path (
    input  logic        clk, rst,
    input  logic        load, add_en,
    input  logic [7:0]  data_in,
    output logic [7:0]  result
);
    logic [7:0] acc;
    logic [7:0] next_acc;

    // Combinational logic
    always_comb begin
        if (load)
            next_acc = data_in;
        else if (add_en)
            next_acc = acc + data_in;
        else
            next_acc = acc;
    end

    // Sequential logic
    always_ff @(posedge clk) begin
        if (rst)
            acc <= 8'h00;
        else
            acc <= next_acc;
    end

    assign result = acc;
endmodule

💡 Hint

Count the registered bits first. Then identify each operation in the combinational block. Remember, if/else if/else creates a priority mux chain.

먼저 등록된 비트를 세세요. 그런 다음 조합 블록의 각 연산을 식별하세요. if/else if/else는 우선순위 멀티플렉서 체인을 생성합니다.

Exercise 2: Optimize the Multiplications 실습 2: 곱셈 최적화

Rewrite each multiplication to use only shifts and adds — no * operator. This eliminates expensive multiplier hardware.

각 곱셈을 시프트와 덧셈만 사용하도록 다시 작성하세요 — * 연산자를 사용하지 않습니다. 비용이 높은 곱셈기 하드웨어를 제거합니다.

// Rewrite each without using *
assign y1 = x * 4;     // #1
assign y2 = x * 3;     // #2
assign y3 = x * 10;    // #3
assign y4 = x * 7;     // #4
assign y5 = x * 12;    // #5

💡 Hint

Break each constant into powers of 2. For example: 10 = 8 + 2 = 2³ + 2¹. So x * 10 = (x << 3) + (x << 1). Subtraction works too: 7 = 8 - 1.

각 상수를 2의 거듭제곱으로 분해하세요. 예: 10 = 8 + 2 = 2³ + 2¹. 따라서 x * 10 = (x << 3) + (x << 1). 빼기도 가능합니다: 7 = 8 - 1.

// #1: 4 = 2² → just shift
assign y1 = x << 2;                    // FREE! Just wires

// #2: 3 = 2 + 1 → shift + add
assign y2 = (x << 1) + x;             // 1 adder

// #3: 10 = 8 + 2 → two shifts + add
assign y3 = (x << 3) + (x << 1);     // 1 adder

// #4: 7 = 8 - 1 → shift + subtract
assign y4 = (x << 3) - x;             // 1 subtractor

// #5: 12 = 8 + 4 → two shifts + add
assign y5 = (x << 3) + (x << 2);     // 1 adder

Key insight: All shifts by constants are free (just wires). So the total cost is just 3 adders and 1 subtractor — instead of 5 full multipliers!

핵심 인사이트: 상수에 의한 모든 시프트는 무료(단순 와이어)입니다. 따라서 총 비용은 3개의 가산기와 1개의 감산기뿐 — 5개의 전체 곱셈기 대신!

Exercise 3: Fix the Bugs 실습 3: 버그 수정

Each of these code snippets has a hardware inference bug. Identify the problem and write the fix.

다음 코드 스니펫에는 하드웨어 추론 버그가 있습니다. 문제를 식별하고 수정하세요.

Bug A: Mystery Latch

always_comb begin
    case (mode)
        2'b00: out = a;
        2'b01: out = b;
        2'b10: out = c;
        // What about 2'b11?
    endcase
end

Bug B: Accidental Priority

// Designer wants equal-priority decode, but wrote:
always_comb begin
    grant = 4'b0000;
    if (req[0]) grant = 4'b0001;
    else if (req[1]) grant = 4'b0010;
    else if (req[2]) grant = 4'b0100;
    else if (req[3]) grant = 4'b1000;
end

Bug C: Expensive Comparison

// Check if value equals a power of 2 (1, 2, 4, 8, 16...)
always_comb begin
    is_pow2 = (val == 1) || (val == 2) || (val == 4) ||
              (val == 8) || (val == 16) || (val == 32) ||
              (val == 64) || (val == 128);
end

Fix A: Add default case

always_comb begin
    case (mode)
        2'b00: out = a;
        2'b01: out = b;
        2'b10: out = c;
        default: out = '0;  // ✅ Prevents latch!
    endcase
end

Problem: Missing 2'b11 case means out must hold its value → latch. Always include default in case statements.

문제: 2'b11 케이스가 없으면 out이 값을 유지해야 합니다 → 래치. case문에 항상 default를 포함하세요.

Fix B: Use round-robin or case

// If truly equal priority is needed, this if/else
// creates priority (req[0] always wins). Options:

// Option 1: Acknowledge it's priority (document intent)
// The if/else IS the design — just document that req[0]
// has highest priority.

// Option 2: Implement actual round-robin (needs state)
// This requires a registered "last_grant" and rotating
// priority — a fundamentally different design.

Problem: if/else creates priority — req[0] always wins over req[3]. If equal access is needed, you need a round-robin arbiter (Day 28!), not just if/else.

문제: if/else는 우선순위를 생성합니다 — req[0]이 항상 req[3]보다 이깁니다. 동등한 접근이 필요하면 if/else가 아닌 라운드 로빈 중재기(Day 28!)가 필요합니다.

Fix C: Use bitwise trick

// Power of 2 check: val has exactly one bit set
// val & (val - 1) clears the lowest set bit
// If result is 0, only one bit was set!
always_comb begin
    is_pow2 = (val != '0) && ((val & (val - 1)) == '0);
end
// Infers: 1 subtractor + AND gate + comparator
// vs original: 8 comparators + 7 OR gates!

Problem: 8 separate equality comparators + OR chain is expensive. The bitwise trick val & (val - 1) == 0 does the same with far less hardware. This is a classic interview question!

문제: 8개의 개별 등가 비교기 + OR 체인은 비용이 높습니다. 비트 트릭 val & (val - 1) == 0은 훨씬 적은 하드웨어로 동일한 작업을 수행합니다. 이것은 고전적인 면접 질문입니다!

Design: Configurable Shift-Add Unit

module shift_add (
    input  logic        clk, rst,
    input  logic [7:0]  data_in,
    input  logic [1:0]  mode,
    output logic [15:0] result
);
    logic [15:0] accum;
    logic [15:0] next_val;

    always_comb begin
        case (mode)
            2'b00: next_val = accum;                             // Hold
            2'b01: next_val = {8'b0, data_in};                  // Load
            2'b10: next_val = accum + {8'b0, data_in};       // Add
            2'b11: next_val = {accum[14:0], 1'b0};           // Shift left
        endcase
    end

    always_ff @(posedge clk) begin
        if (rst)
            accum <= 16'h0000;
        else
            accum <= next_val;
    end

    assign result = accum;
endmodule

Exercise 5: Interview Challenge — Code Reading 실습 5: 면접 챌린지 — 코드 읽기

A common interview question: "Look at this code and tell me what hardware it creates." Practice talking through your answer out loud.

일반적인 면접 질문: "이 코드를 보고 어떤 하드웨어를 생성하는지 말해주세요." 답변을 소리 내어 연습하세요.

module mystery (
    input  logic       clk, rst, en,
    input  logic [3:0] din,
    output logic       match
);
    logic [3:0] r1, r2, r3;

    always_ff @(posedge clk) begin
        if (rst) begin
            r1 <= '0;
            r2 <= '0;
            r3 <= '0;
        end else if (en) begin
            r1 <= din;
            r2 <= r1;
            r3 <= r2;
        end
    end

    assign match = (r1 == 4'hA) && (r2 == 4'hB) && (r3 == 4'hC);
endmodule

🎤 Practice Your Answer

Before revealing the solution, try explaining out loud: "This module creates..." — as if you're in an interview. Cover: (1) what structure it is, (2) how many FFs, (3) what the combinational logic does, (4) what the module's purpose is.

솔루션을 공개하기 전에 소리 내어 설명해보세요: "이 모듈은..." — 면접에서처럼. 다루어야 할 내용: (1) 어떤 구조인지, (2) 몇 개의 FF인지, (3) 조합 논리가 무엇을 하는지, (4) 모듈의 목적이 무엇인지.

Complete Hardware Analysis:

Structure: A 3-stage shift register (pipeline) with enable, feeding a sequence detector.

구조: 인에이블이 있는 3단계 시프트 레지스터(파이프라인)로, 시퀀스 감지기에 공급됩니다.

  • 12 flip-flops: r1[3:0] + r2[3:0] + r3[3:0] = 12 FFs with sync reset and enable
  • 12 muxes: The enable creates a 2:1 mux on each FF input (en ? new : hold)
  • 12 muxes: Reset creates another mux layer (rst ? 0 : enabled_value)
  • 3 comparators: r1==4'hA, r2==4'hB, r3==4'hC (each is a 4-bit equality check)
  • 2 AND gates: Combining the three comparator outputs
  • 12개 플립플롭: r1[3:0] + r2[3:0] + r3[3:0] = 동기 리셋과 인에이블이 있는 12개 FF
  • 12개 멀티플렉서: 인에이블이 각 FF 입력에 2:1 멀티플렉서를 생성 (en ? 새값 : 유지)
  • 12개 멀티플렉서: 리셋이 또 다른 멀티플렉서 레이어를 생성 (rst ? 0 : 인에이블된 값)
  • 3개 비교기: r1==4'hA, r2==4'hB, r3==4'hC (각각 4비트 등가 검사)
  • 2개 AND 게이트: 세 비교기 출력을 결합

Purpose: Detects the sequence C → B → A on the din input (most recent = A in r1). When enabled, it shifts data through a 3-deep history and checks if the last three values were 0xC, 0xB, 0xA in that order. This is a sequence detector — a very common pattern!

목적: din 입력에서 시퀀스 C → B → A를 감지합니다 (가장 최근 = r1의 A). 인에이블되면 데이터를 3단계 히스토리에 시프트하고 마지막 세 값이 순서대로 0xC, 0xB, 0xA였는지 확인합니다. 이것은 시퀀스 감지기 — 매우 일반적인 패턴입니다!

🎯 Today's Practice Takeaways

  1. Always count your flip-flops — bits × registered signals = total FFs
  2. Shift + add replaces multipliers for constant factors
  3. Default cases prevent accidental latches
  4. Read code as hardware — practice describing circuits from RTL
  5. 항상 플립플롭을 세세요 — 비트 × 등록된 신호 = 총 FF
  6. 시프트 + 덧셈은 상수 인수에 대해 곱셈기를 대체합니다
  7. 기본 케이스는 우발적 래치를 방지합니다
  8. 코드를 하드웨어로 읽으세요 — RTL에서 회로를 설명하는 연습을 하세요
