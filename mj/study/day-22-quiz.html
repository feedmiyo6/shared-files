Q1. What is the primary purpose of inserting pipeline registers?파이프라인 레지스터를 삽입하는 주요 목적은?

  • A) Reduce total latencyA) 총 레이턴시 감소
  • B) Increase clock frequency / throughputB) 클럭 주파수 / 처리량 증가
  • C) Reduce areaC) 면적 감소
  • D) Eliminate glitches in outputsD) 출력 글리치 제거
Pipeline registers break long combinational paths, allowing a higher clock frequency. Latency actually increases.파이프라인 레지스터는 긴 조합 경로를 나누어 더 높은 클럭 주파수를 가능하게 합니다. 레이턴시는 실제로 증가합니다.

Q2. A 20ns combinational path is split into 4 equal pipeline stages. What is the approximate new fmax?20ns 조합 경로를 4개의 동일한 파이프라인 스테이지로 나누면 대략적인 새 fmax는?

  • A) 50 MHz
  • B) 100 MHz
  • C) 200 MHz
  • D) 400 MHz
20ns ÷ 4 stages = 5ns per stage → 1/5ns = 200 MHz. (Ignoring register overhead for simplicity.)20ns ÷ 4 스테이지 = 스테이지당 5ns → 1/5ns = 200 MHz. (레지스터 오버헤드 무시.)

Q3. What is a "pass-through register" in pipelining?파이프라이닝에서 "패스스루 레지스터"란?

  • A) A register that bypasses a stage entirelyA) 스테이지를 완전히 우회하는 레지스터
  • B) A register that forwards a signal through a stage without processing itB) 처리하지 않고 신호를 스테이지를 통해 전달하는 레지스터
  • C) A transparent latch used between stagesC) 스테이지 사이에 사용되는 투명 래치
  • D) A register that only updates on valid dataD) 유효한 데이터에서만 업데이트되는 레지스터
Pass-through registers keep signals aligned across stages even when they're not used in that particular stage.패스스루 레지스터는 해당 스테이지에서 사용되지 않더라도 신호의 정렬을 유지합니다.

Q4. A 3-stage pipeline processes inputs A, B, C in consecutive cycles. When does C's result appear?3단계 파이프라인이 연속 사이클에서 입력 A, B, C를 처리합니다. C의 결과는 언제 나타나나요?

  • A) Cycle 3A) 사이클 3
  • B) Cycle 4B) 사이클 4
  • C) Cycle 5C) 사이클 5
  • D) Cycle 6D) 사이클 6
C enters at cycle 3, takes 3 cycles through the pipeline → result at cycle 5. (A→cycle 3, B→cycle 4, C→cycle 5)C는 사이클 3에 들어가고, 파이프라인을 통과하는 데 3 사이클 → 사이클 5에 결과. (A→사이클 3, B→사이클 4, C→사이클 5)

Q5. What limits the maximum clock frequency in a pipelined design?파이프라인 디자인에서 최대 클럭 주파수를 제한하는 것은?

  • A) The total combinational delayA) 총 조합 지연
  • B) The slowest pipeline stageB) 가장 느린 파이프라인 스테이지
  • C) The number of pipeline registersC) 파이프라인 레지스터의 수
  • D) The fastest pipeline stageD) 가장 빠른 파이프라인 스테이지
The clock period must accommodate the slowest stage. This is why balancing stage delays is important.클럭 주기는 가장 느린 스테이지를 수용해야 합니다. 이것이 스테이지 지연 균형이 중요한 이유입니다.

Q6. What is the overhead added by each pipeline register?각 파이프라인 레지스터가 추가하는 오버헤드는?

  • A) Only setup timeA) 셋업 타임만
  • B) Only clock-to-q delayB) 클럭-투-Q 지연만
  • C) Setup time + clock-to-q delayC) 셋업 타임 + 클럭-투-Q 지연
  • D) Hold time + propagation delayD) 홀드 타임 + 전파 지연
Each register eats into the timing budget with tsetup (before clock edge) + tclk-to-q (after clock edge). This is why infinite pipelining doesn't work.각 레지스터는 tsetup(클럭 엣지 전) + tclk-to-q(클럭 엣지 후)로 타이밍 예산을 소모합니다.

Q7. In a 3-stage pipeline, a signal needed only in Stage 3 requires how many pass-through registers?3단계 파이프라인에서 Stage 3에서만 필요한 신호는 몇 개의 패스스루 레지스터가 필요한가요?

  • A) 0
  • B) 1
  • C) 2
  • D) 3
The signal must pass through Stage 1 → register → Stage 2 → register → Stage 3. That's 2 pass-through registers to stay aligned.신호는 Stage 1 → 레지스터 → Stage 2 → 레지스터 → Stage 3을 통과해야 합니다. 정렬을 유지하기 위해 2개의 패스스루 레지스터가 필요합니다.

Q8. What is the purpose of a pipeline valid signal?파이프라인 valid 신호의 목적은?

  • A) To reset the pipelineA) 파이프라인 리셋
  • B) To indicate which stages contain real data vs. bubblesB) 어떤 스테이지가 실제 데이터를 가지고 있는지 표시
  • C) To control clock gatingC) 클럭 게이팅 제어
  • D) To measure pipeline depthD) 파이프라인 깊이 측정
The valid signal travels alongside data through the pipeline. Only when valid=1 should downstream logic treat the output as meaningful.valid 신호는 파이프라인을 통해 데이터와 함께 이동합니다. valid=1일 때만 하위 로직이 출력을 의미있게 처리해야 합니다.

Q9. Stages have delays: S1=15ns, S2=5ns. What's the best improvement?스테이지 지연: S1=15ns, S2=5ns. 최선의 개선 방법은?

  • A) Add more pipeline stages after S2A) S2 뒤에 더 많은 파이프라인 스테이지 추가
  • B) Move some logic from S1 to S2 to balance delaysB) S1에서 S2로 일부 로직을 이동하여 지연 균형
  • C) Remove S2 since it's underutilizedC) S2가 활용도가 낮으므로 제거
  • D) Double the clock frequencyD) 클럭 주파수를 두 배로
Balancing: move logic so both are ~10ns → fmax goes from 67MHz (limited by 15ns) to 100MHz. A 49% improvement!균형 조정: 로직을 이동하여 둘 다 ~10ns → fmax가 67MHz(15ns 제한)에서 100MHz로. 49% 개선!

Q10. Which naming convention is recommended for pipeline registers?파이프라인 레지스터에 권장되는 명명 규칙은?

  • A) pipe_reg_1, pipe_reg_2
  • B) s1_signal, s2_signal
  • C) signal_d1, signal_d2
  • D) Any consistent scheme works equally well
Stage-prefixed naming (s1_, s2_) instantly shows which pipeline stage a signal belongs to, making the design much easier to read and debug.스테이지 접두사 명명(s1_, s2_)은 신호가 어떤 파이프라인 스테이지에 속하는지 즉시 보여줍니다.
