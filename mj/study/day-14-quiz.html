Q1. What defines the critical path in a digital design?디지털 설계에서 크리티컬 패스를 정의하는 것은?

Answer: B. The critical path is the longest combinational delay between any two sequential elements — it determines the maximum clock frequency.

정답: B. 크리티컬 패스는 두 순차 요소 사이의 가장 긴 조합 논리 지연으로, 최대 클럭 주파수를 결정합니다.

Q2. What is the fundamental timing equation?기본 타이밍 방정식은?

Answer: B. T_clk ≥ T_cq + T_comb + T_setup. The clock period must be at least the sum of clock-to-Q, combinational delay, and setup time.

정답: B. T_clk ≥ T_cq + T_comb + T_setup. 클럭 주기는 최소한 Clock-to-Q, 조합 논리 지연, 셋업 타임의 합 이상이어야 합니다.

Q3. Which operation typically creates the deepest combinational logic?일반적으로 가장 깊은 조합 논리를 만드는 연산은?

Answer: C. Multiplication involves many levels of addition and carry propagation, making it one of the deepest combinational operations.

정답: C. 곱셈은 여러 단계의 덧셈과 캐리 전파를 포함하여, 가장 깊은 조합 연산 중 하나입니다.

Q4. What does pipelining trade to reduce critical path delay?파이프라이닝은 크리티컬 패스 지연을 줄이기 위해 무엇을 교환하나요?

Answer: B. Pipelining adds registers that increase latency (results take more cycles) but allows a faster clock because each stage has less combinational logic.

정답: B. 파이프라이닝은 레이턴시를 증가시키는 레지스터를 추가하지만, 각 스테이지의 조합 논리가 적어 더 빠른 클럭을 허용합니다.

Q5. Adding 8 values using a tree structure has what logic depth?트리 구조로 8개의 값을 더하면 로직 깊이는?

Answer: C. Tree addition has depth log₂(N). For 8 values: log₂(8) = 3 levels. Chain addition would be 7 levels.

정답: C. 트리 덧셈의 깊이는 log₂(N)입니다. 8개의 값: log₂(8) = 3 레벨. 체인 덧셈은 7 레벨이 됩니다.

Q6. What does precomputation do to optimize the critical path?사전 계산은 크리티컬 패스를 어떻게 최적화하나요?

Answer: B. Precomputation calculates all possible outcomes in parallel (using more area), then uses a MUX to select the right one. This moves the computation off the MUX-select critical path.

정답: B. 사전 계산은 모든 가능한 결과를 병렬로 계산한 후(더 많은 면적 사용) MUX로 올바른 결과를 선택합니다. 이렇게 하면 MUX 선택 크리티컬 패스에서 계산이 제거됩니다.

Q7. What does unique case tell the synthesis tool?unique case는 합성 도구에 무엇을 알려주나요?

Answer: B. unique case asserts that conditions are mutually exclusive, allowing the synthesizer to generate a parallel MUX tree instead of a priority chain, reducing logic depth.

정답: B. unique case는 조건이 상호 배타적임을 선언하여, 합성기가 우선순위 체인 대신 병렬 MUX 트리를 생성하게 하여 로직 깊이를 줄입니다.

Q8. What does negative slack in a timing report mean?타이밍 리포트에서 음의 슬랙은 무엇을 의미하나요?

Answer: C. Negative slack = Required Time - Arrival Time < 0, meaning data doesn't arrive before the setup time requirement. The design will fail at this clock frequency.

정답: C. 음의 슬랙 = 요구 시간 - 도착 시간 < 0으로, 데이터가 셋업 타임 요구사항 전에 도착하지 못함을 의미합니다. 이 클럭 주파수에서 설계가 실패합니다.

Q9. If T_cq = 0.2ns, T_setup = 0.1ns, and the critical path combinational delay is 4.7ns, what is the minimum clock period?T_cq = 0.2ns, T_setup = 0.1ns이고 크리티컬 패스 조합 논리 지연이 4.7ns이면 최소 클럭 주기는?

Answer: B. T_clk ≥ 0.2 + 4.7 + 0.1 = 5.0ns. Maximum frequency = 1/5.0ns = 200 MHz.

정답: B. T_clk ≥ 0.2 + 4.7 + 0.1 = 5.0ns. 최대 주파수 = 1/5.0ns = 200 MHz.

Q10. Which is NOT a valid way to reduce critical path delay?크리티컬 패스 지연을 줄이는 유효한 방법이 아닌 것은?

Answer: C. Adding more combinational logic in series makes the path LONGER, not shorter. All other options are valid optimization techniques.

정답: C. 더 많은 조합 논리를 직렬로 추가하면 경로가 더 길어집니다. 다른 모든 옵션은 유효한 최적화 기법입니다.
