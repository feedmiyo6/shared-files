Q1. What happens if an FSM enters an illegal state and there is no default case?FSM이 불법 상태에 진입했는데 default 케이스가 없으면 어떻게 되나요?

  • A) It automatically resetsA) 자동으로 리셋됨
  • B) It may get stuck or a latch may be inferredB) 멈추거나 래치가 유추될 수 있음
  • C) The synthesis tool adds recovery logic automaticallyC) 합성 도구가 자동으로 복구 로직 추가
  • D) A compilation error occursD) 컴파일 오류 발생
Without a default case, the FSM has no defined behavior for illegal states. It may remain stuck forever, or the synthesis tool may infer a latch to hold the current values.default 케이스가 없으면 FSM은 불법 상태에 대한 정의된 동작이 없습니다. 영원히 멈추거나 합성 도구가 현재 값을 유지하기 위해 래치를 유추할 수 있습니다.

Q2. Which reset strategy is considered industry standard?어떤 리셋 전략이 업계 표준으로 간주되나요?

  • A) Synchronous onlyA) 동기식만
  • B) Asynchronous onlyB) 비동기식만
  • C) Asynchronous assert, synchronous deassertC) 비동기 어서트, 동기 디어서트
  • D) No reset needed if default case existsD) default 케이스가 있으면 리셋 불필요
Async assert / sync deassert gives the instant reset of async with the clean timing of sync release, avoiding metastability on reset removal.비동기 어서트 / 동기 디어서트는 비동기의 즉각적인 리셋과 동기 릴리스의 깨끗한 타이밍을 결합하여 리셋 해제 시 메타안정성을 방지합니다.

Q3. Why is one-hot encoding especially vulnerable to bit flips?원-핫 인코딩이 비트 플립에 특히 취약한 이유는?

  • A) A single bit flip creates a state with 0 or 2 bits set — both invalidA) 단일 비트 플립이 0개 또는 2개 비트가 설정된 상태를 만듦 — 둘 다 무효
  • B) One-hot uses more flip-flops so there are more bits to flipB) 원-핫이 더 많은 플립플롭을 사용하므로 뒤집힐 비트가 더 많음
  • C) One-hot doesn't support default casesC) 원-핫은 default 케이스를 지원하지 않음
  • D) One-hot encoding is slower than binaryD) 원-핫 인코딩이 바이너리보다 느림
One-hot requires exactly one bit to be 1. Any single bit flip either clears the only set bit (all zeros) or sets a second bit (two bits high) — both are illegal states.원-핫은 정확히 하나의 비트가 1이어야 합니다. 단일 비트 플립은 유일한 설정 비트를 지우거나(모두 0) 두 번째 비트를 설정하여(2개 비트 하이) — 둘 다 불법 상태입니다.

Q4. What does $countones(state) == 1 check in a one-hot FSM?원-핫 FSM에서 $countones(state) == 1은 무엇을 검사하나요?

  • A) The FSM has only one stateA) FSM이 하나의 상태만 있음
  • B) Exactly one bit is set — the state is valid one-hotB) 정확히 하나의 비트가 설정됨 — 유효한 원-핫 상태
  • C) The state register has been resetC) 상태 레지스터가 리셋됨
  • D) The FSM is in state 1D) FSM이 상태 1에 있음
$countones counts the number of 1-bits. For valid one-hot encoding, there must be exactly one bit set at all times.$countones는 1-비트의 수를 셉니다. 유효한 원-핫 인코딩에서는 항상 정확히 하나의 비트가 설정되어야 합니다.

Q5. What is the purpose of a timeout watchdog in an FSM?FSM에서 타임아웃 워치독의 목적은?

  • A) To speed up state transitionsA) 상태 전이 속도 향상
  • B) To reduce power consumptionB) 전력 소비 감소
  • C) To count the number of state transitionsC) 상태 전이 횟수 카운트
  • D) To prevent the FSM from getting stuck in a wait state indefinitelyD) FSM이 대기 상태에 무한히 멈추는 것을 방지
A watchdog timer counts cycles while the FSM is away from IDLE. If the count exceeds a threshold, it forces recovery — preventing infinite hangs when expected inputs never arrive.워치독 타이머는 FSM이 IDLE 상태를 벗어난 동안 사이클을 셉니다. 카운트가 임계값을 초과하면 복구를 강제하여 예상 입력이 도착하지 않을 때 무한 행을 방지합니다.

Q6. What can happen if you use (* full_case *) pragma carelessly?(* full_case *) 프라그마를 부주의하게 사용하면 어떻게 되나요?

  • A) It adds extra safety logicA) 추가 안전 로직이 추가됨
  • B) It forces one-hot encodingB) 원-핫 인코딩을 강제
  • C) Synthesis may optimize away your default recovery logicC) 합성이 default 복구 로직을 최적화하여 제거할 수 있음
  • D) It prevents latch inferenceD) 래치 유추를 방지
full_case tells synthesis that all possible cases are covered, which can cause it to treat the default branch as don't-care and optimize away your recovery logic.full_case는 합성에게 모든 가능한 케이스가 포함되었다고 알려, default 분기를 don't-care로 처리하고 복구 로직을 최적화하여 제거할 수 있습니다.

Q7. In the reset synchronizer pattern, why are two flip-flops used?리셋 동기화 패턴에서 왜 두 개의 플립플롭을 사용하나요?

  • A) To reduce metastability risk when deasserting the async resetA) 비동기 리셋 해제 시 메타안정성 위험 감소
  • B) To create a delay of exactly 2 clock cyclesB) 정확히 2 클럭 사이클 지연 생성
  • C) To double the reset signal strengthC) 리셋 신호 강도를 두 배로
  • D) To filter glitches on the reset lineD) 리셋 라인의 글리치 필터링
The two flip-flops form a synchronizer chain. When the async reset deasserts, it may violate setup/hold timing — the first flop may go metastable but the second flop resolves it to a clean value.두 개의 플립플롭은 동기화 체인을 형성합니다. 비동기 리셋이 해제될 때 셋업/홀드 타이밍을 위반할 수 있지만, 첫 번째 플롭이 메타안정 상태가 되어도 두 번째 플롭이 깨끗한 값으로 해결합니다.

Q8. Which SVA assertion checks that an FSM eventually returns to IDLE?FSM이 결국 IDLE로 돌아오는지 확인하는 SVA 어설션은?

  • A) assert property (state == S_IDLE)A) assert property (state == S_IDLE)
  • B) (state != S_IDLE) |-> ##[1:N] (state == S_IDLE)B) (state != S_IDLE) |-> ##[1:N] (state == S_IDLE)
  • C) $onehot(state)C) $onehot(state)
  • D) state inside {S_IDLE}D) state inside {S_IDLE}
The implication |-> ##[1:N] says: "whenever we're not in IDLE, within 1 to N cycles we must be in IDLE." This is a liveness property — it checks the FSM doesn't get stuck.함축 |-> ##[1:N]는 "IDLE이 아닐 때마다 1~N 사이클 이내에 IDLE에 있어야 한다"를 의미합니다. 이것은 활성 속성으로 FSM이 멈추지 않는지 확인합니다.

Q9. What does the Xilinx FSM_SAFE_STATE = "reset_state" attribute do?Xilinx의 FSM_SAFE_STATE = "reset_state" 속성은 무엇을 하나요?

  • A) Forces binary encodingA) 바이너리 인코딩 강제
  • B) Removes unused states from synthesisB) 합성에서 미사용 상태 제거
  • C) Tells synthesis to add hardware that recovers to the reset state from any illegal stateC) 합성에게 불법 상태에서 리셋 상태로 복구하는 하드웨어를 추가하라고 지시
  • D) Disables FSM optimizationD) FSM 최적화 비활성화
This attribute instructs the Xilinx synthesis tool to insert extra logic that detects illegal states and transitions the FSM back to its reset state, ensuring safety even after optimization.이 속성은 Xilinx 합성 도구에게 불법 상태를 감지하고 FSM을 리셋 상태로 전이하는 추가 로직을 삽입하도록 지시하여, 최적화 후에도 안전성을 보장합니다.

Q10. Which of the following is NOT a source of illegal FSM states?다음 중 불법 FSM 상태의 원인이 아닌 것은?

  • A) Single-event upsets (radiation)A) 단일 이벤트 업셋 (방사선)
  • B) Missing reset at power-onB) 전원 투입 시 리셋 누락
  • C) Metastability from asynchronous inputsC) 비동기 입력으로 인한 메타안정성
  • D) Using too many states in the enumD) enum에 너무 많은 상태 사용
Having many states in an enum is a design choice, not a safety hazard. The other three (SEU, missing reset, metastability) are all real causes of illegal FSM states in hardware.enum에 많은 상태가 있는 것은 설계 선택이지 안전 위험이 아닙니다. 나머지 세 가지(SEU, 리셋 누락, 메타안정성)는 모두 하드웨어에서 불법 FSM 상태의 실제 원인입니다.

Q11. What is the advantage of Hamming distance ≥ 2 between state encodings?상태 인코딩 간 해밍 거리 ≥ 2의 장점은?

  • A) Faster state transitionsA) 더 빠른 상태 전이
  • B) A single bit flip can never land on another valid stateB) 단일 비트 플립이 다른 유효한 상태에 도달할 수 없음
  • C) Fewer flip-flops neededC) 더 적은 플립플롭 필요
  • D) Lower power consumptionD) 더 낮은 전력 소비
If every pair of valid states differs by at least 2 bits, a single bit error always produces an invalid encoding — making it detectable rather than silently transitioning to a wrong state.모든 유효 상태 쌍이 최소 2비트 차이가 나면, 단일 비트 오류는 항상 무효한 인코딩을 생성하여 잘못된 상태로 조용히 전이하는 대신 감지 가능합니다.

Q12. In a safe FSM, where should the error flag be asserted?안전한 FSM에서 에러 플래그는 어디서 어서트되어야 하나요?

  • A) In the default case and in timeout conditionsA) default 케이스와 타임아웃 조건에서
  • B) Only at resetB) 리셋 시에만
  • C) In every state transitionC) 모든 상태 전이에서
  • D) Only when the done signal is highD) done 신호가 높을 때만
The error flag should signal abnormal conditions — illegal state recovery (default case) and watchdog timeouts are the two main scenarios where something went wrong.에러 플래그는 비정상적인 조건을 알려야 합니다 — 불법 상태 복구(default 케이스)와 워치독 타임아웃이 문제가 발생한 두 가지 주요 시나리오입니다.
