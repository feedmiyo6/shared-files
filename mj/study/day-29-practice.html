Exercise 1: Almost-Full FIFO with Watermark

Build a FIFO that asserts an almost_full signal when the occupancy reaches a configurable watermark threshold. This is used in Ethernet switches to trigger pause frames before the buffer overflows.

점유율이 구성 가능한 워터마크 임계값에 도달하면 almost_full 신호를 출력하는 FIFO를 구축하세요. 이더넷 스위치에서 버퍼가 오버플로하기 전에 pause 프레임을 트리거하는 데 사용됩니다.

📋 Requirements

  • Parameterized DEPTH (default 8) and WIDTH (default 32)
  • 매개변수화된 DEPTH (기본값 8) 및 WIDTH (기본값 32)
  • Parameterized WATERMARK (default 6) — assert almost_full when count >= WATERMARK
  • 매개변수화된 WATERMARK (기본값 6) — count >= WATERMARK일 때 almost_full 출력
  • Standard signals: wr_valid, wr_ready, rd_valid, rd_ready
  • 표준 신호: wr_valid, wr_ready, rd_valid, rd_ready
  • Output: almost_full, count, full, empty
  • 출력: almost_full, count, full, empty

Starter Template

module watermark_fifo #(
    parameter DEPTH     = 8,
    parameter WIDTH     = 32,
    parameter WATERMARK = 6
)(

    // Write port
    input  logic                        wr_valid,
    input  logic [WIDTH-1:0]            wr_data,

    // Read port

    output logic [WIDTH-1:0]            rd_data,
    input  logic                        rd_ready,
    // Status
    output logic                        almost_full,
    output logic                        full,
    output logic                        empty,
    output logic [$clog2(DEPTH):0]     count
);

    // 2. Generate do_write and do_read signals
    // 3. Drive status outputs (full, empty, almost_full)
    // 4. Implement pointer and count update logic

💡 Hints

  • almost_full = (count >= WATERMARK) — this fires before full, giving the system time to react
  • almost_full = (count >= WATERMARK) — full 이전에 발생하여 시스템이 반응할 시간을 줌
  • In Ethernet, almost_full triggers a pause frame to the link partner
  • 이더넷에서 almost_full은 링크 파트너에게 pause 프레임을 트리거합니다
  • Use circular pointer arithmetic (pointers wrap at DEPTH)
  • 순환 포인터 산술 사용 (포인터가 DEPTH에서 래핑)
module watermark_fifo #(
    parameter DEPTH     = 8,
    parameter WIDTH     = 32,
    parameter WATERMARK = 6
)(
    input  logic                        clk,
    input  logic                        rst_n,
    input  logic                        wr_valid,
    input  logic [WIDTH-1:0]            wr_data,
    output logic                        wr_ready,
    output logic                        rd_valid,
    output logic [WIDTH-1:0]            rd_data,
    input  logic                        rd_ready,
    output logic                        almost_full,
    output logic                        full,
    output logic                        empty,
    output logic [$clog2(DEPTH):0]     count
);

    logic [WIDTH-1:0] mem [DEPTH];
    logic [$clog2(DEPTH)-1:0] wr_ptr, rd_ptr;

    wire do_write = wr_valid && wr_ready;
    wire do_read  = rd_valid && rd_ready;

    // Status outputs
    assign full        = (count == DEPTH);
    assign empty       = (count == 0);
    assign almost_full = (count >= WATERMARK);
    assign wr_ready    = !full;
    assign rd_valid    = !empty;
    assign rd_data     = mem[rd_ptr];

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            wr_ptr <= '0;
            rd_ptr <= '0;
            count  <= '0;
        end else begin
            if (do_write) begin
                mem[wr_ptr] <= wr_data;
                wr_ptr <= (wr_ptr == DEPTH-1) ? '0 : wr_ptr + 1;
            end
            if (do_read) begin
                rd_ptr <= (rd_ptr == DEPTH-1) ? '0 : rd_ptr + 1;
            end
            case ({do_write, do_read})
                2'b10: count <= count + 1;
                2'b01: count <= count - 1;
                default: count <= count;
            endcase
        end
    end

endmodule

Exercise 2: Credit-Based Flow Control System

Build a complete credit-based flow control system: a credit sender and a credit receiver connected together. The sender tracks credits and only transmits when credits are available. The receiver consumes data and returns credits.

완전한 크레딧 기반 흐름 제어 시스템을 구축하세요: 크레딧 송신자와 크레딧 수신자를 연결합니다. 송신자는 크레딧을 추적하고 크레딧이 있을 때만 전송합니다. 수신자는 데이터를 소비하고 크레딧을 반환합니다.

📋 Requirements

  • MAX_CREDITS = 4 (receiver FIFO depth = 4)
  • MAX_CREDITS = 4 (수신자 FIFO 깊이 = 4)
  • Sender: decrements credits on send, increments on credit_return
  • 송신자: 전송 시 크레딧 감소, credit_return 시 증가
  • Receiver: stores data in FIFO, returns credit when entry consumed by downstream
  • 수신자: FIFO에 데이터 저장, 다운스트림에서 소비 시 크레딧 반환
  • Write a testbench that sends 10 items with a slow consumer (consumes every 3 cycles)
  • 느린 소비자로 10개 항목을 전송하는 테스트벤치 작성 (3 cycle마다 소비)
  • Verify: no data lost, credit count never goes negative or exceeds MAX_CREDITS
  • 검증: 데이터 손실 없음, 크레딧이 음수가 되거나 MAX_CREDITS를 초과하지 않음

💡 Hints

  • The credit_return signal goes from receiver back to sender
  • credit_return 신호는 수신자에서 송신자로 돌아갑니다
  • In real designs, credit_return may travel through pipeline stages — add latency with a shift register for a more realistic simulation
  • 실제 설계에서 credit_return은 파이프라인 단계를 거쳐야 할 수 있음 — 시프트 레지스터로 지연 추가하면 더 현실적
  • Use assertions: assert(credits >= 0) and assert(credits <= MAX_CREDITS)
  • 어서션 사용: assert(credits >= 0) 및 assert(credits <= MAX_CREDITS)
module credit_system #(
    parameter MAX_CREDITS = 4,
    parameter WIDTH       = 8
)(
    input  logic             clk,
    input  logic             rst_n,
    input  logic             prod_valid,
    input  logic [WIDTH-1:0] prod_data,
    output logic             prod_ready,
    output logic             cons_valid,
    output logic [WIDTH-1:0] cons_data,
    input  logic             cons_ready,
    output logic [$clog2(MAX_CREDITS):0] credits_dbg
);

    logic tx_valid, credit_return;
    logic [WIDTH-1:0] tx_data;

    // Credit Sender
    logic [$clog2(MAX_CREDITS):0] credits;
    wire can_send = (credits > 0) && prod_valid;

    assign prod_ready  = (credits > 0);
    assign tx_valid    = can_send;
    assign tx_data     = prod_data;
    assign credits_dbg = credits;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            credits <= MAX_CREDITS;
        else
            case ({can_send, credit_return})
                2'b10: credits <= credits - 1;
                2'b01: credits <= credits + 1;
                default: credits <= credits;
            endcase
    end

    // Credit Receiver (FIFO)
    logic [WIDTH-1:0] fifo [MAX_CREDITS];
    logic [$clog2(MAX_CREDITS)-1:0] wr_ptr, rd_ptr;
    logic [$clog2(MAX_CREDITS):0] fifo_count;

    wire do_read = (fifo_count > 0) && cons_ready;
    assign cons_valid     = (fifo_count > 0);
    assign cons_data      = fifo[rd_ptr];
    assign credit_return = do_read;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            wr_ptr     <= '0;
            rd_ptr     <= '0;
            fifo_count <= '0;
        end else begin
            if (tx_valid) begin
                fifo[wr_ptr] <= tx_data;
                wr_ptr <= wr_ptr + 1;
            end
            if (do_read)
                rd_ptr <= rd_ptr + 1;
            case ({tx_valid, do_read})
                2'b10: fifo_count <= fifo_count + 1;
                2'b01: fifo_count <= fifo_count - 1;
                default: fifo_count <= fifo_count;
            endcase
        end
    end

    // Assertions
    // synthesis translate_off
    always_ff @(posedge clk) begin
        assert(credits <= MAX_CREDITS) else
            $error("Credit overflow! credits=%0d", credits);
        assert(fifo_count <= MAX_CREDITS) else
            $error("FIFO overflow! count=%0d", fifo_count);
    end
    // synthesis translate_on

endmodule

Testbench

module tb_credit_system;
    logic clk, rst_n;
    logic prod_valid, prod_ready;
    logic [7:0] prod_data;
    logic cons_valid, cons_ready;
    logic [7:0] cons_data;
    logic [2:0] credits_dbg;
    integer sent, received;

    credit_system #(.MAX_CREDITS(4), .WIDTH(8)) dut (.*);

    always #5 clk = ~clk;

    // Slow consumer: accepts every 3 cycles
    integer cons_cnt;
    always_ff @(posedge clk) begin
        if (!rst_n) cons_cnt <= 0;
        else cons_cnt <= (cons_cnt == 2) ? 0 : cons_cnt + 1;
    end
    assign cons_ready = (cons_cnt == 0);

    initial begin
        clk = 0; rst_n = 0; prod_valid = 0;
        sent = 0; received = 0;
        #20 rst_n = 1;

        // Send 10 items
        for (int i = 0; i < 10; i++) begin
            prod_valid = 1;
            prod_data  = i;
            @(posedge clk);
            while (!prod_ready) @(posedge clk);
            sent++;
            $display("[%0t] Sent %0d, credits=%0d",
                     $time, i, credits_dbg);
        end
        prod_valid = 0;

        // Wait for consumer to drain
        #200;
        $display("Sent: %0d, Credits final: %0d",
                 sent, credits_dbg);
        $finish;
    end

endmodule

Exercise 3: Skid Buffer with Comprehensive Testbench

Implement a skid buffer that registers the ready signal, then write a testbench that verifies: (1) full throughput when consumer is always ready, (2) correct behavior when consumer stalls randomly, (3) no data loss or duplication.

ready 신호를 레지스터하는 스키드 버퍼를 구현한 다음, 테스트벤치를 작성하여 검증하세요: (1) 소비자가 항상 준비될 때 전체 처리량, (2) 소비자가 무작위로 정지할 때의 올바른 동작, (3) 데이터 손실이나 중복 없음.

📋 Requirements

  • Implement the skid buffer from the lesson
  • 레슨의 스키드 버퍼 구현
  • in_ready must be registered (not combinational from out_ready)
  • in_ready는 레지스터되어야 함 (out_ready에서 조합적이지 않음)
  • Testbench sends 100 sequential values (0-99)
  • 테스트벤치가 100개의 순차 값(0-99) 전송
  • Verify all 100 values are received in order with a scoreboard
  • 스코어보드로 100개 값이 순서대로 수신되는지 검증
  • Add random out_ready deassertion (50% probability)
  • 무작위 out_ready 비활성화 추가 (50% 확률)

💡 Key Insight

The skid buffer's in_ready is !skid_valid — it's registered because skid_valid is a flip-flop output. This means the producer sees ready go low one cycle after the consumer stalls, which is why we need the skid register to catch that one extra word.

스키드 버퍼의 in_ready는 !skid_valid — skid_valid가 플립플롭 출력이므로 레지스터됩니다. 소비자가 정지한 후 1 cycle 후에 생산자가 ready low를 보게 되므로, 그 추가 1 워드를 잡기 위해 스키드 레지스터가 필요합니다.

module skid_buffer #(
    parameter WIDTH = 8
)(
    input  logic             clk,
    input  logic             rst_n,
    input  logic             in_valid,
    input  logic [WIDTH-1:0] in_data,
    output logic             in_ready,
    output logic             out_valid,
    output logic [WIDTH-1:0] out_data,
    input  logic             out_ready
);

    logic [WIDTH-1:0] skid_data;
    logic             skid_valid;

    assign out_valid = skid_valid || in_valid;
    assign out_data  = skid_valid ? skid_data : in_data;
    assign in_ready  = !skid_valid;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            skid_valid <= 1'b0;
        end else if (in_valid && in_ready && !out_ready) begin
            skid_data  <= in_data;
            skid_valid <= 1'b1;
        end else if (out_ready) begin
            skid_valid <= 1'b0;
        end
    end

endmodule

Testbench with Scoreboard

module tb_skid_buffer;
    logic clk, rst_n;
    logic in_valid, in_ready;
    logic [7:0] in_data;
    logic out_valid, out_ready;
    logic [7:0] out_data;
    integer expected, received_cnt;

    skid_buffer #(.WIDTH(8)) dut (.*);

    always #5 clk = ~clk;

    // Random consumer (50% ready)
    always_ff @(posedge clk)
        out_ready <= $urandom_range(0,1);

    // Scoreboard: check output order
    always_ff @(posedge clk) begin
        if (rst_n && out_valid && out_ready) begin
            if (out_data !== expected[7:0]) begin
                $error("MISMATCH: got %0d, expected %0d",
                       out_data, expected);
                $finish;
            end
            expected <= expected + 1;
            received_cnt <= received_cnt + 1;
        end
    end

    initial begin
        clk = 0; rst_n = 0; in_valid = 0;
        expected = 0; received_cnt = 0;
        #20 rst_n = 1;

        // Send 100 values
        for (int i = 0; i < 100; i++) begin
            in_valid = 1;
            in_data  = i;
            @(posedge clk);
            while (!in_ready) @(posedge clk);
        end
        in_valid = 0;

        // Wait for drain
        #500;
        if (received_cnt == 100)
            $display("PASS: All 100 values received in order!");
        else
            $error("FAIL: Only %0d/100 received", received_cnt);
        $finish;
    end

endmodule

🔥 Hard Mode: Credit Return Latency

Modify Exercise 2 so the credit_return signal takes 3 cycles to travel from receiver to sender (simulating a long pipeline). How does this affect the required initial credit count? What happens if you keep MAX_CREDITS = 4 but the round-trip latency is 3?

과제 2를 수정하여 credit_return 신호가 수신자에서 송신자까지 3 cycle이 걸리도록 하세요(긴 파이프라인 시뮬레이션). 이것이 필요한 초기 크레딧 수에 어떤 영향을 미치나요? MAX_CREDITS = 4를 유지하되 왕복 지연이 3이면 어떻게 되나요?

💡 Answer

With 3-cycle return latency, up to 3 extra items could be "in flight" (sent but credit not yet returned). You need MAX_CREDITS = FIFO_DEPTH + return_latency to maintain full throughput. With only 4 credits and 3-cycle latency, the sender stalls frequently because it runs out of credits while waiting for returns — even though the FIFO has space!

3-cycle 반환 지연이 있으면 최대 3개의 추가 항목이 "전송 중"(보냈지만 크레딧 미반환)일 수 있습니다. 전체 처리량을 유지하려면 MAX_CREDITS = FIFO 깊이 + 반환 지연이 필요합니다. 4개 크레딧과 3-cycle 지연만으로는 FIFO에 공간이 있어도 크레딧 대기로 송신자가 자주 정지합니다!
