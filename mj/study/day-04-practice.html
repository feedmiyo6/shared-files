Exercise 1: Convert Verilog to SystemVerilog 연습 1: Verilog를 SystemVerilog로 변환

Rewrite this old-style Verilog module using modern SystemVerilog types and blocks. Replace wire/reg with logic, and use always_ff/always_comb.

이 구식 Verilog 모듈을 최신 SystemVerilog 타입과 블록을 사용하여 다시 작성하세요. wire/reg를 logic으로 바꾸고, always_ff/always_comb을 사용하세요.

// OLD Verilog — Convert this!
module counter_mux (
    input        clk,
    input        rst_n,
    input        sel,
    input  [7:0] data_a,
    input  [7:0] data_b,
    output [7:0] result
);

reg [7:0] mux_out;
reg [7:0] result;

always @(*) begin
    case (sel)
        1'b0: mux_out = data_a;
        1'b1: mux_out = data_b;
    endcase
end

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        result <= 8'd0;
    else
        result <= mux_out;
end

endmodule

Your solution:

당신의 솔루션:

module counter_mux (
    input  logic       clk,
    input  logic       rst_n,
    input  logic       sel,
    input  logic [7:0] data_a,
    input  logic [7:0] data_b,
    output logic [7:0] result
);

logic [7:0] mux_out;

// Combinational: mux
always_comb begin
    case (sel)
        1'b0:    mux_out = data_a;
        1'b1:    mux_out = data_b;
        default: mux_out = data_a;  // Good practice!
    endcase
end

// Sequential: registered output
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        result <= 8'd0;
    else
        result <= mux_out;
end

endmodule

Key changes: (1) All types → logic, (2) always @(*) → always_comb, (3) always @(posedge clk...) → always_ff, (4) Added default case for latch prevention.

주요 변경: (1) 모든 타입 → logic, (2) always @(*) → always_comb, (3) always @(posedge clk...) → always_ff, (4) 래치 방지를 위한 default 케이스 추가.

Exercise 2: Bug Hunt — Find the Errors 연습 2: 버그 찾기 — 오류를 찾으세요

This code has 3 bugs related to wire/reg/logic usage. Find and fix them all.

이 코드에는 wire/reg/logic 사용과 관련된 3개의 버그가 있습니다. 모두 찾아서 고치세요.

module buggy (
    input  reg         clk,        // Bug 1: ???
    input  logic       rst_n,
    output logic [3:0] count
);

logic shared_sig;
assign shared_sig = count[0];   // Driver 1
assign shared_sig = count[1];   // Bug 2: Driver 2 on logic???

always_comb begin
    count <= count + 1;           // Bug 3: ???
end

endmodule

🐛 Bug Analysis

Bug 1: input reg clk — inputs cannot be reg. Fix: input logic clk

Bug 2: Two assign statements to a logic signal — logic only supports one driver. Fix: change to wire (if multi-driver intended) or use a mux.

Bug 3: Non-blocking assignment (<=) in always_comb — combinational blocks must use blocking (=). Also, this is a counter which needs a clock — it should be in always_ff!

module fixed (
    input  logic       clk,         // Fix 1: logic, not reg
    input  logic       rst_n,
    output logic [3:0] count
);

logic count_bit;
assign count_bit = count[0];    // Fix 2: single driver

always_ff @(posedge clk or negedge rst_n) begin  // Fix 3: sequential!
    if (!rst_n)
        count <= 4'd0;
    else
        count <= count + 1;
end

endmodule

Exercise 3: Classify the Hardware 연습 3: 하드웨어 분류

For each signal below, determine if it synthesizes to a flip-flop, combinational logic, or latch. Write your answers then check.

아래의 각 신호가 플립플롭, 조합 논리, 또는 래치로 합성되는지 판별하세요.

logic [7:0] sig_a, sig_b, sig_c, sig_d;

// Signal A
always_ff @(posedge clk) begin
    sig_a <= data_in;
end

// Signal B
always_comb begin
    sig_b = x & y;
end

// Signal C
assign sig_c = sel ? a : b;

// Signal D
always_comb begin
    if (enable)
        sig_d = data_in;
    // No else! What happens?
end

📋 Answers

Signal A: Flip-flop — Driven in always_ff with clock edge → D flip-flop

Signal B: Combinational (AND gate) — always_comb with complete assignment → pure combinational

Signal C: Combinational (MUX) — Continuous assign with ternary → 2:1 multiplexer

Signal D: ⚠️ Latch! — always_comb but missing else branch means sig_d must hold its value when enable is low → inferred latch. This is almost always a bug!

⚠️ The Latch Trap

Signal D is the classic mistake. When an always_comb block doesn't assign a signal in ALL paths, synthesis infers a latch. Fix it by always including a default or else branch:

Signal D는 전형적인 실수입니다. always_comb 블록이 모든 경로에서 신호를 할당하지 않으면 래치가 추론됩니다. 항상 default 또는 else 분기를 포함하여 수정하세요:

always_comb begin
    if (enable)
        sig_d = data_in;
    else
        sig_d = 8'd0;   // ✅ No latch!
end

Exercise 4: Build a Configurable Register 연습 4: 구성 가능한 레지스터 만들기

Design a parameterized register module with enable and async reset. Use proper SystemVerilog types throughout.

적절한 SystemVerilog 타입을 사용하여 인에이블과 비동기 리셋이 있는 매개변수화된 레지스터 모듈을 설계하세요.

Requirements:

요구사항:

  • Parameter WIDTH (default 8)
  • Inputs: clk, rst_n, en, d[WIDTH-1:0]
  • Output: q[WIDTH-1:0]
  • Active-low async reset → output goes to 0
  • Only updates on en = 1
module config_reg #(
    parameter int WIDTH = 8
) (
    input  logic              clk,
    input  logic              rst_n,
    input  logic              en,
    input  logic [WIDTH-1:0] d,
    output logic [WIDTH-1:0] q
);

always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= '0;          // '0 fills all bits with 0
    else if (en)
        q <= d;
    // When en=0: q holds its value (that's what registers do!)
end

endmodule

Note: '0 is a SystemVerilog shorthand that fills all bits with 0, regardless of width. Very handy for parameterized modules! Similarly, '1 fills all bits with 1.

참고: '0은 폭에 관계없이 모든 비트를 0으로 채우는 SystemVerilog 축약형입니다. 매개변수화된 모듈에 매우 유용합니다! 마찬가지로 '1은 모든 비트를 1로 채웁니다.
