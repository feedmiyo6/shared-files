Exercise 1: Basic 2-Flop Synchronizer

📋 Task

Write a 2-flop synchronizer module from scratch. It should have:

처음부터 2-플롭 동기화기 모듈을 작성하세요:

  • Asynchronous active-low reset
  • Single-bit input async_in and output sync_out
  • Both flops driven by clk_dest
  • 비동기 액티브 로우 리셋
  • 단일 비트 입력 async_in과 출력 sync_out
  • 두 플롭 모두 clk_dest로 구동
💡 Hint: Remember: no logic between the two flops. Use non-blocking assignments (<=) for both. 기억: 두 플롭 사이에 로직 없음. 둘 다 논블로킹 할당(<=)을 사용하세요.

Try writing it yourself first, then check the solution:

먼저 직접 작성해 보고, 솔루션을 확인하세요:

Show Solution 
module sync_2ff (
    input  logic clk_dest,
    input  logic rst_n,
    input  logic async_in,
    output logic sync_out
);

    logic meta_ff;

    always_ff @(posedge clk_dest or negedge rst_n) begin
        if (!rst_n) begin
            meta_ff  <= 1'b0;
            sync_out <= 1'b0;
        end else begin
            meta_ff  <= async_in;
            sync_out <= meta_ff;
        end
    end

endmodule

Exercise 2: Testbench with Two Clock Domains

📋 Task

Write a testbench that creates two independent clocks and verifies the synchronizer works. Requirements:

두 개의 독립 클록을 생성하고 동기화기가 작동하는지 검증하는 테스트벤치를 작성하세요:

  • clk_src at 100 MHz (10ns period)
  • clk_dest at 75 MHz (13.33ns period)
  • Toggle async_in from source domain
  • Observe sync_out in destination domain
  • clk_src 100 MHz (10ns 주기)
  • clk_dest 75 MHz (13.33ns 주기)
  • 소스 도메인에서 async_in 토글
  • 목적지 도메인에서 sync_out 관찰
Show Solution 
module tb_sync_2ff;

    logic clk_src, clk_dest, rst_n;
    logic async_in, sync_out;

    // Two independent clocks
    initial clk_src  = 0;
    initial clk_dest = 0;
    always #5     clk_src  = ~clk_src;   // 100 MHz
    always #6.667  clk_dest = ~clk_dest;  // 75 MHz

    // DUT
    sync_2ff dut (
        .clk_dest(clk_dest),
        .rst_n(rst_n),
        .async_in(async_in),
        .sync_out(sync_out)
    );

    initial begin
        rst_n    = 0;
        async_in = 0;
        #20;
        rst_n = 1;

        // Toggle in source domain
        @(posedge clk_src);
        async_in = 1;
        $display("[%0t] async_in → 1", $time);

        // Wait for sync_out to propagate (2 dest clk cycles)
        @(posedge clk_dest);
        @(posedge clk_dest);
        @(posedge clk_dest);  // Extra cycle for safety
        $display("[%0t] sync_out = %b", $time, sync_out);

        // Toggle back to 0
        @(posedge clk_src);
        async_in = 0;
        $display("[%0t] async_in → 0", $time);

        repeat(4) @(posedge clk_dest);
        $display("[%0t] sync_out = %b", $time, sync_out);

        #100;
        $finish;
    end

    // Waveform dump
    initial begin
        $dumpfile("sync_2ff.vcd");
        $dumpvars(0, tb_sync_2ff);
    end

endmodule

Exercise 3: Reset Synchronizer

📋 Task

A common use of synchronizers is for reset signals. Design a reset synchronizer that:

동기화기의 일반적인 용도는 리셋 신호입니다. 다음 조건의 리셋 동기화기를 설계하세요:

  • Asserts reset asynchronously (immediately when reset goes active)
  • De-asserts reset synchronously (aligned to clock edge)
  • This is the industry-standard "async assert, sync de-assert" pattern
  • 리셋 비동기적으로 활성화 (리셋이 활성화되면 즉시)
  • 리셋 동기적으로 비활성화 (클록 에지에 맞춰)
  • 이것은 업계 표준 "비동기 활성화, 동기 비활성화" 패턴
💡 Hint: The async reset in the sensitivity list handles immediate assertion. The synchronizer chain handles clean de-assertion. Feed 1'b1 as the data input (since active-low reset wants to go high on de-assert). 감지 목록의 비동기 리셋이 즉시 활성화를 처리합니다. 동기화기 체인이 깨끗한 비활성화를 처리합니다. 데이터 입력으로 1'b1을 공급하세요 (액티브 로우 리셋이 비활성화 시 하이가 되어야 하므로).
Show Solution 
module reset_sync (
    input  logic clk,
    input  logic async_rst_n,  // Raw async reset (active-low)
    output logic sync_rst_n   // Clean sync reset (active-low)
);

    logic meta_ff;

    always_ff @(posedge clk or negedge async_rst_n) begin
        if (!async_rst_n) begin
            // Async assert: immediately drive reset low
            meta_ff    <= 1'b0;
            sync_rst_n <= 1'b0;
        end else begin
            // Sync de-assert: release reset cleanly
            meta_ff    <= 1'b1;         // Data = 1 (release)
            sync_rst_n <= meta_ff;      // 2-stage sync
        end
    end

endmodule

💡 Why This Pattern?

Async assert ensures the system resets immediately, even if the clock is dead. Sync de-assert ensures all flops in the design come out of reset on the same clock edge, preventing race conditions. This is one of the most important patterns in digital design!

비동기 활성화는 클록이 멈춰도 시스템이 즉시 리셋되도록 합니다. 동기 비활성화는 설계의 모든 플롭이 같은 클록 에지에서 리셋에서 나오도록 하여 경쟁 조건을 방지합니다. 이것은 디지털 설계에서 가장 중요한 패턴 중 하나입니다!

Exercise 4: Bug Hunt 🐛

📋 Find the Bugs

This synchronizer has three bugs. Find and fix them all:

이 동기화기에는 세 가지 버그가 있습니다. 모두 찾아서 수정하세요:

module bad_sync (
    input  logic clk_a,       // Source clock
    input  logic clk_b,       // Destination clock
    input  logic rst_n,
    input  logic async_in,
    output logic sync_out
);

    logic meta_ff;
    logic filtered;

    // Bug 1: Which clock?
    always_ff @(posedge clk_a) begin  // ← WRONG
        if (!rst_n)
            meta_ff <= 1'b0;
        else
            meta_ff <= async_in;
    end

    // Bug 2: What's between the flops?
    assign filtered = meta_ff & ~rst_n;  // ← WRONG

    // Bug 3: Missing reset
    always_ff @(posedge clk_b) begin  // ← WRONG
        sync_out <= filtered;
    end

endmodule
Show Bugs & Fixes

🐛 Bug 1: Wrong clock domain

meta_ff is clocked by clk_a (source domain). Both flops MUST be clocked by clk_b (destination domain).

meta_ff가 clk_a(소스 도메인)로 클로킹됩니다. 두 플롭 모두 clk_b(목적지 도메인)로 클로킹되어야 합니다.

🐛 Bug 2: Logic between flops

The filtered assignment adds combinational logic between FF1 and FF2. This eats into resolution time and defeats the purpose of the synchronizer. The wire must be direct!

filtered 할당이 FF1과 FF2 사이에 조합 로직을 추가합니다. 이것은 해상 시간을 줄이고 동기화기의 목적을 훼손합니다. 와이어는 직접 연결이어야 합니다!

🐛 Bug 3: No reset on FF2

sync_out has no reset — it will power up in an unknown state. Both flops need reset to a known value.

sync_out에 리셋이 없습니다 — 알 수 없는 상태로 전원이 켜집니다. 두 플롭 모두 알려진 값으로 리셋이 필요합니다.

Fixed version:

수정된 버전:

module good_sync (
    input  logic clk_b,       // Only need dest clock
    input  logic rst_n,
    input  logic async_in,
    output logic sync_out
);

    logic meta_ff;

    always_ff @(posedge clk_b or negedge rst_n) begin
        if (!rst_n) begin
            meta_ff  <= 1'b0;
            sync_out <= 1'b0;
        end else begin
            meta_ff  <= async_in;  // Direct!
            sync_out <= meta_ff;   // Direct!
        end
    end

endmodule

Exercise 5: Edge Detector Across Clock Domains

📋 Challenge Task

Design a module that detects a rising edge on async_in (from CLK_A domain) and produces a single-cycle pulse in the CLK_B domain. This combines the synchronizer with an edge detector.

CLK_A 도메인의 async_in에서 상승 에지를 감지하고 CLK_B 도메인에서 단일 사이클 펄스를 생성하는 모듈을 설계하세요. 이것은 동기화기와 에지 감지기를 결합합니다.

💡 Hint: First synchronize with 2 flops, then add a third flop to remember the previous value. Pulse = sync_out & ~sync_out_prev 먼저 2개 플롭으로 동기화한 다음, 세 번째 플롭을 추가하여 이전 값을 기억합니다. 펄스 = sync_out & ~sync_out_prev
Show Solution 
module sync_edge_detect (
    input  logic clk_b,
    input  logic rst_n,
    input  logic async_in,
    output logic pulse_out   // Single-cycle pulse
);

    logic meta_ff, sync_ff, prev_ff;

    always_ff @(posedge clk_b or negedge rst_n) begin
        if (!rst_n) begin
            meta_ff <= 1'b0;
            sync_ff <= 1'b0;
            prev_ff <= 1'b0;
        end else begin
            meta_ff <= async_in;   // Sync stage 1
            sync_ff <= meta_ff;    // Sync stage 2
            prev_ff <= sync_ff;    // Previous value
        end
    end

    // Rising edge = was 0, now 1
    assign pulse_out = sync_ff & ~prev_ff;

endmodule
