1. What is a Module? 1. 모듈이란?

A module is the basic building block in SystemVerilog. Think of it as a "box" with inputs and outputs that does something specific. Just like LEGO blocks, you connect modules together to build bigger designs!

모듈은 SystemVerilog의 기본 구성 요소입니다. 특정 기능을 수행하는 입력과 출력이 있는 "상자"로 생각하세요. 레고 블록처럼, 모듈들을 연결해서 더 큰 설계를 만들 수 있습니다!

Every module has three parts:

모든 모듈은 세 부분으로 구성됩니다:

  • Name: The module's unique identifier (like a function name)
  • 이름: 모듈의 고유 식별자 (함수 이름처럼)
  • Ports: The inputs and outputs (like function parameters)
  • 포트: 입력과 출력 (함수 매개변수처럼)
  • Body: What the module actually does
  • 본문: 모듈이 실제로 하는 일

Basic Module Example

기본 모듈 예제

// This is a simple module that passes data through // 데이터를 통과시키는 간단한 모듈입니다 module my_first_module ( input logic clk, // Clock signal (시계 신호) input logic rst_n, // Reset signal (리셋 신호) input logic [7:0] data_in, // 8-bit input (8비트 입력) output logic [7:0] data_out // 8-bit output (8비트 출력) ); // This part runs on every clock edge always_ff @(posedge clk or negedge rst_n) begin if (!rst_n) data_out <= 8'h00; // Reset to zero else data_out <= data_in; // Pass data through end endmodule
🔰 Beginner's Guide: What's happening here?

Line 1-2: Comments start with // - they're notes for humans, not code

1-2줄: //로 시작하는 것은 주석 - 사람을 위한 메모, 코드 아님

module: Tells SystemVerilog "I'm starting a new module"

module: SystemVerilog에게 "새 모듈 시작"이라고 알림

[7:0]: This means "8 bits wide" (bits numbered 7 down to 0)

[7:0]: "8비트 너비"를 의미 (7번부터 0번까지 비트)

<=: This is "non-blocking assignment" - updates happen at clock edge

<=: "논블로킹 할당" - 클럭 엣지에서 업데이트 발생

2. Port Declarations 2. 포트 선언

Ports are how your module talks to the outside world. There are three types:

포트는 모듈이 외부 세계와 통신하는 방법입니다. 세 가지 종류가 있습니다:

Direction방향 What it does하는 일 Example예시
input Data goes INTO the module데이터가 모듈로 들어감 Clock, reset, data to process클럭, 리셋, 처리할 데이터
output Data comes OUT of the module데이터가 모듈에서 나옴 Results, status flags결과, 상태 플래그
inout Data can go both ways데이터가 양방향으로 이동 Bidirectional buses (rare)양방향 버스 (드물게 사용)

ANSI-style Port Declaration (Modern Way)

ANSI 스타일 포트 선언 (현대적 방법)

✅ ANSI Style (Use This!)

✅ ANSI 스타일 (이것을 사용!)

module adder ( input logic [3:0] a, input logic [3:0] b, output logic [4:0] sum ); assign sum = a + b; endmodule

❌ Old Style (Avoid)

❌ 구식 스타일 (피하기)

module adder (a, b, sum); input [3:0] a; input [3:0] b; output [4:0] sum; assign sum = a + b; endmodule

💡 Tip: Always use ANSI-style (left example). It's cleaner, easier to read, and the modern standard!

💡 팁: 항상 ANSI 스타일(왼쪽 예제)을 사용하세요. 더 깔끔하고, 읽기 쉽고, 현대 표준입니다!

3. Port Types: wire, logic, reg 3. 포트 타입: wire, logic, reg

Simple Rule: In SystemVerilog, just use logic for everything! It works in all situations.

간단한 규칙: SystemVerilog에서는 모든 것에 logic만 사용하세요! 모든 상황에서 작동합니다.

Type When to use사용 시기 Recommendation권장 사항
wire Old Verilog - for connections구형 Verilog - 연결용 ❌ Avoid❌ 피하기
reg Old Verilog - for stored values구형 Verilog - 저장 값용 ❌ Avoid❌ 피하기
logic SystemVerilog - works everywhere!SystemVerilog - 어디서나 작동! ✅ Use this!✅ 이것 사용!

⚠️ Confusing name alert: reg does NOT mean "register"! It's a confusing historical name. That's why logic was created in SystemVerilog - it's clearer!

⚠️ 혼란스러운 이름 주의: reg는 "레지스터"를 의미하지 않습니다! 혼란스러운 역사적 이름입니다. 그래서 SystemVerilog에서 logic이 만들어졌습니다 - 더 명확합니다!

4. Parameters and localparam 4. 파라미터와 localparam

Parameters let you make reusable modules. Instead of hardcoding numbers, use parameters!

파라미터는 재사용 가능한 모듈을 만들 수 있게 합니다. 숫자를 하드코딩하는 대신 파라미터를 사용하세요!

🔰 Why use parameters?

Imagine you build an 8-bit adder. Later you need a 16-bit adder. Without parameters, you'd copy-paste and change all the "8"s to "16"s. With parameters, you just change ONE number!

8비트 가산기를 만들었다고 상상해보세요. 나중에 16비트 가산기가 필요합니다. 파라미터 없이는 복사-붙여넣기하고 모든 "8"을 "16"으로 바꿔야 합니다. 파라미터가 있으면 숫자 하나만 바꾸면 됩니다!

Type Can change it later?나중에 변경 가능? Use for용도
parameter ✅ Yes, when you use the module✅ 예, 모듈 사용 시 Configurable values (WIDTH, SIZE)구성 가능한 값 (WIDTH, SIZE)
localparam ❌ No, fixed forever❌ 아니오, 영구 고정 Internal constants내부 상수

Example: Configurable Counter

예제: 구성 가능한 카운터

// A counter that can be any width! // 어떤 너비든 될 수 있는 카운터! module counter #( parameter int WIDTH = 8, // Default: 8 bits parameter int MAX_COUNT = 255 // Default: count to 255 )( input logic clk, input logic rst_n, input logic enable, output logic [WIDTH-1:0] count, output logic overflow ); // localparam: calculated from parameter, can't be changed localparam int HALF_MAX = MAX_COUNT / 2; always_ff @(posedge clk or negedge rst_n) begin if (!rst_n) begin count <= '0; // Reset to zero overflow <= 1'b0; end else if (enable) begin if (count == MAX_COUNT) begin count <= '0; // Wrap around overflow <= 1'b1; end else begin count <= count + 1; overflow <= 1'b0; end end end endmodule
🔰 Reading the code:

#(...): This section defines parameters (before the port list)

#(...): 이 섹션은 파라미터를 정의합니다 (포트 리스트 앞에)

WIDTH-1:0: If WIDTH=8, this becomes [7:0] (8 bits)

WIDTH-1:0: WIDTH=8이면 [7:0]이 됩니다 (8비트)

'0: Shorthand for "all zeros, whatever the width"

'0: "너비에 상관없이 모두 0"의 약어

5. Module Instantiation 5. 모듈 인스턴스화

Instantiation means "using" a module inside another module. It's like placing a LEGO block inside a bigger structure.

인스턴스화는 다른 모듈 안에서 모듈을 "사용"하는 것입니다. 더 큰 구조 안에 레고 블록을 배치하는 것과 같습니다.

Two Ways to Connect Ports

포트를 연결하는 두 가지 방법

❌ Positional (Risky)

❌ 위치 기반 (위험)

// Order must match exactly! counter u_cnt ( sys_clk, sys_rst_n, cnt_enable, cnt_value, cnt_ovf );

✅ Named (Safe!)

✅ 이름 기반 (안전!)

// Clear what connects to what counter u_cnt ( .clk (sys_clk), .rst_n (sys_rst_n), .enable (cnt_enable), .count (cnt_value), .overflow (cnt_ovf) );
🔰 Understanding the syntax:

.clk(sys_clk): "Connect the module's clk port to my signal sys_clk"

.clk(sys_clk): "모듈의 clk 포트를 내 신호 sys_clk에 연결"

u_cnt: The instance name (like a variable name). Use u_ or i_ prefix by convention.

u_cnt: 인스턴스 이름 (변수명처럼). 관례상 u_ 또는 i_ 접두사 사용.

Instantiation with Custom Parameters

사용자 정의 파라미터로 인스턴스화

module top_level ( input logic clk, input logic rst_n, output logic [15:0] count_16bit, output logic [7:0] count_8bit ); // Instance 1: Make a 16-bit counter counter #( .WIDTH (16), .MAX_COUNT (65535) ) u_counter_16 ( .clk (clk), .rst_n (rst_n), .enable (1'b1), // Always enabled .count (count_16bit), .overflow () // Not used - leave empty ); // Instance 2: Use default 8-bit counter counter u_counter_8 ( .clk (clk), .rst_n (rst_n), .enable (1'b1), .count (count_8bit), .overflow () ); endmodule

💡 Pro tip: When signal name matches port name, you can shorten .clk(clk) to just .clk!

💡 프로 팁: 신호 이름이 포트 이름과 같으면 .clk(clk)를 그냥 .clk로 줄일 수 있습니다!

6. Generate Blocks 6. Generate 블록

Generate blocks let you create multiple copies of hardware using loops. Think of it as "copy-paste at compile time."

Generate 블록은 루프를 사용하여 여러 복사본의 하드웨어를 만들 수 있게 합니다. "컴파일 시 복사-붙여넣기"로 생각하세요.

// Create 8 adders automatically! module ripple_carry_adder #( parameter int WIDTH = 8 )( input logic [WIDTH-1:0] a, input logic [WIDTH-1:0] b, input logic cin, output logic [WIDTH-1:0] sum, output logic cout ); logic [WIDTH:0] carry; assign carry[0] = cin; assign cout = carry[WIDTH]; // This loop creates WIDTH instances of full_adder genvar i; generate for (i = 0; i < WIDTH; i++) begin : gen_adder full_adder u_fa ( .a (a[i]), .b (b[i]), .cin (carry[i]), .sum (sum[i]), .cout (carry[i+1]) ); end endgenerate endmodule
🔰 Understanding generate:

genvar i: A special variable just for generate loops

genvar i: generate 루프 전용 특수 변수

: gen_adder: Label for the generate block (required)

: gen_adder: generate 블록의 레이블 (필수)

Result: If WIDTH=8, this creates 8 full_adder instances automatically!

결과: WIDTH=8이면 8개의 full_adder 인스턴스가 자동으로 생성됩니다!

7. Coding Style Best Practices 7. 코딩 스타일 모범 사례

✅ DO This

✅ 이렇게 하세요

  • Use logic for all signals
  • 모든 신호에 logic 사용
  • Use ANSI-style port declarations
  • ANSI 스타일 포트 선언 사용
  • Use named port connections (.clk(clk))
  • 이름 기반 포트 연결 사용 (.clk(clk))
  • Prefix instance names: u_ or i_
  • 인스턴스 이름 접두사: u_ 또는 i_
  • Use meaningful names: DATA_WIDTH, not W
  • 의미 있는 이름 사용: W가 아닌 DATA_WIDTH
  • Use _n suffix for active-low: rst_n
  • 액티브-로우에 _n 접미사: rst_n

❌ DON'T Do This

❌ 이것은 하지 마세요

  • Positional port connections (hard to read, easy to mess up)
  • 위치 기반 포트 연결 (읽기 어렵고, 실수하기 쉬움)
  • Magic numbers: use parameters instead of 8'hFF
  • 매직 넘버: 8'hFF 대신 파라미터 사용
  • Multiple drivers for the same signal
  • 같은 신호에 여러 드라이버

8. Common Mistakes to Avoid 8. 피해야 할 흔한 실수

Mistake 1: Missing comma or semicolon

실수 1: 쉼표 또는 세미콜론 누락

// ❌ WRONG - missing comma after data_in module buggy ( input logic [7:0] data_in // ← Missing comma! output logic [7:0] data_out ) // ← Missing semicolon! // ✅ CORRECT module fixed ( input logic [7:0] data_in, // ← Comma here output logic [7:0] data_out ); // ← Semicolon here

Mistake 2: Port width mismatch

실수 2: 포트 너비 불일치

// ❌ WRONG - 16-bit signal connected to 8-bit port logic [15:0] wide_data; my_module u_mod ( .data_in(wide_data) // Port expects [7:0]! ); // ✅ CORRECT - slice to correct width my_module u_mod ( .data_in(wide_data[7:0]) // Use lower 8 bits );

Mistake 3: Incomplete case statement

실수 3: 불완전한 case 문

// ❌ WRONG - missing case creates a "latch" (bad!) always_comb begin case (sel) 2'b00: out = a; 2'b01: out = b; 2'b10: out = c; // What about 2'b11? → Creates latch! endcase end // ✅ CORRECT - always include default always_comb begin case (sel) 2'b00: out = a; 2'b01: out = b; 2'b10: out = c; 2'b11: out = d; default: out = 'x; // Good practice! endcase end
