📅 Day 24: Backpressure — Stall Signals & Bubbles

📝 Quiz 💻 Practice

Welcome to Day 24! Yesterday we learned about pipeline hazards. Today we tackle backpressure — the mechanism that prevents data loss when a downstream stage can't accept new data. This is one of the most critical concepts in real digital design.

Day 24에 오신 걸 환영합니다! 어제 파이프라인 해저드를 배웠고, 오늘은 백프레셔(backpressure)를 다룹니다 — 다운스트림 스테이지가 새 데이터를 받을 수 없을 때 데이터 손실을 방지하는 메커니즘입니다. 실제 디지털 설계에서 가장 중요한 개념 중 하나입니다.

1. What Is Backpressure?

Backpressure is a flow control mechanism where a downstream consumer signals upstream that it's not ready to accept more data. Without backpressure, fast producers would overwrite data that slow consumers haven't processed yet.

백프레셔는 다운스트림 소비자가 상류에 "더 이상 데이터를 받을 준비가 안 됐다"고 신호를 보내는 흐름 제어 메커니즘입니다. 백프레셔 없이는 빠른 생산자가 느린 소비자가 아직 처리하지 못한 데이터를 덮어쓰게 됩니다.

🌊 Real-World Analogy

Think of a factory assembly line. If the painting station is slow, the welding station upstream must stop feeding parts — otherwise parts pile up and fall off the conveyor. The painting station raises a "I'm full!" flag. That flag is backpressure.

공장 조립 라인을 생각해보세요. 도장 스테이션이 느리면, 상류의 용접 스테이션은 부품 공급을 중단해야 합니다. 그렇지 않으면 부품이 쌓여 컨베이어에서 떨어집니다. 도장 스테이션이 "나 꽉 찼어!" 깃발을 올립니다. 그 깃발이 백프레셔입니다.

2. Stall Signals

A stall signal freezes one or more pipeline stages, preventing them from advancing. When a stage is stalled, it retains its current data and ignores any new clock edge for data advancement.

스톨(stall) 신호는 하나 이상의 파이프라인 스테이지를 동결시켜 진행을 방지합니다. 스테이지가 스톨되면 현재 데이터를 유지하고 데이터 진행을 위한 새 클럭 에지를 무시합니다.

Basic Stall Mechanism

// Pipeline stage with stall support
module pipe_stage (
    input  logic        clk,
    input  logic        rst_n,
    input  logic        stall,       // Backpressure from downstream
    input  logic [31:0] data_in,
    input  logic        valid_in,
    output logic [31:0] data_out,
    output logic        valid_out
);

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            data_out  <= '0;
            valid_out <= 1'b0;
        end else if (!stall) begin
            // Only advance when NOT stalled
            data_out  <= data_in;
            valid_out <= valid_in;
        end
        // When stalled: hold current values (implicit)
    end

endmodule

💡 Key Insight

The stall signal acts as a clock enable for the pipeline register. When stall = 1, the register doesn't update — it freezes in place. This is the simplest form of backpressure.

스톨 신호는 파이프라인 레지스터의 클럭 인에이블 역할을 합니다. stall = 1이면 레지스터가 업데이트되지 않고 제자리에서 동결됩니다. 이것이 백프레셔의 가장 간단한 형태입니다.

Stall Propagation in a Pipeline

Stalls propagate backward through a pipeline. If Stage 3 stalls, Stage 2 must also stall (it can't push data into a frozen Stage 3), and Stage 1 must stall too.

스톨은 파이프라인을 통해 역방향으로 전파됩니다. 스테이지 3이 스톨되면 스테이지 2도 스톨되어야 하고(동결된 스테이지 3에 데이터를 밀어넣을 수 없으므로), 스테이지 1도 마찬가지입니다.

Stall Propagation: Stage 1 Stage 2 Stage 3 Stage 4 ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │ FETCH │────▶│ DECODE │────▶│ EXEC │────▶│ WRITE │ └────────┘ └────────┘ └────────┘ └────────┘ ▲ ▲ ▲ │ │ │ │ │ └──── stall ◄──┴──── stall ◄──┴──── stall ◄─┘ (source: memory busy)
// Stall chain in a 4-stage pipeline
assign stall_stage3 = stall_stage4;  // Can't push into frozen stage
assign stall_stage2 = stall_stage3;
assign stall_stage1 = stall_stage2;

// Common stall source: slow memory
assign stall_stage4 = mem_busy;  // Write-back waiting for memory

3. Pipeline Bubbles

A bubble is an empty (invalid) pipeline slot. Bubbles are inserted when we need to create a gap in the pipeline — either due to a hazard or when a stall affects only part of the pipeline.

버블(bubble)은 빈(유효하지 않은) 파이프라인 슬롯입니다. 해저드로 인해 또는 스톨이 파이프라인의 일부에만 영향을 줄 때 파이프라인에 갭을 만들어야 할 경우 버블이 삽입됩니다.

🫧 Bubble = NOP (No Operation)

A bubble is essentially a valid = 0 marker flowing through the pipeline. Downstream stages see it and know: "nothing useful here, skip processing." It consumes a cycle but doesn't produce incorrect results.

버블은 본질적으로 파이프라인을 통해 흐르는 valid = 0 마커입니다. 다운스트림 스테이지는 이를 보고 "여기에 유용한 것이 없으니 처리를 건너뛰자"라고 알게 됩니다. 사이클을 소비하지만 잘못된 결과를 생성하지 않습니다.

Inserting a Bubble (Squash + Stall)

// Stage with stall AND bubble insertion
module pipe_stage_bubble (
    input  logic        clk,
    input  logic        rst_n,
    input  logic        stall,       // Hold current data
    input  logic        squash,      // Insert bubble (kill valid)
    input  logic [31:0] data_in,
    input  logic        valid_in,
    output logic [31:0] data_out,
    output logic        valid_out
);

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            data_out  <= '0;
            valid_out <= 1'b0;
        end else if (squash) begin
            // Insert bubble: invalidate this stage
            valid_out <= 1'b0;
            // data_out can be don't-care
        end else if (!stall) begin
            data_out  <= data_in;
            valid_out <= valid_in;
        end
    end

endmodule

4. Combining Stall + Bubble

In real pipelines, you often need both. Consider: Stage 3 detects a data hazard that needs 1 bubble cycle. It must stall Stages 1-2 (don't lose their data) while inserting a bubble into Stage 3→4.

실제 파이프라인에서는 종종 둘 다 필요합니다. 스테이지 3이 1 버블 사이클이 필요한 데이터 해저드를 감지합니다. 스테이지 1-2를 스톨시키고(데이터를 잃지 않도록) 스테이지 3→4에 버블을 삽입해야 합니다.

Cycle N: [A] → [B] → [C] → [D] (C needs data from D) ↑ hazard detected! Cycle N+1: [A] → [B] → [C] → [bubble] (Stall A,B,C; bubble into D's input) stall stall stall Cycle N+2: [A] → [B] → [C] → [D_result] (D done, C can now use forwarded data) ↑ forward

Pipeline Controller

// Pipeline hazard controller
module pipeline_ctrl (
    input  logic data_hazard,     // From hazard detection unit
    input  logic mem_busy,        // Memory not ready
    output logic stall_fetch,
    output logic stall_decode,
    output logic stall_exec,
    output logic stall_wb,
    output logic bubble_exec      // Insert bubble after decode
);

    // Memory stall: freeze entire pipeline
    assign stall_wb     = mem_busy;
    assign stall_exec   = mem_busy;
    assign stall_decode = mem_busy | data_hazard;
    assign stall_fetch  = mem_busy | data_hazard;

    // Data hazard: bubble into execute (only when not mem stall)
    assign bubble_exec  = data_hazard & !mem_busy;

endmodule

⚠️ Common Mistake: Bubble During Stall

Never insert a bubble while the same stage is also stalled! If Stage 3 is stalled (holding valid data), inserting a bubble would destroy that data. The squash signal should be gated: bubble = hazard & !stall.

같은 스테이지가 스톨된 상태에서 버블을 삽입하면 안 됩니다! 스테이지 3이 스톨되어 유효한 데이터를 보유하고 있을 때 버블을 삽입하면 해당 데이터가 파괴됩니다. 스쿼시 신호는 게이팅해야 합니다: bubble = hazard & !stall.

모든 스톨이나 버블은 처리량을 감소시킵니다. 파이프라인의 유효 처리량은:

📊 Throughput Formula

Effective Throughput = 1 / (1 + stall_rate)

If a pipeline stalls 20% of cycles, throughput = 1/1.2 = 83.3% of ideal. In a 5-stage pipeline running at 1 GHz, that's 833M operations/sec instead of 1G.

파이프라인이 20% 사이클 동안 스톨되면, 처리량 = 1/1.2 = 이상적인 것의 83.3%. 1 GHz에서 실행되는 5단계 파이프라인에서 1G 대신 833M 연산/초입니다.

6. Skid Buffer: Elegant Backpressure

A skid buffer (or pipeline register with bypass) is a 1-entry buffer that absorbs a stall cycle. Instead of stalling the upstream immediately, data "skids" into the buffer, buying one extra cycle.

스키드 버퍼(또는 바이패스가 있는 파이프라인 레지스터)는 스톨 사이클을 흡수하는 1-엔트리 버퍼입니다. 상류를 즉시 스톨하는 대신 데이터가 버퍼로 "미끄러져" 들어가 한 사이클의 여유를 줍니다.

// Simple skid buffer
module skid_buffer #(
    parameter WIDTH = 32
)(
    input  logic             clk,
    input  logic             rst_n,
    // Upstream interface
    input  logic [WIDTH-1:0] up_data,
    input  logic             up_valid,
    output logic             up_ready,
    // Downstream interface
    output logic [WIDTH-1:0] dn_data,
    output logic             dn_valid,
    input  logic             dn_ready
);

    logic [WIDTH-1:0] buf_data;
    logic             buf_valid;

    // Ready when buffer is empty
    assign up_ready = !buf_valid;

    // Output: buffer has priority over direct passthrough
    assign dn_data  = buf_valid ? buf_data  : up_data;
    assign dn_valid = buf_valid | up_valid;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            buf_valid <= 1'b0;
        end else if (buf_valid && dn_ready) begin
            // Buffer drains when downstream accepts
            buf_valid <= 1'b0;
        end else if (up_valid && up_ready && !dn_ready) begin
            // Capture into buffer when downstream is busy
            buf_data  <= up_data;
            buf_valid <= 1'b1;
        end
    end

endmodule

💡 Why Skid Buffers Matter

Skid buffers break the combinational stall chain. Without them, a stall at the last stage creates a combinational path all the way back to the first stage (stall propagation). This can become the critical timing path! A skid buffer registers the stall, limiting propagation to one stage at a time.

스키드 버퍼는 조합 스톨 체인을 끊습니다. 없으면 마지막 스테이지의 스톨이 첫 스테이지까지 조합 경로를 만듭니다(스톨 전파). 이것이 크리티컬 타이밍 경로가 될 수 있습니다! 스키드 버퍼는 스톨을 레지스터하여 한 번에 한 스테이지로 전파를 제한합니다.

7. Interview Connection

🎯 What Interviewers Ask

  • "What happens when your pipeline's memory stage takes 3 cycles?" → Stall the entire pipeline for 2 extra cycles, or use a skid buffer to reduce upstream impact.
  • "파이프라인의 메모리 스테이지가 3사이클 걸리면?" → 전체 파이프라인을 2사이클 추가 스톨하거나, 스키드 버퍼로 상류 영향을 줄입니다.
  • "How do you prevent data loss in a pipeline?" → Backpressure via stall signals. Never advance a stage if downstream can't accept.
  • "파이프라인에서 데이터 손실을 어떻게 방지하나요?" → 스톨 신호를 통한 백프레셔. 다운스트림이 받을 수 없으면 스테이지를 절대 진행시키지 않습니다.
  • "Stall vs bubble — when do you use each?" → Stall = downstream not ready (freeze everything). Bubble = need a gap for hazard resolution (downstream keeps moving).
  • "스톨 vs 버블 — 각각 언제 사용?" → 스톨 = 다운스트림 준비 안 됨(모두 동결). 버블 = 해저드 해결을 위한 갭 필요(다운스트림은 계속 진행).

Summary

📝 Key Takeaways

📝 핵심 정리

  1. Backpressure = downstream telling upstream "stop, I'm not ready"
  2. 백프레셔 = 다운스트림이 업스트림에게 "멈춰, 준비 안 됐어"라고 말하는 것
  3. Stall signals freeze pipeline stages by disabling register updates (clock enable)
  4. 스톨 신호는 레지스터 업데이트를 비활성화하여 파이프라인 스테이지를 동결 (클럭 인에이블)
  5. Bubbles insert invalid (NOP) slots that flow downstream
  6. 버블은 다운스트림으로 흐르는 유효하지 않은(NOP) 슬롯을 삽입
  7. Stalls propagate backward, bubbles flow forward
  8. 스톨은 역방향으로 전파, 버블은 순방향으로 흐름
  9. Never bubble + stall the same stage simultaneously — data loss!
  10. 같은 스테이지를 동시에 버블 + 스톨하지 마세요 — 데이터 손실!
  11. Skid buffers break combinational stall chains and improve timing
  12. 스키드 버퍼는 조합 스톨 체인을 끊고 타이밍을 개선
