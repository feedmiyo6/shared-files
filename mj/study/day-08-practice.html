Exercise 2: Convert a Binary FSM to One-Hot

The following FSM uses binary encoding. Rewrite it using one-hot encoding with the case(1'b1) pattern.

다음 FSM은 바이너리 인코딩을 사용합니다. case(1'b1) 패턴을 사용하여 원-핫 인코딩으로 다시 작성하세요.

// Original: Binary-encoded traffic light
typedef enum logic [1:0] {
    RED    = 2'b00,
    GREEN  = 2'b01,
    YELLOW = 2'b10
} light_t;

light_t state, next;

always_comb begin
    next = state;
    case (state)
        RED:    if (timer_done) next = GREEN;
        GREEN:  if (timer_done) next = YELLOW;
        YELLOW: if (timer_done) next = RED;
        default: next = RED;
    endcase
end

assign red_on    = (state == RED);
assign green_on  = (state == GREEN);
assign yellow_on = (state == YELLOW);
// One-hot version
typedef enum logic [2:0] {
    RED    = 3'b001,
    GREEN  = 3'b010,
    YELLOW = 3'b100
} light_t;

light_t state, next;

always_comb begin
    next = state;
    case (1'b1)  // One-hot case pattern
        state[0]: if (timer_done) next = GREEN;  // RED
        state[1]: if (timer_done) next = YELLOW; // GREEN
        state[2]: if (timer_done) next = RED;    // YELLOW
        default:  next = RED;  // Illegal state recovery!
    endcase
end

// Outputs are now single-bit checks — no decode needed!
assign red_on    = state[0];
assign green_on  = state[1];
assign yellow_on = state[2];

Exercise 3: Binary-Gray Converter Module

Write a parameterized SystemVerilog module that converts an N-bit binary input to Gray code output. Then write the reverse (Gray to binary).

N비트 바이너리 입력을 그레이 코드 출력으로 변환하는 매개변수화된 SystemVerilog 모듈을 작성하세요. 그런 다음 역변환(그레이 → 바이너리)도 작성하세요.

💡 Hint: Binary→Gray is one line: assign gray = bin ^ (bin >> 1);
Gray→Binary needs a loop: each bit depends on the XOR of all higher bits. 바이너리→그레이는 한 줄: assign gray = bin ^ (bin >> 1);
그레이→바이너리는 루프가 필요: 각 비트가 모든 상위 비트의 XOR에 의존합니다. 
// Parameterized Binary to Gray converter
module bin2gray #(
    parameter int WIDTH = 4
)(
    input  logic [WIDTH-1:0] bin,
    output logic [WIDTH-1:0] gray
);
    assign gray = bin ^ (bin >> 1);
endmodule

// Parameterized Gray to Binary converter
module gray2bin #(
    parameter int WIDTH = 4
)(
    input  logic [WIDTH-1:0] gray,
    output logic [WIDTH-1:0] bin
);
    always_comb begin
        bin[WIDTH-1] = gray[WIDTH-1];  // MSB same
        for (int i = WIDTH-2; i >= 0; i--)
            bin[i] = bin[i+1] ^ gray[i];
    end
endmodule

Exercise 4: Encoding Trade-off Analysis

You're designing an FSM with 32 states for an FPGA. Compare the resource usage:

32개 상태의 FSM을 FPGA용으로 설계하고 있습니다. 리소스 사용량을 비교하세요:

a) How many flip-flops for binary encoding?
b) How many flip-flops for one-hot encoding?
c) Which has simpler next-state logic and why?
d) Which would you choose for an FPGA and why?

a) 바이너리 인코딩에 필요한 플립플롭 수?
b) 원-핫 인코딩에 필요한 플립플롭 수?
c) 어느 것의 다음 상태 로직이 더 간단하고 왜?
d) FPGA에 어떤 것을 선택할 것이고 왜?

Analysis

a) Binary: ⌈log₂(32)⌉ = 5 flip-flops

b) One-hot: 32 flip-flops

c) One-hot has simpler next-state logic. With binary, every transition requires decoding all 5 bits. With one-hot, checking state is a single-bit test. The combinational logic fan-in is much smaller.

d) For FPGA: One-hot. FPGAs have abundant flip-flops (each LUT comes with one), so the extra 27 flip-flops cost almost nothing. The reduced combinational logic means faster clock speeds and easier timing closure. For 32 states, the speed gain usually outweighs the area cost on FPGAs.

Note: For an ASIC with 32+ states, binary might be preferred to save area, since flip-flops have real silicon cost.

참고: 32개 이상의 상태가 있는 ASIC의 경우, 플립플롭에 실제 실리콘 비용이 있으므로 면적을 절약하기 위해 바이너리가 선호될 수 있습니다.

Exercise 5: Add Illegal State Recovery

This one-hot FSM has a bug — it doesn't handle illegal states. Add recovery logic so the FSM returns to IDLE if it enters an illegal state.

이 원-핫 FSM에 버그가 있습니다 — 불법 상태를 처리하지 않습니다. 불법 상태에 진입하면 IDLE로 돌아가는 복구 로직을 추가하세요.

typedef enum logic [2:0] {
    IDLE = 3'b001,
    LOAD = 3'b010,
    EXEC = 3'b100
} state_t;

always_ff @(posedge clk or negedge rst_n)
    if (!rst_n) state <= IDLE;
    else         state <= next;

// BUG: No illegal state handling!
always_comb begin
    next = state;
    case (1'b1)
        state[0]: if (start) next = LOAD;
        state[1]:              next = EXEC;
        state[2]: if (done)  next = IDLE;
    endcase
end
// Fixed: Illegal state recovery added
always_comb begin
    next = state;
    case (1'b1)
        state[0]: if (start) next = LOAD;
        state[1]:              next = EXEC;
        state[2]: if (done)  next = IDLE;
        default:  next = IDLE;  // ← Recovery!
    endcase
    
    // Additional safety: check one-hot property
    if (!$onehot(state))
        next = IDLE;  // Force recovery if not one-hot
end

// For synthesis, you can also add an assertion:
// assert property (@(posedge clk) $onehot(state))
//     else $error("Illegal state detected!");

Why this matters: In space/radiation environments, SEU (single-event upsets) can flip bits. If bit 0 and bit 1 are both high (3'b011), that's no valid state. The default catches it and recovers gracefully.

왜 중요한가: 우주/방사선 환경에서 SEU가 비트를 뒤집을 수 있습니다. 비트 0과 1이 모두 high(3'b011)이면 유효한 상태가 아닙니다. default가 이를 감지하고 정상적으로 복구합니다.
