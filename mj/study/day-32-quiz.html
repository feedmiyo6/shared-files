3 What does an if-else inside always_comb infer? always_comb 내부의 if-else는 무엇을 추론하는가?

  • A) Flip-flop with enableA) 인에이블이 있는 플립플롭
  • B) 2:1 MultiplexerB) 2:1 멀티플렉서
  • C) DecoderC) 디코더
  • D) AdderD) 가산기
✅ An if-else in combinational logic infers a 2:1 mux. The condition is the select signal, and the two branches are the data inputs.✅ 조합 논리의 if-else는 2:1 멀티플렉서를 추론합니다. 조건은 선택 신호이고, 두 분기는 데이터 입력입니다.

4 What is the key difference between if-else if chains and case statements for synthesis? 합성에서 if-else if 체인과 case 문의 주요 차이점은?

  • A) if-else if creates priority chains; case creates parallel mux treesA) if-else if는 우선순위 체인을 만들고; case는 병렬 멀티플렉서 트리를 만듦
  • B) They produce identical hardwareB) 동일한 하드웨어를 생성함
  • C) case can only handle 2 inputsC) case는 2개의 입력만 처리 가능
  • D) if-else if uses less areaD) if-else if가 더 적은 면적을 사용함
✅ if-else if creates a priority chain of cascaded muxes (longer critical path). case allows the tool to build a flatter, parallel mux tree — shorter path, better timing.✅ if-else if는 캐스케이드된 멀티플렉서의 우선순위 체인을 만듭니다 (더 긴 크리티컬 패스). case는 도구가 더 평평하고 병렬적인 멀티플렉서 트리를 구축할 수 있게 합니다.

5 What hardware does assign y = a << 3; (constant shift) infer? assign y = a << 3; (상수 시프트)는 어떤 하드웨어를 추론하는가?

  • A) A barrel shifterA) 배럴 시프터
  • B) A multiplier by 8B) 8배 곱셈기
  • C) Just wires (zero cost!)C) 단순 와이어 (비용 제로!)
  • D) An adder chainD) 가산기 체인
✅ A constant shift is just rewiring — bit 0 connects to bit 3, bit 1 to bit 4, etc. No gates needed at all! It's literally free in hardware.✅ 상수 시프트는 단순한 재배선입니다 — 비트 0이 비트 3에, 비트 1이 비트 4에 연결됩니다. 게이트가 전혀 필요 없습니다!

6 Which operation has the HIGHEST area cost? 가장 높은 면적 비용을 가진 연산은?

  • A) Addition (a + b)A) 덧셈 (a + b)
  • B) Multiplication (a * b)B) 곱셈 (a * b)
  • C) Comparison (a == b)C) 비교 (a == b)
  • D) Division (a / b)D) 나눗셈 (a / b)
✅ Division is the most expensive arithmetic operation. It typically requires iterative algorithms or very large combinational circuits. Multiplication is second. Avoid division in combinational logic!✅ 나눗셈은 가장 비싼 산술 연산입니다. 일반적으로 반복 알고리즘이나 매우 큰 조합 회로가 필요합니다. 곱셈이 두 번째입니다.

7 How does synthesis optimize a * 3? 합성은 a * 3을 어떻게 최적화하는가?

  • A) It uses a full multiplierA) 전체 곱셈기를 사용함
  • B) It converts to (a << 1) + a (shift + add)B) (a << 1) + a (시프트 + 가산)로 변환
  • C) It uses a lookup tableC) 룩업 테이블을 사용함
  • D) It creates three copies of the adderD) 가산기의 세 복사본을 생성함
✅ Synthesis tools decompose constant multiplications into shifts and adds. a * 3 = a * (2 + 1) = (a << 1) + a. This is much cheaper than a full multiplier!✅ 합성 도구는 상수 곱셈을 시프트와 가산으로 분해합니다. a * 3 = a * (2 + 1) = (a << 1) + a. 이것은 전체 곱셈기보다 훨씬 저렴합니다!

8 What does ^data (XOR reduction) give you? ^data (XOR 축소)는 무엇을 제공하는가?

  • A) The largest bitA) 가장 큰 비트
  • B) Bitwise inversionB) 비트 반전
  • C) Parity (odd/even number of 1s)C) 패리티 (1의 홀수/짝수 개수)
  • D) Population countD) 1의 개수
✅ XOR reduction produces a single-bit parity output: 1 if there's an odd number of 1-bits, 0 if even. It creates a tree of XOR gates — very useful for error detection!✅ XOR 축소는 단일 비트 패리티 출력을 생성합니다: 1비트의 수가 홀수면 1, 짝수면 0. XOR 게이트의 트리를 생성합니다 — 오류 감지에 매우 유용합니다!

9 What determines whether an array infers Block RAM or flip-flop array? 배열이 블록 RAM을 추론할지 플립플롭 배열을 추론할지 결정하는 것은?

  • B) The array sizeB) 배열 크기
  • C) Whether you use logic or regC) logic 또는 reg 사용 여부
  • D) The number of write portsD) 쓰기 포트 수
✅ Synchronous reads (inside always_ff) let the tool infer block RAM. Asynchronous reads (assign rd = mem[addr]) force the tool to use flip-flop arrays — potentially thousands of FFs!✅ 동기식 읽기(always_ff 내부)는 블록 RAM을 추론할 수 있게 합니다. 비동기식 읽기는 플립플롭 배열을 사용하게 합니다.

  • B) 1,024B) 1,024개
  • C) 2,048C) 2,048개
  • D) 8D) 8개
✅ 8 bits × 256 entries = 2,048 flip-flops. This is why synchronous reads (block RAM) are so important for memory — one RAM block vs 2,048 FFs!✅ 8비트 × 256 항목 = 2,048 플립플롭. 이것이 메모리에서 동기식 읽기(블록 RAM)가 중요한 이유입니다!

11 What hardware does assign equal = (a == b); infer for 8-bit signals? 8비트 신호에 대해 assign equal = (a == b);는 어떤 하드웨어를 추론하는가?

  • A) A subtractorA) 감산기
  • B) XNOR gates per bit, then AND reductionB) 비트별 XNOR 게이트, 그 다음 AND 축소
  • C) A lookup tableC) 룩업 테이블
  • D) A multiplexer treeD) 멀티플렉서 트리
✅ Equality comparison: XOR each pair of bits (produces 0 if equal), then NOR/AND all the XOR results together. If all bits match, output is 1.✅ 동등 비교: 각 비트 쌍을 XOR하고(같으면 0 생성), 모든 XOR 결과를 NOR/AND합니다. 모든 비트가 일치하면 출력은 1입니다.

12 In an always_ff block, what happens if you write if (enable) data <= in; with NO else clause? always_ff 블록에서 else 절 없이 if (enable) data <= in;을 작성하면 어떻게 되는가?

  • A) A latch is inferredA) 래치가 추론됨
  • B) Flip-flop with clock enable — data holds its valueB) 클록 인에이블이 있는 플립플롭 — 데이터가 값을 유지함
  • C) Compilation errorC) 컴파일 오류
  • D) The signal is driven to zeroD) 신호가 0으로 구동됨
✅ In always_ff, a missing else is fine — the flip-flop simply holds its current value when the condition is false. This infers a clock enable on the flip-flop (NOT a latch — latches come from missing else in always_comb!).✅ always_ff에서 else가 없어도 괜찮습니다 — 조건이 거짓일 때 플립플롭이 현재 값을 유지합니다. 이것은 플립플롭의 클록 인에이블을 추론합니다 (래치가 아닙니다!).
