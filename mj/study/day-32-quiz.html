Q1. What hardware does always_ff @(posedge clk) with an assignment infer?

  • A) Multiplexer
  • B) Flip-flops (registers)
  • C) Latches
  • D) AND gates

B) Flip-flops. Every signal assigned inside an always_ff block triggered by a clock edge infers flip-flops. Each bit of the signal = one flip-flop.

B) 플립플롭. 클록 에지에 의해 트리거되는 always_ff 블록 내에서 할당된 모든 신호는 플립플롭을 추론합니다. 신호의 각 비트 = 하나의 플립플롭.

Q2. How many flip-flops does logic [15:0] counter in an always_ff block infer?

  • A) 1
  • B) 8
  • C) 16
  • D) 32

C) 16. A 16-bit signal registered in always_ff infers 16 flip-flops — one per bit.

C) 16. always_ff에서 등록된 16비트 신호는 16개의 플립플롭을 추론합니다 — 비트당 하나.

Q3. An if/else chain in always_comb infers:

  • A) Priority multiplexer chain
  • B) Decoder
  • C) Flip-flops
  • D) RAM

A) Priority mux chain. Each if creates a 2:1 mux. The first condition has highest priority (checked first), creating a cascaded chain of muxes.

A) 우선순위 멀티플렉서 체인. 각 if는 2:1 멀티플렉서를 생성합니다. 첫 번째 조건이 가장 높은 우선순위(먼저 검사)를 가지며, 멀티플렉서의 연쇄 체인을 만듭니다.

Q4. Why is case often better than if/else for mutually exclusive conditions?

  • A) It uses fewer flip-flops
  • B) It creates a balanced mux with shorter critical path
  • C) It avoids using any gates
  • D) It always runs faster at simulation

B) Balanced mux. A case statement tells the synthesizer all conditions are mutually exclusive, allowing it to build a single wide mux instead of a priority chain. Shorter critical path = better timing.

B) 균형 멀티플렉서. case 문은 합성기에게 모든 조건이 상호 배타적임을 알려주어 우선순위 체인 대신 단일 넓은 멀티플렉서를 구축할 수 있게 합니다. 더 짧은 크리티컬 패스 = 더 나은 타이밍.

Q5. Which operation is the MOST expensive in terms of area?

  • A) a + b (addition)
  • B) a & b (AND)
  • C) a << 3 (constant shift)
  • D) a * b (multiplication)

D) Multiplication. Multiplier area grows quadratically with bit width. A 32×32 multiplier requires ~1000+ gates. Shifts are free, AND is cheap, addition is moderate.

D) 곱셈. 곱셈기 면적은 비트 폭에 따라 이차적으로 증가합니다. 32×32 곱셈기는 ~1000개 이상의 게이트가 필요합니다. 시프트는 무료, AND는 저렴, 덧셈은 보통입니다.

Q6. What hardware does a << 3 (constant shift) become?

  • A) Just wires — zero gates (free!)
  • B) A barrel shifter
  • C) A multiplier
  • D) An adder

A) Just wires. A constant shift is simply reconnecting wires at different positions. No gates needed! This is why a << 3 (multiply by 8) is preferred over a * 8.

A) 단순 와이어. 상수 시프트는 단순히 다른 위치에서 와이어를 다시 연결하는 것입니다. 게이트가 필요 없습니다! 이것이 a << 3 (8을 곱하기)이 a * 8보다 선호되는 이유입니다.

Q7. What does this code infer?

always_comb begin
    if (sel)
        out = data_a;
    // no else clause
end
  • A) A multiplexer
  • B) A flip-flop
  • C) An unintentional latch
  • D) An AND gate

C) Unintentional latch. Without an else clause, out must hold its previous value when sel=0. In combinational logic, this requires a latch — almost always a bug.

C) 의도치 않은 래치. else 절이 없으면 sel=0일 때 out이 이전 값을 유지해야 합니다. 조합 논리에서 이것은 래치가 필요합니다 — 거의 항상 버그입니다.

Q8. How would you efficiently implement a * 5 without a multiplier?

  • A) a + a + a + a + a
  • B) (a << 2) + a
  • C) a << 5
  • D) a & 5

B) (a << 2) + a. Shift left by 2 = multiply by 4 (free, just wires). Then add the original value. Total cost: one adder. Much cheaper than a full multiplier!

B) (a << 2) + a. 왼쪽으로 2비트 시프트 = 4 곱하기 (무료, 단순 와이어). 그런 다음 원래 값을 더합니다. 총 비용: 가산기 하나. 전체 곱셈기보다 훨씬 저렴합니다!

Q9. In the ALU example, the case(op) statement with 4 options infers:

  • A) Four separate operations + a 4:1 mux to select
  • B) Only the selected operation runs
  • C) A single adder that changes modes
  • D) Four flip-flops

A) All four operations + mux. In hardware, ALL operations compute simultaneously — the adder, subtractor, AND, and XOR all run in parallel. The mux then selects which result to pass through based on op. This is fundamentally different from software!

A) 네 가지 연산 모두 + 멀티플렉서. 하드웨어에서 모든 연산은 동시에 계산됩니다 — 가산기, 감산기, AND, XOR이 모두 병렬로 실행됩니다. 그런 다음 멀티플렉서가 op를 기반으로 어떤 결과를 통과시킬지 선택합니다. 이것은 소프트웨어와 근본적으로 다릅니다!

Q10. Which of these operations is NOT free (requires actual gates)?

  • A) {a, b} concatenation
  • B) data[7:4] bit slicing
  • C) a << b variable shift
  • D) a << 4 constant shift

C) Variable shift. When the shift amount is a variable (not a constant), synthesis must build a barrel shifter — a real circuit with muxes. Constant shifts, concatenation, and slicing are all just wire routing (free).

C) 변수 시프트. 시프트 양이 변수(상수가 아닌)일 때, 합성은 멀티플렉서가 있는 실제 회로인 배럴 시프터를 구축해야 합니다. 상수 시프트, 연결, 슬라이싱은 모두 와이어 라우팅(무료)입니다.

Q11. A counter (count <= count + 1 in always_ff) infers:

  • A) Just flip-flops
  • B) Just an adder
  • C) A multiplexer
  • D) An adder feeding back into flip-flops

D) Adder + flip-flops with feedback. The + 1 creates an adder, the always_ff creates flip-flops, and the count <= count + 1 creates a feedback path from the FF output through the adder back to the FF input.

D) 피드백이 있는 가산기 + 플립플롭. + 1은 가산기를 생성하고, always_ff는 플립플롭을 생성하며, count <= count + 1은 FF 출력에서 가산기를 통해 FF 입력으로 돌아가는 피드백 경로를 만듭니다.

Q12. What happens to assign bus = en ? data : 'z inside an ASIC?

  • A) Creates a tri-state buffer
  • B) Synthesized as a multiplexer (no internal tri-state)
  • C) Creates a latch
  • D) Causes a synthesis error

B) Mux. Modern ASICs and FPGAs don't have internal tri-state buffers. Synthesis converts tri-state assignments on internal signals into multiplexers. Only I/O pads get actual tri-state buffers.

B) 멀티플렉서. 현대 ASIC과 FPGA에는 내부 트라이스테이트 버퍼가 없습니다. 합성은 내부 신호의 트라이스테이트 할당을 멀티플렉서로 변환합니다. I/O 패드만 실제 트라이스테이트 버퍼를 받습니다.
