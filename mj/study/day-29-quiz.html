Q1. What is the primary purpose of flow control in digital design?디지털 설계에서 흐름 제어의 주요 목적은?

  • A. Increase clock frequency클럭 주파수 증가
  • B. Prevent data loss when producer and consumer rates differ생산자와 소비자 속도가 다를 때 데이터 손실 방지
  • C. Reduce power consumption전력 소비 감소
  • D. Simplify the synthesis process합성 과정 단순화

✅ B. Flow control ensures no data is lost when a producer generates data faster than a consumer can process it. It manages the rate mismatch between the two sides.

✅ B. 흐름 제어는 생산자가 소비자보다 빠르게 데이터를 생성할 때 데이터가 손실되지 않도록 합니다.

Q2. In a FIFO-based flow control system, when should the producer stop writing?FIFO 기반 흐름 제어에서 생산자는 언제 쓰기를 중단해야 하나요?

  • A. When the FIFO is emptyFIFO가 비었을 때
  • B. When the FIFO is half fullFIFO가 반쯤 찼을 때
  • C. When the FIFO is fullFIFO가 가득 찼을 때
  • D. When the consumer asserts valid소비자가 valid를 출력할 때

✅ C. The producer must stop writing when the FIFO is full (wr_ready = 0). Writing to a full FIFO causes data corruption or loss.

✅ C. FIFO가 가득 찼을 때(wr_ready = 0) 생산자는 쓰기를 중단해야 합니다. 가득 찬 FIFO에 쓰면 데이터 손상이 발생합니다.

Q3. In credit-based flow control, what does the sender's credit count represent?크레딧 기반 흐름 제어에서 송신자의 크레딧 수는 무엇을 나타내나요?

  • A. Number of bytes sent so far지금까지 보낸 바이트 수
  • B. Available slots in the receiver's buffer수신자 버퍼의 사용 가능한 슬롯 수
  • C. Clock cycles until next transmission다음 전송까지의 클럭 사이클 수
  • D. Priority level of the data데이터의 우선순위 레벨

✅ B. Credits represent the number of available buffer slots at the receiver. Each credit = one slot. The sender can only send when credits > 0, guaranteeing the receiver can store the data.

✅ B. 크레딧은 수신자의 사용 가능한 버퍼 슬롯 수를 나타냅니다. 크레딧 1개 = 슬롯 1개. 송신자는 크레딧 > 0일 때만 전송할 수 있어 수신자가 데이터를 저장할 수 있음을 보장합니다.

Q4. What is the main advantage of credit-based flow control over ready/valid?Ready/valid 대비 크레딧 기반 흐름 제어의 주요 장점은?

  • A. Uses less area더 적은 면적 사용
  • B. Simpler to implement구현이 더 간단
  • C. Eliminates the combinational ready path from receiver to sender수신자에서 송신자로의 조합 ready 경로를 제거
  • D. Works without a clock클럭 없이 작동

✅ C. In ready/valid, the ready signal creates a combinational path from receiver back to sender, which can become the critical timing path. Credit-based flow control removes this — the sender decides locally using its credit counter.

✅ C. Ready/valid에서 ready 신호는 수신자에서 송신자로의 조합 경로를 만들어 임계 타이밍 경로가 될 수 있습니다. 크레딧 기반은 이를 제거합니다 — 송신자가 크레딧 카운터로 로컬에서 결정합니다.

Q5. A credit-based sender starts with 4 credits. It sends 3 items and receives 1 credit return. How many credits remain?크레딧 기반 송신자가 4개 크레딧으로 시작합니다. 3개를 보내고 1개 크레딧을 반환받았습니다. 남은 크레딧은?

  • A. 0
  • B. 1
  • C. 2
  • D. 3

✅ C. Start: 4. Send 3: 4 - 3 = 1. Receive 1 return: 1 + 1 = 2 credits remaining.

✅ C. 시작: 4. 3개 전송: 4 - 3 = 1. 1개 반환: 1 + 1 = 2 크레딧 남음.

Q6. What is a "credit leak" and why is it dangerous?"크레딧 누수"란 무엇이며 왜 위험한가요?

  • A. Sending data without credits — causes overflow크레딧 없이 데이터 전송 — 오버플로 발생
  • B. A credit consumed but never returned — causes eventual deadlock소비된 크레딧이 반환되지 않음 — 결국 데드락 발생
  • C. Credits incrementing beyond max — causes data duplication크레딧이 최대값 초과 — 데이터 중복 발생
  • D. Credits resetting to zero — causes temporary stall크레딧이 0으로 리셋 — 일시적 정지 발생

✅ B. A credit leak occurs when the receiver consumes data but fails to return the credit. Over time, the sender's credits drain to zero, permanently stalling the link — a deadlock. This is one of the hardest bugs to find because it may take millions of cycles to manifest.

✅ B. 크레딧 누수는 수신자가 데이터를 소비하지만 크레딧을 반환하지 못할 때 발생합니다. 시간이 지나면 송신자의 크레딧이 0으로 줄어 영구적으로 링크가 정지됩니다 — 데드락. 수백만 사이클 후에야 나타날 수 있어 찾기 가장 어려운 버그 중 하나입니다.

Q7. What is the purpose of a skid buffer (elastic buffer)?스키드 버퍼(탄성 버퍼)의 목적은?

  • A. Store large amounts of data for CDCCDC를 위한 대량 데이터 저장
  • B. Break the combinational ready path while maintaining throughput처리량을 유지하면서 조합 ready 경로를 끊음
  • C. Convert between different data widths다른 데이터 폭 간 변환
  • D. Implement arbitration between multiple senders여러 송신자 간 중재 구현

✅ B. A skid buffer adds 1-2 entries of storage to register the ready signal, breaking the combinational path from consumer to producer. It maintains full throughput (no bubble cycles) by absorbing data when the output stalls.

✅ B. 스키드 버퍼는 1~2개의 저장 항목을 추가하여 ready 신호를 레지스터합니다. 출력이 정지될 때 데이터를 흡수하여 전체 처리량을 유지합니다(버블 사이클 없음).

Q8. In Ethernet, what is a "pause frame" (IEEE 802.3x)?이더넷에서 "pause 프레임" (IEEE 802.3x)이란?

  • A. A frame that requests the sender to stop transmitting for a specified time송신자에게 지정된 시간 동안 전송을 중단하도록 요청하는 프레임
  • B. A special frame used for link training링크 트레이닝에 사용되는 특수 프레임
  • C. A debug frame for monitoring traffic트래픽 모니터링을 위한 디버그 프레임
  • D. A frame that resets the MAC address tableMAC 주소 테이블을 리셋하는 프레임

✅ A. An 802.3x pause frame is a special MAC control frame that tells the link partner to stop transmitting for a specified number of quanta (1 quanta = 512 bit times). This is XON/XOFF flow control at the Ethernet level.

✅ A. 802.3x pause 프레임은 링크 파트너에게 지정된 quanta 수만큼 전송을 중단하도록 하는 MAC 제어 프레임입니다 (1 quanta = 512 비트 시간). 이더넷 수준의 XON/XOFF 흐름 제어입니다.

Q9. How should you size a FIFO buffer?FIFO 버퍼 크기는 어떻게 결정해야 하나요?

  • A. Based on average data rate평균 데이터 속도 기준
  • B. Always use power-of-2 depths for simplicity간단하게 항상 2의 거듭제곱 깊이 사용
  • C. Based on worst-case burst where producer outpaces consumer생산자가 소비자를 앞지르는 최악의 버스트 기준
  • D. As large as possible to be safe안전을 위해 최대한 크게

✅ C. FIFO depth must handle the worst-case burst scenario. The formula is: Depth ≥ B × (R_p - R_c) / R_p, where B is burst length, R_p is producer rate, and R_c is consumer rate. Making it "as large as possible" wastes area.

✅ C. FIFO 깊이는 최악의 버스트 시나리오를 처리해야 합니다. 공식: 깊이 ≥ B × (R_p - R_c) / R_p. "최대한 크게"는 면적을 낭비합니다.

Q10. What happens in a skid buffer when in_valid is asserted but out_ready is deasserted?스키드 버퍼에서 in_valid가 활성이지만 out_ready가 비활성일 때 무슨 일이 발생하나요?

  • A. The data is dropped데이터가 드롭됩니다
  • B. The data is stored in the skid register, and in_ready goes low데이터가 스키드 레지스터에 저장되고 in_ready가 low가 됩니다
  • C. The data wraps around to the input데이터가 입력으로 되돌아갑니다
  • D. The module resets모듈이 리셋됩니다

✅ B. When input data arrives but the output is blocked, the skid buffer stores the data in its internal register and deasserts in_ready to prevent the producer from sending more. When out_ready returns, the skid data is forwarded and in_ready goes high again.

✅ B. 입력 데이터가 도착했지만 출력이 차단되면, 스키드 버퍼는 내부 레지스터에 데이터를 저장하고 in_ready를 비활성화합니다. out_ready가 돌아오면 스키드 데이터가 전달되고 in_ready가 다시 활성화됩니다.

Q11. Which flow control mechanism is best for chip-to-chip communication with many pipeline stages in between?중간에 많은 파이프라인 단계가 있는 칩 간 통신에 가장 적합한 흐름 제어 메커니즘은?

  • A. Ready/validReady/valid
  • B. Credit-based크레딧 기반
  • C. FIFO only (no flow control signals)FIFO만 (흐름 제어 신호 없음)
  • D. Clock gating클럭 게이팅

✅ B. Credit-based flow control is ideal for long-distance communication because the sender doesn't need a round-trip signal from the receiver. It pre-allocates buffer space via credits, allowing full-throughput operation even with many pipeline stages. This is why PCIe and Network-on-Chip (NoC) use credits.

✅ B. 크레딧 기반 흐름 제어는 장거리 통신에 이상적입니다. 송신자가 수신자로부터의 왕복 신호가 필요 없기 때문입니다. PCIe와 NoC가 크레딧을 사용하는 이유입니다.

Q12. In the FIFO flow control module, what does case ({do_write, do_read}) handle?FIFO 흐름 제어 모듈에서 case ({do_write, do_read})는 무엇을 처리하나요?

case ({do_write, do_read})
    2'b10: count <= count + 1;
    2'b01: count <= count - 1;
    default: count <= count;
endcase
  • A. Error checking for invalid states잘못된 상태의 오류 검사
  • B. Correctly updating the count for all combinations of simultaneous read/write동시 읽기/쓰기의 모든 조합에 대해 count를 올바르게 업데이트
  • C. Priority encoding for write over read쓰기 우선순위 인코딩
  • D. Resetting the FIFO when empty비었을 때 FIFO 리셋

✅ B. The case statement handles all four combinations: write-only (count++), read-only (count--), both (count stays same), and neither (count stays same). The default case covers both "both" and "neither" since both result in no net change.

✅ B. case 문은 네 가지 조합을 처리합니다: 쓰기만(count++), 읽기만(count--), 둘 다(count 유지), 아무것도 아님(count 유지). default는 "둘 다"와 "아무것도 아님" 모두를 커버합니다.
