Day 3: Blocking vs Non-blocking Assignments Day 3: Blocking vs Non-blocking 할당

Understanding the difference between = and <= is one of the most critical concepts in Verilog/SystemVerilog. Getting this wrong causes race conditions and simulation/synthesis mismatches.

=와 <=의 차이를 이해하는 것은 Verilog/SystemVerilog에서 가장 중요한 개념 중 하나입니다. 이를 잘못 이해하면 레이스 컨디션과 시뮬레이션/합성 불일치가 발생합니다.

🎯 The Core Difference 🎯 핵심 차이점

Blocking Assignment ( = ) Blocking 할당 ( = )

Executes immediately and sequentially. The next line waits until this assignment completes. Like normal programming!

즉시 그리고 순차적으로 실행됩니다. 다음 줄은 이 할당이 완료될 때까지 기다립니다. 일반 프로그래밍과 같습니다!

Non-blocking Assignment ( <= ) Non-blocking 할당 ( <= )

Evaluates the RHS immediately but defers the update to the end of the time step. All non-blocking assignments in the same block see the old values.

RHS를 즉시 평가하지만 업데이트는 타임 스텝 끝으로 연기합니다. 같은 블록의 모든 non-blocking 할당은 이전 값을 봅니다.

⚡ Why Does This Matter? ⚡ 왜 중요할까요?

Consider a shift register. We want data to shift through 3 flip-flops on each clock edge:

시프트 레지스터를 생각해보세요. 각 클럭 엣지에서 데이터가 3개의 플립플롭을 통해 이동하기를 원합니다:

❌ WRONG: Using Blocking in Sequential Logic ❌ 잘못된 예: 순차 논리에서 Blocking 사용 

// BAD - Using blocking (=) in always_ff
always_ff @(posedge clk) begin
    q1 = d;     // q1 updates NOW
    q2 = q1;    // q2 sees NEW q1 (wrong!)
    q3 = q2;    // q3 sees NEW q2 (wrong!)
end
// Result: d instantly appears at q1, q2, q3!
// No shift - all get same value!

✅ CORRECT: Using Non-blocking in Sequential Logic ✅ 올바른 예: 순차 논리에서 Non-blocking 사용 

// GOOD - Using non-blocking (<=) in always_ff
always_ff @(posedge clk) begin
    q1 <= d;    // Schedule: q1 will get d
    q2 <= q1;   // Schedule: q2 will get OLD q1
    q3 <= q2;   // Schedule: q3 will get OLD q2
end
// Result: Data shifts through properly!
// d→q1→q2→q3 over 3 clock cycles

⚠️ Common Mistake ⚠️ 흔한 실수

Using = in always_ff creates race conditions because the order of assignments matters. Non-blocking <= makes all assignments "happen simultaneously" at the clock edge, which matches how real hardware works.

always_ff에서 =를 사용하면 할당 순서가 중요해져서 레이스 컨디션이 발생합니다. Non-blocking <=는 모든 할당이 클럭 엣지에서 "동시에 발생"하게 하여, 실제 하드웨어 동작과 일치합니다.

🔧 The Golden Rules 🔧 황금 규칙

Rule 1: Combinational Logic → Blocking ( = ) 규칙 1: 조합 논리 → Blocking ( = ) 

always_comb begin
    sum   = a + b;           // Use =
    carry = (a & b) | (sum & cin);  // Use =
end

Rule 2: Sequential Logic → Non-blocking ( <= ) 규칙 2: 순차 논리 → Non-blocking ( <= ) 

always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        counter <= '0;       // Use <=
    else
        counter <= counter + 1; // Use <=
end

Rule 3: Never Mix Them! 규칙 3: 절대 섞지 마세요!

Don't use both = and <= on the same signal. Don't use blocking in always_ff or non-blocking in always_comb.

같은 신호에 =와 <=를 모두 사용하지 마세요. always_ff에서 blocking을 사용하거나 always_comb에서 non-blocking을 사용하지 마세요.

🔍 Simulation Event Queue 🔍 시뮬레이션 이벤트 큐

To really understand this, you need to know how the simulator works:

이를 정확히 이해하려면 시뮬레이터가 어떻게 동작하는지 알아야 합니다:

Simulation Regions (Simplified) 시뮬레이션 영역 (간략화) 

// Within each time step:
1. Active Region     - Blocking assignments execute
2. NBA Region        - Non-blocking assignments update
3. Postponed Region  - $monitor, $strobe execute

Non-blocking assignments evaluate RHS in the Active region but write LHS in the NBA region. This is why they all see "old" values!

Non-blocking 할당은 Active 영역에서 RHS를 평가하지만 NBA 영역에서 LHS를 씁니다. 이것이 모두 "이전" 값을 보는 이유입니다!

📝 Real-World Example: Counter with Enable 📝 실제 예제: Enable이 있는 카운터 

module counter_with_enable (
    input  logic       clk,
    input  logic       rst_n,
    input  logic       enable,
    output logic [7:0] count,
    output logic       overflow
);

// Combinational logic - use BLOCKING
logic [7:0] next_count;
logic       will_overflow;

always_comb begin
    next_count    = count + 8'd1;   // =
    will_overflow = (count == 8'hFF); // =
end

// Sequential logic - use NON-BLOCKING
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        count    <= 8'b0;   // <=
        overflow <= 1'b0;   // <=
    end else if (enable) begin
        count    <= next_count;    // <=
        overflow <= will_overflow; // <=
    end
end

endmodule
