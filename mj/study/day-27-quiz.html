Q1. How many channels does a full AXI interface have?

Q1. 전체 AXI 인터페이스에는 몇 개의 채널이 있습니까?

  • A) 3 (Address, Data, Response)
  • B) 4 (Write Addr, Write Data, Read Addr, Read Data)
  • C) 5 (AW, W, B, AR, R)
  • D) 6 (AW, W, B, AR, R, ACK)

✅ C) 5 channels. AXI has separate write (AW, W, B) and read (AR, R) paths. The write path has 3 channels: Write Address (AW), Write Data (W), and Write Response (B). The read path has 2: Read Address (AR) and Read Data (R) — the read data channel includes the response.

✅ C) 5개 채널. AXI는 쓰기(AW, W, B)와 읽기(AR, R) 경로가 분리되어 있습니다. 쓰기 경로에는 3개 채널이 있고, 읽기 경로에는 2개 채널이 있습니다.

Q2. Which direction does the Write Response (B) channel flow?

Q2. 쓰기 응답(B) 채널의 방향은?

  • A) Master → Slave
  • B) Slave → Master
  • C) Bidirectional
  • D) Interconnect → Both

✅ B) Slave → Master. The slave sends the write response back to the master to confirm whether the write was successful (OKAY) or encountered an error (SLVERR, DECERR).

✅ B) 슬레이브 → 마스터. 슬레이브는 쓰기 응답을 마스터에게 보내 쓰기가 성공했는지(OKAY) 또는 오류가 발생했는지(SLVERR, DECERR) 확인합니다.

Q3. If AWLEN = 7, how many data beats are in the burst?

Q3. AWLEN = 7이면 버스트에 몇 개의 데이터 비트가 있습니까?

  • A) 8
  • B) 7
  • C) 16
  • D) 128

✅ A) 8 beats. Burst length = AWLEN + 1. So AWLEN = 7 means 7 + 1 = 8 data beats in the burst transfer.

✅ A) 8비트. 버스트 길이 = AWLEN + 1. 따라서 AWLEN = 7은 7 + 1 = 8개의 데이터 비트를 의미합니다.

Q4. What is the purpose of WSTRB (Write Strobes)?

Q4. WSTRB(쓰기 스트로브)의 목적은 무엇입니까?

  • A) Error detection on the data bus
  • B) Indicating the burst type
  • C) Byte-level write enable control
  • D) Signaling the last beat of a burst

✅ C) Byte-level write enable. Each bit of WSTRB corresponds to one byte of WDATA. If WSTRB[n] = 1, byte n is written; otherwise it's preserved unchanged. This avoids costly read-modify-write operations.

✅ C) 바이트 수준 쓰기 활성화. WSTRB의 각 비트는 WDATA의 한 바이트에 해당합니다. WSTRB[n] = 1이면 바이트 n이 기록되고, 그렇지 않으면 변경되지 않습니다.

Q5. Which AMBA protocol is best for simple register access with no burst support?

Q5. 버스트 지원 없이 간단한 레지스터 접근에 가장 적합한 AMBA 프로토콜은?

  • A) AXI (Full)
  • B) AXI-Lite
  • C) AXI-Stream
  • D) AHB

✅ B) AXI-Lite. AXI-Lite is a simplified version of AXI designed specifically for simple register access. It doesn't support bursts, transaction IDs, or narrow transfers — perfect for configuration registers in IP blocks.

✅ B) AXI-Lite. AXI-Lite는 간단한 레지스터 접근을 위해 설계된 AXI의 단순화 버전입니다. 버스트, 트랜잭션 ID, 좁은 전송을 지원하지 않습니다.

Q6. What does BRESP = 2'b11 (DECERR) indicate?

Q6. BRESP = 2'b11(DECERR)은 무엇을 나타냅니까?

  • A) Write completed successfully
  • B) Slave encountered an internal error
  • C) No slave exists at the target address
  • D) Exclusive access succeeded

✅ C) No slave exists at the target address. DECERR (Decode Error) means the interconnect could not route the transaction to any slave — the address doesn't map to anything. SLVERR (2'b10) is when a slave exists but returned an error.

✅ C) 대상 주소에 슬레이브가 없음. DECERR(디코드 에러)는 인터커넥트가 어떤 슬레이브에도 트랜잭션을 라우팅할 수 없었음을 의미합니다.

Q7. What is the most common burst type for sequential memory access?

Q7. 순차 메모리 접근에 가장 일반적인 버스트 유형은?

  • A) INCR (incrementing)
  • B) FIXED
  • C) WRAP
  • D) STREAM

✅ A) INCR. Incrementing bursts are by far the most common — the address increments by the transfer size each beat. FIXED is for FIFO access (same address), WRAP is for cache line fills.

✅ A) INCR. 증가 버스트가 가장 일반적입니다 — 매 비트마다 전송 크기만큼 주소가 증가합니다.

Q8. What enables out-of-order transaction completion in AXI?

Q8. AXI에서 순서 무관 트랜잭션 완료를 가능하게 하는 것은?

  • A) WLAST signal
  • B) BRESP codes
  • C) Write strobes
  • D) Transaction IDs (AWID/ARID/BID/RID)

✅ D) Transaction IDs. Each transaction is tagged with an ID. The slave returns responses with matching IDs, allowing a fast slave to respond before a slow one, regardless of request order. The master uses the ID to match responses to their original requests.

✅ D) 트랜잭션 ID. 각 트랜잭션에 ID가 태그되어 슬레이브가 일치하는 ID로 응답을 반환하여 빠른 슬레이브가 먼저 응답할 수 있습니다.

Q9. In AXI, can write data (W channel) arrive before the write address (AW channel)?

Q9. AXI에서 쓰기 데이터(W 채널)가 쓰기 주소(AW 채널)보다 먼저 도착할 수 있습니까?

  • A) No, address must always come first
  • B) Yes, AW and W channels are independent
  • C) Only in AXI-Lite mode
  • D) Only with FIXED burst type

✅ B) Yes, they're independent. This is a key AXI feature that often surprises newcomers. The AW and W channels operate independently — data can be streamed while the address is still being routed through the interconnect. The slave must buffer data until it knows the address.

✅ B) 네, 독립적입니다. 이것은 신입자를 놀라게 하는 AXI의 핵심 특징입니다. AW와 W 채널은 독립적으로 동작합니다.

Q10. What signal indicates the last data beat in an AXI burst transfer?

Q10. AXI 버스트 전송에서 마지막 데이터 비트를 나타내는 신호는?

  • A) WLAST / RLAST
  • B) BVALID
  • C) AWLEN reaching 0
  • D) WSTRB = 0

✅ A) WLAST / RLAST. The WLAST signal is asserted on the write data channel's final beat, and RLAST on the read data channel's final beat. These are critical for the slave to know when a burst is complete.

✅ A) WLAST / RLAST. WLAST는 쓰기 데이터 채널의 마지막 비트에서 어설션되고, RLAST는 읽기 데이터 채널의 마지막 비트에서 어설션됩니다.

Q11. If AWSIZE = 3'b010 on a 64-bit bus, how many bytes per beat?

Q11. 64비트 버스에서 AWSIZE = 3'b010이면 비트당 몇 바이트입니까?

  • A) 2 bytes
  • B) 3 bytes
  • C) 4 bytes
  • D) 8 bytes

✅ C) 4 bytes. AWSIZE encodes bytes per beat as 2^AWSIZE. So 3'b010 = 2, and 2² = 4 bytes per beat. This is a "narrow transfer" on a 64-bit (8-byte) bus since it doesn't use the full width.

✅ C) 4 바이트. AWSIZE는 비트당 바이트를 2^AWSIZE로 인코딩합니다. 3'b010 = 2이고, 2² = 4 바이트입니다.

Q12. What happens when a master sets WSTRB = 4'b0110 with WDATA = 32'hAABBCCDD?

Q12. 마스터가 WSTRB = 4'b0110, WDATA = 32'hAABBCCDD를 설정하면?

  • A) All 4 bytes are written
  • B) Only bytes 1 (CC) and 2 (BB) are written
  • C) Only bytes 0 (DD) and 3 (AA) are written
  • D) Transaction is rejected as invalid

✅ B) Only bytes 1 and 2. WSTRB = 4'b0110 means: bit 0 = 0 (byte 0/DD not written), bit 1 = 1 (byte 1/CC written), bit 2 = 1 (byte 2/BB written), bit 3 = 0 (byte 3/AA not written). Bytes 0 and 3 are preserved at their previous values.

✅ B) 바이트 1과 2만 기록. WSTRB = 4'b0110: 비트 1 = 1(바이트 1/CC 기록), 비트 2 = 1(바이트 2/BB 기록), 나머지는 보존.
