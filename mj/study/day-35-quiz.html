Q1: What format is the industry standard for synthesis constraints?

Q1: 합성 제약조건의 산업 표준 형식은 무엇인가?

  • A) UCF (User Constraint File)UCF (사용자 제약 파일)
  • B) XDC (Xilinx Design Constraints)XDC (Xilinx 설계 제약)
  • C) SDC (Synopsys Design Constraints)SDC (Synopsys 설계 제약)
  • D) TCL (Tool Command Language)TCL (도구 명령 언어)

✅ SDC is the industry standard, used across Synopsys, Cadence, and FPGA tools (Vivado uses XDC which is SDC-compatible). TCL is the scripting language SDC is written in, not the constraint format itself.

✅ SDC는 Synopsys, Cadence 및 FPGA 도구 전반에서 사용되는 산업 표준입니다(Vivado는 SDC 호환 XDC 사용). TCL은 SDC가 작성되는 스크립팅 언어이지 제약 형식 자체가 아닙니다.

Q2: create_clock -name clk -period 8.0 [get_ports clk]는 무엇을 정의하는가?

  • D) An 800 MHz clock800 MHz 클럭

✅ 주기는 나노초 단위입니다. 1/8ns = 125 MHz. -period 플래그는 전체 클럭 주기 시간을 지정합니다.

Q3: What is "slack" in a timing report?

Q3: 타이밍 리포트에서 "slack"이란 무엇인가?

  • A) Required time − Arrival time요구 시간 − 도착 시간
  • B) Arrival time − Required time도착 시간 − 요구 시간
  • C) Clock period − Setup time클럭 주기 − 셋업 시간
  • D) Total path delay총 경로 지연

✅ Slack = Data Required Time − Data Arrival Time. Positive slack means timing is met; negative slack means violation.

✅ Slack = 데이터 요구 시간 − 데이터 도착 시간. 양수 슬랙은 타이밍 충족, 음수 슬랙은 위반을 의미합니다.

Q4: When should you use set_false_path?

Q4: set_false_path를 언제 사용해야 하는가?

  • A) When a path is slow but still needs to work경로가 느리지만 여전히 작동해야 할 때
  • B) When a path takes multiple clock cycles경로가 여러 클럭 사이클을 소요할 때
  • C) When a path will never be active in real operation경로가 실제 동작에서 절대 활성화되지 않을 때
  • D) When you want to ignore all timing모든 타이밍을 무시하고 싶을 때

✅ False paths are for paths that are structurally present but never functionally exercised — like async reset, static config registers, or test-only pins. For multi-cycle paths, use set_multicycle_path instead.

✅ False path는 구조적으로 존재하지만 기능적으로 활성화되지 않는 경로용입니다 — 비동기 리셋, 정적 구성 레지스터, 테스트 전용 핀 등. 다중 사이클 경로는 set_multicycle_path를 사용하세요.

Q5: For a 3-cycle multicycle setup path, what should the hold value be?

Q5: 3사이클 멀티사이클 셋업 경로의 경우, 홀드 값은 얼마여야 하는가?

  • A) 00
  • B) 11
  • C) 2 (N − 1)2 (N − 1)
  • D) 3 (same as setup)3 (셋업과 동일)

✅ The hold value should be N−1 where N is the setup multicycle count. For setup=3, hold=2. This ensures the hold check stays at the correct launch edge.

✅ 홀드 값은 N−1이어야 합니다 (N = 셋업 멀티사이클 수). 셋업=3이면 홀드=2. 이렇게 해야 홀드 체크가 올바른 발사 에지에 유지됩니다.

Q6: What does set_clock_groups -asynchronous do?

Q6: set_clock_groups -asynchronous는 무엇을 하는가?

  • A) Creates new clock domains automatically자동으로 새 클럭 도메인 생성
  • B) Tells the tool not to check timing between those clock domains도구에게 해당 클럭 도메인 사이의 타이밍을 확인하지 않도록 지시
  • C) Inserts synchronizers between clock domains클럭 도메인 사이에 동기화기 삽입
  • D) Makes all clocks run at the same frequency모든 클럭을 동일 주파수로 실행

✅ set_clock_groups -asynchronous declares that timing paths between the specified clock groups should NOT be analyzed. This prevents the tool from wasting effort on impossible cross-domain paths. You still need to handle CDC properly in your RTL!

✅ set_clock_groups -asynchronous는 지정된 클럭 그룹 간의 타이밍 경로를 분석하지 않도록 선언합니다. 도구가 불가능한 크로스 도메인 경로에 노력을 낭비하는 것을 방지합니다. RTL에서 CDC를 적절히 처리하는 것은 여전히 필요합니다!

Q7: What does set_input_delay 3.0 -clock clk [get_ports data_in] specify?

Q7: set_input_delay 3.0 -clock clk [get_ports data_in]는 무엇을 지정하는가?

  • A) data_in arrives 3 ns after the clock edge (external delay)data_in이 클럭 에지 후 3 ns에 도착 (외부 지연)
  • B) data_in must be delayed by 3 ns inside the designdata_in이 설계 내부에서 3 ns 지연되어야 함
  • C) The input buffer has 3 ns delay입력 버퍼의 지연이 3 ns
  • D) data_in is sampled 3 ns before the clock edgedata_in이 클럭 에지 3 ns 전에 샘플링됨

✅ set_input_delay tells the tool that the input data arrives 3 ns after the clock edge — this is the delay from the external source. It reduces the available time for internal logic.

✅ set_input_delay는 입력 데이터가 클럭 에지 후 3 ns에 도착한다고 도구에 알려줍니다 — 이것은 외부 소스의 지연입니다. 내부 논리에 사용 가능한 시간이 줄어듭니다.

Q8: What does WNS stand for and what is the target value?

Q8: WNS는 무엇을 의미하며 목표 값은 무엇인가?

  • A) Worst Net Slack — target is negative최악 넷 슬랙 — 목표는 음수
  • B) Wire Network Slack — target is zero와이어 네트워크 슬랙 — 목표는 0
  • C) Worst Negative Slack — target is as negative as possible최악 음수 슬랙 — 목표는 가능한 한 음수
  • D) Worst Negative Slack — target is ≥ 0 (positive or zero)최악 음수 슬랙 — 목표는 ≥ 0 (양수 또는 0)

✅ WNS = Worst Negative Slack. It shows the timing of the most critical path. Target is ≥ 0 (met). When WNS is negative, your design has timing violations.

✅ WNS = 최악 음수 슬랙. 가장 중요한 경로의 타이밍을 보여줍니다. 목표는 ≥ 0 (충족). WNS가 음수이면 설계에 타이밍 위반이 있습니다.

Q9: In FPGA, how is design area typically measured?

Q9: FPGA에서 설계 면적은 일반적으로 어떻게 측정되는가?

  • A) µm² (micrometers squared)µm² (마이크로미터 제곱)
  • B) LUTs, FFs, BRAMs, and DSP slicesLUT, FF, BRAM 및 DSP 슬라이스
  • C) Transistor count트랜지스터 수

✅ FPGAs measure area in resource utilization: LUTs (Look-Up Tables), FFs (Flip-Flops), BRAMs (Block RAMs), and DSP slices. ASIC designs use µm² or gate equivalents.

✅ FPGA는 리소스 사용률로 면적을 측정합니다: LUT (Look-Up Table), FF (플립플롭), BRAM (블록 RAM), DSP 슬라이스. ASIC 설계는 µm² 또는 게이트 등가를 사용합니다.

Q10: For a 10 ns clock period with T_clk-to-q=0.3ns, T_setup=0.2ns, and T_skew=0.1ns, how much time is available for combinational logic?

Q10: 10 ns 클럭 주기에서 T_clk-to-q=0.3ns, T_setup=0.2ns, T_skew=0.1ns인 경우, 조합 논리에 사용 가능한 시간은?

  • A) 9.7 ns9.7 ns
  • B) 9.5 ns9.5 ns
  • C) 9.4 ns9.4 ns
  • D) 9.8 ns9.8 ns

✅ T_comb = T_period − T_clk-to-q − T_setup − T_skew = 10 − 0.3 − 0.2 − 0.1 = 9.4 ns

✅ T_comb = T_period − T_clk-to-q − T_setup − T_skew = 10 − 0.3 − 0.2 − 0.1 = 9.4 ns

Q11: Which strategy should you try FIRST when a path fails timing?

Q11: 경로가 타이밍에 실패할 때 먼저 시도해야 할 전략은?

  • A) Check if it's a real path — can it be constrained as false/multicycle?실제 경로인지 확인 — false/multicycle로 제약할 수 있는가?
  • B) Increase the clock period클럭 주기 증가
  • C) Upsize all cells in the path경로의 모든 셀 크기 증가
  • D) Remove the constraint제약 제거

✅ Always check if the path is actually valid first. Many timing violations come from over-constraining paths that don't need single-cycle timing (static config, test pins, CDC paths). Upsizing cells is a last resort.

✅ 항상 먼저 경로가 실제로 유효한지 확인하세요. 많은 타이밍 위반은 단일 사이클 타이밍이 필요하지 않은 경로를 과도하게 제약해서 발생합니다 (정적 구성, 테스트 핀, CDC 경로). 셀 크기 증가는 최후의 수단입니다.

Q12: What does set_max_fanout 32 [current_design] do?

Q12: set_max_fanout 32 [current_design]는 무엇을 하는가?

  • A) Limits each module to 32 outputs각 모듈의 출력을 32개로 제한
  • B) Limits any single net to drive at most 32 loads — tool will buffer/clone if exceeded단일 넷이 최대 32개의 로드만 구동하도록 제한 — 초과시 도구가 버퍼/복제
  • C) Sets the maximum number of flip-flops to 32최대 플립플롭 수를 32개로 설정
  • D) Limits the number of inputs to any gate to 32게이트 입력 수를 32개로 제한

✅ set_max_fanout limits how many loads a single driver can have. When exceeded, the synthesis tool will automatically clone or buffer the driver to reduce fanout, which helps with timing but increases area slightly.

✅ set_max_fanout은 단일 드라이버가 가질 수 있는 로드 수를 제한합니다. 초과하면 합성 도구가 자동으로 드라이버를 복제하거나 버퍼를 추가하여 팬아웃을 줄입니다. 타이밍에 도움이 되지만 면적이 약간 증가합니다.
