1. Why Async FIFOs?

In previous lessons, we learned about 2-flop synchronizers (single-bit), handshake protocols, and Gray code counters. But what if you need to transfer streams of multi-bit data between clock domains continuously? That's where the asynchronous FIFO comes in.

이전 수업에서 2-플립플롭 동기화기(단일 비트), 핸드셰이크 프로토콜, 그레이 코드 카운터를 배웠습니다. 하지만 클럭 도메인 간에 멀티비트 데이터 스트림을 지속적으로 전송해야 한다면? 그때 비동기 FIFO가 필요합니다.

🎯 Async FIFO = Dual-Port RAM + Gray Code Pointers + Synchronizers

An async FIFO is a buffer that safely transfers data between two independent clock domains. The writer pushes data using its clock, and the reader pops data using its own clock — with no shared clock required.

비동기 FIFO는 두 개의 독립적인 클럭 도메인 사이에서 안전하게 데이터를 전송하는 버퍼입니다. 쓰기 측은 자체 클럭으로 데이터를 넣고, 읽기 측은 자체 클럭으로 데이터를 꺼냅니다 — 공유 클럭이 필요 없습니다.

3. Why Gray Code Pointers?

This is the critical insight of async FIFO design. When a pointer crosses clock domains, it goes through a 2-flop synchronizer. If the pointer used binary encoding, multiple bits could change simultaneously, and the synchronizer might capture an inconsistent value.

이것이 비동기 FIFO 설계의 핵심 통찰입니다. 포인터가 클럭 도메인을 건널 때 2-플립플롭 동기화기를 거칩니다. 포인터가 이진 인코딩을 사용하면 여러 비트가 동시에 변경되어 동기화기가 불일치 값을 캡처할 수 있습니다.

Binary vs Gray Code Transition

DecimalBinaryGrayBits Changed (Binary)변경된 비트 (이진)
3011010——
41001103 bits! ⚠️3비트! ⚠️
51011112 bits2비트
61101012 bits2비트
71111001 bit1비트

Gray code guarantees only 1 bit changes per increment. If the synchronizer catches the old or new value, both are valid — no glitch values possible!

그레이 코드는 증가당 1비트만 변경을 보장합니다. 동기화기가 이전 또는 새 값을 캡처하면 둘 다 유효합니다 — 글리치 값 불가능!

Gray Code Conversion

// Binary to Gray conversion
assign gray = binary ^ (binary >> 1);

// Gray to Binary conversion (for address generation)
assign binary[N]   = gray[N];        // MSB is the same
assign binary[N-1] = gray[N] ^ gray[N-1];
// ... each bit = XOR of all higher Gray bits

4. Full and Empty Flag Generation

The most critical part of async FIFO design: correctly generating full and empty flags without metastability issues.

비동기 FIFO 설계에서 가장 중요한 부분: 메타스태빌리티 문제 없이 full과 empty 플래그를 올바르게 생성하는 것.

🔑 Key Principle: Pointers Use N+1 Bits

For a FIFO with 2N entries, we use N+1 bit pointers. The extra MSB distinguishes between full and empty:

2N 항목의 FIFO에서 N+1 비트 포인터를 사용합니다. 추가 MSB가 풀과 엠프티를 구분합니다:

  • Empty: Write Gray pointer == Read Gray pointer (identical)
  • Empty: 쓰기 그레이 포인터 == 읽기 그레이 포인터 (동일)
  • Full: Write Gray pointer and Read Gray pointer differ in the top 2 bits but match in all lower bits
  • Full: 쓰기 그레이 포인터와 읽기 그레이 포인터가 상위 2비트가 다르고 나머지 하위 비트는 동일
// EMPTY flag — generated in READ clock domain
// Compare read pointer with synchronized write pointer
assign empty = (rd_gray_ptr == wr_gray_ptr_sync);

// FULL flag — generated in WRITE clock domain
// Compare write pointer with synchronized read pointer
// Full when: top 2 bits differ, rest match (in Gray code)
assign full = (wr_gray_ptr[N]   != rd_gray_ptr_sync[N]) &&
              (wr_gray_ptr[N-1] != rd_gray_ptr_sync[N-1]) &&
              (wr_gray_ptr[N-2:0] == rd_gray_ptr_sync[N-2:0]);

⚠️ Conservative Flags

Because the synchronized pointers are always slightly stale (2 clock cycles behind), the flags are conservative:

동기화된 포인터는 항상 약간 오래된 값(2 클럭 사이클 뒤처짐)이므로, 플래그는 보수적입니다:

  • Full may assert early — writer stops even if there's space → safe, just loses throughput
  • Full이 일찍 표시될 수 있음 — 공간이 있어도 쓰기 중단 → 안전, 처리량만 감소
  • Empty may assert early — reader stops even if there's data → safe, just adds latency
  • Empty가 일찍 표시될 수 있음 — 데이터가 있어도 읽기 중단 → 안전, 지연만 추가

They will never miss a true full/empty condition → no data corruption!

진정한 full/empty 상태를 절대 놓치지 않음 → 데이터 손상 없음!

5. Complete Async FIFO Module

module async_fifo #(
    parameter DATA_WIDTH = 8,
    parameter ADDR_WIDTH = 4   // 2^4 = 16 entries
)(
    // Write interface
    input  logic                    wr_clk,
    input  logic                    wr_rst_n,
    input  logic                    wr_en,
    input  logic [DATA_WIDTH-1:0]  wr_data,
    output logic                    full,

    // Read interface
    input  logic                    rd_clk,
    input  logic                    rd_rst_n,
    input  logic                    rd_en,
    output logic [DATA_WIDTH-1:0]  rd_data,
    output logic                    empty
);

    localparam DEPTH = 1 << ADDR_WIDTH;

    // ── Memory ──
    logic [DATA_WIDTH-1:0] mem [DEPTH];

    // ── Pointers (N+1 bits for full/empty detection) ──
    logic [ADDR_WIDTH:0] wr_bin, wr_gray;
    logic [ADDR_WIDTH:0] rd_bin, rd_gray;

    // ── Synchronized pointers ──
    logic [ADDR_WIDTH:0] wr_gray_sync;  // wr_gray synced to rd_clk
    logic [ADDR_WIDTH:0] rd_gray_sync;  // rd_gray synced to wr_clk

    // ── Write address (lower bits of binary pointer) ──
    logic [ADDR_WIDTH-1:0] wr_addr, rd_addr;
    assign wr_addr = wr_bin[ADDR_WIDTH-1:0];
    assign rd_addr = rd_bin[ADDR_WIDTH-1:0];

    // ═══════════════════════════════════
    // Write Logic (wr_clk domain)
    // ═══════════════════════════════════
    always_ff @(posedge wr_clk or negedge wr_rst_n) begin
        if (!wr_rst_n) begin
            wr_bin  <= '0;
            wr_gray <= '0;
        end else if (wr_en && !full) begin
            mem[wr_addr] <= wr_data;
            wr_bin  <= wr_bin + 1;
            wr_gray <= (wr_bin + 1) ^ ((wr_bin + 1) >> 1);
        end
    end

    // ═══════════════════════════════════
    // Read Logic (rd_clk domain)
    // ═══════════════════════════════════
    assign rd_data = mem[rd_addr];

    always_ff @(posedge rd_clk or negedge rd_rst_n) begin
        if (!rd_rst_n) begin
            rd_bin  <= '0;
            rd_gray <= '0;
        end else if (rd_en && !empty) begin
            rd_bin  <= rd_bin + 1;
            rd_gray <= (rd_bin + 1) ^ ((rd_bin + 1) >> 1);
        end
    end

    // ═══════════════════════════════════
    // 2-Flop Synchronizers
    // ═══════════════════════════════════
    logic [ADDR_WIDTH:0] wr_gray_meta, rd_gray_meta;

    // Sync wr_gray → rd_clk domain
    always_ff @(posedge rd_clk or negedge rd_rst_n) begin
        if (!rd_rst_n) {wr_gray_sync, wr_gray_meta} <= '0;
        else          {wr_gray_sync, wr_gray_meta} <= {wr_gray_meta, wr_gray};
    end

    // Sync rd_gray → wr_clk domain
    always_ff @(posedge wr_clk or negedge wr_rst_n) begin
        if (!wr_rst_n) {rd_gray_sync, rd_gray_meta} <= '0;
        else          {rd_gray_sync, rd_gray_meta} <= {rd_gray_meta, rd_gray};
    end

    // ═══════════════════════════════════
    // Full & Empty Flags
    // ═══════════════════════════════════
    assign empty = (rd_gray == wr_gray_sync);

    assign full  = (wr_gray[ADDR_WIDTH]     != rd_gray_sync[ADDR_WIDTH])     &&
                   (wr_gray[ADDR_WIDTH-1]   != rd_gray_sync[ADDR_WIDTH-1])   &&
                   (wr_gray[ADDR_WIDTH-2:0] == rd_gray_sync[ADDR_WIDTH-2:0]);

endmodule

6. Data Flow Walkthrough

📝 Step-by-Step: Writing Data

  1. Writer checks full flag — if not full, proceed
  2. Data written to mem[wr_addr]
  3. Binary write pointer increments
  4. New Gray code write pointer calculated
  5. Gray write pointer passes through 2-flop synchronizer to read domain (takes 2 rd_clk cycles)
  6. Read domain uses synced write pointer to update empty flag
  1. 쓰기 측이 full 플래그 확인 — 가득 차지 않으면 진행
  2. 데이터가 mem[wr_addr]에 기록됨
  3. 이진 쓰기 포인터 증가
  4. 새 그레이 코드 쓰기 포인터 계산
  5. 그레이 쓰기 포인터가 2-플립플롭 동기화기를 통해 읽기 도메인으로 전달 (2 rd_clk 사이클 소요)
  6. 읽기 도메인이 동기화된 쓰기 포인터로 empty 플래그 업데이트

Reset리셋 Both domains need async reset — must be coordinated to avoid pointer mismatch 두 도메인 모두 비동기 리셋 필요 — 포인터 불일치를 방지하기 위해 조정 필수
Sizing크기 조정 Depth depends on clock ratio and burst length — must absorb worst-case burst 깊이는 클럭 비율과 버스트 길이에 따라 결정 — 최악의 버스트를 흡수해야 함
Latency지연 2-3 clock cycles of synchronization latency for flag updates 플래그 업데이트에 2-3 클럭 사이클의 동기화 지연

💡 Sizing Rule of Thumb

FIFO depth ≥ (burst_length × f_wr) / (f_rd - f_wr) for continuous streaming. In practice, add extra depth for the synchronization latency (2-3 cycles on each side).

FIFO 깊이 ≥ (버스트_길이 × f_wr) / (f_rd - f_wr) 연속 스트리밍의 경우. 실제로 동기화 지연(양쪽 2-3 사이클)을 위한 추가 깊이를 더합니다.

8. Common Interview Questions

🎤 Questions You Should Be Ready For

  1. Why must FIFO depth be a power of 2? — Gray code only has single-bit transitions when wrapping around powers of 2.
  2. Can flags give false full/empty? — Yes, but only conservatively (false full or false empty). Never a dangerous miss.
  3. Where is the full flag generated? — In the write clock domain (where the writer needs it).
  4. Where is the empty flag generated? — In the read clock domain (where the reader needs it).
  5. What happens if you use binary pointers instead of Gray? — Multi-bit transitions can cause the synchronizer to capture an invalid intermediate value, potentially corrupting full/empty detection.
  1. FIFO 깊이가 2의 거듭제곱이어야 하는 이유? — 그레이 코드는 2의 거듭제곱에서 래핑할 때만 단일 비트 전환을 가집니다.
  2. 플래그가 거짓 full/empty를 줄 수 있나? — 네, 하지만 보수적으로만 (거짓 full 또는 거짓 empty). 위험한 누락은 절대 없습니다.
  3. full 플래그는 어디서 생성되나? — 쓰기 클럭 도메인에서 (쓰기 측이 필요하므로).
  4. empty 플래그는 어디서 생성되나? — 읽기 클럭 도메인에서 (읽기 측이 필요하므로).
  5. 그레이 대신 이진 포인터를 사용하면? — 다중 비트 전환으로 동기화기가 잘못된 중간값을 캡처하여 full/empty 감지가 손상될 수 있습니다.
