📅 Day 28: Arbitration — Priority & Round-Robin

📝 Quiz 🔧 Practice ← Day 27

When multiple masters want to use a shared resource (bus, memory, FIFO), an arbiter decides who gets access. Today we study the two most fundamental arbitration schemes: fixed-priority and round-robin.

여러 마스터가 공유 자원(버스, 메모리, FIFO)을 사용하려 할 때, 아비터(arbiter)가 누구에게 접근 권한을 줄지 결정합니다. 오늘은 가장 기본적인 두 가지 중재 방식: 고정 우선순위(fixed-priority)와 라운드 로빈(round-robin)을 공부합니다.

1. Why Arbitration Matters

In any SoC, multiple blocks compete for shared resources. Without arbitration:

모든 SoC에서 여러 블록이 공유 자원을 두고 경쟁합니다. 중재 없이는:

  • Two masters could drive the bus simultaneously → bus contention
  • 두 마스터가 동시에 버스를 구동 → 버스 충돌(bus contention)
  • Data corruption, undefined behavior
  • 데이터 손상, 정의되지 않은 동작
  • Some masters could starve — never getting access
  • 일부 마스터가 기아 상태(starvation)에 빠질 수 있음 — 영원히 접근 못함

🎯 Arbiter's Job

Accept requests from N masters, produce exactly one grant at a time. The grant signal tells the winning master it can proceed.

N개의 마스터로부터 요청(request)을 받아, 한 번에 정확히 하나의 승인(grant)만 발행합니다. 승인 신호는 해당 마스터가 진행할 수 있음을 알려줍니다.

Master 0 ──req[0]──┐ ┌──grant[0]──→ Master 0 Master 1 ──req[1]──┤ ┌────────┐ ├──grant[1]──→ Master 1 Master 2 ──req[2]──┼──→│ ARBITER │──┼──grant[2]──→ Master 2 Master 3 ──req[3]──┘ └────────┘ └──grant[3]──→ Master 3

2. Fixed-Priority Arbitration

The simplest scheme: assign each master a fixed priority level. The highest-priority requester always wins.

가장 간단한 방식: 각 마스터에 고정된 우선순위를 부여합니다. 가장 높은 우선순위의 요청자가 항상 이깁니다.

How It Works

Priority: Master 0 > Master 1 > Master 2 > Master 3. If Master 0 requests, it always gets the grant — regardless of who else is requesting.

우선순위: Master 0 > Master 1 > Master 2 > Master 3. Master 0이 요청하면, 다른 누가 요청하든 항상 승인을 받습니다.

module priority_arbiter #(
    parameter N = 4
)(
    input  logic [N-1:0] req,
    output logic [N-1:0] grant
);

    // Combinational — no clock needed
    always_comb begin
        grant = '0;  // Default: no grant
        for (int i = 0; i < N; i++) begin
            if (req[i]) begin
                grant[i] = 1'b1;
                break;  // First requester wins
            end
        end
    end

endmodule

💡 One-Liner Trick

You can also compute fixed-priority grant with bit manipulation: grant = req & (~req + 1). This isolates the lowest set bit — equivalent to highest priority if bit 0 is highest.

비트 연산으로도 고정 우선순위 승인을 계산할 수 있습니다: grant = req & (~req + 1). 이것은 최하위 설정 비트를 분리합니다 — 비트 0이 최우선이면 동일한 결과입니다.

Scenario (req)GrantWinner
4'b10104'b0010Master 1
4'b11114'b0001Master 0
4'b11004'b0100Master 2
4'b00014'b0001Master 0

⚠️ Starvation Problem

If Master 0 always has a request pending, Masters 1-3 never get the grant. This is the fundamental weakness of fixed-priority — low-priority masters can starve indefinitely.

Master 0이 항상 요청을 걸고 있으면, Master 1-3은 절대 승인을 받지 못합니다. 이것이 고정 우선순위의 근본적 약점입니다 — 낮은 우선순위의 마스터는 무한정 기아 상태에 빠질 수 있습니다.

3. Round-Robin Arbitration

Round-robin solves starvation by rotating priority after each grant. The last winner gets the lowest priority next time.

라운드 로빈은 각 승인 후 우선순위를 회전시켜 기아 문제를 해결합니다. 마지막 승자는 다음 번에 가장 낮은 우선순위를 받습니다.

The Concept: Rotating Priority Pointer

Cycle 1: Priority → [0] > 1 > 2 > 3 Grant → Master 0 Cycle 2: Priority → [1] > 2 > 3 > 0 Grant → Master 1 Cycle 3: Priority → [2] > 3 > 0 > 1 Grant → Master 2 Cycle 4: Priority → [3] > 0 > 1 > 2 Grant → Master 3 Cycle 5: Priority → [0] > 1 > 2 > 3 (wraps around)

A pointer register tracks who has highest priority. After granting, the pointer advances to the next master. This guarantees every master gets a fair share over time.

포인터 레지스터가 누가 최우선인지 추적합니다. 승인 후 포인터가 다음 마스터로 이동합니다. 이렇게 하면 시간이 지나면서 모든 마스터가 공정하게 접근할 수 있습니다.

Implementation: Mask-Based Round-Robin

The classic approach uses a mask to suppress requests from masters that have already been served in this "round":

전통적인 방식은 마스크를 사용하여 이번 "라운드"에서 이미 서비스된 마스터의 요청을 억제합니다:

module round_robin_arbiter #(
    parameter N = 4
)(
    input  logic              clk,
    input  logic              rst_n,
    input  logic [N-1:0]     req,
    output logic [N-1:0]     grant
);

    logic [N-1:0] mask;        // Tracks which masters still have priority
    logic [N-1:0] masked_req;  // req AND mask
    logic [N-1:0] mask_grant;  // Grant from masked requests
    logic [N-1:0] raw_grant;   // Grant from unmasked requests

    // Masked request = only consider unserved masters
    assign masked_req = req & mask;

    // Priority encode masked requests (isolate LSB)
    assign mask_grant = masked_req & (~masked_req + 1);

    // Priority encode raw requests (fallback)
    assign raw_grant = req & (~req + 1);

    // Use masked grant if any masked request exists, else raw
    assign grant = (|masked_req) ? mask_grant : raw_grant;

    // Update mask after each grant
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            mask <= {N{1'b1}};  // All enabled at reset
        end else if (|grant) begin
            if (|masked_req)
                // Clear granted bit and all lower bits in mask
                mask <= mask & ~((mask_grant << 1) - 1)
                         & ~mask_grant;
            else
                // All masked out — reset mask, clear granted + below
                mask <= ~((raw_grant << 1) - 1) & ~raw_grant;
        end
    end

endmodule

Let's trace through with N=4, all requesting (req = 4'b1111):

N=4, 모두 요청 중인 경우(req = 4'b1111)를 따라가 봅시다:

4100010001000 (M3)0000

Perfect fairness! Each master gets exactly one grant per round.

완벽한 공정성! 각 마스터가 라운드당 정확히 한 번의 승인을 받습니다.

4. Pointer-Based Round-Robin (Alternative)

Another common implementation uses a simple pointer register that advances after each grant. The "barrel shift" approach rotates requests so the next-in-line always appears at position 0:

또 다른 일반적인 구현은 각 승인 후 이동하는 간단한 포인터 레지스터를 사용합니다. "배럴 시프트" 방식은 요청을 회전시켜 다음 차례가 항상 위치 0에 나타나게 합니다:

module rr_arbiter_pointer #(
    parameter N = 4
)(
    input  logic                     clk,
    input  logic                     rst_n,
    input  logic [N-1:0]            req,
    output logic [N-1:0]            grant
);

    logic [$clog2(N)-1:0] ptr;  // Points to highest-priority master
    logic [2*N-1:0]      dbl_req;
    logic [2*N-1:0]      dbl_grant;

    // Double the request vector for wrap-around search
    assign dbl_req = {req, req} >> ptr;

    // Isolate lowest set bit (highest-priority after rotation)
    assign dbl_grant = dbl_req & (~dbl_req + 1);

    // Rotate grant back to original position
    always_comb begin
        logic [2*N-1:0] shifted;
        shifted = dbl_grant << ptr;
        grant   = shifted[N-1:0] | shifted[2*N-1:N];
    end

    // Advance pointer after grant
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            ptr <= '0;
        else if (|grant) begin
            // Find which master was granted, advance ptr past it
            for (int i = 0; i < N; i++)
                if (grant[i])
                    ptr <= (i + 1) % N;
        end
    end

endmodule

6. Weighted Round-Robin

Sometimes pure fairness isn't ideal — some masters need more bandwidth. Weighted round-robin (WRR) gives each master a configurable number of grants per round:

순수한 공정성이 항상 이상적이지는 않습니다 — 일부 마스터는 더 많은 대역폭이 필요합니다. 가중 라운드 로빈(WRR)은 각 마스터에 라운드당 설정 가능한 승인 횟수를 부여합니다:

💡 WRR Example

With weights [3, 1, 1, 1]:

가중치 [3, 1, 1, 1]인 경우:

  • Master 0 gets 3 grants → Master 1 gets 1 → Master 2 gets 1 → Master 3 gets 1 → repeat
  • Master 0: 3회 승인 → Master 1: 1회 → Master 2: 1회 → Master 3: 1회 → 반복

Master 0 gets 50% bandwidth, others get ~17% each. Use a credit counter per master — decrement on grant, skip when zero.

Master 0은 대역폭의 50%, 나머지는 각각 ~17%를 받습니다. 마스터별 크레딧 카운터를 사용합니다 — 승인 시 감소, 0일 때 건너뜀.

7. Real-World Applications

🌍 Where You'll See Arbiters

  • AXI Interconnect: Multiple masters → shared slaves. Round-robin is default for most AXI interconnects.
  • AXI 인터커넥트: 다수 마스터 → 공유 슬레이브. 대부분의 AXI 인터커넥트에서 라운드 로빈이 기본.
  • Ethernet Switch: Multiple ports competing for egress — uses WRR or deficit round-robin (DRR).
  • 이더넷 스위치: 여러 포트가 출력을 두고 경쟁 — WRR 또는 DRR(적자 라운드 로빈) 사용.
  • CPU Cache: Arbiter decides which core accesses shared L2/L3.
  • CPU 캐시: 아비터가 어떤 코어가 공유 L2/L3에 접근하는지 결정.
  • DMA Controller: Multiple DMA channels competing for memory bus.
  • DMA 컨트롤러: 여러 DMA 채널이 메모리 버스를 두고 경쟁.

🔗 Connection to Your Work

In automotive Ethernet switches (like the ones at Microchip), arbitration is critical. When multiple ports send frames simultaneously, the switch fabric uses arbitration to decide which frame gets forwarded first. Understanding priority vs round-robin directly applies to QoS (Quality of Service) in networking!

자동차 이더넷 스위치(예: Microchip 제품)에서 중재는 매우 중요합니다. 여러 포트가 동시에 프레임을 보낼 때, 스위치 패브릭은 중재를 사용하여 어떤 프레임을 먼저 전달할지 결정합니다. 우선순위 vs 라운드 로빈의 이해는 네트워킹의 QoS(서비스 품질)에 직접 적용됩니다!

8. Key Takeaways

📌 Summary

  1. Arbiters resolve contention when multiple masters request a shared resource
  2. 아비터는 여러 마스터가 공유 자원을 요청할 때 경합을 해결합니다
  3. Fixed-priority is simple (combinational) but causes starvation
  4. 고정 우선순위는 간단하지만(조합 논리) 기아 상태를 유발합니다
  5. Round-robin is fair, starvation-free, uses a rotating pointer/mask
  6. 라운드 로빈은 공정하고 기아가 없으며, 회전하는 포인터/마스크를 사용합니다
  7. Weighted round-robin adds configurable bandwidth allocation
  8. 가중 라운드 로빈은 설정 가능한 대역폭 할당을 추가합니다
  9. The grant = req & (~req + 1) trick isolates the lowest set bit — fundamental to priority encoding
  10. grant = req & (~req + 1) 트릭은 최하위 설정 비트를 분리합니다 — 우선순위 인코딩의 핵심
