6주차, 2일 — 어제 Ready/Valid 핸드셰이킹을 심층적으로 다뤘습니다. 오늘은 그 기반 위에 ARM의 산업 표준 버스 프로토콜인 AXI (Advanced eXtensible Interface)를 살펴봅니다. AXI는 모든 채널에서 Ready/Valid를 사용합니다.

1. What is AXI?

AXI is part of the AMBA (Advanced Microcontroller Bus Architecture) family, defined by ARM. It's the go-to protocol for high-performance on-chip communication in modern SoCs. Almost every chip you'll work with uses some form of AMBA/AXI.

AXI는 ARM이 정의한 AMBA (Advanced Microcontroller Bus Architecture) 제품군의 일부입니다. 현대 SoC에서 고성능 온칩 통신을 위한 핵심 프로토콜입니다. 여러분이 작업할 거의 모든 칩이 AMBA/AXI의 일부 형태를 사용합니다.

2. The Five AXI Channels

AXI's key architectural insight: separate read and write paths with independent channels. This allows simultaneous reads and writes — no waiting!

AXI의 핵심 아키텍처 인사이트: 읽기와 쓰기 경로를 분리하여 독립적인 채널을 사용합니다. 이로써 동시 읽기와 쓰기가 가능합니다 — 대기 시간 없음!

┌─────────────┐ ┌─────────────┐ │ │ ──AW (Write Addr)──▶ │ │ │ │ ──W (Write Data)──▶ │ │ │ MASTER │ ◀──B (Write Resp)── │ SLAVE │ │ (CPU) │ ──AR (Read Addr) ──▶ │ (Memory) │ │ │ ◀──R (Read Data) ── │ │ └─────────────┘ └─────────────┘

💡 Why Separate Channels?

Each channel has its own Ready/Valid handshake. This means the write address can be accepted before write data arrives, or multiple reads can be outstanding at once. This decoupling is what gives AXI its performance advantage.

각 채널은 자체 Ready/Valid 핸드셰이크를 가집니다. 즉, 쓰기 데이터가 도착하기 전에 쓰기 주소를 수락할 수 있고, 여러 읽기 요청을 동시에 처리할 수 있습니다. 이 디커플링이 AXI의 성능 이점을 제공합니다.

3. Channel Signals in Detail

Write Address Channel (AW)

// Write Address Channel signals
logic                  AWVALID;   // Master: address valid
logic                  AWREADY;   // Slave: ready to accept
logic [31:0]          AWADDR;    // Write address
logic [7:0]           AWLEN;     // Burst length (0-255 → 1-256 beats)
logic [2:0]           AWSIZE;    // Bytes per beat (2^AWSIZE)
logic [1:0]           AWBURST;   // Burst type: FIXED/INCR/WRAP
logic [3:0]           AWID;      // Transaction ID

Write Data Channel (W)

// Write Data Channel signals
logic                  WVALID;    // Master: data valid
logic                  WREADY;    // Slave: ready for data
logic [31:0]          WDATA;     // Write data
logic [3:0]           WSTRB;     // Write strobes (byte enables)
logic                  WLAST;     // Last beat in burst

Write Response Channel (B)

// Write Response Channel signals
logic                  BVALID;    // Slave: response valid
logic                  BREADY;    // Master: ready for response
logic [1:0]           BRESP;     // Response: OKAY/EXOKAY/SLVERR/DECERR
logic [3:0]           BID;       // Transaction ID (matches AWID)

Read Address Channel (AR)

// Read Address Channel signals
logic                  ARVALID;   // Master: address valid
logic                  ARREADY;   // Slave: ready to accept
logic [31:0]          ARADDR;    // Read address
logic [7:0]           ARLEN;     // Burst length
logic [2:0]           ARSIZE;    // Bytes per beat
logic [1:0]           ARBURST;   // Burst type
logic [3:0]           ARID;      // Transaction ID

Read Data Channel (R)

// Read Data Channel signals
logic                  RVALID;    // Slave: data valid
logic                  RREADY;    // Master: ready for data
logic [31:0]          RDATA;     // Read data
logic [1:0]           RRESP;     // Response status
logic                  RLAST;     // Last beat in burst
logic [3:0]           RID;       // Transaction ID (matches ARID)

4. Burst Transfers

A single AXI address transaction can trigger multiple data beats — this is called a burst. Instead of sending an address for every word, you send one address and stream the data.

단일 AXI 주소 트랜잭션이 여러 데이터 비트를 트리거할 수 있습니다 — 이를 버스트라고 합니다. 모든 워드에 대해 주소를 보내는 대신, 하나의 주소를 보내고 데이터를 스트리밍합니다.

🔄 Burst Types

🔄 버스트 유형

TypeAWBURSTAddress Behavior주소 동작Use Case사용 사례
FIXED2'b00Same address every beat매 비트마다 같은 주소FIFO access (same reg)FIFO 접근 (같은 레지스터)
INCR2'b01Address increments each beat매 비트마다 주소 증가Sequential memory (most common!)순차 메모리 (가장 일반적!)
WRAP2'b10Wraps at boundary경계에서 래핑Cache line fills캐시 라인 채움

Burst length: AWLEN + 1 = number of beats. So AWLEN = 3 means 4 beats. AWLEN = 0 is a single transfer (still technically a "burst of 1").

버스트 길이: AWLEN + 1 = 비트 수. 따라서 AWLEN = 3은 4비트를 의미합니다. AWLEN = 0은 단일 전송입니다 (기술적으로 "1개의 버스트").

Beat size: 2^AWSIZE = bytes per beat. For a 32-bit bus: AWSIZE = 2 (2² = 4 bytes).

비트 크기: 2^AWSIZE = 비트당 바이트. 32비트 버스의 경우: AWSIZE = 2 (2² = 4 바이트).

5. Write Strobes (WSTRB)

Write strobes enable byte-level write control. Each bit in WSTRB corresponds to one byte of WDATA.

쓰기 스트로브는 바이트 수준 쓰기 제어를 가능하게 합니다. WSTRB의 각 비트는 WDATA의 한 바이트에 해당합니다.

// For a 32-bit data bus (4 bytes):
// WSTRB[0] → WDATA[7:0]   (byte 0)
// WSTRB[1] → WDATA[15:8]  (byte 1)
// WSTRB[2] → WDATA[23:16] (byte 2)
// WSTRB[3] → WDATA[31:24] (byte 3)

// Example: Write only bytes 0 and 2
WSTRB = 4'b0101;  // Only bytes 0 and 2 are written
WDATA = 32'hDEADBEEF;
// Byte 0 (EF) → written
// Byte 1 (BE) → NOT written (preserved)
// Byte 2 (AD) → written
// Byte 3 (DE) → NOT written (preserved)

💡 Why WSTRB Matters

Without byte strobes, writing a single byte to a 32-bit word would require a read-modify-write — read the full word, change one byte, write it all back. WSTRB lets the slave handle it atomically. This is critical for things like memory-mapped registers where only certain bytes should change.

바이트 스트로브 없이는 32비트 워드에 단일 바이트를 쓰려면 읽기-수정-쓰기가 필요합니다 — 전체 워드를 읽고, 한 바이트를 변경하고, 다시 전체를 씁니다. WSTRB는 슬레이브가 이를 원자적으로 처리하게 합니다.

7. Transaction IDs — Out-of-Order Completion

Each transaction gets an ID tag (AWID/ARID). The slave returns data/responses with matching IDs (BID/RID). This allows:

각 트랜잭션은 ID 태그(AWID/ARID)를 받습니다. 슬레이브는 일치하는 ID(BID/RID)와 함께 데이터/응답을 반환합니다. 이를 통해:

  • Out-of-order completion — a fast memory can respond before a slow peripheral
  • 순서 무관 완료 — 빠른 메모리가 느린 주변장치보다 먼저 응답할 수 있음
  • Interleaving — data from different transactions can be mixed on the channel
  • 인터리빙 — 다른 트랜잭션의 데이터가 채널에서 혼합될 수 있음
  • Multiple outstanding transactions — don't wait for one to finish before starting the next
  • 다중 미처리 트랜잭션 — 하나가 끝날 때까지 기다리지 않고 다음을 시작
// Master issues two reads with different IDs:
// Time 0: AR transaction with ARID=0, addr=0x1000 (slow memory)
// Time 1: AR transaction with ARID=1, addr=0x2000 (fast SRAM)
// Time 5: R data arrives  with RID=1  (fast one returns first!)
// Time 10: R data arrives with RID=0  (slow one completes later)

Here's how a complete write works step by step:

⚠️ Key Rule: Address ≠ Data Ordering

In AXI, write data can arrive BEFORE the write address! The AW and W channels are independent. The slave must be able to buffer data until it knows the destination address. This is surprising but critical for performance — the master can start streaming data while the address is still being routed through an interconnect.

AXI에서 쓰기 데이터가 쓰기 주소보다 먼저 도착할 수 있습니다! AW와 W 채널은 독립적입니다. 슬레이브는 목적지 주소를 알 때까지 데이터를 버퍼링할 수 있어야 합니다. 이는 놀랍지만 성능에 중요합니다.

10. Simple AXI-Lite Slave (SystemVerilog)

Here's a minimal AXI-Lite slave with 4 registers — the most common starting point for any IP block:

여기 4개의 레지스터를 가진 최소한의 AXI-Lite 슬레이브가 있습니다 — 모든 IP 블록의 가장 일반적인 시작점입니다:

module axi_lite_slave #(
    parameter ADDR_WIDTH = 4,
    parameter DATA_WIDTH = 32
)(
    input  logic                       ACLK,
    input  logic                       ARESETn,

    // Write Address Channel
    input  logic [ADDR_WIDTH-1:0]     AWADDR,
    input  logic                       AWVALID,
    output logic                       AWREADY,

    // Write Data Channel
    input  logic [DATA_WIDTH-1:0]     WDATA,
    input  logic [DATA_WIDTH/8-1:0]   WSTRB,
    input  logic                       WVALID,
    output logic                       WREADY,

    // Write Response Channel
    output logic [1:0]                BRESP,
    output logic                       BVALID,
    input  logic                       BREADY,

    // Read Address Channel
    input  logic [ADDR_WIDTH-1:0]     ARADDR,
    input  logic                       ARVALID,
    output logic                       ARREADY,

    // Read Data Channel
    output logic [DATA_WIDTH-1:0]     RDATA,
    output logic [1:0]                RRESP,
    output logic                       RVALID,
    input  logic                       RREADY
);

    // 4 internal registers
    logic [DATA_WIDTH-1:0] reg_file [0:3];

    // ---- Write Logic ----
    logic aw_done, w_done;
    logic [ADDR_WIDTH-1:0] wr_addr;

    // Accept write address
    assign AWREADY = !aw_done;

    always_ff @(posedge ACLK or negedge ARESETn)
        if (!ARESETn)
            aw_done <= 1'b0;
        else if (BVALID && BREADY)
            aw_done <= 1'b0;
        else if (AWVALID && AWREADY)
            aw_done <= 1'b1;

    // Capture write address
    always_ff @(posedge ACLK)
        if (AWVALID && AWREADY)
            wr_addr <= AWADDR;

    // Accept write data & update registers
    assign WREADY = !w_done;

    always_ff @(posedge ACLK or negedge ARESETn)
        if (!ARESETn)
            w_done <= 1'b0;
        else if (BVALID && BREADY)
            w_done <= 1'b0;
        else if (WVALID && WREADY)
            w_done <= 1'b1;

    // Write to register file with byte strobes
    always_ff @(posedge ACLK)
        if (WVALID && WREADY)
            for (int i = 0; i < DATA_WIDTH/8; i++)
                if (WSTRB[i])
                    reg_file[wr_addr[3:2]][i*8 +: 8] <= WDATA[i*8 +: 8];

    // Write response
    assign BVALID = aw_done && w_done;
    assign BRESP  = 2'b00;  // Always OKAY

    // ---- Read Logic ----
    logic rd_valid;

    assign ARREADY = !rd_valid;

    always_ff @(posedge ACLK or negedge ARESETn)
        if (!ARESETn)
            rd_valid <= 1'b0;
        else if (RVALID && RREADY)
            rd_valid <= 1'b0;
        else if (ARVALID && ARREADY)
            rd_valid <= 1'b1;

    always_ff @(posedge ACLK)
        if (ARVALID && ARREADY)
            RDATA <= reg_file[ARADDR[3:2]];

    assign RVALID = rd_valid;
    assign RRESP  = 2'b00;

endmodule

11. Key Takeaways

🎯 Today's Key Points

🎯 오늘의 핵심 포인트

  1. 5 channels: AW, W, B (write path) + AR, R (read path) — all use Ready/Valid
  2. 5개 채널: AW, W, B (쓰기 경로) + AR, R (읽기 경로) — 모두 Ready/Valid 사용
  3. Bursts: One address, multiple data beats — FIXED, INCR, or WRAP
  4. 버스트: 하나의 주소, 여러 데이터 비트 — FIXED, INCR, 또는 WRAP
  5. WSTRB: Byte-level write enable — no need for read-modify-write
  6. WSTRB: 바이트 수준 쓰기 활성화 — 읽기-수정-쓰기 불필요
  7. Transaction IDs: Enable out-of-order completion and interleaving
  8. 트랜잭션 ID: 순서 무관 완료 및 인터리빙 가능
  9. AXI-Lite: Simplified version for register access — no bursts, no IDs
  10. AXI-Lite: 레지스터 접근을 위한 단순화 버전 — 버스트 없음, ID 없음
  11. Response codes: OKAY, EXOKAY, SLVERR, DECERR — always check!
  12. 응답 코드: OKAY, EXOKAY, SLVERR, DECERR — 항상 확인!

🔗 Connection to Your Work

In your Ethernet PHY/Switch work at Microchip, the register configuration interfaces likely use AXI-Lite for MDIO register access, while bulk data paths (packet buffers, DMA) would use full AXI. Understanding both is essential for your digital design transition!

Microchip에서의 이더넷 PHY/Switch 작업에서, 레지스터 구성 인터페이스는 MDIO 레지스터 접근에 AXI-Lite를, 대량 데이터 경로(패킷 버퍼, DMA)는 전체 AXI를 사용할 가능성이 높습니다. 디지털 설계 전환에 둘 다 이해하는 것이 필수적입니다!
