📝 Day 21 Quiz: Latency vs Throughput

📖 Lesson 💻 Practice

Q1. What does latency measure?

Q1. 레이턴시는 무엇을 측정하나요?

✅ Correct! Latency is the time for a single operation to complete.✅ 정답! 레이턴시는 단일 연산이 완료되는 시간입니다.
❌ Latency = time for ONE piece of data from input to output.❌ 레이턴시 = 하나의 데이터가 입력에서 출력까지 걸리는 시간.

Q2. A 3-stage pipeline runs at 300 MHz. What is the latency in nanoseconds?

Q2. 3단계 파이프라인이 300 MHz로 동작합니다. 레이턴시는 몇 나노초인가요?

✅ Correct! 3 cycles × (1/300MHz) = 3 × 3.33ns = 10ns.✅ 정답! 3 사이클 × (1/300MHz) = 3 × 3.33ns = 10ns.
❌ Latency = cycles × period = 3 × (1/300M) = 10ns.❌ 레이턴시 = 사이클 × 주기 = 3 × (1/300M) = 10ns.

Q3. What does pipelining primarily improve?

Q3. 파이프라이닝은 주로 무엇을 개선하나요?

✅ Correct! Pipelining improves throughput by overlapping operations.✅ 정답! 파이프라이닝은 연산을 겹쳐 처리량을 향상시킵니다.
❌ Pipelining increases throughput, not reduces latency.❌ 파이프라이닝은 처리량을 증가시키지, 레이턴시를 줄이지 않습니다.

Q4. Little's Law states L = λ × W. What does L represent?

Q4. Little's Law에서 L = λ × W. L은 무엇을 나타내나요?

✅ Correct! L = average number of items in the system (in-flight).✅ 정답! L = 시스템 내 평균 항목 수 (전송 중).
❌ L = average items in system. λ = throughput. W = latency.❌ L = 시스템 내 평균 항목. λ = 처리량. W = 레이턴시.

Q5. A system has throughput of 1 Gops/s and latency of 20 ns. How many operations are in-flight?

Q5. 시스템의 처리량이 1 Gops/s이고 레이턴시가 20ns일 때, 전송 중인 연산은 몇 개인가요?

✅ Correct! 1G × 20ns = 1×10⁹ × 20×10⁻⁹ = 20 operations.✅ 정답! 1G × 20ns = 1×10⁹ × 20×10⁻⁹ = 20개 연산.
❌ In-flight = throughput × latency = 1G × 20ns = 20.❌ 전송 중 = 처리량 × 레이턴시 = 1G × 20ns = 20.

Q6. Which application would prioritize latency over throughput?

Q6. 어떤 응용이 처리량보다 레이턴시를 우선시하나요?

✅ Correct! Interrupt handlers must respond quickly — latency is critical.✅ 정답! 인터럽트 핸들러는 빠르게 응답해야 합니다 — 레이턴시가 중요합니다.
❌ Interrupt handlers need fast response time → latency-sensitive.❌ 인터럽트 핸들러는 빠른 응답 시간이 필요 → 레이턴시 민감.

Q7. Adding pipeline stages increases _____ (in cycles) but can improve _____.

Q7. 파이프라인 단계를 추가하면 _____(사이클)이 증가하지만 _____을 개선할 수 있습니다.

✅ Correct! More stages → more cycles (latency) but faster clock (throughput).✅ 정답! 더 많은 단계 → 더 많은 사이클(레이턴시) 하지만 더 빠른 클럭(처리량).
❌ Pipeline stages increase latency (cycles) but improve throughput.❌ 파이프라인 단계는 레이턴시(사이클)를 증가시키지만 처리량을 개선합니다.

Q8. What is a key reason NOT to add more pipeline stages?

Q8. 파이프라인 단계를 더 추가하지 않는 핵심 이유는?

✅ Correct! Each register adds setup time + clk-to-q delay, limiting diminishing returns.✅ 정답! 각 레지스터가 셋업 타임 + clk-to-q 지연을 추가하여 수확체감을 초래합니다.
❌ Register overhead (setup/hold + clk-to-q) limits how much pipelining helps.❌ 레지스터 오버헤드(셋업/홀드 + clk-to-q)가 파이프라이닝의 효과를 제한합니다.

Q9. A non-pipelined design runs at 100 MHz. After adding 4 pipeline stages, it runs at 350 MHz. What's the throughput improvement?

Q9. 파이프라인 없는 설계가 100 MHz로 동작합니다. 4개 파이프라인 단계 추가 후 350 MHz로 동작합니다. 처리량 개선은?

✅ Correct! 350M/100M = 3.5× throughput. Not 4× due to register overhead!✅ 정답! 350M/100M = 3.5× 처리량. 레지스터 오버헤드로 4×가 아닙니다!
❌ Throughput = new freq / old freq = 350/100 = 3.5×.❌ 처리량 = 새 주파수 / 이전 주파수 = 350/100 = 3.5×.

Q10. How do you calculate minimum FIFO depth for a CDC crossing?

Q10. CDC 크로싱을 위한 최소 FIFO 깊이는 어떻게 계산하나요?

✅ Correct! Little's Law: FIFO depth ≥ throughput × synchronization latency.✅ 정답! Little's Law: FIFO 깊이 ≥ 처리량 × 동기화 레이턴시.
❌ Use Little's Law: depth = throughput × latency to avoid overflow.❌ Little's Law 사용: 깊이 = 처리량 × 레이턴시로 오버플로 방지.
