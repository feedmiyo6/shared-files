Section 1: ASIC Design Flow 섹션 1: ASIC 설계 흐름

1 Describe the overall ASIC design flow 전체 ASIC 설계 흐름을 설명하세요

🚀 Elevator Pitch

"The ASIC design flow takes a chip from idea to silicon in roughly 8 stages: Spec → Architecture → RTL Design → Functional Verification → Synthesis → Physical Design (Place & Route) → Signoff (Timing, DRC/LVS) → Fabrication & Test. Think of it as a funnel — each stage adds more physical detail and removes more bugs."

"ASIC 설계 흐름은 칩을 아이디어에서 실리콘까지 대략 8단계로 진행합니다: 사양 → 아키텍처 → RTL 설계 → 기능 검증 → 합성 → 물리적 설계 (배치 및 배선) → 사인오프 (타이밍, DRC/LVS) → 제조 및 테스트. 각 단계가 더 많은 물리적 세부사항을 추가하고 더 많은 버그를 제거하는 깔때기라고 생각하세요."

RTL Synthesis Place & Route DRC/LVS STA Signoff Tapeout GDS-II

🧠 Mnemonic: "Smart Architects Run Very Smoothly Past Signoff Tapeout"

🧠 암기법: Spec → Arch → RTL → Verify → Synth → P&R → Signoff → Tapeout

(Spec, Architecture, RTL, Verification, Synthesis, Physical, Signoff, Tapeout)

🎤 Interview Tip

Start by saying: "The ASIC flow has 8 major stages, and I like to think of them in two halves — the front-end (logic) and back-end (physical)." Then walk through each stage. Interviewers love when you frame the big picture before diving in.

"ASIC 흐름은 8가지 주요 단계가 있으며, 저는 프론트엔드(논리)와 백엔드(물리)로 나누어 생각합니다." 그런 다음 각 단계를 설명하세요. 면접관들은 세부사항에 들어가기 전에 큰 그림을 잡아주는 것을 좋아합니다.

🔄 Common Follow-ups

🔄 예상 후속 질문

  • "What tools do you use at each stage?" (Synopsys DC, ICC2, VCS; Cadence Genus, Innovus)
  • "각 단계에서 어떤 도구를 사용하나요?" (Synopsys DC, ICC2, VCS; Cadence Genus, Innovus)
  • "Where do most bugs get caught?" (Functional verification — 70% of design effort)
  • "대부분의 버그는 어디서 발견되나요?" (기능 검증 — 설계 노력의 70%)
  • "What happens if you find a timing violation after P&R?"
  • "P&R 후에 타이밍 위반을 발견하면 어떻게 하나요?"

2 Explain each stage of the design flow 설계 흐름의 각 단계를 설명하세요

The 8 Stages — Deep Dive

8단계 — 심층 분석

1. Specification: Define what the chip does — functionality, performance targets, power budget, area constraints, interfaces. This is the "contract" everyone builds to.

1. 사양: 칩의 기능 정의 — 기능성, 성능 목표, 전력 예산, 면적 제약, 인터페이스. 모두가 이에 맞춰 만드는 "계약서"입니다.

2. Architecture: High-level block diagram. Decide on bus architecture, clock domains, memory subsystem, pipeline depth. Trade off area vs speed vs power. Typically done in SystemC or spreadsheets.

2. 아키텍처: 상위 수준 블록 다이어그램. 버스 구조, 클록 도메인, 메모리 서브시스템, 파이프라인 깊이 결정. 면적 vs 속도 vs 전력 트레이드오프.

3. RTL Design: Write Verilog/SystemVerilog. The design is described at Register-Transfer Level — data moving between registers through combinational logic. This is the "source code" of your chip.

3. RTL 설계: Verilog/SystemVerilog 작성. 레지스터 전송 수준에서 설계를 기술 — 조합 논리를 통해 레지스터 간에 데이터가 이동합니다.

4. Functional Verification: Prove the RTL is correct. UVM testbenches, constrained random, formal verification, code/functional coverage. This is ~70% of the effort!

4. 기능 검증: RTL이 올바른지 증명. UVM 테스트벤치, 제약 랜덤, 형식 검증, 코드/기능 커버리지. 전체 노력의 ~70%!

5. Synthesis: Convert RTL to gate-level netlist using a standard cell library. Tool maps your Verilog to actual AND, OR, FF cells. Optimizes for timing, area, power. Output: gate-level netlist + SDC constraints.

5. 합성: 표준 셀 라이브러리를 사용하여 RTL을 게이트 수준 넷리스트로 변환. 도구가 Verilog를 실제 AND, OR, FF 셀에 매핑합니다.

6. Physical Design (Place & Route): Place standard cells on the floorplan, route metal interconnects, insert clock tree (CTS), optimize timing. Output: DEF file with physical locations.

6. 물리적 설계 (배치 및 배선): 플로어플랜에 표준 셀 배치, 금속 배선 라우팅, 클록 트리 삽입 (CTS), 타이밍 최적화.

7. Signoff: Final checks before sending to fab. STA (PrimeTime), DRC/LVS (Calibre), power analysis (PTPX), signal integrity. Every check must pass — no exceptions.

7. 사인오프: 팹 전송 전 최종 검사. STA (PrimeTime), DRC/LVS (Calibre), 전력 분석 (PTPX), 신호 무결성.

8. Fabrication & Test: Generate GDS-II, send to foundry. After fabrication, test with ATPG patterns (scan chains, BIST). Yield analysis follows.

8. 제조 및 테스트: GDS-II 생성, 파운드리 전송. 제조 후 ATPG 패턴으로 테스트 (스캔 체인, BIST).

💡 Key Insight for Interview

💡 면접 핵심 인사이트

Emphasize the iterative nature — you don't just go straight through. Timing violations after P&R send you back to synthesis. Verification bugs send you back to RTL. Show you understand it's a loop, not a waterfall.

반복적 특성을 강조하세요 — 한 번에 쭉 진행되지 않습니다. P&R 후 타이밍 위반이 있으면 합성으로 돌아갑니다.

3 Synchronous Design vs. Asynchronous Design 동기 설계 vs. 비동기 설계

🚀 Elevator Pitch

"In synchronous design, all state changes happen on clock edges — it's predictable, testable, and what 99% of the industry uses. In asynchronous design, events propagate based on handshaking without a global clock — lower power but much harder to verify and time."

"동기 설계에서는 모든 상태 변화가 클록 엣지에서 발생합니다 — 예측 가능하고, 테스트 가능하며, 업계의 99%가 사용합니다. 비동기 설계에서는 글로벌 클록 없이 핸드셰이킹에 기반하여 이벤트가 전파됩니다 — 더 낮은 전력이지만 검증과 타이밍이 훨씬 어렵습니다."

Section 2: FSM & Memory 섹션 2: FSM & 메모리

4 What is an FSM? FSM이란 무엇인가요?

🚀 Elevator Pitch

"A Finite State Machine is a sequential circuit with a finite number of states, transitions between those states based on inputs, and outputs based on the current state (and possibly inputs). There are two types: Moore — outputs depend only on state, and Mealy — outputs depend on state AND inputs."

"유한 상태 기계는 유한한 수의 상태를 가진 순차 회로로, 입력에 기반한 상태 전이와 현재 상태(및 입력)에 기반한 출력을 가집니다. 두 가지 유형: Moore — 출력이 상태에만 의존, Mealy — 출력이 상태와 입력에 의존."

🧠 "Moore = More states (output only from state), Mealy = iMMediate (output responds to input immediately)"

🧠 "Moore = 더 많은 상태 (상태에서만 출력), Mealy = 즉각적 (입력에 즉시 응답)"

FSM Components

FSM 구성 요소

  • State register — flip-flops holding current state
  • 상태 레지스터 — 현재 상태를 저장하는 플립플롭
  • Next-state logic — combinational logic computing next state from current state + inputs
  • 다음 상태 논리 — 현재 상태 + 입력에서 다음 상태를 계산하는 조합 논리
  • Output logic — combinational logic computing outputs
  • 출력 논리 — 출력을 계산하는 조합 논리

Encoding schemes: Binary (log₂N FFs, compact), One-hot (N FFs, faster decode, preferred in FPGAs), Gray (for low-power state transitions).

인코딩 방식: 이진 (log₂N FF, 컴팩트), 원-핫 (N FF, 빠른 디코드, FPGA에서 선호), 그레이 (저전력 상태 전이).

🔄 Common Follow-ups

🔄 예상 후속 질문

  • "When would you choose Moore over Mealy?" → Moore when glitch-free output is critical (output is registered). Mealy for faster response (one cycle earlier).
  • "언제 Moore를 Mealy 대신 선택하나요?" → 글리치 없는 출력이 중요할 때 Moore. 더 빠른 응답이 필요할 때 Mealy (한 사이클 빠름).
  • "How do you handle unused states?" → Default transition to reset/safe state to avoid lock-up.
  • "사용하지 않는 상태는 어떻게 처리하나요?" → 잠금 방지를 위해 리셋/안전 상태로 기본 전이.

5a Architectural components of a controller 컨트롤러의 아키텍처 구성 요소

🚀 Elevator Pitch

"A digital controller has three main parts: the datapath (registers, ALU, multiplexers — does the computation), the control unit (FSM that generates control signals to orchestrate the datapath), and the memory (stores data/instructions). Think of it like a restaurant: the kitchen (datapath) does the work, the manager (control unit) decides what to do, and the pantry (memory) holds ingredients."

"디지털 컨트롤러는 세 가지 주요 부분이 있습니다: 데이터패스 (레지스터, ALU, 멀티플렉서 — 계산 수행), 제어 유닛 (데이터패스를 조율하는 제어 신호를 생성하는 FSM), 메모리 (데이터/명령어 저장)."

Datapath Control unit ALU Register file Multiplexer Microcode

5b What is Non-volatile memory? 비휘발성 메모리란?

🚀 Elevator Pitch

"Non-volatile memory retains data even when power is off. Examples: Flash (NAND/NOR), ROM, EEPROM, MRAM, ReRAM. The key mechanism is trapped charge on a floating gate (for Flash) or programmed connections (for ROM). It's the reason your phone remembers your apps after you restart it."

"비휘발성 메모리는 전원이 꺼져도 데이터를 유지합니다. 예: Flash (NAND/NOR), ROM, EEPROM, MRAM, ReRAM. 핵심 메커니즘은 플로팅 게이트에 갇힌 전하(Flash) 또는 프로그래밍된 연결(ROM)입니다."

💡 SRAM vs DRAM Quick Hit

💡 SRAM vs DRAM 빠른 정리

SRAM: 6 transistors/cell, fast, expensive, no refresh → caches. DRAM: 1 transistor + 1 capacitor/cell, dense, cheap, needs refresh → main memory.

SRAM: 셀당 6 트랜지스터, 빠름, 비쌈, 리프레시 불필요 → 캐시. DRAM: 셀당 1 트랜지스터 + 1 커패시터, 고밀도, 저가, 리프레시 필요 → 메인 메모리.

5d Difference between Op-Amp vs Comparator 오피앰프 vs 비교기의 차이

🚀 Elevator Pitch

"Both amplify the difference between two inputs, but an op-amp is designed for linear operation with feedback (high gain, compensated for stability), while a comparator is designed for open-loop operation — it slams to VDD or GND to give a digital 1 or 0. Never use an op-amp as a comparator — it's slow to recover and can oscillate. Never use a comparator with feedback — it has no compensation and will ring."

"둘 다 두 입력 간의 차이를 증폭하지만, 오피앰프는 피드백을 사용한 선형 동작용(높은 이득, 안정성 보상)이고, 비교기는 개방 루프 동작용 — VDD 또는 GND로 급격히 이동하여 디지털 1 또는 0을 출력합니다."

⚠️ Classic Interview Trap

"Can you use an op-amp as a comparator?" — Technically it works but: slow slew rate, may latch up, no hysteresis. Always say NO in an interview and explain why.

"오피앰프를 비교기로 쓸 수 있나요?" — 기술적으로 되지만: 느린 슬루율, 래치업 가능성, 히스테리시스 없음. 면접에서는 항상 안 된다고 하고 이유를 설명하세요.

Section 3: Digital Building Blocks 섹션 3: 디지털 기본 블록

6a Difference between a latch and a flip-flop? 래치와 플립플롭의 차이?

🚀 Elevator Pitch

"A latch is level-sensitive — it's transparent when the enable is high and holds when low. A flip-flop is edge-triggered — it captures data only at the clock edge. Flip-flops are preferred in synchronous design because they have a well-defined sampling point, making timing analysis clean. A D flip-flop is essentially two latches in series (master-slave)."

"래치는 레벨 감지 — 인에이블이 높을 때 투명하고 낮을 때 홀드합니다. 플립플롭은 에지 트리거 — 클록 에지에서만 데이터를 캡처합니다. 플립플롭은 잘 정의된 샘플링 포인트가 있어 동기 설계에서 선호됩니다."

🧠 "Latch = Level, Flip-flop = eFfedge (edge)"

🧠 "래치 = 레벨, 플립플롭 = 에지"

Level-sensitive Edge-triggered Master-slave Transparent Setup/Hold

🔄 Common Follow-ups

🔄 예상 후속 질문

  • "When would you use a latch instead of a flip-flop?" → Time borrowing in high-frequency designs; latches are smaller (fewer transistors).
  • "래치를 플립플롭 대신 언제 사용하나요?" → 고주파 설계에서의 타임 보로잉; 래치가 더 작음 (더 적은 트랜지스터).

6b Difference between sequential and combinational circuits? 순차 회로와 조합 회로의 차이?

🚀 Elevator Pitch

"Combinational — output depends ONLY on current inputs. No memory. Think: mux, adder, decoder. Sequential — output depends on current inputs AND past history (stored in FFs/latches). Think: counters, FSMs, registers. The key distinction is memory elements."

"조합 — 출력이 현재 입력에만 의존. 메모리 없음. 예: 먹스, 가산기, 디코더. 순차 — 출력이 현재 입력과 과거 이력(FF/래치에 저장)에 의존. 예: 카운터, FSM, 레지스터. 핵심 차이는 메모리 요소입니다."

6c Race condition and Timing loop 레이스 컨디션과 타이밍 루프

🚀 Elevator Pitch

"A race condition occurs when two signals compete to arrive at the same point, and the circuit behavior depends on which arrives first — the outcome is nondeterministic. A timing loop (or combinational loop) is when a signal feeds back to itself through purely combinational logic with no register breaking the path — this creates oscillation or undefined behavior. Synthesis tools flag these as errors."

"레이스 컨디션은 두 신호가 같은 지점에 도달하려고 경쟁할 때 발생하며, 어느 것이 먼저 도착하느냐에 따라 회로 동작이 달라집니다. 타이밍 루프(조합 루프)는 신호가 레지스터 없이 순수 조합 논리를 통해 자기 자신으로 피드백될 때 발생합니다 — 발진이나 미정의 동작을 만듭니다."

⚠️ Key Distinction

Race condition = timing-dependent behavior (can happen even in well-structured circuits if timing is tight). Timing loop = structural problem in the netlist (always a design bug). Fix: insert a register to break the loop.

레이스 컨디션 = 타이밍 의존 동작. 타이밍 루프 = 넷리스트의 구조적 문제 (항상 설계 버그). 해결: 루프를 끊는 레지스터 삽입.

🚀 Elevator Pitch

"For binary encoding: ⌈log₂(7)⌉ = 3 flip-flops (3 bits can represent 8 states, which covers 7). For one-hot encoding: 7 flip-flops — one FF per state, exactly one is hot at any time. One-hot uses more FFs but simpler next-state logic and faster decoding."

"이진 인코딩: ⌈log₂(7)⌉ = 3개 플립플롭 (3비트로 8상태 표현 가능, 7상태 커버). 원-핫 인코딩: 7개 플립플롭 — 상태당 하나의 FF, 항상 정확히 하나만 활성."

Quick Math

빠른 계산

  • Binary: N states → ⌈log₂(N)⌉ FFs. 7 states → ⌈log₂(7)⌉ = ⌈2.81⌉ = 3 FFs
  • 이진: N 상태 → ⌈log₂(N)⌉ FF. 7 상태 → ⌈log₂(7)⌉ = ⌈2.81⌉ = 3 FF
  • One-hot: N states → N FFs. 7 states → 7 FFs
  • 원-핫: N 상태 → N FF. 7 상태 → 7 FF

🎤 Interview Tip

Always mention the trade-off: "Binary uses fewer flip-flops but more complex decode logic. One-hot uses more FFs but the next-state and output logic is simpler and faster — each state is just one bit. In FPGAs, one-hot is often preferred because FFs are abundant. In ASICs, binary is more common to save area."

항상 트레이드오프를 언급하세요: "이진은 더 적은 FF를 사용하지만 더 복잡한 디코드 논리가 필요합니다. 원-핫은 더 많은 FF를 사용하지만 다음 상태 및 출력 논리가 더 간단하고 빠릅니다."

8a What are setup time and hold time? 셋업 타임과 홀드 타임이란?

🚀 Elevator Pitch

"Setup time (Tsu) is the minimum time data must be stable BEFORE the clock edge. Hold time (Th) is the minimum time data must be stable AFTER the clock edge. Violating setup = the FF might capture the wrong value (data hasn't settled). Violating hold = the new data corrupts the capture of the current data."

"셋업 타임 (Tsu)은 클록 에지 전에 데이터가 안정되어야 하는 최소 시간입니다. 홀드 타임 (Th)은 클록 에지 후에 데이터가 안정되어야 하는 최소 시간입니다."

🧠 "Setup = BEFORE the edge (data arrives early enough), Hold = AFTER the edge (data stays long enough)"

🧠 "셋업 = 에지 전 (데이터가 충분히 일찍 도착), 홀드 = 에지 후 (데이터가 충분히 오래 유지)"

셋업 체크: Tclk > Tcq + Tcomb + Tsu

Hold check: Tcq + Tcomb > Th (data must not change too fast)

홀드 체크: Tcq + Tcomb > Th

Where Tcq = clock-to-Q delay of launching FF, Tcomb = combinational delay.

여기서 Tcq = 실행 FF의 클록-투-Q 지연, Tcomb = 조합 지연.

9a Blocking vs Non-blocking in Verilog Verilog에서 블로킹 vs 논블로킹

🚀 Elevator Pitch

"Blocking (=) executes sequentially — each statement completes before the next starts. Used for combinational logic in always @(*). Non-blocking (<=) executes concurrently — all RHS values are evaluated first, then all LHS are updated simultaneously at the end of the time step. Used for sequential logic in always @(posedge clk). Mixing them up is the #1 Verilog bug."

"블로킹 (=)은 순차적으로 실행 — 각 문이 완료된 후 다음이 시작됩니다. always @(*)에서 조합 논리에 사용. 논블로킹 (<=)은 동시에 실행 — 모든 RHS 값이 먼저 평가된 후 모든 LHS가 시간 단계 끝에서 동시에 업데이트됩니다. always @(posedge clk)에서 순차 논리에 사용."

// COMBINATIONAL — use blocking (=)
always @(*) begin
    y = a & b;     // executes first
    z = y | c;     // uses updated y
end

// SEQUENTIAL — use non-blocking (<=)
always @(posedge clk) begin
    q1 <= d;       // both evaluate RHS at same time
    q2 <= q1;      // gets OLD q1, not new — shift register!
end

⚠️ Classic Mistake

Using blocking in sequential logic creates race conditions in simulation. Using non-blocking in combinational logic can cause simulation-synthesis mismatch. The rule is absolute: = for combinational, <= for sequential.

순차 논리에서 블로킹 사용은 시뮬레이션에서 레이스 컨디션을 만듭니다. 조합 논리에서 논블로킹 사용은 시뮬레이션-합성 불일치를 유발합니다. 규칙: 조합 = 블로킹, 순차 = 논블로킹.

10c Why does CMOS use both p & n transistors? CMOS가 p & n 트랜지스터를 모두 사용하는 이유?

🚀 Elevator Pitch

"CMOS uses complementary NMOS and PMOS to create a rail-to-rail output with zero static power. PMOS pulls up to VDD (passes strong 1), NMOS pulls down to GND (passes strong 0). At any time, only one network is conducting — there's no direct path from VDD to GND in steady state, so static power is essentially zero. This is the killer advantage of CMOS over NMOS-only logic."

"CMOS는 상보적 NMOS와 PMOS를 사용하여 레일-투-레일 출력과 제로 정적 전력을 만듭니다. 정상 상태에서 VDD에서 GND로의 직접 경로가 없으므로 정적 전력이 본질적으로 제로입니다."

Why Both?

왜 둘 다?

  • NMOS passes strong 0 but weak 1 (VDD - Vth)
  • NMOS는 강한 0을 통과시키지만 약한 1 (VDD - Vth)
  • PMOS passes strong 1 but weak 0 (|Vth|)
  • PMOS는 강한 1을 통과시키지만 약한 0 (|Vth|)
  • Together: full-swing output (0 to VDD), no static current, high noise margins
  • 함께: 풀 스윙 출력 (0 ~ VDD), 정적 전류 없음, 높은 노이즈 마진

10e Threshold voltage and body effect 문턱 전압과 바디 효과

🚀 Elevator Pitch

"Threshold voltage (Vth) is the minimum gate-to-source voltage needed to create a conducting channel. The body effect is when Vth increases because the source-to-body voltage (VSB) is non-zero — the body acts like a second gate. This matters in stacked transistors where the source of the upper transistor isn't at ground."

"문턱 전압 (Vth)은 전도 채널을 만드는 데 필요한 최소 게이트-소스 전압입니다. 바디 효과는 소스-바디 전압 (VSB)이 0이 아닐 때 Vth가 증가하는 현상입니다."

Body Effect Equation

바디 효과 방정식

Vth = Vth0 + γ(√(2φf + VSB) - √(2φf))

Where γ = body effect coefficient, φf = Fermi potential, VSB = source-body voltage.

여기서 γ = 바디 효과 계수, φf = 페르미 전위, VSB = 소스-바디 전압.

Practical impact: In a stack of NMOS (like a NAND gate), the bottom transistor has VSB = 0 but the upper transistor has VSB > 0, so its Vth is higher → it's slower. This is why long NMOS stacks are avoided.

11a What is channel length modulation? 채널 길이 변조란?

🚀 Elevator Pitch

"In saturation, the channel is supposed to be pinched off, and current should be constant regardless of VDS. But in reality, increasing VDS pushes the pinch-off point closer to the source, effectively shortening the channel. Shorter channel → more current. This is modeled by the (1 + λVDS) factor in the saturation equation. λ is inversely proportional to channel length — short channels have worse CLM."

"포화에서 채널이 핀치오프되어 전류가 VDS에 관계없이 일정해야 합니다. 그러나 실제로 VDS 증가는 핀치오프 지점을 소스 쪽으로 밀어 채널을 효과적으로 단축합니다. 이는 (1 + λVDS) 인자로 모델링됩니다."

💡 Why It Matters

💡 왜 중요한가

CLM means the output resistance of a MOSFET in saturation is finite (ro = 1/λID), not infinite. This limits amplifier gain. For analog design, long channels are used to minimize λ. For digital, it means the I-V curves aren't perfectly flat in saturation.

CLM은 포화 상태에서 MOSFET의 출력 저항이 무한이 아닌 유한함을 의미합니다 (ro = 1/λID). 아날로그 설계에서는 λ를 최소화하기 위해 긴 채널을 사용합니다.

11b What is charge sharing? 전하 공유란?

🚀 Elevator Pitch

"Charge sharing happens in dynamic logic and DRAM when a precharged node connects to an uncharged (or differently charged) parasitic capacitance through a transistor. The charge redistributes between the two capacitors, causing the precharged node's voltage to drop unexpectedly. If it drops below the threshold, you get a wrong logic value."

"전하 공유는 동적 논리와 DRAM에서 프리차지된 노드가 트랜지스터를 통해 충전되지 않은 기생 커패시턴스에 연결될 때 발생합니다. 전하가 재분배되어 프리차지된 노드의 전압이 예기치 않게 하락합니다."

Fix: Add precharge transistors to internal nodes, or use keeper transistors

해결: 내부 노드에 프리차지 트랜지스터 추가, 또는 키퍼 트랜지스터 사용

🚀 Elevator Pitch

"Electromigration is the physical movement of metal atoms in interconnect wires due to momentum transfer from high-density current flow. 12a Three basic types of capacitors in CMOS design CMOS 설계의 세 가지 기본 커패시터 유형

The Three Capacitors

세 가지 커패시터

  1. Gate capacitance (Cgate / Cox) — Formed between the gate electrode and the channel (thin oxide dielectric). This is the "intentional" capacitance that controls the transistor. Cox = εox·A/tox
  2. 게이트 커패시턴스 (Cgate / Cox) — 게이트 전극과 채널 사이에 형성 (얇은 산화물 유전체). 트랜지스터를 제어하는 "의도적" 커패시턴스.
  3. Diffusion/Junction capacitance (Cj) — PN junction capacitance at source/drain to substrate. Voltage-dependent (reverse-biased junction). This is parasitic.
  4. 확산/접합 커패시턴스 (Cj) — 소스/드레인에서 기판으로의 PN 접합 커패시턴스. 전압 의존적 (역바이어스 접합). 기생 성분.
  5. Overlap/Fringing capacitance (Cov) — Gate-to-source and gate-to-drain overlap where the gate extends over the source/drain diffusion regions. Also includes fringing fields.
  6. 오버랩/프린징 커패시턴스 (Cov) — 게이트가 소스/드레인 확산 영역 위로 확장되는 게이트-소스, 게이트-드레인 오버랩.

12b List in order of consideration 고려 순서로 나열

Order of Importance (Largest Impact First)

중요도 순서 (가장 큰 영향 먼저)

  1. Gate capacitance (Cox) — Dominates; it's what you drive when switching. Determines dynamic power and speed.
  2. 게이트 커패시턴스 (Cox) — 지배적; 스위칭 시 구동하는 것. 동적 전력과 속도 결정.
  3. Diffusion capacitance (Cj) — Second; significant in deep submicron. Contributes to load on driving gate.
  4. 확산 커패시턴스 (Cj) — 두 번째; 딥 서브미크론에서 중요. 구동 게이트의 부하에 기여.
  5. Overlap capacitance (Cov) — Third; causes Miller effect (Cgd is multiplied by gain), significant in high-speed design.
  6. 오버랩 커패시턴스 (Cov) — 세 번째; 밀러 효과 유발 (Cgd가 이득으로 곱해짐), 고속 설계에서 중요.

In modern nodes, wire capacitance (Cwire) also dominates — often larger than device capacitance!

현대 노드에서는 와이어 커패시턴스 (Cwire)도 지배적 — 종종 디바이스 커패시턴스보다 큼!

12c What is latch-up, and how can it be eliminated? 래치업이란, 어떻게 제거할 수 있나요?

🚀 Elevator Pitch

"Latch-up is a parasitic SCR (thyristor) triggering in CMOS. The PNPN structure formed by the p-substrate, n-well, p-diffusion, and n-diffusion creates two parasitic BJTs that form a positive feedback loop. Once triggered (by noise, ESD, or going below GND / above VDD), it creates a low-impedance path from VDD to GND — essentially a short circuit that draws massive current and can destroy the chip."

"래치업은 CMOS에서 기생 SCR(사이리스터) 트리거링입니다. p-기판, n-웰, p-확산, n-확산으로 형성된 PNPN 구조가 양성 피드백 루프를 형성하는 두 개의 기생 BJT를 만듭니다. 트리거되면 VDD에서 GND로의 저임피던스 경로를 만들어 칩을 파괴할 수 있습니다."

Prevention Methods

예방 방법

  1. Guard rings — N+ ring around NMOS (tied to GND), P+ ring around PMOS (tied to VDD) to collect minority carriers
  2. 가드 링 — NMOS 주위 N+ 링 (GND 연결), PMOS 주위 P+ 링 (VDD 연결)
  3. Increase well/substrate contacts — reduce parasitic resistance (Rwell, Rsub), making it harder to forward-bias the parasitic BJTs
  4. 웰/기판 접촉 증가 — 기생 저항 감소, 기생 BJT의 순방향 바이어스를 어렵게 함
  5. Increase spacing between NMOS and PMOS
  6. NMOS와 PMOS 사이 간격 증가
  7. Use epitaxial (EPI) substrate — low-resistance substrate shunts parasitic current
  8. 에피택셜 (EPI) 기판 사용 — 저저항 기판이 기생 전류를 분로
  9. SOI (Silicon on Insulator) — eliminates the PNPN structure entirely
  10. SOI (실리콘 온 인슐레이터) — PNPN 구조를 완전히 제거

🧠 "LATCH-up prevention: Layout guards, Add contacts, Thick spacing, Choose EPI/SOI, Handle I/O carefully"

🧠 "래치업 예방: 가드링, 접촉 추가, 간격 확대, EPI/SOI 선택, I/O 주의"

13c How to design a divide-by-3 counter with equal duty cycle? 균등 듀티 사이클의 3분주 카운터 설계 방법?

🚀 Elevator Pitch

"A simple mod-3 counter gives you divide-by-3 but with 33%/67% duty cycle. For 50% duty cycle, the trick is: use two counters — one triggered on posedge, one on negedge — both counting mod-3. Then OR their outputs. Each produces a pulse of 1 clock cycle out of 3, but offset by half a cycle. ORing them gives a symmetric waveform."

"간단한 mod-3 카운터는 3분주를 제공하지만 33%/67% 듀티 사이클입니다. 50% 듀티 사이클을 위해: 두 개의 카운터 사용 — 하나는 posedge, 하나는 negedge 트리거 — 둘 다 mod-3 카운팅. 그런 다음 출력을 OR합니다."

// Divide-by-3 with 50% duty cycle
reg [1:0] cnt_pos, cnt_neg;
wire out_pos, out_neg, clk_div3;

// Posedge counter
always @(posedge clk or posedge rst)
  if (rst) cnt_pos <= 0;
  else     cnt_pos <= (cnt_pos == 2) ? 0 : cnt_pos + 1;

// Negedge counter
always @(negedge clk or posedge rst)
  if (rst) cnt_neg <= 0;
  else     cnt_neg <= (cnt_neg == 2) ? 0 : cnt_neg + 1;

assign out_pos = (cnt_pos == 0);
assign out_neg = (cnt_neg == 0);
assign clk_div3 = out_pos | out_neg;

⚠️ Interview Note

Some interviewers want a different approach: a mod-3 Johnson counter (2-bit ring with feedback). Either approach works — the key insight is that you need both clock edges to get 50% duty cycle from an odd divider.

일부 면접관은 다른 접근을 원합니다: mod-3 존슨 카운터 (피드백이 있는 2비트 링). 핵심은 홀수 분주에서 50% 듀티 사이클을 얻으려면 양쪽 클록 에지가 필요하다는 것입니다.

14b Parallel to Serial conversion from the counter register 카운터 레지스터에서 병렬-직렬 변환 

// Parallel-to-Serial converter using shift register
module par_to_ser (
    input        clk, rst, load,
    input  [4:0] par_in,    // 5-bit parallel from counter
    output       ser_out,
    output reg   done
);
    reg [4:0] shift_reg;
    reg [2:0] bit_cnt;

    assign ser_out = shift_reg[4];  // MSB first

    always @(posedge clk or posedge rst) begin
        if (rst) begin
            shift_reg <= 5'b0;
            bit_cnt   <= 0;
            done      <= 0;
        end else if (load) begin
            shift_reg <= par_in;
            bit_cnt   <= 0;
            done      <= 0;
        end else if (bit_cnt < 5) begin
            shift_reg <= {shift_reg[3:0], 1'b0};  // Shift left
            bit_cnt   <= bit_cnt + 1;
            done      <= (bit_cnt == 4);
        end
    end
endmodule

💡 Key Concept

💡 핵심 개념

Parallel-to-serial = load all bits at once, shift out one per clock. The shift register is the fundamental building block. MSB-first or LSB-first depends on which end you tap. Always clarify with the interviewer which bit order they want.

병렬-직렬 = 모든 비트를 한 번에 로드, 클록당 하나씩 시프트 아웃. 시프트 레지스터가 기본 빌딩 블록입니다.

14c Design a sequence detect circuit (count 25) 시퀀스 검출 회로 설계 (25 카운트)

🚀 Elevator Pitch

"A sequence detector that counts to 25 is essentially a counter that asserts an output when count reaches 25. This can be done with a simple 5-bit counter (since 2⁵ = 32 > 25) and a comparator."

"25까지 카운트하는 시퀀스 검출기는 카운트가 25에 도달하면 출력을 표명하는 카운터입니다."

// Detect when count reaches 25
module count_detect_25 (
    input            clk, rst,
    output reg       detect,
    output reg [4:0] count
);
    always @(posedge clk or posedge rst) begin
        if (rst) begin
            count  <= 5'b0;
            detect <= 1'b0;
        end else begin
            if (count == 5'd24) begin
                count  <= 5'b0;       // Reset after reaching 25
                detect <= 1'b1;      // Assert detect
            end else begin
                count  <= count + 1;
                detect <= 1'b0;
            end
        end
    end
endmodule

💡 Note

💡 참고

We compare against 24 (not 25) because counting starts from 0. Count 0→24 = 25 counts. The detect pulse is one clock cycle wide. If overlapping detection is needed (e.g., detect "25" in a serial bitstream), you'd use an FSM-based approach instead.

"An ideal clock arrives at all flip-flops at exactly the same time — zero skew, zero latency. It's a simplification used during synthesis. A propagated clock models the actual clock tree — with real insertion delay, skew between endpoints, and jitter. Propagated clock reports show different arrival times at different FFs, which can help or hurt timing (useful skew vs harmful skew)."

"이상 클록은 모든 플립플롭에 정확히 같은 시간에 도착합니다 — 스큐 제로, 레이턴시 제로. 합성 중 사용되는 단순화입니다. 전파 클록은 실제 클록 트리를 모델링합니다 — 실제 삽입 지연, 스큐, 지터 포함."

16c What is time borrowing related to STA in PrimeTime? PrimeTime에서 STA와 관련된 타임 보로잉이란?

🚀 Elevator Pitch

"Time borrowing is a technique used with latch-based designs (not flip-flop) where a latch can 'borrow' time from the next clock phase. Since a latch is transparent when its enable is active, if data arrives late, it can still pass through — effectively stealing time from the next stage's computation window. This allows one stage to exceed its clock period budget as long as the next stage has slack to spare."

"타임 보로잉은 래치 기반 설계에서 래치가 다음 클록 위상에서 시간을 '빌릴' 수 있는 기법입니다. 래치는 인에이블이 활성일 때 투명하므로 데이터가 늦게 도착해도 통과할 수 있습니다 — 다음 단계에 여유가 있는 한."

How It Works

작동 원리

  • Flip-flops: Data MUST arrive before the clock edge. Period. No borrowing possible.
  • 플립플롭: 데이터가 클록 에지 전에 반드시 도착해야 합니다. 보로잉 불가능.
  • Latches: Data can arrive anytime during the transparent phase. If it arrives late (past the ideal capture point), it "borrows" time from the next stage.
  • 래치: 투명 위상 중 언제든 데이터 도착 가능. 늦게 도착하면 다음 단계에서 시간을 "빌림".
  • Limit: You can only borrow up to the latch's transparent window minus setup time.
  • 한계: 래치의 투명 윈도우에서 셋업 타임을 뺀 만큼만 빌릴 수 있습니다.

PrimeTime automatically calculates time borrowing when it encounters latches. It reports how much time was borrowed and whether the next stage can tolerate it.

PrimeTime은 래치를 만나면 자동으로 타임 보로잉을 계산합니다.

💡 Why It Matters

💡 왜 중요한가

Time borrowing is one of the main reasons high-performance processors use latches instead of flip-flops in critical paths. It naturally balances the timing across pipeline stages. Intel and ARM have used latch-based designs extensively.

타임 보로잉은 고성능 프로세서가 크리티컬 패스에서 래치를 사용하는 주요 이유 중 하나입니다.

🔄 Common Follow-ups

🔄 예상 후속 질문

  • "What's the downside of time borrowing?" → More complex STA, harder to debug timing, can cascade — if one stage borrows too much, it creates a chain reaction.
  • "타임 보로잉의 단점은?" → 더 복잡한 STA, 타이밍 디버깅 어려움, 연쇄 반응 가능.
  • "Difference between time borrowing and useful skew?" → Time borrowing is inherent to latches (automatic). Useful skew is intentionally adjusting clock arrival times at flip-flops (manual/CTS).
  • "타임 보로잉과 유용한 스큐의 차이?" → 타임 보로잉은 래치에 고유(자동). 유용한 스큐는 FF에서 의도적으로 클록 도착 시간 조정(수동/CTS).
