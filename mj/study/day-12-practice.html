Exercise 2: Clock Skew Impact

Same path as Exercise 1, but now the capture clock (FF_B) arrives 0.15ns early. What's the new hold slack?

연습 1과 같은 경로지만, 캡처 클럭(FF_B)이 0.15ns 일찍 도착합니다. 새로운 홀드 슬랙은?

ParameterValue
t_clk2q (FF_A)0.15 ns
t_comb0.08 ns
t_hold (FF_B)0.10 ns
Clock skew0.15 ns (capture early)

Hold slack = ns

홀드 슬랙 = ns

Hold slack = (t_clk2q + t_comb) - (t_hold + t_skew) = (0.15 + 0.08) - (0.10 + 0.15) = 0.23 - 0.25 = -0.02 ns ❌

홀드 슬랙 = (t_clk2q + t_comb) - (t_hold + t_skew) = (0.15 + 0.08) - (0.10 + 0.15) = 0.23 - 0.25 = -0.02 ns ❌

Negative slack → HOLD VIOLATION! The clock skew turned a passing path into a failing one. A delay buffer of at least 0.02ns must be inserted.

음의 슬랙 → 홀드 위반! 클럭 스큐가 통과 경로를 실패 경로로 바꿨습니다. 최소 0.02ns의 지연 버퍼를 삽입해야 합니다.

Exercise 3: Identify the Problem

Look at this SystemVerilog code. Which paths are most at risk for hold violations and why?

이 SystemVerilog 코드를 보세요. 홀드 위반 위험이 가장 높은 경로는 어디이며 그 이유는?

module shift_register (
    input  logic       clk, rst_n,
    input  logic       d_in,
    output logic [3:0] q
);
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            q <= 4'b0;
        end else begin
            q[0] <= d_in;       // Path A: d_in → q[0]
            q[1] <= q[0];        // Path B: q[0] → q[1]
            q[2] <= q[1];        // Path C: q[1] → q[2]
            q[3] <= q[2];        // Path D: q[2] → q[3]
        end
    end
endmodule

Paths B, C, and D are all at risk for hold violations!

경로 B, C, D 모두 홀드 위반 위험이 있습니다!

Each is a direct flip-flop to flip-flop connection with zero combinational logic in between. The data path delay is just t_clk2q (no t_comb). If there's any clock skew between the source and destination FFs, hold violations are very likely.

각각은 중간에 조합 로직이 없는 플립플롭 간 직접 연결입니다. 데이터 경로 지연은 t_clk2q뿐입니다 (t_comb 없음). 소스와 목적지 FF 사이에 클럭 스큐가 있으면 홀드 위반이 매우 발생하기 쉽습니다.

Shift registers are classic hold-violation hotspots! The P&R tool will automatically insert delay buffers on these paths. This is why shift registers are commonly mentioned in timing closure discussions.

시프트 레지스터는 전형적인 홀드 위반 핫스팟입니다! P&R 도구가 이 경로에 자동으로 지연 버퍼를 삽입합니다. 이것이 시프트 레지스터가 타이밍 클로저 논의에서 자주 언급되는 이유입니다.

Exercise 5: Fix the Hold Violation

You have a hold violation with slack = -0.08ns. Each delay buffer adds 0.03ns of delay. How many buffers do you need to insert?

홀드 슬랙이 -0.08ns인 위반이 있습니다. 각 지연 버퍼는 0.03ns의 지연을 추가합니다. 몇 개의 버퍼를 삽입해야 하나요?

Number of buffers needed:

필요한 버퍼 수:

3 buffers needed.

3개의 버퍼가 필요합니다.

Need to add at least 0.08ns of delay. Each buffer = 0.03ns.
• 2 buffers = 0.06ns → still -0.02ns slack ❌
• 3 buffers = 0.09ns → now +0.01ns slack ✅
Always round UP — you need to fully cover the violation.

최소 0.08ns의 지연을 추가해야 합니다. 각 버퍼 = 0.03ns.
• 2개 버퍼 = 0.06ns → 여전히 -0.02ns 슬랙 ❌
• 3개 버퍼 = 0.09ns → 이제 +0.01ns 슬랙 ✅
항상 올림하세요 — 위반을 완전히 커버해야 합니다.
