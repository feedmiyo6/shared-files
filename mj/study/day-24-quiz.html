Q1. What is backpressure in a pipeline?

파이프라인에서 백프레셔란 무엇인가요?

  • A) A technique to increase clock frequency
  • B) A flow control mechanism where downstream signals upstream to stop sending data
  • C) A method to add more pipeline stages
  • D) A way to bypass pipeline registers

✅ B) Backpressure is when a downstream consumer tells the upstream producer: "I'm not ready, hold your data." This prevents data loss when the consumer is slower than the producer.

✅ B) 백프레셔는 다운스트림 소비자가 업스트림 생산자에게 "준비 안 됐으니 데이터를 보류해"라고 알려주는 것입니다. 소비자가 생산자보다 느릴 때 데이터 손실을 방지합니다.

Q2. How does a stall signal work in a pipeline register?

파이프라인 레지스터에서 스톨 신호는 어떻게 작동하나요?

  • A) It clears the register to zero
  • B) It inverts the stored data
  • C) It acts as a clock enable — when asserted, the register holds its current value
  • D) It doubles the clock frequency for that stage

✅ C) The stall signal disables the register update. Code pattern: if (!stall) data_out <= data_in; — when stalled, the register simply doesn't change, preserving its current data.

✅ C) 스톨 신호는 레지스터 업데이트를 비활성화합니다. 코드 패턴: if (!stall) data_out <= data_in; — 스톨 시 레지스터는 변경되지 않고 현재 데이터를 보존합니다.

Q3. In which direction do stall signals propagate?

스톨 신호는 어느 방향으로 전파되나요?

  • A) Forward (upstream → downstream)
  • B) Backward (downstream → upstream)
  • C) Both directions simultaneously
  • D) They don't propagate — each stage handles stalls independently

✅ B) Stalls propagate backward. If Stage 4 can't accept data, Stage 3 must stall (can't push into a frozen stage), then Stage 2, then Stage 1. The stall ripples upstream.

✅ B) 스톨은 역방향으로 전파됩니다. 스테이지 4가 데이터를 받을 수 없으면, 스테이지 3이 스톨되고, 그 다음 2, 1 순서로 스톨이 상류로 물결칩니다.

Q4. What is a pipeline bubble?

파이프라인 버블이란 무엇인가요?

  • A) A hardware buffer that stores overflow data
  • B) An invalid (NOP) slot inserted into the pipeline
  • C) A clock gating technique
  • D) An error condition that crashes the pipeline

✅ B) A bubble is a slot with valid = 0 that flows through the pipeline. Downstream stages see it and skip processing. It's essentially a NOP that takes up one cycle.

✅ B) 버블은 valid = 0인 슬롯으로 파이프라인을 통해 흐릅니다. 다운스트림 스테이지는 이를 보고 처리를 건너뜁니다. 본질적으로 한 사이클을 차지하는 NOP입니다.

Q5. In which direction do bubbles flow?

버블은 어느 방향으로 흐르나요?

  • A) Forward (same direction as data)
  • B) Backward (opposite to data flow)
  • C) They stay in the stage where they were created
  • D) Both directions

✅ A) Bubbles flow forward through the pipeline, just like valid data. They are inserted at a specific stage and propagate downstream, creating a gap in the data flow.

✅ A) 버블은 유효한 데이터처럼 파이프라인을 순방향으로 흐릅니다. 특정 스테이지에서 삽입되어 다운스트림으로 전파되며 데이터 흐름에 갭을 만듭니다.

Q6. What happens if you insert a bubble into a stage that is also stalled?

스톨된 스테이지에 버블을 삽입하면 어떻게 되나요?

  • A) The bubble is queued for later
  • B) Nothing — the stall takes priority
  • C) Data loss — the valid data being held is destroyed
  • D) The pipeline automatically resolves the conflict

✅ C) This is a critical bug! If a stage is stalled (holding valid data) and you squash it with a bubble, the valid data is overwritten with invalid. The fix: bubble = hazard & !stall — never bubble a stalled stage.

✅ C) 이것은 치명적인 버그입니다! 스테이지가 스톨되어(유효한 데이터 보유) 버블로 스쿼시하면 유효한 데이터가 무효로 덮어써집니다. 수정: bubble = hazard & !stall — 스톨된 스테이지에는 절대 버블을 넣지 마세요.

Q7. Given a pipeline that stalls 25% of cycles, what is the effective throughput?

25% 사이클 동안 스톨되는 파이프라인의 유효 처리량은?

  • A) 25%
  • B) 75%
  • C) 80%
  • D) 100%

✅ C) Effective throughput = 1 / (1 + stall_rate) = 1 / 1.25 = 80%. If your pipeline runs at 1 GHz, you get 800M operations/sec instead of 1G.

✅ C) 유효 처리량 = 1 / (1 + 스톨률) = 1 / 1.25 = 80%. 1 GHz 파이프라인이면 1G 대신 800M 연산/초입니다.

Q8. What is a skid buffer?

스키드 버퍼란 무엇인가요?

  • A) A large FIFO between pipeline stages
  • B) A small (1-entry) buffer that absorbs a stall cycle, breaking the combinational stall chain
  • C) A bypass path that skips pipeline stages
  • D) A technique to merge multiple bubbles into one

✅ B) A skid buffer is a 1-entry register that catches data when downstream stalls. Instead of instantly stalling upstream, it "absorbs" one cycle. This breaks the combinational stall chain that can become a critical timing path.

✅ B) 스키드 버퍼는 다운스트림이 스톨될 때 데이터를 잡는 1-엔트리 레지스터입니다. 상류를 즉시 스톨하는 대신 한 사이클을 "흡수"합니다. 크리티컬 타이밍 경로가 될 수 있는 조합 스톨 체인을 끊습니다.

Q9. When should you use a stall vs. a bubble?

스톨 vs 버블은 언제 사용해야 하나요?

  • A) Stall for hazards, bubble for memory delays
  • B) Stall when downstream isn't ready (freeze everything); bubble when you need a gap for hazard resolution (downstream keeps moving)
  • C) They're interchangeable — use whichever is simpler
  • D) Always use bubbles — stalls are deprecated

✅ B) Stall = "stop the whole pipeline, downstream can't accept." Bubble = "insert a gap, downstream keeps flowing." Stalls freeze upstream; bubbles flow downstream. Different tools for different problems.

✅ B) 스톨 = "전체 파이프라인 정지, 다운스트림이 받을 수 없음." 버블 = "갭 삽입, 다운스트림은 계속 흐름." 스톨은 상류를 동결; 버블은 하류로 흐릅니다. 다른 문제에 다른 도구입니다.

Q10. Why is a combinational stall chain a timing problem?

조합 스톨 체인이 타이밍 문제인 이유는?

assign stall_3 = stall_4;
assign stall_2 = stall_3;
assign stall_1 = stall_2;
  • A) It uses too many flip-flops
  • B) It creates a long combinational path from Stage 4 back to Stage 1 that must settle in one clock cycle
  • C) It causes metastability
  • D) It wastes power due to clock gating

✅ B) These are all assign statements — pure combinational logic. A stall at Stage 4 must propagate through Stage 3 → 2 → 1 all within one clock cycle. In a deep pipeline (10+ stages), this combinational chain becomes the critical path. Skid buffers fix this by registering the stall signal.

✅ B) 이것들은 모두 assign 문 — 순수 조합 로직입니다. 스테이지 4의 스톨이 3 → 2 → 1을 한 클럭 사이클 내에 통과해야 합니다. 깊은 파이프라인(10+ 스테이지)에서 이 조합 체인이 크리티컬 패스가 됩니다. 스키드 버퍼는 스톨 신호를 레지스터하여 이를 해결합니다.

Q11. In this pipeline controller, what does bubble_exec do?

assign stall_decode = mem_busy | data_hazard;
assign stall_fetch  = mem_busy | data_hazard;
assign bubble_exec  = data_hazard & !mem_busy;
  • A) Stalls the execute stage
  • B) Inserts an invalid slot into the execute stage while fetch/decode are stalled
  • C) Flushes the entire pipeline
  • D) Forwards data from writeback to execute

✅ B) When there's a data hazard (but no memory stall), fetch and decode freeze in place, while a bubble (valid=0) is pushed into execute. This creates a 1-cycle gap so the hazard resolves. Note: it's gated by !mem_busy to prevent bubbling during a memory stall.

✅ B) 데이터 해저드가 있을 때(메모리 스톨 아닌), 페치와 디코드는 제자리에서 동결되고 버블(valid=0)이 실행 스테이지에 삽입됩니다. 해저드가 해결되도록 1사이클 갭을 만듭니다. !mem_busy로 게이팅하여 메모리 스톨 중 버블 삽입을 방지합니다.

Q12. In the skid buffer design, when is up_ready deasserted?

스키드 버퍼 설계에서 up_ready는 언제 디어서트되나요?

  • A) When downstream is not ready
  • B) When the internal buffer is full (buf_valid = 1)
  • C) When reset is asserted
  • D) When upstream has no valid data

✅ B) up_ready = !buf_valid. The skid buffer can accept one item even when downstream stalls. Once that buffer slot is full, it must tell upstream to stop. This is what "breaks" the stall chain — upstream gets one extra cycle before it sees the stall.

✅ B) up_ready = !buf_valid. 스키드 버퍼는 다운스트림이 스톨되어도 한 항목을 받을 수 있습니다. 버퍼 슬롯이 차면 상류에 멈추라고 해야 합니다. 이것이 스톨 체인을 "끊는" 것 — 상류가 스톨을 보기 전에 한 사이클의 여유를 줍니다.
