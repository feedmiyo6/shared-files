📘 Day 7: Moore vs Mealy Machines

Yesterday you learned FSM fundamentals — states, transitions, and how to code them. Today we dive into the two types of FSMs: Moore and Mealy. Understanding when to use each is a key interview topic and essential for real design work.

어제 FSM의 기본을 배웠습니다. 오늘은 FSM의 두 가지 유형인 Moore와 Mealy를 깊이 다룹니다. 각각 언제 사용하는지 아는 것은 면접에서 자주 나오는 핵심 주제입니다.

1. The Core Difference

🔑 One Sentence Summary

Moore: Output depends ONLY on the current state.
Mealy: Output depends on the current state AND current inputs.

Moore: 출력은 현재 상태에만 의존합니다.
Mealy: 출력은 현재 상태와 현재 입력 모두에 의존합니다.

This single difference has big implications for timing, latency, and how many states you need.

이 하나의 차이가 타이밍, 지연 시간, 필요한 상태 수에 큰 영향을 줍니다.

Moore Machine

2. Moore Machine: Outputs from State Only

In a Moore machine, each state has a fixed output. The output changes only when the state changes — which means on the next clock edge. This makes Moore outputs synchronous and glitch-free.

Moore 머신에서는 각 상태가 고정된 출력을 가집니다. 출력은 상태가 변할 때만 바뀌므로, 다음 클럭 에지에서만 변합니다. Moore 출력은 동기적이고 글리치가 없습니다.

Example: Simple Detector (Moore)

Let's design a sequence detector that outputs 1 when it sees the pattern "01" on the input. Moore version:

입력에서 "01" 패턴을 감지하면 1을 출력하는 시퀀스 감지기를 설계합니다. Moore 버전:

module moore_01_detector (
    input  logic clk, rst_n, din,
    output logic detected
);

    typedef enum logic [1:0] {
        IDLE    = 2'b00,  // Haven't seen anything useful
        SAW_0   = 2'b01,  // Saw '0', waiting for '1'
        SAW_01  = 2'b10   // Saw '01' → output HIGH
    } state_t;

    state_t state, next_state;

    // State register
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    // Next state logic
    always_comb begin
        case (state)
            IDLE:   next_state = din ? IDLE  : SAW_0;
            SAW_0:  next_state = din ? SAW_01 : SAW_0;
            SAW_01: next_state = din ? IDLE  : SAW_0;
            default: next_state = IDLE;
        endcase
    end

    // Moore output — depends ONLY on state
    assign detected = (state == SAW_01);

endmodule

💡 Key Observation

Notice the output line: detected = (state == SAW_01). No din involved! That's pure Moore — output is a function of state alone.

출력 라인을 주목하세요: detected = (state == SAW_01). din이 없습니다! 순수 Moore — 출력은 상태만의 함수입니다.

3. Mealy Machine: Outputs from State + Input

In a Mealy machine, outputs can change combinationally with the input — even within a clock cycle. This means Mealy can react one cycle faster than Moore, but the output may have glitches.

Mealy 머신에서는 출력이 입력과 함께 조합적으로 변할 수 있습니다. 클럭 사이클 내에서도 변합니다. Mealy는 Moore보다 한 사이클 빠르게 반응하지만, 출력에 글리치가 있을 수 있습니다.

Example: Same Detector (Mealy)

module mealy_01_detector (
    input  logic clk, rst_n, din,
    output logic detected
);

    typedef enum logic {
        IDLE  = 1'b0,  // Haven't seen anything useful
        SAW_0 = 1'b1   // Saw '0', waiting for '1'
    } state_t;            // Only 2 states! (vs 3 in Moore)

    state_t state, next_state;

    // State register
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    // Next state logic
    always_comb begin
        case (state)
            IDLE:  next_state = din ? IDLE  : SAW_0;
            SAW_0: next_state = din ? IDLE  : SAW_0;
            default: next_state = IDLE;
        endcase
    end

    // Mealy output — depends on state AND input
    assign detected = (state == SAW_0) && din;

endmodule

🔑 Mealy Advantage: Fewer States!

The Mealy version needs only 2 states vs Moore's 3 states. Because it can factor the input into the output, it doesn't need a separate "detection" state. The output goes high in the same cycle the '1' arrives.

Mealy 버전은 Moore의 3개 상태 대비 2개 상태만 필요합니다. 입력을 출력에 반영할 수 있으므로, 별도의 "감지" 상태가 필요 없습니다. '1'이 도착하는 같은 사이클에 출력이 올라갑니다.

⚠️ Critical Insight: The 1-Cycle Latency Difference

Mealy detects the pattern in cycle 2, but Moore doesn't output until cycle 3. This is because Moore must first enter the SAW_01 state, then output on the next cycle. Mealy outputs immediately because it combines state + input combinationally.

Mealy는 사이클 2에서 패턴을 감지하지만, Moore는 사이클 3까지 출력하지 않습니다. Moore는 먼저 SAW_01 상태에 진입한 후, 다음 사이클에서 출력해야 하기 때문입니다. Mealy는 상태 + 입력을 조합적으로 결합하므로 즉시 출력합니다.

6. Registered Mealy: Best of Both Worlds

In practice, you often want Mealy's fewer states but Moore's clean output. The solution: register the Mealy output. This adds one cycle of latency (matching Moore), but keeps the smaller state space.

실무에서는 Mealy의 적은 상태 수와 Moore의 깨끗한 출력을 모두 원합니다. 해결책: Mealy 출력을 레지스터에 등록합니다. 한 사이클의 지연이 추가되지만(Moore와 동일), 상태 공간은 작게 유지됩니다.

// Registered Mealy output — glitch-free!
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        detected_reg <= 1'b0;
    else
        detected_reg <= (state == SAW_0) && din;
end

assign detected = detected_reg;

💡 Industry Practice

Most real designs use registered Mealy or Moore. Raw (unregistered) Mealy outputs are risky because glitches can cause problems in downstream logic. When an interviewer asks "Moore or Mealy?" — mentioning registered Mealy shows deeper understanding.

대부분의 실제 설계는 레지스터드 Mealy 또는 Moore를 사용합니다. 등록되지 않은 Mealy 출력은 글리치가 하류 로직에 문제를 일으킬 수 있어 위험합니다. 면접에서 "Moore vs Mealy?"라는 질문에 레지스터드 Mealy를 언급하면 깊은 이해를 보여줍니다.

7. When to Choose Which

🏗️ Design Decision Guide

Choose Moore when:

  • Output drives other FSMs or crosses clock domains
  • You need guaranteed glitch-free outputs
  • Simplicity and safety matter more than latency
  • Output is used as a control signal (enable, reset, etc.)

Moore를 선택할 때:

  • 출력이 다른 FSM을 구동하거나 클럭 도메인을 넘을 때
  • 글리치 없는 출력이 보장되어야 할 때
  • 단순성과 안전성이 지연 시간보다 중요할 때
  • 출력이 제어 신호(enable, reset 등)로 사용될 때

Choose Mealy when:

  • Latency is critical (need same-cycle response)
  • You want to minimize state count
  • Output is consumed by registered logic anyway
  • Protocol requires immediate acknowledgment

Mealy를 선택할 때:

  • 지연 시간이 중요할 때 (같은 사이클 응답 필요)
  • 상태 수를 최소화하고 싶을 때
  • 출력이 어차피 레지스터된 로직에서 소비될 때
  • 프로토콜이 즉각적인 확인 응답을 요구할 때

8. Common Interview Question

🎯 "Can you convert between Moore and Mealy?"

Yes! Any Moore machine can be converted to Mealy (and vice versa). The key trade-off:

  • Moore → Mealy: Merge states, reduce count, but output may glitch
  • Mealy → Moore: Split states so each has unique output, adds states but cleans output

네! 모든 Moore 머신은 Mealy로 변환할 수 있고 (반대도 가능). 핵심 트레이드오프:

  • Moore → Mealy: 상태를 병합하고 수를 줄이지만, 출력에 글리치 가능
  • Mealy → Moore: 각 상태가 고유한 출력을 갖도록 분할, 상태 수 증가하지만 출력 깨끗
