Q1. What does "timing closure" mean?"타이밍 클로저"란 무엇을 의미합니까?

  • A) The design compiles without syntax errorsA) 설계가 구문 오류 없이 컴파일됨
  • B) All timing paths meet setup and hold requirementsB) 모든 타이밍 경로가 셋업 및 홀드 요구 사항을 충족
  • C) The simulation passes all test casesC) 시뮬레이션이 모든 테스트 케이스를 통과
  • D) The clock signal is properly terminatedD) 클럭 신호가 올바르게 종료됨
✅ Timing closure means every path in the design meets its setup and hold timing constraints at the target frequency.✅ 타이밍 클로저란 설계의 모든 경로가 목표 주파수에서 셋업 및 홀드 타이밍 제약을 충족하는 것을 의미합니다.

Q3. Positive slack means:양의 슬랙은 다음을 의미합니다:

  • A) The path has a timing violationA) 경로에 타이밍 위반이 있음
  • B) The path barely meets timingB) 경로가 간신히 타이밍을 충족
  • C) The path has margin — it meets timing with room to spareC) 경로에 여유가 있음 — 여유를 가지고 타이밍을 충족
  • D) The clock is too fastD) 클럭이 너무 빠름
✅ Positive slack = Required time - Arrival time > 0. The data arrives early, so there's timing margin.✅ 양의 슬랙 = 필요 시간 - 도착 시간 > 0. 데이터가 일찍 도착하므로 타이밍 여유가 있습니다.

Q4. Which SDC command excludes a path from timing analysis?타이밍 분석에서 경로를 제외하는 SDC 명령은?

  • A) set_multicycle_pathA) set_multicycle_path
  • B) set_false_pathB) set_false_path
  • C) set_disable_timingC) set_disable_timing

✅ set_false_path tells STA to ignore a path entirely — useful for async resets, CDC paths, and debug-only logic.✅ set_false_path는 STA에게 경로를 완전히 무시하도록 지시합니다 — 비동기 리셋, CDC 경로, 디버그 전용 로직에 유용합니다.

Q5. What is the PRIMARY fix for setup violations at the RTL level?RTL 수준에서 셋업 위반의 주요 수정 방법은?

  • A) Pipelining — add register stages to break long pathsA) 파이프라이닝 — 긴 경로를 나누기 위해 레지스터 단계 추가
  • B) Adding delay buffersB) 지연 버퍼 추가
  • C) Increasing clock skewC) 클럭 스큐 증가
  • D) Removing flip-flopsD) 플립플롭 제거
✅ Pipelining splits a long combinational path into shorter stages, each fitting within one clock period. It increases latency by 1 cycle per stage but allows higher frequency.✅ 파이프라이닝은 긴 조합 논리 경로를 더 짧은 단계로 분할하여 각 단계가 하나의 클럭 주기 내에 맞도록 합니다. 단계당 1사이클의 지연이 증가하지만 더 높은 주파수를 허용합니다.

Q6. When pipelining, what must you do with control signals used in later stages?파이프라이닝 시, 이후 단계에서 사용되는 제어 신호는 어떻게 해야 합니까?

  • A) Leave them connected directly — they're fast enoughA) 직접 연결한 채로 두기 — 충분히 빠름
  • B) Remove them from the designB) 설계에서 제거
  • C) Pipeline them too — delay them the same number of stagesC) 함께 파이프라인 — 같은 수의 단계만큼 지연
  • D) Convert them to asynchronous signalsD) 비동기 신호로 변환
✅ All signals used together in a pipeline stage must be aligned. If you pipeline data but not the select signal, the mux would use a select value from a different cycle — a functional bug!✅ 파이프라인 단계에서 함께 사용되는 모든 신호는 정렬되어야 합니다. 데이터는 파이프라인하면서 선택 신호는 하지 않으면, 먹스가 다른 사이클의 선택 값을 사용하게 됩니다 — 기능적 버그!

Q7. Which is NOT a valid use of set_false_path?set_false_path의 올바르지 않은 사용은?

  • A) Async reset to data registersA) 비동기 리셋에서 데이터 레지스터로
  • B) Paths between unrelated clock domainsB) 관련 없는 클럭 도메인 간의 경로
  • C) Debug-only logic not active in normal modeC) 일반 모드에서 활성화되지 않는 디버그 전용 로직
  • D) The critical path that's hard to optimizeD) 최적화하기 어려운 크리티컬 패스
✅ You can't mark a real functional path as false just because it's hard to meet timing! False paths must be structurally impossible or functionally inactive.✅ 타이밍을 충족하기 어렵다고 해서 실제 기능 경로를 거짓으로 표시할 수는 없습니다! 거짓 경로는 구조적으로 불가능하거나 기능적으로 비활성인 경로여야 합니다.

Q9. A set_multicycle_path 2 -setup constraint means:set_multicycle_path 2 -setup 제약은 다음을 의미합니다:

  • A) The path must complete in half a cycleA) 경로가 반 사이클 내에 완료되어야 함
  • B) The path is checked twice per cycleB) 경로가 사이클당 두 번 검사됨
  • C) Data has 2 clock cycles to propagate (setup check relaxed)C) 데이터가 전파되는 데 2 클럭 사이클이 있음 (셋업 체크 완화)
  • D) The clock runs at half speed on this pathD) 이 경로에서 클럭이 절반 속도로 작동
✅ Multicycle path of 2 means the capturing flip-flop doesn't sample until the 2nd clock edge, giving the combinational logic twice as long to settle.✅ 멀티사이클 경로 2는 캡처 플립플롭이 2번째 클럭 에지까지 샘플링하지 않아, 조합 논리가 안정되는 데 두 배의 시간을 준다는 의미입니다.

Q10. Hold violations are typically fixed by:홀드 위반은 일반적으로 다음으로 수정됩니다:

  • A) Removing pipeline stagesA) 파이프라인 단계 제거
  • B) Inserting delay buffers on fast pathsB) 빠른 경로에 지연 버퍼 삽입
  • C) Increasing clock frequencyC) 클럭 주파수 증가
  • D) Adding more combinational logicD) 더 많은 조합 논리 추가
✅ Hold violations occur when data changes too quickly. Inserting delay buffers slows the data path so it remains stable long enough after the clock edge.✅ 홀드 위반은 데이터가 너무 빨리 변할 때 발생합니다. 지연 버퍼를 삽입하면 데이터 경로가 느려져 클럭 에지 후 충분히 오래 안정 상태를 유지합니다.

Q11. What is the correct order of the timing closure flow?타이밍 클로저 흐름의 올바른 순서는?

  • A) RTL → SDC → Synthesis → STA → Fix → RepeatA) RTL → SDC → 합성 → STA → 수정 → 반복
  • B) STA → RTL → SDC → Fix → SynthesisB) STA → RTL → SDC → 수정 → 합성
  • C) SDC → STA → RTL → Synthesis → FixC) SDC → STA → RTL → 합성 → 수정
  • D) Synthesis → RTL → Fix → SDC → STAD) 합성 → RTL → 수정 → SDC → STA
✅ Write RTL first, define constraints (SDC), synthesize to gates, run STA to find violations, fix them, and iterate.✅ 먼저 RTL을 작성하고, 제약 조건(SDC)을 정의하고, 게이트로 합성하고, STA를 실행하여 위반을 찾고, 수정한 후 반복합니다.

Q12. When should reducing clock frequency be considered?클럭 주파수 감소는 언제 고려해야 합니까?

  • A) As the first optimization attemptA) 첫 번째 최적화 시도로
  • B) Before trying pipeliningB) 파이프라이닝을 시도하기 전에
  • C) Whenever there's negative slackC) 음의 슬랙이 있을 때마다
  • D) As a last resort after other techniques failD) 다른 기법이 실패한 후 최후의 수단으로
✅ Reducing frequency means lower performance. Try false paths, multicycle paths, logic restructuring, and pipelining first. Frequency reduction is the last resort.✅ 주파수 감소는 성능 저하를 의미합니다. 먼저 거짓 경로, 멀티사이클 경로, 로직 구조 변경, 파이프라이닝을 시도하세요. 주파수 감소는 최후의 수단입니다.
