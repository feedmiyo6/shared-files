FIFO Design Part 1 — Quiz FIFO 설계 Part 1 — 퀴즈

1 What does FIFO stand for? FIFO는 무엇의 약자인가?
A. Fast Input, Fast Output
B. First In, First Out
C. First In, Final Out
D. Forward Input, Forward Output
Answer: B 정답: B

FIFO = First In, First Out. The first data written is the first data read.

FIFO = First In, First Out(선입선출). 처음 쓴 데이터가 처음 읽힙니다.

2 What is the primary purpose of a FIFO in digital design? 디지털 설계에서 FIFO의 주요 목적은 무엇인가?
A. To sort data in ascending order
B. To buffer data between components with different speeds
C. To compress data for storage
D. To encrypt data for security
Answer: B 정답: B

FIFOs buffer data between components operating at different rates or in different clock domains.

FIFO는 서로 다른 속도로 작동하거나 다른 클럭 도메인에 있는 컴포넌트 사이에서 데이터를 버퍼링합니다.

3 What does the write pointer (wr_ptr) point to? 쓰기 포인터(wr_ptr)는 무엇을 가리키는가?
A. The last location that was written
B. The next location where data will be written
C. The last location that was read
D. The middle of the FIFO
Answer: B 정답: B

The write pointer points to the next location where data will be written.

쓰기 포인터는 데이터가 쓰여질 다음 위치를 가리킵니다.

4 In a FIFO with DEPTH=16, what happens when a 4-bit pointer with value 15 is incremented? DEPTH=16인 FIFO에서 값이 15인 4비트 포인터가 증가하면 어떻게 되는가?
A. It stays at 15 (saturates)
B. It becomes 16
C. It wraps to 0
D. It causes an overflow error
Answer: C 정답: C

Due to overflow, 15 + 1 = 0 for a 4-bit value. This gives us automatic wrapping!

오버플로우로 인해 4비트 값에 대해 15 + 1 = 0이 됩니다. 이것이 자동 래핑입니다!

5 What is the condition for an empty FIFO? 빈 FIFO의 조건은 무엇인가?
A. wr_ptr > rd_ptr
B. wr_ptr < rd_ptr
C. wr_ptr == rd_ptr
D. wr_ptr == rd_ptr - 1
Answer: C 정답: C

When wr_ptr equals rd_ptr, the FIFO is empty — everything written has been read.

wr_ptr가 rd_ptr와 같을 때 FIFO는 비어 있습니다 — 쓴 모든 것이 읽혔습니다.

6 For a FIFO with DEPTH=8 (3-bit pointers), if wr_ptr=5 and rd_ptr=2, how many items are in the FIFO? DEPTH=8(3비트 포인터)인 FIFO에서 wr_ptr=5, rd_ptr=2일 때 FIFO에 몇 개의 항목이 있는가?
A. 2
B. 3
C. 5
D. 7
Answer: B 정답: B

Items in FIFO = wr_ptr - rd_ptr = 5 - 2 = 3 items (at locations 2, 3, and 4).

FIFO의 항목 = wr_ptr - rd_ptr = 5 - 2 = 3개(위치 2, 3, 4에 있음).

7 Which of these is a valid use case for a FIFO? FIFO의 유효한 사용 사례는 무엇인가?
A. Clock domain crossing
B. Rate matching between producer and consumer
C. Absorbing data bursts
D. All of the above
Answer: D 정답: D

All are valid use cases: CDC, rate matching, and burst handling.

모두 유효한 사용 사례입니다: CDC, 속도 매칭, 버스트 처리.

8 In the simple FIFO design, why does the full condition waste one location? 간단한 FIFO 설계에서 full 조건이 왜 하나의 위치를 낭비하는가?
A. To store parity information
B. To distinguish full from empty (both can't use wr_ptr == rd_ptr)
C. For error correction
D. It's a hardware limitation
Answer: B 정답: B

We need different conditions for full and empty. If both used wr_ptr == rd_ptr, we couldn't tell them apart!

full과 empty에 대해 다른 조건이 필요합니다. 둘 다 wr_ptr == rd_ptr를 사용하면 구분할 수 없습니다!

9 What type of always block should be used for pointer updates? 포인터 업데이트에 어떤 유형의 always 블록을 사용해야 하는가?
A. always_comb
B. always_latch
C. always_ff @(posedge clk)
D. always @(*)
Answer: C 정답: C

Pointers are sequential logic — they need flip-flops, so use always_ff.

포인터는 순차 논리입니다 — 플립플롭이 필요하므로 always_ff를 사용합니다.

10 If a FIFO has DEPTH=4 and we perform: write(A), write(B), read(), write(C), what is the state? FIFO의 DEPTH=4이고 write(A), write(B), read(), write(C)를 수행하면 상태는 어떻게 되는가?
A. wr_ptr=2, rd_ptr=1, contains [B, C]
B. wr_ptr=3, rd_ptr=1, contains [B, C]
C. wr_ptr=3, rd_ptr=0, contains [A, B, C]
D. wr_ptr=2, rd_ptr=0, contains [A, B]
Answer: B 정답: B

After writes: wr_ptr=2. After read: rd_ptr=1 (A was read). After write C: wr_ptr=3. Contains B at [1] and C at [2].

쓰기 후: wr_ptr=2. 읽기 후: rd_ptr=1(A가 읽혔음). C 쓴 후: wr_ptr=3. [1]에 B와 [2]에 C가 있음.

11 What happens if you read from an empty FIFO? 빈 FIFO에서 읽으면 어떻게 되는가?
A. Returns the last valid data
B. Returns random data
C. Underflow condition — should be prevented by checking empty flag
D. The FIFO automatically refills
Answer: C 정답: C

Reading from empty is an underflow. Good designs check the empty flag before reading.

비어 있는 곳에서 읽는 것은 언더플로우입니다. 좋은 설계는 읽기 전에 empty 플래그를 확인합니다.

12 For a synchronous FIFO, what clock domain do read and write pointers share? 동기식 FIFO의 경우 읽기 및 쓰기 포인터가 공유하는 클럭 도메인은 무엇인가?
A. They use different clocks
B. They share the same clock
C. Read uses clock, write doesn't
D. They alternate clocks
Answer: B 정답: B

Synchronous FIFOs use the same clock for both read and write operations.

동기식 FIFO는 읽기 및 쓰기 작업 모두에 동일한 클럭을 사용합니다.
