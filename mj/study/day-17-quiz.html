📝 Day 17 Quiz: 2-Flop Synchronizer

Q1. In a 2-flop synchronizer, which clock drives both flip-flops?2-플롭 동기화기에서 어떤 클록이 두 플립플롭을 구동합니까?

Both flops are clocked by the receiving domain clock. The purpose is to give metastable signals time to resolve in the destination domain.두 플롭 모두 수신 도메인 클록으로 클로킹됩니다. 목적은 메타스테이블 신호가 목적지 도메인에서 안정될 시간을 주는 것입니다.

Q2. What is the purpose of the first flip-flop (FF1) in the synchronizer?동기화기에서 첫 번째 플립플롭(FF1)의 목적은 무엇입니까?

FF1 captures the asynchronous signal and may go metastable. It gets one full clock period to resolve before FF2 samples it.FF1은 비동기 신호를 캡처하며 메타스테이블 상태가 될 수 있습니다. FF2가 샘플링하기 전에 전체 클록 주기 동안 안정될 시간을 가집니다.

Q3. Why must there be NO combinational logic between FF1 and FF2?왜 FF1과 FF2 사이에 조합 로직이 없어야 합니까?

Logic between the flops adds propagation delay, eating into the resolution time. The metastable signal needs the full clock period to settle.플롭 사이의 로직은 전파 지연을 추가하여 해상 시간을 줄입니다. 메타스테이블 신호는 안정되기 위해 전체 클록 주기가 필요합니다.

Q4. How does MTBF relate to resolution time?MTBF는 해상 시간과 어떤 관계가 있습니까?

MTBF grows exponentially with resolution time (it's in the exponent of the formula). This is why even a small increase in resolution time dramatically improves reliability.MTBF는 해상 시간에 따라 기하급수적으로 증가합니다 (공식의 지수에 있음). 해상 시간의 작은 증가도 신뢰성을 극적으로 향상시키는 이유입니다.

Q5. A 2-flop synchronizer is appropriate for which type of signal?2-플롭 동기화기는 어떤 유형의 신호에 적합합니까?

The 2-flop synchronizer only works for single-bit signals. Multi-bit signals require gray code encoding or handshake protocols because each bit may resolve differently.2-플롭 동기화기는 단일 비트 신호에만 작동합니다. 멀티비트 신호는 각 비트가 다르게 안정될 수 있으므로 그레이 코드 인코딩이나 핸드셰이크 프로토콜이 필요합니다.

Q6. What does the ASYNC_REG synthesis attribute do?ASYNC_REG 합성 속성은 무엇을 합니까?

ASYNC_REG tells the synthesis/P&R tool that this register is part of a synchronizer. The tool will keep the flops close together and won't merge or optimize them away.ASYNC_REG는 합성/배치 도구에 이 레지스터가 동기화기의 일부임을 알립니다. 도구는 플롭을 가까이 유지하고 병합하거나 최적화하지 않습니다.

Q7. In a parameterized N-stage synchronizer with sync_pipe[STAGES-1:0], which bit is the output?매개변수화된 N단 동기화기에서 sync_pipe[STAGES-1:0]일 때, 어떤 비트가 출력입니까?

The signal shifts from bit 0 toward the MSB. sync_pipe[STAGES-1] is the last stage — the fully resolved output.신호는 비트 0에서 MSB 방향으로 이동합니다. sync_pipe[STAGES-1]이 마지막 단계 — 완전히 안정된 출력입니다.

Q8. What latency (in clock cycles) does a 2-flop synchronizer add?2-플롭 동기화기는 몇 클록 사이클의 지연을 추가합니까?

Two flip-flops = 2 clock cycles of latency in the receiving domain. This is the inherent cost of synchronization.두 개의 플립플롭 = 수신 도메인에서 2 클록 사이클의 지연. 이것은 동기화의 본질적인 비용입니다.

Q9. When would you use a 3-flop synchronizer instead of 2?2 대신 3-플롭 동기화기를 사용하는 경우는?

At very high frequencies (>1 GHz), the resolution time per stage shrinks, so a third flop provides additional resolution time. Safety-critical systems also use 3+ flops for extra margin.초고주파(>1 GHz)에서는 스테이지당 해상 시간이 줄어들어 세 번째 플롭이 추가 해상 시간을 제공합니다. 안전 최우선 시스템도 추가 여유를 위해 3개 이상의 플롭을 사용합니다.

Q10. What happens if you synchronize a 4-bit counter with four independent 2-flop synchronizers?4비트 카운터를 4개의 독립 2-플롭 동기화기로 동기화하면 어떻게 됩니까?

When multiple bits change simultaneously (e.g., 0111→1000), each synchronizer resolves independently. Some bits might update one cycle before others, creating values that never existed (e.g., 1111). This is why gray code is essential for multi-bit CDC!여러 비트가 동시에 변할 때 (예: 0111→1000), 각 동기화기가 독립적으로 안정됩니다. 일부 비트가 다른 비트보다 한 사이클 먼저 업데이트되어 존재하지 않는 값(예: 1111)이 생길 수 있습니다. 이것이 멀티비트 CDC에 그레이 코드가 필수적인 이유입니다!
