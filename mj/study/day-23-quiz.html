Q1. Which type of hazard occurs when an instruction reads a register before a previous instruction has written its result?이전 명령이 결과를 쓰기 전에 다음 명령이 레지스터를 읽을 때 어떤 유형의 해저드가 발생하는가?

  • A) Structural hazard구조적 해저드
  • B) Data hazard (RAW)데이터 해저드 (RAW)
  • C) Control hazard제어 해저드
  • D) Data hazard (WAR)데이터 해저드 (WAR)
✅ RAW (Read-After-Write) is the classic data hazard: instruction B reads a value that instruction A hasn't finished writing yet. This is the most common and most important hazard type.✅ RAW (쓰기 후 읽기)는 고전적인 데이터 해저드입니다: 명령 B가 명령 A가 아직 쓰기를 완료하지 않은 값을 읽습니다. 가장 흔하고 중요한 해저드 유형입니다.

Q2. What is the primary purpose of data forwarding (bypassing)?데이터 포워딩(바이패싱)의 주요 목적은?

  • A) Increase clock frequency클록 주파수 증가
  • B) Reduce pipeline depth파이프라인 깊이 감소
  • C) Reduce stalls from data hazards by sending results directly to where they're needed결과를 필요한 곳으로 직접 전달하여 데이터 해저드 스톨 감소
  • D) Eliminate all branch penalties모든 분기 패널티 제거
✅ Forwarding sends computed results directly from one pipeline stage to an earlier stage's input, bypassing the register file write-back. This eliminates most data hazard stalls without adding extra cycles.✅ 포워딩은 계산된 결과를 한 파이프라인 스테이지에서 이전 스테이지의 입력으로 직접 전달하여 레지스터 파일 쓰기를 우회합니다. 추가 사이클 없이 대부분의 데이터 해저드 스톨을 제거합니다.

Q3. In a 5-stage pipeline, a load instruction is immediately followed by an instruction that uses the loaded value. With forwarding, how many stall cycles are needed?5단계 파이프라인에서 로드 명령 바로 다음에 로드된 값을 사용하는 명령이 옵니다. 포워딩이 있을 때 몇 사이클의 스톨이 필요한가?

  • A) 0 — forwarding handles it completely0 — 포워딩이 완전히 처리
  • B) 1 — data isn't available until end of MEM stage1 — MEM 스테이지 끝까지 데이터 사용 불가
  • C) 2 — same as without forwarding2 — 포워딩 없을 때와 동일
  • D) 3 — loads always need 3 stalls3 — 로드는 항상 3 스톨 필요
✅ This is the load-use hazard. The load data isn't available until the end of MEM, but the dependent instruction needs it at the start of EX. Even with forwarding, we need exactly 1 stall cycle — then we forward from MEM→EX.✅ 이것이 load-use 해저드입니다. 로드 데이터는 MEM 끝까지 사용 불가하지만, 의존 명령은 EX 시작에서 필요합니다. 포워딩이 있어도 정확히 1 스톨 사이클이 필요하고, 그 후 MEM→EX 포워딩합니다.

Q4. What causes a control hazard?제어 해저드의 원인은?

  • A) The pipeline doesn't know the next instruction address because a branch hasn't been resolved분기가 해결되지 않아 다음 명령 주소를 알 수 없음
  • B) Two instructions compete for the same ALU두 명령이 같은 ALU를 놓고 경쟁
  • C) A register is written after being read레지스터가 읽힌 후 쓰여짐
  • D) The clock frequency is too high클록 주파수가 너무 높음
✅ Control hazards arise because branch instructions change the flow of execution, but the pipeline has already fetched subsequent instructions that may be wrong. The branch decision typically isn't known until the EX stage.✅ 제어 해저드는 분기 명령이 실행 흐름을 변경하지만, 파이프라인이 이미 잘못된 후속 명령을 페치했기 때문에 발생합니다. 분기 결정은 보통 EX 스테이지까지 알 수 없습니다.

Q5. In a 2-bit saturating branch predictor, what does the 2-bit counter value 10 represent?2비트 포화 분기 예측기에서 2비트 카운터 값 10은 무엇을 나타내는가?

  • A) Strongly not taken강하게 취해지지 않음
  • B) Weakly not taken약하게 취해지지 않음
  • C) Weakly taken약하게 취해짐
  • D) Strongly taken강하게 취해짐
✅ The 2-bit counter states: 00=strongly not taken, 01=weakly not taken, 10=weakly taken, 11=strongly taken. The MSB (bit 1) determines the prediction: 1x → predict taken, 0x → predict not taken.✅ 2비트 카운터 상태: 00=강하게 미취, 01=약하게 미취, 10=약하게 취, 11=강하게 취. MSB(비트 1)가 예측을 결정: 1x → 취해짐 예측, 0x → 미취 예측.

Q6. What happens during a pipeline flush?파이프라인 플러시 중 무엇이 일어나는가?

  • A) All pipeline stages are paused for one cycle모든 파이프라인 스테이지가 한 사이클 동안 일시 정지
  • B) Incorrectly fetched instructions are replaced with NOPs and the PC is redirected잘못 페치된 명령이 NOP으로 대체되고 PC가 리디렉션됨
  • C) The entire pipeline is emptied and restarted from scratch전체 파이프라인이 비워지고 처음부터 재시작
  • D) Data is forwarded to all stages simultaneously데이터가 모든 스테이지에 동시에 포워딩됨
✅ A flush replaces the incorrectly speculated instructions (in IF/ID and ID/EX registers) with NOPs, effectively canceling them. The PC is then redirected to the correct branch target. Instructions already past the branch point continue normally.✅ 플러시는 잘못 추측된 명령(IF/ID 및 ID/EX 레지스터)을 NOP으로 대체하여 효과적으로 취소합니다. PC는 올바른 분기 대상으로 리디렉션됩니다. 분기 지점을 이미 지난 명령은 정상 계속됩니다.

Q7. Which of the following is a structural hazard?다음 중 구조적 해저드는?

  • A) An ADD instruction writes to R3, then SUB reads R3ADD 명령이 R3에 쓰고, SUB가 R3을 읽음
  • B) A branch instruction changes the PC분기 명령이 PC를 변경
  • C) IF and MEM stages both need single-port memory in the same cycleIF와 MEM 스테이지가 같은 사이클에 단일 포트 메모리를 모두 필요
  • D) Two branches appear back-to-back두 분기가 연속으로 나타남
✅ A structural hazard is when two stages need the same hardware resource simultaneously. IF needs memory to fetch the next instruction, while MEM needs it for a load/store. Solution: separate instruction and data caches (Harvard architecture).✅ 구조적 해저드는 두 스테이지가 동시에 같은 하드웨어 자원을 필요로 할 때입니다. IF는 다음 명령 페치를 위해, MEM은 로드/스토어를 위해 메모리가 필요합니다. 해결: 별도의 명령/데이터 캐시 (하버드 아키텍처).

Q8. In the forwarding unit, why does EX/MEM forwarding have higher priority than MEM/WB forwarding?포워딩 유닛에서 EX/MEM 포워딩이 MEM/WB 포워딩보다 우선순위가 높은 이유는?

  • A) EX/MEM is faster to accessEX/MEM이 접근이 더 빠름
  • B) MEM/WB data may be corruptMEM/WB 데이터가 손상될 수 있음
  • C) EX/MEM uses less powerEX/MEM이 전력을 덜 사용
  • D) EX/MEM has the most recent result — if both write the same register, we want the latest valueEX/MEM이 가장 최근 결과를 가짐 — 둘 다 같은 레지스터에 쓰면 최신 값을 원함
✅ If two instructions in-flight both write the same register (e.g., ADD R1,... then SUB R1,...), EX/MEM holds the more recent instruction's result. We must forward the latest value to ensure correctness.✅ 비행 중인 두 명령이 같은 레지스터에 쓰면 (예: ADD R1,... 후 SUB R1,...), EX/MEM이 더 최근 명령의 결과를 보유합니다. 정확성을 위해 최신 값을 포워딩해야 합니다.

Q9. Why is the 2-bit saturating predictor better than a 1-bit predictor for loops?루프에서 2비트 포화 예측기가 1비트 예측기보다 나은 이유는?

  • A) It uses less hardware하드웨어를 덜 사용
  • B) It tolerates one wrong outcome before changing prediction, avoiding mispredicts at loop entry/exit예측 변경 전에 한 번의 오류를 허용하여 루프 진입/종료 시 오예측 방지
  • C) It predicts both taken and not-taken simultaneously취해짐과 미취를 동시에 예측
  • D) It can predict indirect branches간접 분기를 예측할 수 있음
✅ A 1-bit predictor flips after every misprediction — in a loop, it mispredicts twice (once at loop exit, once at loop re-entry). The 2-bit counter requires two consecutive mispredictions to flip, so it only mispredicts once at loop exit.✅ 1비트 예측기는 매번 오예측 후 뒤집힘 — 루프에서 두 번 오예측 (루프 종료와 재진입). 2비트 카운터는 뒤집히려면 연속 두 번의 오예측이 필요하여, 루프 종료 시 한 번만 오예측합니다.

Q10. Consider this instruction sequence in a 5-stage pipeline with forwarding:포워딩이 있는 5단계 파이프라인에서 다음 명령 시퀀스를 고려하세요:

LW   R1, 0(R2)     // Load word into R1
ADD  R3, R1, R4    // Uses R1 immediately
SUB  R5, R1, R6    // Uses R1 one cycle later

How many total stall cycles are needed?

총 몇 스톨 사이클이 필요한가?

  • A) 1 — only the ADD needs a stall (load-use); SUB gets R1 via forwarding1 — ADD만 스톨 필요 (load-use); SUB는 포워딩으로 R1을 받음
  • B) 2 — both ADD and SUB need stalls2 — ADD와 SUB 모두 스톨 필요
  • C) 0 — forwarding handles everything0 — 포워딩이 모두 처리
  • D) 3 — loads always need 3 stalls3 — 로드는 항상 3 스톨 필요
✅ The ADD immediately after the load creates a load-use hazard requiring 1 stall cycle. After that stall, the load data is available from MEM and can be forwarded. The SUB (now 2 cycles after the load) gets R1 via normal MEM/WB forwarding with no additional stall.✅ 로드 바로 다음의 ADD가 load-use 해저드를 생성하여 1 스톨 사이클이 필요합니다. 스톨 후 로드 데이터가 MEM에서 사용 가능하여 포워딩됩니다. SUB (로드 후 2 사이클)는 추가 스톨 없이 MEM/WB 포워딩으로 R1을 받습니다.

Q11. What is a "bubble" in pipeline terminology?파이프라인 용어에서 "버블"이란?

  • A) An extra pipeline stage added for performance성능을 위해 추가된 여분의 파이프라인 스테이지
  • B) A forwarded data value포워딩된 데이터 값
  • C) A NOP inserted into the pipeline to resolve a hazard (wasted cycle)해저드 해결을 위해 파이프라인에 삽입된 NOP (낭비된 사이클)
  • D) The first instruction in a pipeline파이프라인의 첫 번째 명령
✅ A "bubble" (or "pipeline bubble") is a NOP that's inserted when a stall occurs. No useful work happens during a bubble cycle — the pipeline stage effectively does nothing while waiting for the hazard to clear.✅ "버블"(또는 "파이프라인 버블")은 스톨 발생 시 삽입되는 NOP입니다. 버블 사이클 동안 유용한 작업이 없으며 — 해저드가 해소될 때까지 파이프라인 스테이지가 사실상 아무것도 하지 않습니다.

Q12. A "predict not taken" strategy in a 5-stage pipeline (branch resolved in EX) has what penalty when the branch IS taken?5단계 파이프라인(EX에서 분기 해결)에서 "미취 예측" 전략은 분기가 실제로 취해질 때 어떤 패널티를 가지는가?

  • A) 0 cycles — no penalty0 사이클 — 패널티 없음
  • B) 2 cycles — must flush IF and ID stages2 사이클 — IF와 ID 스테이지를 플러시해야 함
  • C) 1 cycle — only flush IF stage1 사이클 — IF 스테이지만 플러시
  • D) 5 cycles — must flush entire pipeline5 사이클 — 전체 파이프라인 플러시
✅ When predicting "not taken" but the branch IS taken, the two instructions fetched after the branch (in IF and ID stages) are wrong and must be flushed — a 2-cycle penalty. When the prediction is correct (branch not taken), there's zero penalty.✅ "미취"로 예측했지만 분기가 실제 취해지면, 분기 후 페치된 두 명령(IF와 ID 스테이지)이 잘못되어 플러시해야 합니다 — 2 사이클 패널티. 예측이 맞으면 패널티 없습니다.
