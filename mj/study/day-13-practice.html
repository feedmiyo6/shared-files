Exercise 1: Setup & Hold Analysis with Skew

Given the following circuit parameters, determine if setup and hold constraints are met:

다음 회로 매개변수가 주어졌을 때, 셋업과 홀드 제약이 충족되는지 판단하세요:

// Circuit parameters:
Clock period   = 8 ns
t_cq           = 0.4 ns
t_setup        = 0.3 ns
t_hold         = 0.15 ns
t_comb         = 6.5 ns
Clock skew     = +0.3 ns

a) Setup slack = 셋업 슬랙 = ns

b) Hold slack = 홀드 슬랙 = ns

💡 Hint: Setup slack = (t_clk + t_skew) − (t_cq + t_comb + t_setup). Hold slack = (t_cq + t_comb) − (t_hold + t_skew). 셋업 슬랙 = (t_clk + t_skew) − (t_cq + t_comb + t_setup). 홀드 슬랙 = (t_cq + t_comb) − (t_hold + t_skew). 
// Setup check:
Setup slack = (t_clk + t_skew) - (t_cq + t_comb + t_setup)
           = (8.0 + 0.3) - (0.4 + 6.5 + 0.3)
           = 8.3 - 7.2
           = +1.1 ns ✅ PASS

// Hold check:
Hold slack = (t_cq + t_comb) - (t_hold + t_skew)
           = (0.4 + 6.5) - (0.15 + 0.3)
           = 6.9 - 0.45
           = +6.45 ns ✅ PASS

Exercise 2: Finding the Maximum Safe Skew

A path has these parameters. What is the maximum positive skew that won't cause a hold violation?

경로의 매개변수입니다. 홀드 위반을 일으키지 않는 최대 양의 스큐는 얼마인가요?

t_cq   = 0.25 ns
t_hold = 0.1 ns
t_comb = 0.5 ns (short path — nearly direct connection)

Max safe skew = 최대 안전 스큐 = ns

💡 Hint: At the hold limit: t_cq + t_comb = t_hold + t_skew_max. Solve for t_skew_max. 홀드 한계에서: t_cq + t_comb = t_hold + t_skew_max. t_skew_max를 구하세요. 
// At hold limit (slack = 0):
t_cq + t_comb = t_hold + t_skew_max
0.25 + 0.5 = 0.1 + t_skew_max
t_skew_max = 0.75 - 0.1 = 0.65 ns

// Any skew > 0.65 ns causes hold violation!
// This is why short paths near clock tree imbalances are dangerous

Exercise 3: Useful Skew Application

You have a two-stage pipeline. Stage 1 is critical (setup failing), Stage 2 has plenty of slack. Calculate the optimal useful skew.

2단계 파이프라인이 있습니다. 1단계는 크리티컬(셋업 실패), 2단계는 충분한 슬랙을 가집니다. 최적의 유용한 스큐를 계산하세요.

Clock period = 4 ns
t_cq         = 0.2 ns
t_setup      = 0.15 ns
t_hold       = 0.1 ns

// Stage 1: FF_A → [comb1] → FF_B
t_comb1      = 4.2 ns  // Too long! Violates setup

// Stage 2: FF_B → [comb2] → FF_C
t_comb2      = 2.0 ns  // Plenty of slack

// Shortest path from FF_A to FF_B:
t_comb1_min = 0.3 ns

a) Stage 1 setup slack (no skew) = 1단계 셋업 슬랙 (스큐 없음) = ns

b) How much useful skew on FF_B to fix Stage 1? (minimum) = 1단계를 수정하기 위한 FF_B의 유용한 스큐 (최소) = ns

c) With 0.6ns useful skew on FF_B, does the hold check on Stage 1's shortest path pass? FF_B에 0.6ns 유용한 스큐 적용 시, 1단계 최단 경로의 홀드 검사는 통과하나요? 

// a) Stage 1 setup slack (no skew):
slack = t_clk - (t_cq + t_comb1 + t_setup)
     = 4.0 - (0.2 + 4.2 + 0.15)
     = 4.0 - 4.55 = -0.55 ns ❌ FAIL!

// b) Need skew ≥ 0.55 ns to make slack ≥ 0
// Setup: t_clk + t_skew ≥ t_cq + t_comb + t_setup
//   4.0 + t_skew ≥ 4.55
//   t_skew ≥ 0.55 ns

// c) With 0.6ns useful skew, hold check on shortest path:
Hold slack = (t_cq + t_comb1_min) - (t_hold + t_skew)
           = (0.2 + 0.3) - (0.1 + 0.6)
           = 0.5 - 0.7 = -0.2 ns

// Wait — HOLD VIOLATION! The answer is actually NO.
// But the max path hold slack:
Hold slack (max path) = (0.2 + 0.3) - (0.1 + 0.6) = -0.2 ns ❌

// Hmm, let me reconsider...
// t_cq + t_comb_min = 0.2 + 0.3 = 0.5 ns
// t_hold + t_skew = 0.1 + 0.6 = 0.7 ns
// 0.5 < 0.7 → HOLD VIOLATION!
// Need to insert 0.2ns delay buffer on shortest path

⚠️ Trick Question!

The hold check actually fails! This demonstrates why useful skew must be applied carefully — you must check hold timing on ALL paths, especially the shortest ones. A 0.2ns delay buffer would fix this.

홀드 검사가 실제로 실패합니다! 이것은 유용한 스큐를 신중하게 적용해야 하는 이유를 보여줍니다 — 모든 경로, 특히 최단 경로의 홀드 타이밍을 검사해야 합니다. 0.2ns 지연 버퍼로 이를 수정할 수 있습니다.

Exercise 4: Skew Impact Table

Fill in the table: for each scenario, determine the effect on setup and hold slack compared to zero-skew.

표를 채우세요: 각 시나리오에서 스큐 없음 대비 셋업과 홀드 슬랙에 미치는 영향을 판단하세요.

Scenario Setup Slack Hold Slack
Positive skew (+0.3ns)
Negative skew (−0.3ns)

Positive skew: Setup = Better ↑ (more time), Hold = Worse ↓ (less margin)

양의 스큐: 셋업 = 개선 ↑ (더 많은 시간), 홀드 = 악화 ↓ (적은 마진)

Negative skew: Setup = Worse ↓ (less time), Hold = Better ↑ (more margin)

음의 스큐: 셋업 = 악화 ↓ (적은 시간), 홀드 = 개선 ↑ (더 많은 마진)

Remember: skew adds to one side and subtracts from the other — it's always a tradeoff!

기억하세요: 스큐는 한 쪽에 더하고 다른 쪽에서 빼는 것입니다 — 항상 트레이드오프입니다!

Exercise 5: Multi-Path Skew Analysis

A chip has three paths between flip-flops with the following clock arrival times. Identify which paths have potential hold violations.

칩에 다음 클럭 도달 시간을 가진 세 개의 경로가 있습니다. 잠재적 홀드 위반이 있는 경로를 식별하세요.

// Common parameters:
t_cq   = 0.2 ns,  t_hold = 0.1 ns

// Path A: FF1 → FF2
t_clk→FF1 = 1.0 ns,  t_clk→FF2 = 1.8 ns
t_comb_min = 0.5 ns

// Path B: FF3 → FF4
t_clk→FF3 = 1.2 ns,  t_clk→FF4 = 1.1 ns
t_comb_min = 0.1 ns

// Path C: FF5 → FF6
t_clk→FF5 = 0.8 ns,  t_clk→FF6 = 1.5 ns
t_comb_min = 0.2 ns

Which paths have hold violations? (Enter A, B, C, or combinations like AC)

어떤 경로에 홀드 위반이 있나요? (A, B, C 또는 AC 같은 조합 입력)

// Path A: skew = 1.8 - 1.0 = +0.8 ns
Hold slack = (0.2 + 0.5) - (0.1 + 0.8) = 0.7 - 0.9 = -0.2 ns ❌

// Wait — Path A also fails!
// Path B: skew = 1.1 - 1.2 = -0.1 ns
Hold slack = (0.2 + 0.1) - (0.1 + (-0.1)) = 0.3 - 0.0 = +0.3 ns ✅

// Path C: skew = 1.5 - 0.8 = +0.7 ns
Hold slack = (0.2 + 0.2) - (0.1 + 0.7) = 0.4 - 0.8 = -0.4 ns ❌

// Both A and C have hold violations!
// Path A needs ≥ 0.2ns delay buffer
// Path C needs ≥ 0.4ns delay buffer

⚠️ Correction

Both paths A and C fail hold timing! Large positive skew on short paths is the classic hold violation pattern. The correct answer is AC.

경로 A와 C 모두 홀드 타이밍에 실패합니다! 짧은 경로에 대한 큰 양의 스큐는 전형적인 홀드 위반 패턴입니다. 정답은 AC입니다.
