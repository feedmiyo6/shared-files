// Unpipelined multiplier — all in one cycle

1. 확인: T_cq + T_comb + T_su = 100 + 900 + 50 = 1050ps > 1000ps → 위반! ❌ (슬랙 = -50ps)

2. Place register between Stage B and Stage C:
— Stage 1: A+B = 200+300 = 500ps
— Stage 2: C+D = 250+150 = 400ps

Exercise 3: Code It — Pipeline a Long Path

Transform this unpipelined module into a 2-stage pipelined version. Try it yourself, then check the solution!

이 파이프라인 없는 모듈을 2단계 파이프라인 버전으로 변환하세요. 직접 해본 후 풀이를 확인하세요!

// GIVEN: Unpipelined — violates setup at target frequency
module compute (
    input  logic        clk, rst_n,
    input  logic [15:0] a, b, c,
    output logic [31:0] result
);
    logic [31:0] product, sum;

    // Long combinational path: multiply then add
    always_comb begin
        product = a * b;       // Slow multiply
        sum     = product + c;  // Add on top
    end

    always_ff @(posedge clk or negedge rst_n)
        if (!rst_n) result <= '0;
        else        result <= sum;
endmodule

💡 Hint

💡 힌트

Split the multiply and add into two separate clock cycles. You'll need a pipeline register to store the intermediate product, and you'll also need to delay the c input by one cycle so it's available when needed.

곱셈과 덧셈을 두 개의 별도 클럭 사이클로 분할하세요. 중간 곱을 저장할 파이프라인 레지스터가 필요하고, c 입력도 한 사이클 지연시켜 필요할 때 사용할 수 있도록 해야 합니다.

💡 Show Solution 💡 풀이 보기 
// SOLUTION: 2-stage pipeline
module compute_pipelined (
    input  logic        clk, rst_n,
    input  logic [15:0] a, b, c,
    output logic [31:0] result
);
    // Pipeline registers
    logic [31:0] product_r;  // Stores multiply result
    logic [15:0] c_r;        // Delayed c input

    // Stage 1: Multiply (slow operation isolated)
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            product_r <= '0;
            c_r       <= '0;
        end else begin
            product_r <= a * b;  // Multiply in stage 1
            c_r       <= c;      // Delay c to match!
        end
    end

    // Stage 2: Add (uses pipelined values)
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            result <= '0;
        else
            result <= product_r + c_r;  // Add in stage 2
    end

    // Result appears 2 cycles after input
    // But each stage has shorter combinational path!
endmodule

⚠️ Common Mistake

Don't forget to pipeline ALL inputs that are needed in later stages! If c is used in stage 2 but enters in stage 1, it must be delayed by one cycle. Forgetting this causes a functional bug where stage 2 uses the wrong value of c.

후속 단계에서 필요한 모든 입력을 파이프라이닝하는 것을 잊지 마세요! c가 단계 2에서 사용되지만 단계 1에서 입력되면, 한 사이클 지연시켜야 합니다. 이를 잊으면 단계 2가 잘못된 c 값을 사용하는 기능 버그가 발생합니다.
