Exercise 1: Gray Code Converter Module

Write a parameterized module that converts between binary and Gray code in both directions.

이진 코드와 그레이 코드 사이를 양방향으로 변환하는 매개변수화된 모듈을 작성하세요.

📋 Requirements

  • Parameter WIDTH for bit width
  • Function bin2gray: binary → Gray
  • Function gray2bin: Gray → binary
  • Verify: gray2bin(bin2gray(x)) == x for all values
  • 비트 폭을 위한 매개변수 WIDTH
  • 함수 bin2gray: 이진 → 그레이
  • 함수 gray2bin: 그레이 → 이진
  • 검증: 모든 값에 대해 gray2bin(bin2gray(x)) == x
💡 Hint: bin2gray = bin ^ (bin >> 1). For gray2bin, XOR each bit with all higher bits. bin2gray = bin ^ (bin >> 1). gray2bin의 경우 각 비트를 모든 상위 비트와 XOR합니다. 
module gray_code_conv #(
    parameter WIDTH = 5
)(
    input  logic [WIDTH-1:0] bin_in,
    output logic [WIDTH-1:0] gray_out,

    input  logic [WIDTH-1:0] gray_in,
    output logic [WIDTH-1:0] bin_out
);

    // Binary to Gray: XOR with right-shifted self
    assign gray_out = bin_in ^ (bin_in >> 1);

    // Gray to Binary: each bit = XOR of all higher Gray bits
    always_comb begin
        bin_out[WIDTH-1] = gray_in[WIDTH-1];  // MSB same
        for (int i = WIDTH-2; i >= 0; i--)
            bin_out[i] = bin_out[i+1] ^ gray_in[i];
    end

endmodule

Exercise 2: 2-Flop Synchronizer (Parameterized)

Write a parameterized multi-bit synchronizer that uses 2 flip-flop stages. This is used to pass Gray code pointers across clock domains.

2단 플립플롭을 사용하는 매개변수화된 멀티비트 동기화기를 작성하세요. 그레이 코드 포인터를 클럭 도메인 간에 전달하는 데 사용됩니다.

⚠️ Important

This synchronizer is ONLY safe for Gray-coded values (single-bit transitions). Do NOT use it for arbitrary binary values!

이 동기화기는 그레이 코드 값(단일 비트 전환)에만 안전합니다. 임의의 이진 값에 사용하지 마세요!

module sync_2ff #(
    parameter WIDTH = 5
)(
    input  logic                   clk,
    input  logic                   rst_n,
    input  logic [WIDTH-1:0]      data_in,
    output logic [WIDTH-1:0]      data_out
);

    logic [WIDTH-1:0] meta;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            meta     <= '0;
            data_out <= '0;
        end else begin
            meta     <= data_in;   // Stage 1: may go metastable
            data_out <= meta;      // Stage 2: resolved
        end
    end

endmodule

Exercise 3: Full/Empty Flag Logic

Given Gray-coded write and read pointers (5 bits for a 16-deep FIFO), write the combinational logic for full and empty flags.

그레이 코드 쓰기/읽기 포인터(16 깊이 FIFO용 5비트)가 주어졌을 때, full과 empty 플래그의 조합 논리를 작성하세요.

📋 Remember

  • Empty (in rd_clk domain): rd_gray == wr_gray_sync
  • Full (in wr_clk domain): top 2 bits differ, lower bits match
  • Pointers are 5 bits [4:0] for 16-entry FIFO
  • Empty (rd_clk 도메인): rd_gray == wr_gray_sync
  • Full (wr_clk 도메인): 상위 2비트 다르고, 하위 비트 일치
  • 16-엔트리 FIFO용 포인터는 5비트 [4:0]
// Empty: generated in READ clock domain
// wr_gray_sync is the write pointer synchronized to rd_clk
assign empty = (rd_gray == wr_gray_sync);

// Full: generated in WRITE clock domain
// rd_gray_sync is the read pointer synchronized to wr_clk
// In Gray code: full when top 2 MSBs differ, rest match
assign full = (wr_gray[4]   != rd_gray_sync[4])   &&  // MSB differs
              (wr_gray[3]   != rd_gray_sync[3])   &&  // 2nd MSB differs
              (wr_gray[2:0] == rd_gray_sync[2:0]);  // Rest match

// WHY top 2 bits in Gray code?
// In binary: full when wr_bin[4] != rd_bin[4] and wr_bin[3:0] == rd_bin[3:0]
// In Gray: the binary MSB difference maps to top 2 Gray bits differing
// because gray[4] = bin[4] ^ bin[3], gray[3] = bin[3] ^ bin[2]

Exercise 4: Complete Async FIFO Testbench

Write a testbench that verifies the async FIFO with different write and read clocks. Test: fill to full, drain to empty, simultaneous read/write.

서로 다른 쓰기/읽기 클럭으로 비동기 FIFO를 검증하는 테스트벤치를 작성하세요. 테스트: 가득 찰 때까지 채우기, 비울 때까지 비우기, 동시 읽기/쓰기.

module tb_async_fifo;

    parameter DATA_WIDTH = 8;
    parameter ADDR_WIDTH = 3;  // 8-deep FIFO for quick testing

    logic wr_clk, rd_clk, wr_rst_n, rd_rst_n;
    logic wr_en, rd_en;
    logic [DATA_WIDTH-1:0] wr_data, rd_data;
    logic full, empty;

    // Instantiate DUT
    async_fifo #(
        .DATA_WIDTH(DATA_WIDTH),
        .ADDR_WIDTH(ADDR_WIDTH)
    ) dut (.*);

    // Different clock frequencies!
    initial wr_clk = 0;
    always #5  wr_clk = ~wr_clk;  // 100 MHz write

    initial rd_clk = 0;
    always #7  rd_clk = ~rd_clk;  // ~71 MHz read

    initial begin
        // Reset both domains
        wr_rst_n = 0; rd_rst_n = 0;
        wr_en = 0; rd_en = 0; wr_data = 0;
        #50;
        wr_rst_n = 1; rd_rst_n = 1;
        #20;

        // ── Test 1: Fill FIFO to full ──
        $display("=== Test 1: Fill to Full ===");
        for (int i = 0; i < 8; i++) begin
            @(posedge wr_clk);
            wr_en = 1; wr_data = i * 10;
        end
        @(posedge wr_clk); wr_en = 0;
        #50;  // Wait for sync
        $display("Full=%b (expect 1)", full);

        // ── Test 2: Drain FIFO to empty ──
        $display("=== Test 2: Drain to Empty ===");
        for (int i = 0; i < 8; i++) begin
            @(posedge rd_clk);
            rd_en = 1;
            $display("Read[%0d]: %0d", i, rd_data);
        end
        @(posedge rd_clk); rd_en = 0;
        #50;
        $display("Empty=%b (expect 1)", empty);

        // ── Test 3: Simultaneous R/W ──
        $display("=== Test 3: Simultaneous R/W ===");
        fork
            begin  // Writer
                for (int i = 0; i < 20; i++) begin
                    @(posedge wr_clk);
                    wr_en = !full; wr_data = i;
                end
                wr_en = 0;
            end
            begin  // Reader (start after small delay)
                #30;
                for (int i = 0; i < 20; i++) begin
                    @(posedge rd_clk);
                    rd_en = !empty;
                    if (rd_en) $display("Read: %0d", rd_data);
                end
                rd_en = 0;
            end
        join

        #100;
        $display("=== All Tests Complete ===");
        $finish;
    end

endmodule

Exercise 5: FIFO Depth Calculation

Calculate the minimum FIFO depth for these scenarios (pen & paper exercise):

다음 시나리오에 대한 최소 FIFO 깊이를 계산하세요 (종이 연습):

📋 Scenarios

  1. Write clock: 200 MHz, Read clock: 100 MHz, Burst length: 16 words. How deep?
  2. Write clock: 150 MHz, Read clock: 150 MHz, Burst: 8 words with gaps. Minimum depth?
  3. Why do we round up to the next power of 2?
  1. 쓰기 클럭: 200 MHz, 읽기 클럭: 100 MHz, 버스트 길이: 16 워드. 깊이는?
  2. 쓰기 클럭: 150 MHz, 읽기 클럭: 150 MHz, 버스트: 갭이 있는 8 워드. 최소 깊이?
  3. 왜 다음 2의 거듭제곱으로 올림하나요?

Scenario 1: Writer is 2× faster than reader. During a 16-word burst, reader can consume 8 words. Net accumulation = 16 - 8 = 8 words. Add 2-3 for sync latency → minimum 11, round to 16 (2⁴).

시나리오 1: 쓰기가 읽기보다 2배 빠름. 16 워드 버스트 동안 읽기가 8워드 소비. 순 축적 = 16 - 8 = 8 워드. 동기화 지연 2-3 추가 → 최소 11, 16(2⁴)으로 올림.

Scenario 2: Same frequency — theoretically depth=1 works. But burst of 8 with gaps means reader might not keep up during the burst. Need at least 8 + 2-3 sync latency = ~11, round to 16.

시나리오 2: 동일 주파수 — 이론적으로 깊이=1 작동. 하지만 갭이 있는 8 버스트는 버스트 중 읽기가 따라가지 못할 수 있음. 최소 8 + 동기화 지연 2-3 = ~11, 16으로 올림.

Scenario 3: Power of 2 is required because Gray code only has single-bit transitions when wrapping at power-of-2 boundaries. Non-power-of-2 would break the Gray code property!

시나리오 3: 2의 거듭제곱 필요 이유: 그레이 코드가 2의 거듭제곱 경계에서 래핑할 때만 단일 비트 전환을 가지기 때문. 2의 거듭제곱이 아니면 그레이 코드 속성이 깨짐!
