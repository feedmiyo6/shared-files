📝 Day 10 Quiz: FSM Practice

📖 Lesson 💻 Practice

Q1. In the traffic light controller, why is the emergency check placed BEFORE the case statement?교통 신호등 컨트롤러에서 비상 체크를 case문 앞에 배치하는 이유는?

✅ B. By placing the emergency check in an if-else before the case, it takes priority over all other state transitions regardless of current state.✅ B. case문 앞에 if-else로 비상 체크를 배치하면, 현재 상태와 관계없이 모든 상태 전환보다 우선합니다.

Q2. The traffic light uses a separate timer register. What's the alternative, and why is it worse?신호등이 별도의 timer 레지스터를 사용합니다. 대안은 무엇이고 왜 더 나쁜가요?

✅ B. Without a timer, you'd need separate states for each cycle (GREEN_NS_1 through GREEN_NS_10), creating 26+ states instead of 5. A timer register is much cleaner.✅ B. 타이머 없이는 각 사이클마다 별도 상태가 필요합니다 (GREEN_NS_1부터 GREEN_NS_10까지), 5개 대신 26개 이상의 상태가 됩니다.

Q3. In the sequence detector, what state transition happens when we're in GOT_101 and receive din=0?시퀀스 디텍터에서 GOT_101 상태에서 din=0을 받으면 어떤 상태 전환이 일어나나요?

✅ B. We've seen "1010". The last two bits "10" could be the start of "1011", so we go to GOT_10. This is the key insight for overlapping detection.✅ B. "1010"을 보았습니다. 마지막 두 비트 "10"이 "1011"의 시작일 수 있으므로 GOT_10으로 갑니다. 오버래핑 감지의 핵심 통찰입니다.

Q4. The sequence detector uses a Mealy machine. What makes it Mealy?시퀀스 디텍터는 Mealy 머신을 사용합니다. Mealy인 이유는?

✅ B. In the GOT_101 state, detected is only asserted when din=1. Output depends on current state AND current input = Mealy.✅ B. GOT_101 상태에서 detected는 din=1일 때만 어서트됩니다. 출력이 현재 상태와 현재 입력에 의존 = Mealy.

Q5. For a non-overlapping version of the 1011 detector, what changes in GOT_101 when din=1?1011 디텍터의 논오버래핑 버전에서 GOT_101에서 din=1일 때 무엇이 변하나요?

✅ A. Non-overlapping: after detecting "1011", go to IDLE to start fresh. Overlapping: go to GOT_1 because the final "1" could start a new "1011".✅ A. 논오버래핑: "1011" 감지 후 IDLE로 가서 새로 시작. 오버래핑: 마지막 "1"이 새로운 "1011"을 시작할 수 있으므로 GOT_1로 이동.

Q6. Why does the traffic light output logic use a separate always_comb block?신호등 출력 로직이 별도의 always_comb 블록을 사용하는 이유는?

✅ B. The 3-block pattern (Day 6!) keeps code organized and maintainable. Each block has one job: register state, compute next state, compute outputs.✅ B. 3블록 패턴(6일차!)은 코드를 체계적이고 유지보수하기 쉽게 합니다. 각 블록은 하나의 역할: 상태 등록, 다음 상태 계산, 출력 계산.

Q7. What happens if the traffic light FSM enters an illegal state and there's no default case?신호등 FSM이 불법 상태에 진입하고 default case가 없으면 어떻게 되나요?

✅ B. Without a default case, the combinational block doesn't define outputs for unknown states, causing latch inference. The FSM gets stuck with no way to recover — exactly what Day 9 warned about!✅ B. default case 없이는 조합 블록이 알 수 없는 상태의 출력을 정의하지 않아 래치가 추론됩니다. FSM은 복구할 방법 없이 멈춥니다 — 9일차에서 경고한 것!

Q8. In the testbench, what does @(posedge clk) inside the task do?테스트벤치에서 task 안의 @(posedge clk)은 무엇을 하나요?

✅ B. The @(posedge clk) event control waits until the next rising edge, synchronizing our test stimulus with the clock — just like real hardware would sample inputs.✅ B. @(posedge clk) 이벤트 제어는 다음 상승 에지까지 기다려서, 테스트 자극을 클럭과 동기화합니다 — 실제 하드웨어가 입력을 샘플링하는 것처럼.

Q9. For the traffic light, what type of FSM is the output logic?신호등에서 출력 로직은 어떤 타입의 FSM인가요?

✅ B. The output case statement only looks at state — not any inputs. Outputs are purely a function of current state = Moore machine.✅ B. 출력 case문은 state만 봅니다 — 입력은 보지 않습니다. 출력이 순전히 현재 상태의 함수 = Moore 머신.

Q10. When designing an FSM for an interview, what should you do FIRST?면접에서 FSM을 설계할 때 가장 먼저 해야 할 일은?

✅ C. Always start with requirements and a state diagram. Ask clarifying questions (overlapping? Moore/Mealy?). Then code. Interviewers value structured thinking over fast typing.✅ C. 항상 요구사항과 상태 다이어그램으로 시작하세요. 명확한 질문을 하세요 (오버래핑? Moore/Mealy?). 그 다음 코딩. 면접관은 빠른 타이핑보다 구조적 사고를 중시합니다.
