Q1. Why can't you synchronize a binary counter across clock domains by putting a 2-flop sync on each bit?왜 각 비트에 2-플립플롭 동기화기를 넣어 바이너리 카운터를 클록 도메인 간에 동기화할 수 없나요?

  • Binary counters are too fast to synchronize바이너리 카운터가 동기화하기에 너무 빠르다
  • Multiple bits change simultaneously, so the receiving clock may capture a mix of old and new bits여러 비트가 동시에 변경되어 수신 클록이 이전과 새 비트의 혼합을 캡처할 수 있다
  • 2-flop synchronizers only work with clock signals2-플립플롭 동기화기는 클록 신호에서만 작동한다
  • Binary counters consume too much power for CDC바이너리 카운터는 CDC에 너무 많은 전력을 소비한다
When a binary counter goes from e.g. 0111→1000, all 4 bits change. Each bit may resolve to old or new independently, giving a completely wrong value.바이너리 카운터가 예를 들어 0111→1000으로 갈 때, 4비트 모두 변경됩니다. 각 비트가 독립적으로 이전 또는 새 값으로 해결되어 완전히 잘못된 값을 줄 수 있습니다.

Q2. What is the key property of Gray code?그레이 코드의 핵심 속성은 무엇인가요?

  • It uses fewer bits than binary바이너리보다 적은 비트를 사용한다
  • It is self-correcting for errors오류에 대해 자기 수정된다
  • Only one bit changes between consecutive values연속된 값 사이에서 하나의 비트만 변경된다
  • It encodes parity information in each bit각 비트에 패리티 정보를 인코딩한다
Gray code's defining property: adjacent values differ in exactly one bit position, making it safe to synchronize across clock domains.그레이 코드의 정의 속성: 인접한 값은 정확히 하나의 비트 위치에서만 다르므로 클록 도메인 간 동기화에 안전합니다.

Q4. What is the formula for binary-to-Gray conversion?바이너리→그레이 변환 공식은?

  • gray = bin + (bin >> 1)
  • gray = bin ^ (bin >> 1)
  • gray = bin & (bin >> 1)
  • gray = bin | (bin >> 1)
XOR of binary with itself shifted right by 1. This is a single gate per bit in hardware!바이너리와 자체를 오른쪽으로 1만큼 시프트한 것의 XOR. 하드웨어에서 비트당 하나의 게이트입니다!

Q5. In Gray-to-binary conversion, how is each binary bit calculated?그레이→바이너리 변환에서 각 바이너리 비트는 어떻게 계산되나요?

  • XOR of current Gray bit with the Gray bit below현재 그레이 비트와 아래 그레이 비트의 XOR
  • XOR of all Gray bits from MSB down to the current positionMSB에서 현재 위치까지 모든 그레이 비트의 XOR
  • AND of current Gray bit with the computed binary bit above현재 그레이 비트와 위의 계산된 바이너리 비트의 AND
  • Direct copy from Gray code그레이 코드에서 직접 복사
bin[i] = gray[N] ^ gray[N-1] ^ ... ^ gray[i]. It's a cascading XOR from MSB down.bin[i] = gray[N] ^ gray[N-1] ^ ... ^ gray[i]. MSB에서 아래로의 연쇄 XOR입니다.

Q6. How does a typical Gray code counter work internally?일반적인 그레이 코드 카운터는 내부적으로 어떻게 작동하나요?

  • Directly increments in Gray code using special logic특별한 로직으로 그레이 코드에서 직접 증가
  • Uses a lookup table to find the next Gray value룩업 테이블로 다음 그레이 값을 찾는다
  • Maintains a binary counter and converts the output to Gray바이너리 카운터를 유지하고 출력을 그레이로 변환한다
  • Counts in one-hot encoding and converts to Gray원-핫 인코딩으로 카운트하고 그레이로 변환한다
The standard pattern: binary counter + bin2gray conversion. Simpler and more reliable than trying to count directly in Gray code.표준 패턴: 바이너리 카운터 + bin2gray 변환. 그레이 코드에서 직접 카운트하는 것보다 간단하고 더 안정적입니다.

Q7. Why do async FIFO pointers use N+1 bits for a 2N-deep FIFO?비동기 FIFO 포인터가 2N 깊이의 FIFO에 N+1 비트를 사용하는 이유는?

  • To handle signed arithmetic부호 있는 연산을 처리하기 위해
  • To distinguish between full and empty conditionsfull과 empty 상태를 구분하기 위해
  • Gray code requires an extra bit for encoding그레이 코드가 인코딩에 추가 비트가 필요하기 때문
  • To provide error detection오류 감지를 제공하기 위해
With N bits, full and empty both look like rd_ptr == wr_ptr. The extra MSB lets us detect when the write pointer has wrapped around — same lower bits but different MSB means FULL.N비트에서는 full과 empty 모두 rd_ptr == wr_ptr처럼 보입니다. 추가 MSB로 쓰기 포인터가 래핑되었는지 감지할 수 있습니다 — 같은 하위 비트지만 다른 MSB는 FULL을 의미합니다.

Q8. When should Gray-to-binary conversion happen in a CDC path?CDC 경로에서 그레이→바이너리 변환은 언제 해야 하나요?

  • Before the 2-flop synchronizer (in the source domain)2-플립플롭 동기화기 전 (소스 도메인에서)
  • After the 2-flop synchronizer (in the destination domain)2-플립플롭 동기화기 후 (목적지 도메인에서)
  • Between the two flops of the synchronizer동기화기의 두 플립플롭 사이에서
  • It doesn't matter where어디서든 상관없다
The whole point is to synchronize the Gray value (only 1 bit changes). You convert back to binary AFTER synchronization, in the destination domain.핵심은 그레이 값을 동기화하는 것입니다 (1비트만 변경). 동기화 후 목적지 도메인에서 바이너리로 다시 변환합니다.

Q10. Why does Gray code only work correctly for power-of-2 FIFO depths?그레이 코드가 2의 거듭제곱 FIFO 깊이에서만 올바르게 작동하는 이유는?

  • Non-power-of-2 rollover breaks the single-bit-change guarantee2의 거듭제곱이 아닌 롤오버가 단일 비트 변경 보장을 깨뜨린다
  • Gray code can only represent power-of-2 numbers그레이 코드는 2의 거듭제곱 숫자만 표현할 수 있다
  • The XOR conversion only works for even numbersXOR 변환은 짝수에서만 작동한다
  • Hardware cannot implement non-power-of-2 counters하드웨어가 2의 거듭제곱이 아닌 카운터를 구현할 수 없다
Gray code guarantees 1-bit change only when counting through the full 2N sequence. If you wrap at a non-power-of-2 value, the transition from max back to 0 may change multiple bits.그레이 코드는 전체 2N 시퀀스를 통해 카운트할 때만 1비트 변경을 보장합니다. 2의 거듭제곱이 아닌 값에서 래핑하면 최대값에서 0으로의 전환이 여러 비트를 변경할 수 있습니다.

Q11. In the Gray code counter module, why is gray_next computed from bin_next (not bin_count)?그레이 코드 카운터 모듈에서 gray_next가 bin_count가 아닌 bin_next에서 계산되는 이유는?

  • To reduce power consumption전력 소비를 줄이기 위해
  • So the Gray output is registered and aligned with the binary counter그레이 출력이 레지스터되고 바이너리 카운터와 정렬되도록
  • bin_count has timing violationsbin_count에 타이밍 위반이 있다
  • It doesn't matter which is used어느 것을 사용하든 상관없다
By converting bin_next to gray_next and registering it, the gray_count output is always one clean registered version — matching the binary counter's value on the same clock edge. This avoids combinational glitches on the output.bin_next를 gray_next로 변환하고 레지스터하면, gray_count 출력은 항상 하나의 깨끗한 레지스터된 버전입니다 — 같은 클록 엣지에서 바이너리 카운터의 값과 일치합니다.

Q12. How many XOR gates are needed to convert an N-bit binary value to Gray code?N비트 바이너리 값을 그레이 코드로 변환하는 데 몇 개의 XOR 게이트가 필요한가요?

  • N
  • N-1 (MSB passes through unchanged)N-1 (MSB는 변경 없이 통과)
  • 2N
  • N²
gray[N-1] = bin[N-1] (no gate needed), and gray[i] = bin[i+1] ^ bin[i] for i = 0 to N-2. That's N-1 XOR gates. Very cheap in hardware!gray[N-1] = bin[N-1] (게이트 불필요), gray[i] = bin[i+1] ^ bin[i] (i = 0 ~ N-2). 즉 N-1개의 XOR 게이트입니다. 하드웨어에서 매우 저렴합니다!
