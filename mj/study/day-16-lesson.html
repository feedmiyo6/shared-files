📅 Day 16: Metastability

Week 4: Clock Domain Crossing — Welcome to the scariest topic in digital design! Today we tackle metastability — the fundamental physics problem that makes clock domain crossing so dangerous.

4주차: 클록 도메인 크로싱 — 디지털 설계에서 가장 무서운 주제에 오신 것을 환영합니다! 오늘은 메타스테이빌리티(준안정 상태)를 다룹니다 — 클록 도메인 크로싱을 위험하게 만드는 근본적인 물리 문제입니다.

1. What Is Metastability?

Every flip-flop needs data to be stable for a minimum time window around the clock edge. This window has two parts:

모든 플립플롭은 클록 에지 주변의 최소 시간 창 동안 데이터가 안정적이어야 합니다. 이 창은 두 부분으로 구성됩니다:

  • Setup time (tsu): Data must be stable before the clock edge
  • 셋업 시간 (tsu): 클록 에지 이전에 데이터가 안정적이어야 함
  • Hold time (th): Data must remain stable after the clock edge
  • 홀드 시간 (th): 클록 에지 이후에 데이터가 안정적으로 유지되어야 함

🎯 The Problem

When data transitions during the setup/hold window, the flip-flop enters a metastable state — it's neither 0 nor 1, but somewhere in between. The output voltage hovers near the threshold, and it takes an unpredictable amount of time to resolve to a valid logic level.

데이터가 셋업/홀드 윈도우 동안 전환되면, 플립플롭은 준안정 상태에 진입합니다 — 0도 아니고 1도 아닌 그 사이 어딘가에 있게 됩니다. 출력 전압이 임계값 근처에서 머물며, 유효한 로직 레벨로 안정되는 데 예측 불가능한 시간이 걸립니다.

         ◄──────────►   ◄──────────►
              t_su            t_h
                    │
    Data:  ─────────┼─────────────────
           STABLE   │ clock  STABLE
                    │  edge
                    ▼

2. Why Does This Happen? (The Physics)

A flip-flop is built from two cross-coupled inverters forming a bistable element — it has two stable states (0 and 1) and one unstable equilibrium point in between.

플립플롭은 쌍안정 요소를 형성하는 교차 결합된 두 인버터로 구성됩니다 — 두 개의 안정 상태(0과 1)와 그 사이에 하나의 불안정 평형점이 있습니다.

⚖️ The Ball-on-a-Hill Analogy

Imagine a ball on a hill with valleys on each side:

양쪽에 골짜기가 있는 언덕 위의 공을 상상해보세요:

  • Left valley = Logic 0 (stable)
  • 왼쪽 골짜기 = 로직 0 (안정적)
  • Right valley = Logic 1 (stable)
  • 오른쪽 골짜기 = 로직 1 (안정적)
  • Hilltop = Metastable (unstable — any tiny noise will push it one way)
  • 언덕 꼭대기 = 준안정 (불안정 — 아주 작은 노이즈도 한쪽으로 밀어냄)

When data changes during the window, you're placing the ball perfectly on top of the hill. It will eventually fall to one side, but you don't know when or which side.

데이터가 윈도우 동안 변하면, 공을 언덕 꼭대기에 완벽하게 올려놓는 것입니다. 결국 한쪽으로 떨어지겠지만, 언제 그리고 어느 쪽으로 떨어질지 알 수 없습니다.

         │          (ball on hill)
         │
    GND ─── ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  Logic 0 (stable)

3. Resolution Time

The time a flip-flop takes to escape the metastable state is called the resolution time. It follows an exponential probability distribution:

플립플롭이 준안정 상태에서 벗어나는 데 걸리는 시간을 해결 시간이라고 합니다. 이것은 지수 확률 분포를 따릅니다:

📐 Resolution Time Formula

The probability of staying metastable decreases exponentially with time:

준안정 상태를 유지할 확률은 시간이 지남에 따라 기하급수적으로 감소합니다:

// Probability of remaining metastable after time t:
P(tres > t) = Tw · fclk · fdata · e-t/τ

// Where:
//   T_w    = metastability window (setup + hold violation zone)
//   f_clk  = clock frequency
//   f_data = data change frequency
//   τ (tau) = resolution time constant (technology dependent)
//   t      = time allowed for resolution

Key takeaway: You can never eliminate metastability — you can only make it astronomically unlikely by giving the flip-flop more time to resolve.

핵심 요점: 메타스테이빌리티를 완전히 제거할 수는 없습니다 — 플립플롭에게 해결할 시간을 더 줌으로써 천문학적으로 낮은 확률로만 만들 수 있습니다.

4. Mean Time Between Failures (MTBF)

MTBF tells you how often, on average, a metastability failure will occur:

MTBF는 평균적으로 메타스테이빌리티 실패가 얼마나 자주 발생하는지 알려줍니다:

📊 MTBF Formula

// Mean Time Between Failures:
MTBF = et_res/τ / (Tw · fclk · fdata)

// Example: 2-flop synchronizer at 500 MHz
//   τ = 20 ps (typical 7nm process)
//   T_w = 40 ps
//   f_clk = 500 MHz, f_data = 100 MHz
//   t_res = 1 clock period = 2 ns

MTBF = e2000ps/20ps / (40e-12 × 500e6 × 100e6)
MTBF ≈ e100 / 2000
MTBF ≈ 1.3 × 1040 seconds  // Way longer than the universe!

With a 2-flop synchronizer, MTBF is typically billions of years. Without synchronization, failures can happen every few seconds!

2-플립플롭 동기화기를 사용하면 MTBF는 일반적으로 수십억 년입니다. 동기화 없이는 몇 초마다 실패가 발생할 수 있습니다!

Synchronizer Stages Resolution Time Typical MTBF
0 (no sync) 0 Seconds to minutes
1 flip-flop ~1 clock period Hours to days
2 flip-flops ✅ ~2 clock periods Millions of years
3 flip-flops ~3 clock periods 1030+ years

5. When Does Metastability Occur?

Metastability is inevitable whenever you cross between clock domains or handle asynchronous signals:

메타스테이빌리티는 클록 도메인 간 전환이나 비동기 신호를 처리할 때 불가피합니다:

Scenario Risk Level Example
Same clock domain None (if timing is met) Flip-flop to flip-flop, same clock
Button/switch input 🔴 High User pressing a button (async)
Different clock frequencies 🔴 High 100 MHz → 250 MHz domain
Same freq, different phase 🔴 High Two PLLs generating same freq
External interface signals 🔴 High UART RX, SPI MISO

6. The 2-Flop Synchronizer

The standard solution for single-bit signals crossing clock domains is the 2-flop synchronizer:

클록 도메인을 넘나드는 단일 비트 신호의 표준 해결책은 2-플립플롭 동기화기입니다:

module sync_2ff (
    input  logic clk_dst,     // Destination clock
    input  logic rst_n,       // Active-low reset
    input  logic data_in,     // Async input (from source domain)
    output logic data_out     // Synchronized output
);

    logic meta_ff;  // First flop - might go metastable!

    always_ff @(posedge clk_dst or negedge rst_n) begin
        if (!rst_n) begin
            meta_ff  <= 1'b0;
            data_out <= 1'b0;
        end else begin
            meta_ff  <= data_in;   // Stage 1: capture (may be metastable)
            data_out <= meta_ff;  // Stage 2: resolve (almost certainly stable)
        end
    end

endmodule

💡 Why Two Flops?

The first flop might go metastable, but it has an entire clock period to resolve before the second flop samples it. The probability of both flops being metastable is exponentially smaller — the exponent in the MTBF formula doubles!

첫 번째 플립플롭은 준안정 상태가 될 수 있지만, 두 번째 플립플롭이 샘플링하기 전에 전체 클록 주기 동안 해결할 시간이 있습니다. 두 플립플롭 모두 준안정 상태일 확률은 기하급수적으로 작습니다 — MTBF 공식의 지수가 두 배가 됩니다!

⚠️ Common Mistakes

  • Adding logic between sync flops: Never put combinational logic between the two synchronizer flip-flops — it eats into resolution time
  • 동기화 플립플롭 사이에 로직 추가: 두 동기화 플립플롭 사이에 조합 로직을 넣지 마세요 — 해결 시간을 줄입니다
  • Synchronizing multi-bit signals with separate 2FFs: Each bit may resolve on different cycles, giving you corrupted data. Use Gray code or handshake protocols instead (Days 18-19)
  • 별도의 2FF로 멀티비트 신호 동기화: 각 비트가 다른 사이클에서 해결되어 손상된 데이터를 줄 수 있습니다. 대신 그레이 코드나 핸드셰이크 프로토콜을 사용하세요 (18-19일차)
  • Forgetting to constrain in synthesis: Tell the tool these are synchronizer flops so it places them close together
  • 합성에서 제약을 잊기: 이것이 동기화 플립플롭임을 도구에 알려서 서로 가까이 배치하도록 하세요

7. Factors Affecting MTBF

Factor Effect on MTBF What You Can Do
Higher clock frequency ⬇️ Decreases MTBF Add more sync stages
Higher data rate ⬇️ Decreases MTBF Reduce unnecessary transitions
More sync stages ⬆️ Increases MTBF exponentially Use 3 stages for very high freq
Faster technology (smaller τ) ⬆️ Increases MTBF Choose appropriate process node
Higher voltage ⬆️ Increases MTBF (faster switching) Trade power for reliability

8. Real-World Consequences

💥 What Happens When Metastability Hits?

  • Data corruption: Downstream logic sees a glitch or wrong value
  • 데이터 손상: 하위 로직이 글리치나 잘못된 값을 봄
  • FSM lockup: State machine enters illegal state (remember Day 9?)
  • FSM 잠금: 상태 머신이 불법 상태에 진입 (9일차 기억나세요?)
  • Control signal errors: Enable/reset signals fire at wrong time
  • 제어 신호 오류: 활성화/리셋 신호가 잘못된 시간에 발생
  • System crash: In the worst case, entire system becomes non-functional
  • 시스템 충돌: 최악의 경우 전체 시스템이 작동 불능 상태

The scary part: these failures are non-deterministic and non-reproducible. They might happen once a week, and you'll never see them in simulation!

무서운 점: 이러한 실패는 비결정적이고 재현 불가능합니다. 일주일에 한 번 발생할 수 있으며, 시뮬레이션에서는 절대 볼 수 없습니다!

9. Summary

📝 Key Takeaways

  1. Metastability occurs when data changes during the setup/hold window
  2. 메타스테이빌리티는 데이터가 셋업/홀드 윈도우 동안 변할 때 발생합니다
  3. It cannot be eliminated, only made astronomically unlikely
  4. 제거할 수 없으며, 천문학적으로 낮은 확률로만 만들 수 있습니다
  5. The 2-flop synchronizer is the standard solution for single-bit CDC
  6. 2-플립플롭 동기화기는 단일 비트 CDC의 표준 해결책입니다
  7. MTBF increases exponentially with each synchronizer stage
  8. MTBF는 각 동기화 단계마다 기하급수적으로 증가합니다
  9. Never put logic between synchronizer flip-flops
  10. 동기화 플립플롭 사이에 로직을 절대 넣지 마세요
  11. Multi-bit signals need special techniques (Gray code, handshake, FIFO)
  12. 멀티비트 신호는 특별한 기술이 필요합니다 (그레이 코드, 핸드셰이크, FIFO)
