🔧 Exercise 2: Fix the Buggy Source

This ready/valid source has a critical protocol violation. Find and fix it!

이 ready/valid 소스에는 중요한 프로토콜 위반이 있습니다. 찾아서 고치세요!

module buggy_source #(
    parameter DATA_W = 8
)(
    input  logic              clk,
    input  logic              rst_n,
    input  logic              data_available,
    input  logic [DATA_W-1:0] next_data,
    output logic              o_valid,
    output logic [DATA_W-1:0] o_data,
    input  logic              i_ready
);

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            o_valid <= 1'b0;
            o_data  <= '0;
        end else begin
            // BUG: What's wrong here?
            o_valid <= data_available;
            o_data  <= next_data;
        end
    end

endmodule

💡 Hint: What happens when o_valid=1, i_ready=0, and data_available changes? Think about the stall rule.

💡 힌트: o_valid=1, i_ready=0이고 data_available이 변경되면 어떻게 됩니까? 스톨 규칙을 생각해보세요.

🐛 The Bug

The source updates o_valid and o_data every cycle, regardless of whether a stall is happening. If o_valid=1 and i_ready=0 (stall), but data_available goes low, the source will deassert valid — protocol violation! It also changes o_data during the stall.

소스가 스톨 여부와 관계없이 매 사이클 o_valid와 o_data를 업데이트합니다. o_valid=1이고 i_ready=0(스톨)이지만 data_available이 로우가 되면 소스가 valid를 디어서트합니다 — 프로토콜 위반! 또한 스톨 중에 o_data를 변경합니다.

✅ Fixed Code

always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        o_valid <= 1'b0;
        o_data  <= '0;
    end else if (o_valid && !i_ready) begin
        // STALL: hold valid and data stable!
        // Do nothing — keep current values
    end else begin
        // Transfer complete or idle: safe to update
        o_valid <= data_available;
        o_data  <= next_data;
    end
end

Key fix: Added the o_valid && !i_ready stall condition. During stall, the always_ff block does nothing — holding both signals stable.

핵심 수정: o_valid && !i_ready 스톨 조건을 추가했습니다. 스톨 중 always_ff 블록은 아무것도 하지 않아 두 신호를 안정적으로 유지합니다.

🔧 Exercise 3: Write a Ready/Valid Counter Source

Design a module that outputs an incrementing counter (0, 1, 2, 3, ...) using the ready/valid protocol. The counter only advances when a transfer occurs. Include proper stall handling!

Ready/valid 프로토콜을 사용하여 증가하는 카운터 (0, 1, 2, 3, ...)를 출력하는 모듈을 설계하세요. 카운터는 전송이 발생할 때만 진행됩니다. 적절한 스톨 처리를 포함하세요!

📋 Requirements

  • Output: o_valid, o_data[7:0] (8-bit counter)
  • 출력: o_valid, o_data[7:0] (8비트 카운터)
  • Input: i_ready
  • 입력: i_ready
  • o_valid is always high (always has data)
  • o_valid는 항상 하이 (항상 데이터가 있음)
  • Counter only increments when valid && ready
  • 카운터는 valid && ready일 때만 증가
  • Proper async reset (counter starts at 0)
  • 적절한 비동기 리셋 (카운터는 0에서 시작)

✅ Solution

module rv_counter (
    input  logic       clk,
    input  logic       rst_n,
    output logic       o_valid,
    output logic [7:0] o_data,
    input  logic       i_ready
);

    // Always have data to send
    assign o_valid = 1'b1;

    // Transfer detection
    logic transfer;
    assign transfer = o_valid && i_ready;

    // Counter — only increments on transfer
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            o_data <= 8'd0;
        else if (transfer)
            o_data <= o_data + 8'd1;
        // else: stall — hold current value
    end

endmodule

Key points:

핵심 포인트:

  • o_valid = 1 always — this counter always has data to send
  • o_valid = 1 항상 — 이 카운터는 항상 보낼 데이터가 있음
  • Counter increments ONLY on transfer — stall holds the value
  • 카운터는 transfer 시에만 증가 — 스톨 시 값 유지
  • No deadlock risk: valid doesn't depend on ready
  • 데드락 위험 없음: valid가 ready에 의존하지 않음
  • Data stays stable during stall (implicit in the else branch)
  • 스톨 중 데이터 안정 유지 (else 분기에 암시적)

module tb_rv_counter;
    logic clk, rst_n, o_valid, i_ready;
    logic [7:0] o_data;

    rv_counter dut (.*);

    // Clock: 10ns period
    initial clk = 0;
    always #5 clk = ~clk;

    initial begin
        rst_n = 0; i_ready = 0;
        #20 rst_n = 1;

        // Back-to-back transfers
        @(posedge clk) i_ready <= 1;
        repeat(5) @(posedge clk);

        // Stall for 3 cycles
        i_ready <= 0;
        repeat(3) @(posedge clk);

        // Resume
        i_ready <= 1;
        repeat(5) @(posedge clk);

        // Random ready
        repeat(20) begin
            @(posedge clk) i_ready <= $urandom_range(0,1);
        end

        $finish;
    end

    // Monitor
    always @(posedge clk) begin
        if (o_valid && i_ready)
            $display("[%0t] TRANSFER: data=%0d", $time, o_data);
    end

endmodule
