Exercise 1: Pulse Synchronizer

🎯 Task

Implement a pulse synchronizer module. Given a single-cycle pulse in clk_a domain, produce a single-cycle pulse in clk_b domain using the toggle-and-edge-detect technique.

clk_a 도메인의 단일 사이클 펄스를 받아 토글-엣지 감지 기법으로 clk_b 도메인에서 단일 사이클 펄스를 생성하는 펄스 동기화기 모듈을 구현하세요.

Requirements:

요구사항:

  • Use a toggle flip-flop in domain A
  • 도메인 A에서 토글 플립플롭 사용
  • Use a 2-flop synchronizer in domain B
  • 도메인 B에서 2-플립플롭 동기화기 사용
  • Detect edges using XOR to regenerate the pulse
  • XOR을 사용하여 엣지를 감지하고 펄스를 재생성
  • Include async active-low reset for both domains
  • 두 도메인 모두에 비동기 active-low 리셋 포함

Start with this skeleton:

이 스켈레톤으로 시작하세요:

module pulse_sync (
    input  logic clk_a,
    input  logic rst_a_n,
    input  logic pulse_in,
    input  logic clk_b,
    input  logic rst_b_n,
    output logic pulse_out
);

    // TODO: Declare internal signals

    // TODO: Toggle in domain A

    // TODO: 2-flop sync in domain B

    // TODO: Edge detect for pulse output

endmodule
💡 Hint: You need 4 internal signals: toggle_a, sync_1, sync_2, and sync_prev. The pulse output is sync_2 ^ sync_prev. 4개의 내부 신호가 필요합니다: toggle_a, sync_1, sync_2, sync_prev. 펄스 출력은 sync_2 ^ sync_prev입니다. 
module pulse_sync (
    input  logic clk_a,
    input  logic rst_a_n,
    input  logic pulse_in,
    input  logic clk_b,
    input  logic rst_b_n,
    output logic pulse_out
);

    logic toggle_a;
    logic sync_1, sync_2, sync_prev;

    // Toggle in domain A on each pulse
    always_ff @(posedge clk_a or negedge rst_a_n) begin
        if (!rst_a_n)
            toggle_a <= 1'b0;
        else if (pulse_in)
            toggle_a <= ~toggle_a;
    end

    // 2-flop synchronizer + previous value in domain B
    always_ff @(posedge clk_b or negedge rst_b_n) begin
        if (!rst_b_n) begin
            sync_1    <= 1'b0;
            sync_2    <= 1'b0;
            sync_prev <= 1'b0;
        end else begin
            sync_1    <= toggle_a;
            sync_2    <= sync_1;
            sync_prev <= sync_2;
        end
    end

    // XOR detects any edge = regenerated pulse
    assign pulse_out = sync_2 ^ sync_prev;

endmodule

Exercise 2: Req/Ack Handshake CDC

🎯 Task

Implement a simplified req/ack handshake module that transfers an 8-bit command from a fast clock domain (100 MHz) to a slow clock domain (25 MHz). Focus on the receiver side — the sender side is provided.

빠른 클록 도메인(100 MHz)에서 느린 클록 도메인(25 MHz)으로 8비트 명령을 전달하는 간소화된 req/ack 핸드셰이크 모듈을 구현하세요. 수신측에 집중하세요 — 송신측은 제공됩니다.

Complete the receiver logic:

수신측 로직을 완성하세요:

// Receiver side - clk_slow domain
// Given: req_sync_2 (synchronized req from sender)
// Given: data_reg (stable data from sender)
// Output: data_out, valid_out, ack_b

always_ff @(posedge clk_slow or negedge rst_n) begin
    if (!rst_n) begin
        // TODO: Reset all outputs
    end else begin
        // TODO: Default valid_out to 0
        // TODO: On rising edge of req_sync_2:
        //   - Capture data_reg into data_out
        //   - Assert valid_out for one cycle
        //   - Assert ack_b
        // TODO: When req_sync_2 goes low:
        //   - De-assert ack_b
    end
end
💡 Hint: You need a req_sync_prev register to detect the rising edge of req_sync_2. Rising edge = req_sync_2 && !req_sync_prev. req_sync_2의 상승 엣지를 감지하기 위해 req_sync_prev 레지스터가 필요합니다. 상승 엣지 = req_sync_2 && !req_sync_prev. 
logic req_sync_prev;

always_ff @(posedge clk_slow or negedge rst_n) begin
    if (!rst_n) begin
        data_out      <= 8'b0;
        valid_out     <= 1'b0;
        ack_b         <= 1'b0;
        req_sync_prev <= 1'b0;
    end else begin
        valid_out     <= 1'b0;  // Default: one-cycle pulse
        req_sync_prev <= req_sync_2;

        // Rising edge of synchronized req
        if (req_sync_2 && !req_sync_prev) begin
            data_out  <= data_reg;  // Safe to sample!
            valid_out <= 1'b1;
            ack_b     <= 1'b1;
        end

        // When req goes away, release ack
        if (!req_sync_2) begin
            ack_b <= 1'b0;
        end
    end
end

Exercise 3: Timing Analysis Challenge

🎯 Scenario

You have a 4-phase handshake between a 200 MHz sender and a 50 MHz receiver. Each 2-flop synchronizer adds 2 clock cycles of latency in the destination domain. Calculate the minimum time for one complete transfer and the maximum throughput.

200 MHz 송신측과 50 MHz 수신측 사이에 4-phase 핸드셰이크가 있습니다. 각 2-플립플롭 동기화기는 목적지 도메인에서 2 클록 사이클의 레이턴시를 추가합니다. 한 번의 완전한 전송에 필요한 최소 시간과 최대 처리량을 계산하세요.

Work through these steps:

다음 단계를 풀어보세요:

  1. What is the clock period of each domain?
  2. 각 도메인의 클록 주기는?
  3. Phase 1 (req↑ sync): How long for req to sync into receiver domain?
  4. Phase 1 (req↑ 동기화): req가 수신측 도메인으로 동기화되는데 얼마나 걸리나요?
  5. Phase 2 (ack↑ sync): How long for ack to sync into sender domain?
  6. Phase 2 (ack↑ 동기화): ack가 송신측 도메인으로 동기화되는데 얼마나 걸리나요?
  7. Phase 3+4: Same again for de-assertion
  8. Phase 3+4: 디어서트에 대해 같은 과정
  9. Total time and throughput?
  10. 총 시간과 처리량?

📝 Solution

Clock periods:

클록 주기:

  • Sender (200 MHz): Ts = 5 ns
  • Receiver (50 MHz): Tr = 20 ns

4-phase timing:

4-phase 타이밍:

  1. req↑ syncs into receiver: 2 × Tr = 2 × 20 = 40 ns
  2. req↑ 수신측으로 동기화: 2 × Tr = 2 × 20 = 40 ns
  3. ack↑ syncs into sender: 2 × Ts = 2 × 5 = 10 ns
  4. ack↑ 송신측으로 동기화: 2 × Ts = 2 × 5 = 10 ns
  5. req↓ syncs into receiver: 2 × Tr = 40 ns
  6. req↓ 수신측으로 동기화: 2 × Tr = 40 ns
  7. ack↓ syncs into sender: 2 × Ts = 10 ns
  8. ack↓ 송신측으로 동기화: 2 × Ts = 10 ns

Total: 40 + 10 + 40 + 10 = 100 ns per transfer

총합: 40 + 10 + 40 + 10 = 전송당 100 ns

Max throughput: 1 / 100 ns = 10 MHz = 10 million transfers/sec

최대 처리량: 1 / 100 ns = 10 MHz = 초당 1000만 전송

Note: This is much slower than either clock! That's the handshake tradeoff — safety over speed. For 8-bit data: 10M × 8 bits = 80 Mbps effective bandwidth.

참고: 이는 어느 클록보다도 훨씬 느립니다! 이것이 핸드셰이크의 트레이드오프 — 속도보다 안전성. 8비트 데이터의 경우: 10M × 8 bits = 80 Mbps 유효 대역폭.
