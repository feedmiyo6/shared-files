Yesterday you learned what synthesis does at a high level. Today we zoom in: every line of RTL code you write maps to specific hardware structures. Understanding this mapping is what separates someone who writes code from someone who designs hardware.

어제는 합성(synthesis)이 무엇을 하는지 높은 수준에서 배웠습니다. 오늘은 더 깊이 들어갑니다: 여러분이 작성하는 RTL 코드의 모든 줄은 특정 하드웨어 구조에 매핑됩니다. 이 매핑을 이해하는 것이 코드를 작성하는 사람과 하드웨어를 설계하는 사람의 차이입니다.

1. The Code → Hardware Mental Model 1. 코드 → 하드웨어 멘탈 모델

🧠 Key Insight

When you write SystemVerilog, you're not writing software instructions. You're describing circuits. The synthesis tool's job is to figure out what circuit you described and build it from the standard cells in its library.

SystemVerilog를 작성할 때, 소프트웨어 명령어를 작성하는 것이 아닙니다. 회로를 설명하는 것입니다. 합성 도구의 역할은 여러분이 설명한 회로가 무엇인지 파악하고 라이브러리의 표준 셀로 그것을 구축하는 것입니다.

Here's the fundamental mapping every digital designer must know:

모든 디지털 설계자가 알아야 할 기본 매핑입니다:

2. Flip-Flops: The Storage Elements 2. 플립플롭: 저장 요소

Any signal assigned inside always_ff @(posedge clk) becomes a flip-flop. Every bit = one flip-flop. This is the #1 rule of inferred hardware.

always_ff @(posedge clk) 내부에서 할당된 모든 신호는 플립플롭이 됩니다. 모든 비트 = 하나의 플립플롭. 이것이 추론 하드웨어의 #1 규칙입니다.

Simple Register 단순 레지스터 

always_ff @(posedge clk or posedge rst) begin
    if (rst)
        q <= 8'h00;        // Reset value
    else
        q <= d;             // D input → Q output
end
// Infers: 8 flip-flops with async reset

Register with Enable 인에이블이 있는 레지스터 

always_ff @(posedge clk) begin
    if (rst)
        q <= '0;
    else if (en)          // Enable signal
        q <= d;
    // else: q holds its value (implicit)
end
// Infers: flip-flops + mux on D input (enable gating)

💡 Cost Awareness

Each bit of a registered signal = one flip-flop. A logic [31:0] data_reg = 32 flip-flops. A logic [7:0] mem [0:255] = 2,048 flip-flops! Always think about how many bits you're registering.

등록된 신호의 각 비트 = 하나의 플립플롭. logic [31:0] data_reg = 32개의 플립플롭. logic [7:0] mem [0:255] = 2,048개의 플립플롭! 몇 비트를 등록하고 있는지 항상 생각하세요.

3. Multiplexers: The Decision Makers 3. 멀티플렉서: 의사 결정기

Every if/else and ? : in combinational logic becomes a multiplexer. Nested if/else chains create priority mux chains — which have timing implications.

조합 논리에서 모든 if/else와 ? :는 멀티플렉서가 됩니다. 중첩된 if/else 체인은 우선순위 멀티플렉서 체인을 생성합니다 — 이는 타이밍에 영향을 미칩니다.

If/Else → Priority Mux If/Else → 우선순위 멀티플렉서 

always_comb begin
    if (sel_a)
        out = data_a;        // Highest priority
    else if (sel_b)
        out = data_b;        // Second priority
    else if (sel_c)
        out = data_c;        // Third priority
    else
        out = data_d;        // Default
end
// Infers: chain of 2:1 muxes — sel_a checked first!
// Critical path: sel_c → out (deepest in chain)

Case → Balanced Mux Case → 균형 멀티플렉서 

always_comb begin
    case (sel)
        2'b00: out = data_a;
        2'b01: out = data_b;
        2'b10: out = data_c;
        2'b11: out = data_d;
    endcase
end
// Infers: 4:1 mux — all paths equal priority
// Better timing than if/else chain!

⚠️ If/Else vs Case — Timing Impact

A chain of 8 if/else creates 8 levels of muxes in series (long critical path). A case with 8 options creates a single wide mux (shorter path). Use case when conditions are mutually exclusive — it gives the synthesizer freedom to optimize.

8개의 if/else 체인은 직렬로 8단계의 멀티플렉서를 생성합니다 (긴 크리티컬 패스). 8개 옵션의 case는 단일 넓은 멀티플렉서를 생성합니다 (짧은 경로). 조건이 상호 배타적일 때 case를 사용하세요 — 합성기에게 최적화의 자유를 줍니다.

4. Arithmetic: Adders, Subtractors, Multipliers 4. 산술: 가산기, 감산기, 곱셈기

Arithmetic operators map directly to dedicated hardware. But their cost varies enormously.

산술 연산자는 전용 하드웨어에 직접 매핑됩니다. 그러나 비용은 크게 다릅니다.

OperatorHardwareArea CostTiming Cost
a + bAdderLow (linear with width)Moderate
a - bSubtractor (adder + invert)LowModerate
a * bMultiplierHIGH (quadratic!)HIGH
a / bDividerVERY HIGHVERY HIGH
a % bModulo (divider)VERY HIGHVERY HIGH
a << n (constant)Wires only!FREEFREE
a << b (variable)Barrel shifterModerateModerate

The Multiplication Trap 곱셈의 함정 

// This looks innocent...
assign result = a * b;  // 32-bit * 32-bit

// But it infers a HUGE multiplier:
//   - ~1000+ gates
//   - Multiple clock cycles of combinational delay
//   - May need pipelining to meet timing

// Power-of-2 multiply is FREE:
assign times_8 = a << 3;   // Just wires! a * 8

// Constant multiply is cheaper:
assign times_5 = (a << 2) + a;  // a*4 + a = a*5

💡 Shift Tricks

Shifting by a constant is free — it's just rewiring. a << 3 = multiply by 8 with zero gates. Always prefer shifts for power-of-2 operations. Division by power-of-2: a >> 2 = divide by 4 (for unsigned).

상수만큼의 시프트는 무료입니다 — 단순히 배선 변경입니다. a << 3 = 게이트 제로로 8을 곱합니다. 2의 거듭제곱 연산에는 항상 시프트를 선호하세요. 2의 거듭제곱으로 나누기: a >> 2 = 4로 나누기 (부호 없는 경우).

5. Free Operations: Wires Are Just Routing 5. 무료 연산: 와이어는 단순한 라우팅

Some operations that look like they "do something" are actually free — they just rearrange wires:

무언가를 "하는 것처럼" 보이는 일부 연산은 실제로 무료입니다 — 단순히 와이어를 재배열합니다:

// All of these are FREE — just wire routing:

// Concatenation — merging wires
assign word = {upper, lower};

// Bit slicing — selecting wires
assign nibble = byte_val[3:0];

// Constant shift — rewiring
assign shifted = data << 4;

// Replication — fanning out wires
assign sign_ext = {24{val[7]}, val};

// Bit reversal — just routing
assign reversed[7:0] = {data[0], data[1], data[2], data[3],
                          data[4], data[5], data[6], data[7]};

🎯 Why This Matters

When optimizing for area or timing, know what's free and what costs gates. Restructuring a * 6 as (a << 2) + (a << 1) replaces a multiplier with two shifts (free) and one adder (cheap). That's a massive savings!

면적이나 타이밍을 최적화할 때, 무엇이 무료이고 무엇이 게이트를 소비하는지 알아야 합니다. a * 6을 (a << 2) + (a << 1)로 재구성하면 곱셈기를 두 개의 시프트(무료)와 하나의 가산기(저렴)로 대체합니다. 엄청난 절약입니다!

6. Common Inference Patterns 6. 일반적인 추론 패턴

Counter → Adder + Register 카운터 → 가산기 + 레지스터 

always_ff @(posedge clk) begin
    if (rst)
        count <= '0;
    else
        count <= count + 1;  // Adder feeds back into register
end
// Infers: N-bit adder → N flip-flops → feedback loop

Shift Register → Chain of Flip-Flops 시프트 레지스터 → 플립플롭 체인 

always_ff @(posedge clk) begin
    pipe[0] <= data_in;
    pipe[1] <= pipe[0];
    pipe[2] <= pipe[1];
end
// Infers: 3-stage pipeline (FF → FF → FF)
// Each pipe[n] = W flip-flops (W = data width)

Decoder → AND/OR Logic 디코더 → AND/OR 로직 

always_comb begin
    enable = '0;         // Default all bits to 0
    case (addr)
        2'b00: enable[0] = 1'b1;
        2'b01: enable[1] = 1'b1;
        2'b10: enable[2] = 1'b1;
        2'b11: enable[3] = 1'b1;
    endcase
end
// Infers: 2-to-4 decoder (a few AND gates)

Tri-state → Mux (in modern synthesis) 트라이스테이트 → 멀티플렉서 (현대 합성에서) 

// You write this:
assign bus = en ? data : 'z;

// Synthesis maps it to:
// For internal signals → MUX (no tri-state inside ASIC/FPGA)
// For I/O pads → actual tri-state buffer

7. Dangerous Inferences to Watch For 7. 주의해야 할 위험한 추론

⚠️ Unintentional Latches

If you forget a default assignment or miss a branch in always_comb, synthesis infers a latch — almost always a bug. We'll cover this in depth on Day 33!

always_comb에서 기본 할당을 잊거나 분기를 놓치면 합성이 래치를 추론합니다 — 거의 항상 버그입니다. Day 33에서 이것을 자세히 다룹니다!

// 🚫 BAD: Missing else → latch!
always_comb begin
    if (sel)
        out = data_a;
    // No else! What is 'out' when sel=0?
    // → Must hold previous value → LATCH inferred!
end

// ✅ GOOD: Default assignment prevents latch
always_comb begin
    out = data_b;       // Default value
    if (sel)
        out = data_a;
end

⚠️ Combinational Loops

If a signal depends on itself without a clock edge, you get a combinational loop — the circuit oscillates or settles to an unknown value. Synthesis tools will flag this as an error.

클록 에지 없이 신호가 자기 자신에 의존하면 조합 루프가 발생합니다 — 회로가 진동하거나 알 수 없는 값으로 정착합니다. 합성 도구가 이를 오류로 표시합니다.

// 🚫 COMBINATIONAL LOOP — never do this!
always_comb begin
    a = b + 1;
    b = a + 1;  // a depends on b, b depends on a!
end

8. Thinking in Hardware: A Complete Example 8. 하드웨어로 생각하기: 완전한 예제

Let's trace through a real module and identify every piece of hardware it infers:

실제 모듈을 추적하며 추론하는 모든 하드웨어를 식별해봅시다:

module alu_simple (
    input  logic        clk, rst,
    input  logic [7:0]  a, b,
    input  logic [1:0]  op,
    output logic [7:0]  result
);
    logic [7:0] alu_out;  // Combinational wire

    // Combinational: 4:1 mux + adder + AND + XOR
    always_comb begin
        case (op)
            2'b00: alu_out = a + b;  // → Adder
            2'b01: alu_out = a - b;  // → Subtractor
            2'b10: alu_out = a & b;  // → AND gates
            2'b11: alu_out = a ^ b;  // → XOR gates
        endcase
    end

    // Sequential: 8 flip-flops for output register
    always_ff @(posedge clk) begin
        if (rst)
            result <= 8'h00;
        else
            result <= alu_out;  // Register the output
    end
endmodule

📦 Hardware Breakdown

  • 8-bit adder — for a + b
  • 8-bit subtractor — for a - b
  • 8x AND gates — for a & b
  • 8x XOR gates — for a ^ b
  • 4:1 mux (8-bit wide) — the case statement selects one of four results
  • 8 flip-flops — the output register
  • 8 muxes — reset path (rst ? 0 : alu_out)
  • 8비트 가산기 — a + b용
  • 8비트 감산기 — a - b용
  • 8개 AND 게이트 — a & b용
  • 8개 XOR 게이트 — a ^ b용
  • 4:1 멀티플렉서 (8비트 폭) — case문이 4개 결과 중 하나를 선택
  • 8개 플립플롭 — 출력 레지스터
  • 8개 멀티플렉서 — 리셋 경로 (rst ? 0 : alu_out)

📋 Today's Key Takeaways 📋 오늘의 핵심 요약

  1. always_ff → flip-flops. Every bit = one FF. Know your bit counts.
  2. if/else → priority mux chain. Use case when possible for better timing.
  3. Multiplication is expensive. Prefer shifts and adds for constants.
  4. Concatenation, slicing, constant shifts are FREE. Just wire routing.
  5. Missing branches → latches. Always provide defaults in combinational logic.
  6. Think in hardware. Every line of RTL maps to gates, muxes, or flip-flops.
  7. always_ff → 플립플롭. 모든 비트 = 하나의 FF. 비트 수를 파악하세요.
  8. if/else → 우선순위 멀티플렉서 체인. 가능하면 더 나은 타이밍을 위해 case를 사용하세요.
  9. 곱셈은 비용이 높습니다. 상수에는 시프트와 덧셈을 선호하세요.
  10. 연결, 슬라이싱, 상수 시프트는 무료. 단순한 와이어 라우팅입니다.
  11. 빠진 분기 → 래치. 조합 논리에서 항상 기본값을 제공하세요.
  12. 하드웨어로 생각하세요. RTL의 모든 줄은 게이트, 멀티플렉서 또는 플립플롭에 매핑됩니다.
