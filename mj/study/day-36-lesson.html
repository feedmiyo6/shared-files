What is a FIFO? FIFO란 무엇인가?

FIFO stands for First In, First Out. It's a fundamental data structure in digital design that acts as a buffer between two clock domains or between components with different data rates.

FIFO는 First In, First Out(선입선출)의 약자입니다. 두 개의 클럭 도메인 사이나 서로 다른 데이터 속도를 가진 컴포넌트 사이에서 버퍼 역할을 하는 디지털 설계의 기본 데이터 구조입니다.

Real-World Analogy 실제 세계 비유

Think of a FIFO like a line at a coffee shop. The first person in line (first in) is the first to get their coffee (first out). The line can grow when people arrive faster than they're served, and shrink when the barista works faster than customers arrive.

FIFO를 커피숍의 줄에 비유해 보세요. 줄의 첫 번째 사람(선입)이 가장 먼저 커피를 받습니다(선출). 사람들이 제공되는 것보다 빨리 도착할 때 줄이 길어지고, 바리스타가 고객보다 빨리 일할 때 줄이 짧아집니다.

Why Do We Need FIFOs? 왜 FIFO가 필요한가?

FIFOs solve several common problems in digital systems:

FIFO는 디지털 시스템의 여러 일반적인 문제를 해결합니다:

  • Clock Domain Crossing (CDC): Transfer data safely between different clock domains
  • 클럭 도메인 교차(CDC): 서로 다른 클럭 도메인 간에 데이터를 안전하게 전송
  • Rate Matching: Buffer data when producer and consumer have different speeds
  • 속도 매칭: 생산자와 소비자의 속도가 다를 때 데이터 버퍼링
  • Burst Handling: Absorb temporary bursts of data without loss
  • 버스트 처리: 데이터 손실 없이 일시적인 데이터 버스트 흡수
  • Decoupling: Allow producer and consumer to operate independently
  • 디커플링: 생산자와 소비자가 독립적으로 작동할 수 있도록 함

FIFO Structure: The Two Pointers FIFO 구조: 두 개의 포인터

At the heart of every FIFO are two pointers:

모든 FIFO의 핵심에는 두 개의 포인터가 있습니다:

1. Write Pointer (wr_ptr) 1. 쓰기 포인터 (wr_ptr)

Points to the next location where data will be written. Incremented on every successful write operation.

데이터가 쓰여질 다음 위치를 가리킵니다. 모든 성공적인 쓰기 작업에서 증가합니다.

2. Read Pointer (rd_ptr) 2. 읽기 포인터 (rd_ptr)

Points to the next location where data will be read. Incremented on every successful read operation.

데이터가 읽혀질 다음 위치를 가리킵니다. 모든 성공적인 읽기 작업에서 증가합니다.

Basic FIFO Implementation 기본 FIFO 구현

Here's a synchronous FIFO with read and write pointers:

읽기 및 쓰기 포인터가 있는 동기식 FIFO입니다:

// Synchronous FIFO - Single Clock Domain
// 동기식 FIFO - 단일 클럭 도메인
module sync_fifo #(
    parameter DATA_WIDTH = 8,
    parameter DEPTH = 16,
    parameter ADDR_WIDTH = 4  // log2(DEPTH)
)(
    input  logic clk,
    input  logic rst_n,
    
    // Write interface
    input  logic wr_en,
    input  logic [DATA_WIDTH-1:0] wr_data,
    
    // Read interface
    input  logic rd_en,
    output logic [DATA_WIDTH-1:0] rd_data,
    
    // Status
    output logic full,
    output logic empty
);

    // Memory array
    logic [DATA_WIDTH-1:0] mem [0:DEPTH-1];
    
    // Pointers
    logic [ADDR_WIDTH-1:0] wr_ptr, rd_ptr;
    
    // Write operation
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            wr_ptr <= 0;
        end else if (wr_en && !full) begin
            mem[wr_ptr] <= wr_data;
            wr_ptr <= wr_ptr + 1;
        end
    end
    
    // Read operation
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            rd_ptr <= 0;
        end else if (rd_en && !empty) begin
            rd_ptr <= rd_ptr + 1;
        end
    end
    
    // Combinational read data
    assign rd_data = mem[rd_ptr];
    
    // Status flags
    assign empty = (wr_ptr == rd_ptr);
    assign full  = (wr_ptr == rd_ptr - 1);

endmodule

Pointer Arithmetic: The Key Insight 포인터 연산: 핵심 통찰

The pointers wrap around using modulo arithmetic. For a FIFO with DEPTH = 16:

포인터는 모듈로 연산을 사용하여 래핑됩니다. DEPTH = 16인 FIFO의 경우:

  • wr_ptr goes: 0 → 1 → 2 → ... → 15 → 0 → 1 ...
  • wr_ptr는 다음과 같이 이동: 0 → 1 → 2 → ... → 15 → 0 → 1 ...
  • rd_ptr follows the same pattern
  • rd_ptr도 동일한 패턴을 따름

💡 Tip: In SystemVerilog, adding 1 to a 4-bit pointer that holds 15 results in 0 automatically due to overflow. This gives us "free" wrapping!

💡 팁: SystemVerilog에서 15를 보유한 4비트 포인터에 1을 더하면 오버플로우로 인해 자동으로 0이 됩니다. 이것이 "무료" 래핑입니다!

Full and Empty Conditions Full 및 Empty 조건

Here's the tricky part: how do we distinguish between full and empty?

여기가 까다로운 부분입니다: full과 empty를 어떻게 구분할까요?

Empty Condition Empty 조건

empty = (wr_ptr == rd_ptr)

When both pointers are equal, the FIFO is empty. This makes intuitive sense — we've read everything we've written.

empty = (wr_ptr == rd_ptr)

두 포인터가 같을 때 FIFO는 비어 있습니다. 직관적으로 이해할 수 있습니다 — 쓴 모든 것을 읽었습니다.

Full Condition (Simple Version) Full 조건 (간단한 버전)

full = (wr_ptr == rd_ptr - 1)

The FIFO is full when the write pointer is just behind the read pointer (with wrap-around). However, this wastes one location!

full = (wr_ptr == rd_ptr - 1)

쓰기 포인터가 읽기 포인터 바로 뒤에 있을 때(래핑 포함) FIFO는 꽉 찹니다. 그러나 이것은 하나의 위치를 낭비합니다!

⚠️ The Full/Empty Ambiguity Problem ⚠️ Full/Empty 모호성 문제

If wr_ptr == rd_ptr means empty, and we want to use all locations, how do we detect full? Tomorrow we'll learn about using an extra bit to solve this!

wr_ptr == rd_ptr가 empty를 의미하고 모든 위치를 사용하려면 어떻게 full을 감지할까요? 내일 추가 비트를 사용하여 이를 해결하는 방법을 배우겠습니다!
