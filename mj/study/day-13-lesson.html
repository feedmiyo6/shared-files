1. What is Clock Skew?

Clock skew is the difference in arrival time of the same clock edge at two different flip-flops. Even though we draw one clock driving everything, the physical reality is that the clock signal travels through wires and buffers, arriving at different points at slightly different times.

클럭 스큐는 동일한 클럭 에지가 두 개의 서로 다른 플립플롭에 도달하는 시간 차이입니다. 하나의 클럭이 모든 것을 구동하는 것처럼 그리지만, 물리적으로 클럭 신호는 와이어와 버퍼를 통해 전파되므로 각 지점에 약간 다른 시간에 도달합니다.

📐 Formal Definition

Clock skew (tskew) = tclk→FF2 − tclk→FF1

클럭 스큐 (tskew) = tclk→FF2 − tclk→FF1

Where FF1 is the launching flop and FF2 is the capturing flop.

여기서 FF1은 발신 플립플롭이고 FF2는 수신 플립플롭입니다.

  • Positive skew: Clock arrives at FF2 later than FF1 → helps setup, hurts hold
  • 양의 스큐: 클럭이 FF2에 FF1보다 늦게 도달 → 셋업에 유리, 홀드에 불리
  • Negative skew: Clock arrives at FF2 earlier than FF1 → hurts setup, helps hold
  • 음의 스큐: 클럭이 FF2에 FF1보다 일찍 도달 → 셋업에 불리, 홀드에 유리
         CLK Source
             │
        ┌────┴────┐
        │ Clock   │
        │  Tree   │
        └─┬────┬──┘
          │    │
     Buffer  Buffer
       +     ++
          │    │
     ┌────┴┐ ┌┴────┐
     │ FF1 │ │ FF2 │
     └─────┘ └─────┘
       t₁       t₂

  Skew = t₂ - t₁

2. Sources of Clock Skew

Clock skew has several root causes in real chips:

실제 칩에서 클럭 스큐의 근본 원인은 여러 가지가 있습니다:

Source Description 설명 Typical Impact 일반적 영향
Wire Length Different distances from clock source to flip-flops 클럭 소스에서 플립플롭까지 거리 차이 10-100 ps 10-100 ps
Buffer Delay Variation Clock buffers in the tree have different delays due to process variation 클럭 트리의 버퍼들이 공정 변동으로 지연 차이 발생 5-50 ps 5-50 ps
Load Imbalance Different fan-out at different branches of clock tree 클럭 트리의 다른 분기에서 팬아웃 차이 10-30 ps 10-30 ps

Voltage Drop (IR Drop) Power supply voltage varies across the chip 전원 공급 전압이 칩 전체에서 변동 10-50 ps 10-50 ps

3. Clock Trees: How Chips Distribute Clocks

To minimize skew, chips use clock tree synthesis (CTS) — the tool builds a balanced tree of buffers so the clock arrives at all flip-flops at roughly the same time.

스큐를 최소화하기 위해 칩은 클럭 트리 합성(CTS)을 사용합니다 — 도구가 균형 잡힌 버퍼 트리를 구축하여 클럭이 모든 플립플롭에 거의 동시에 도달하도록 합니다.

🌳 Clock Tree Topologies

  • H-Tree: Symmetric H-shaped structure — equal path length to all endpoints
  • H-트리: 대칭 H자 구조 — 모든 종단까지 동일한 경로 길이
  • Balanced Buffer Tree: CTS tool inserts buffers to balance delays
  • 균형 버퍼 트리: CTS 도구가 지연을 균형 맞추기 위해 버퍼를 삽입
  • Clock Mesh/Grid: Low-skew but high-power, used in high-performance designs
  • 클럭 메시/그리드: 낮은 스큐지만 높은 전력, 고성능 설계에 사용

4. Clock Skew and Timing Equations

Remember the setup and hold equations from Days 11 and 12? Clock skew modifies both:

11일과 12일에서 배운 셋업 및 홀드 방정식을 기억하시나요? 클럭 스큐는 두 가지 모두 수정합니다:

⏱ Setup Time with Skew

The data must arrive at FF2 before the clock edge at FF2:

데이터는 FF2에서의 클럭 에지 전에 FF2에 도달해야 합니다:

// Setup constraint (must satisfy):
t_clk_period + t_skew ≥ t_cq + t_comb + t_setup

// Rearranged — maximum combinational delay:
t_comb_max ≤ t_clk_period + t_skew - t_cq - t_setup

// Positive skew → MORE time for combinational logic (helpful!)
// Negative skew → LESS time for combinational logic (harmful!)

⚠️ Hold Time with Skew

This is where positive skew becomes dangerous:

양의 스큐가 위험해지는 부분입니다:

// Hold constraint (must satisfy):
t_cq + t_comb ≥ t_hold + t_skew

// Rearranged — minimum combinational delay:
t_comb_min ≥ t_hold + t_skew - t_cq

// Positive skew → need MORE combinational delay (harder to meet!)
// Negative skew → need LESS combinational delay (easier to meet!)

Key insight: Hold violations from skew cannot be fixed by slowing the clock. They are frequency-independent! This is why hold violations are more critical.

핵심 통찰: 스큐로 인한 홀드 위반은 클럭을 느리게 해도 고칠 수 없습니다. 주파수와 무관합니다! 이것이 홀드 위반이 더 치명적인 이유입니다.

5. Worked Example

Let's trace through a concrete timing scenario:

구체적인 타이밍 시나리오를 추적해봅시다:

📊 Example Circuit Parameters

// Given:
Clock period    = 5 ns (200 MHz)
t_cq            = 0.3 ns
t_setup         = 0.2 ns
t_hold          = 0.1 ns
t_comb          = 2.0 ns
Clock skew      = +0.5 ns (positive — FF2 gets clock late)

// ─── Setup Check ───
Required: t_clk + t_skew ≥ t_cq + t_comb + t_setup
           5.0 + 0.5 ≥ 0.3 + 2.0 + 0.2
           5.5 ≥ 2.5  ✅ PASS (slack = 3.0 ns)

// ─── Hold Check ───
Required: t_cq + t_comb ≥ t_hold + t_skew
           0.3 + 2.0 ≥ 0.1 + 0.5
           2.3 ≥ 0.6  ✅ PASS (slack = 1.7 ns)

Now what if the combinational path is very short (e.g., direct wire from FF1 to FF2)?

조합 경로가 매우 짧다면 어떻게 될까요? (예: FF1에서 FF2로 직접 와이어)

t_comb = 0.0 ns (direct connection!)

// Hold Check:
0.3 + 0.0 ≥ 0.1 + 0.5
0.3 ≥ 0.6  ❌ FAIL! (slack = -0.3 ns)

// The new data arrives at FF2 BEFORE the old data is captured!
// Fix: Insert delay buffers to add ≥ 0.3 ns of path delay

7. Useful Skew — Intentional Clock Skew

Sometimes engineers intentionally add skew to help timing. If Path A is the critical setup path and has negative slack, you can delay the clock to FF2 (positive skew) to borrow time from the next stage.

때로는 엔지니어가 타이밍을 돕기 위해 의도적으로 스큐를 추가합니다. Path A가 셋업의 크리티컬 패스이고 음의 슬랙이 있다면, FF2의 클럭을 지연시켜(양의 스큐) 다음 단계에서 시간을 빌릴 수 있습니다.

Without useful skew:
  FF1 ──[4.8ns path]──> FF2 ──[2.0ns path]──> FF3
  Period = 5ns          Period = 5ns
  Slack = -0.1ns ❌     Slack = +2.8ns ✅

With useful skew (+0.5ns on FF2):
  FF1 ──[4.8ns path]──> FF2 ──[2.0ns path]──> FF3
  Period = 5.5ns        Period = 4.5ns
  Slack = +0.4ns ✅     Slack = +2.3ns ✅

  "Borrowed" 0.5ns from the relaxed path!

💡 Interview Tip

When asked "Can you increase clock frequency by adding skew?" — the answer is YES, with useful skew. But emphasize that it's a zero-sum game: you borrow time from one stage and give it to another. Total cycle time doesn't change. And you must re-verify hold timing!

"스큐를 추가하면 클럭 주파수를 높일 수 있나요?"라는 질문에 — 답은 네, 유용한 스큐로 가능합니다. 하지만 이것이 제로섬 게임임을 강조하세요: 한 단계에서 시간을 빌려 다른 단계에 줍니다. 총 사이클 시간은 변하지 않습니다. 그리고 홀드 타이밍을 재검증해야 합니다!

8. Clock Skew vs Clock Jitter

These are often confused — know the difference!

이 두 개념은 자주 혼동됩니다 — 차이를 알아두세요!

Property Clock Skew Clock Jitter
Definition Spatial — different arrival times at different flip-flops in the same cycle Temporal — variation in clock period from cycle to cycle at the same flip-flop
정의 공간적 — 같은 사이클에서 다른 플립플롭에 다른 도달 시간 시간적 — 같은 플립플롭에서 사이클마다 클럭 주기 변동
Predictable? Mostly yes — deterministic based on physical layout No — random variation from PLL, noise, power supply
예측 가능? 대부분 예 — 물리적 레이아웃 기반 결정적 아니오 — PLL, 노이즈, 전원 공급의 무작위 변동
Affects Both setup and hold Mainly setup (reduces effective period)
영향 셋업과 홀드 모두 주로 셋업 (유효 주기 감소)
Fix Better clock tree (CTS) Better PLL, power supply filtering
해결 더 나은 클럭 트리 (CTS) 더 나은 PLL, 전원 공급 필터링

9. Key Takeaways

🎯 Remember These

  1. Clock skew = arrival time difference of the same clock edge at two flip-flops
  2. 클럭 스큐 = 같은 클럭 에지의 두 플립플롭 도달 시간 차이
  3. Positive skew helps setup, hurts hold — and vice versa for negative skew
  4. 양의 스큐는 셋업에 유리, 홀드에 불리 — 음의 스큐는 반대
  5. Hold violations are frequency-independent — can't fix by slowing the clock!
  6. 홀드 위반은 주파수와 무관 — 클럭을 느리게 해도 고칠 수 없음!
  7. CTS (Clock Tree Synthesis) is the primary tool to minimize skew
  8. CTS (클럭 트리 합성)가 스큐를 최소화하는 주요 도구
  9. Useful skew is intentional — borrows time from relaxed paths
  10. 유용한 스큐는 의도적 — 여유 있는 경로에서 시간을 빌림
  11. Skew ≠ Jitter — skew is spatial, jitter is temporal
  12. 스큐 ≠ 지터 — 스큐는 공간적, 지터는 시간적
