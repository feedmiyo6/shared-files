Exercise 1: Binary ↔ Gray Converter Module

Implement a parameterized module that can convert between binary and Gray code in both directions.

양방향으로 바이너리와 그레이 코드를 변환할 수 있는 파라미터화된 모듈을 구현하세요.

Requirements

  • Parameterized width (default 4)
  • 파라미터화된 폭 (기본 4)
  • Input: binary value and Gray value
  • 입력: 바이너리 값과 그레이 값
  • Output: Gray-encoded output and binary-decoded output
  • 출력: 그레이 인코딩 출력과 바이너리 디코딩 출력
  • Pure combinational (no clock needed)
  • 순수 조합 논리 (클록 불필요)

🔍 Hint: bin2gray is one line: XOR with right-shift. gray2bin needs a loop from MSB down.

🔍 힌트: bin2gray는 한 줄: 오른쪽 시프트와 XOR. gray2bin은 MSB에서 아래로 루프가 필요합니다.

module gray_converter #(
    parameter int WIDTH = 4
)(
    // Binary to Gray
    input  logic [WIDTH-1:0] bin_in,
    output logic [WIDTH-1:0] gray_out,

    // Gray to Binary
    input  logic [WIDTH-1:0] gray_in,
    output logic [WIDTH-1:0] bin_out
);

    // Binary → Gray: XOR with right-shifted self
    assign gray_out = bin_in ^ (bin_in >> 1);

    // Gray → Binary: cascading XOR from MSB
    always_comb begin
        bin_out[WIDTH-1] = gray_in[WIDTH-1];
        for (int i = WIDTH-2; i >= 0; i--)
            bin_out[i] = bin_out[i+1] ^ gray_in[i];
    end

endmodule

Exercise 2: Gray Code Counter with Enable

Design a 4-bit Gray code counter with synchronous reset, count enable, and both binary and Gray outputs.

동기 리셋, 카운트 이네이블, 바이너리와 그레이 출력을 모두 갖는 4비트 그레이 코드 카운터를 설계하세요.

Requirements

  • 5-bit counter (4 address bits + 1 wrap bit)
  • 5비트 카운터 (4 주소 비트 + 1 래핑 비트)
  • Async active-low reset
  • 비동기 액티브-로우 리셋
  • Count enable signal
  • 카운트 이네이블 신호
  • Output both gray_count and bin_count
  • gray_count와 bin_count 모두 출력

🔍 Hint: Compute bin_next and gray_next combinationally, then register both on the clock edge. The Gray output must be registered (not combinational) for safe CDC.

🔍 힌트: bin_next와 gray_next를 조합적으로 계산한 다음, 클록 엣지에서 둘 다 레지스터하세요. 안전한 CDC를 위해 그레이 출력은 반드시 레지스터되어야 합니다.

module gray_counter #(
    parameter int ADDR_WIDTH = 4
)(
    input  logic                    clk,
    input  logic                    rst_n,
    input  logic                    enable,
    output logic [ADDR_WIDTH:0]    gray_count,
    output logic [ADDR_WIDTH:0]    bin_count
);

    logic [ADDR_WIDTH:0] bin_next, gray_next;

    // Next binary value
    assign bin_next = bin_count + (enable ? 1 : 0);

    // Convert next binary to Gray
    assign gray_next = bin_next ^ (bin_next >> 1);

    // Register both outputs
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            bin_count  <= '0;
            gray_count <= '0;
        end else begin
            bin_count  <= bin_next;
            gray_count <= gray_next;
        end
    end

endmodule

Exercise 3: Gray Counter + Synchronizer Testbench

Write a testbench that instantiates a Gray code counter in one clock domain, synchronizes it to another domain, and verifies the synchronized value is always a valid (past or current) counter value.

하나의 클록 도메인에서 그레이 코드 카운터를 인스턴스화하고, 다른 도메인으로 동기화한 후, 동기화된 값이 항상 유효한 (과거 또는 현재) 카운터 값인지 검증하는 테스트벤치를 작성하세요.

Requirements

  • Two clock domains: 100MHz and 75MHz
  • 두 클록 도메인: 100MHz와 75MHz
  • Gray counter running on clk_fast (100MHz)
  • clk_fast (100MHz)에서 실행되는 그레이 카운터
  • 2-flop synchronizer bringing Gray pointer to clk_slow (75MHz)
  • 그레이 포인터를 clk_slow (75MHz)로 가져오는 2-플립플롭 동기화기
  • Convert synchronized Gray back to binary and check validity
  • 동기화된 그레이를 바이너리로 역변환하고 유효성 검사

🔍 Hint: The synchronized value will always lag behind the actual counter. Verify that the synced binary value is ≤ the actual binary count and ≥ (actual count - max_latency). A margin of 3-4 cycles is typical.

🔍 힌트: 동기화된 값은 항상 실제 카운터보다 뒤처집니다. 동기화된 바이너리 값이 실제 바이너리 카운트 이하이고 (실제 카운트 - 최대 레이턴시) 이상인지 확인하세요. 3-4 사이클의 마진이 일반적입니다.

module tb_gray_cdc;

    parameter int WIDTH = 4;

    // Two independent clocks
    logic clk_fast, clk_slow, rst_n;

    // 100 MHz fast clock
    initial begin
        clk_fast = 0;
        forever #5 clk_fast = ~clk_fast;  // 10ns period
    end

    // 75 MHz slow clock
    initial begin
        clk_slow = 0;
        forever #6.67 clk_slow = ~clk_slow;  // ~13.3ns period
    end

    // Gray counter outputs (fast domain)
    logic [WIDTH:0] gray_count, bin_count;

    // Synchronized outputs (slow domain)
    logic [WIDTH:0] gray_sync;
    logic [WIDTH:0] sync_ff1, sync_ff2;
    logic [WIDTH:0] bin_synced;

    // Instantiate Gray counter (fast domain)
    gray_counter #(.ADDR_WIDTH(WIDTH)) u_counter (
        .clk(clk_fast),
        .rst_n(rst_n),
        .enable(1'b1),
        .gray_count(gray_count),
        .bin_count(bin_count)
    );

    // 2-flop synchronizer (slow domain)
    always_ff @(posedge clk_slow or negedge rst_n) begin
        if (!rst_n) begin
            sync_ff1 <= '0;
            sync_ff2 <= '0;
        end else begin
            sync_ff1 <= gray_count;
            sync_ff2 <= sync_ff1;
        end
    end

    assign gray_sync = sync_ff2;

    // Gray to binary conversion (slow domain)
    always_comb begin
        bin_synced[WIDTH] = gray_sync[WIDTH];
        for (int i = WIDTH-1; i >= 0; i--)
            bin_synced[i] = bin_synced[i+1] ^ gray_sync[i];
    end

    // Stimulus
    initial begin
        rst_n = 0;
        #50;
        rst_n = 1;

        // Let counter run for many cycles
        #5000;

        $display("=== Test Passed ===");
        $finish;
    end

    // Monitor: synced value should lag behind actual
    always @(posedge clk_slow) begin
        if (rst_n) begin
            // Synced value must be ≤ actual count
            if (bin_synced > bin_count) begin
                $error("Synced value %0d > actual %0d!",
                       bin_synced, bin_count);
            end
            $display("[%0t] actual=%0d synced=%0d (lag=%0d)",
                    $time, bin_count, bin_synced,
                    bin_count - bin_synced);
        end
    end

endmodule

🌟 Bonus: Full/Empty Detection with Gray Pointers

Preview for Day 20! Given a write Gray pointer and a read Gray pointer (both N+1 bits), write combinational logic to detect FULL and EMPTY conditions.

20일차 미리보기! 쓰기 그레이 포인터와 읽기 그레이 포인터 (둘 다 N+1 비트)가 주어졌을 때, FULL과 EMPTY 조건을 감지하는 조합 논리를 작성하세요.

Key Insight

EMPTY: Write Gray pointer == Read Gray pointer (identical)
FULL: The top 2 bits of write and read Gray pointers are inverted, and the remaining bits are equal.

EMPTY: 쓰기 그레이 포인터 == 읽기 그레이 포인터 (동일)
FULL: 쓰기와 읽기 그레이 포인터의 상위 2비트가 반전되고, 나머지 비트는 동일합니다.

🔍 Hint: In Gray code, when write pointer is exactly one full cycle ahead of read pointer, the top 2 MSBs are complemented while the rest match. Think about why this is true by looking at the Gray code table!

🔍 힌트: 그레이 코드에서 쓰기 포인터가 읽기 포인터보다 정확히 한 전체 사이클 앞서면, 상위 2개의 MSB가 보수되고 나머지는 일치합니다. 그레이 코드 테이블을 보면서 이것이 왜 그런지 생각해보세요!

// Full and Empty detection using Gray code pointers
// wr_gray and rd_gray are (ADDR_WIDTH+1) bits

// EMPTY: pointers are identical
assign empty = (wr_gray_sync == rd_gray);

// FULL: top 2 bits inverted, rest equal
assign full = (wr_gray[ADDR_WIDTH]     != rd_gray_sync[ADDR_WIDTH])     &&  // MSB different
              (wr_gray[ADDR_WIDTH-1]   != rd_gray_sync[ADDR_WIDTH-1])   &&  // 2nd MSB different
              (wr_gray[ADDR_WIDTH-2:0] == rd_gray_sync[ADDR_WIDTH-2:0]);  // Rest equal

// Note: empty uses wr_gray_sync (synchronized TO read domain)
//       full  uses rd_gray_sync (synchronized TO write domain)
// This is conservative: may report full/empty slightly early, never late!

🎯 What to Focus On

  • Exercise 1: Make sure your gray2bin loop direction is correct (MSB down to LSB)
  • 연습 1: gray2bin 루프 방향이 올바른지 확인하세요 (MSB에서 LSB로)
  • Exercise 2: Both outputs MUST be registered — combinational Gray output defeats the purpose
  • 연습 2: 두 출력 모두 반드시 레지스터되어야 합니다 — 조합 그레이 출력은 목적을 무효화합니다
  • Exercise 3: Notice how the synced value always lags by 2-3 cycles — that's expected!
  • 연습 3: 동기화된 값이 항상 2-3 사이클 뒤처지는 것에 주목하세요 — 이것은 예상된 것입니다!
  • Bonus: Understanding full/empty with Gray pointers is the key to async FIFOs (Day 20)
  • 보너스: 그레이 포인터로 full/empty를 이해하는 것이 비동기 FIFO의 핵심입니다 (20일차)
