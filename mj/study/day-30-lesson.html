1. The Big Picture: System-on-Chip Bus Architecture

In real SoC designs, you rarely have just one module talking to another. You have multiple initiators (CPUs, DMAs, accelerators) trying to access multiple targets (memory, peripherals, registers). A bus integration layer routes requests and manages traffic.

실제 SoC 설계에서는 하나의 모듈이 다른 하나와만 통신하는 경우는 드뭅니다. 여러 이니시에이터(CPU, DMA, 가속기)가 여러 타겟(메모리, 주변장치, 레지스터)에 접근하려 합니다. 버스 통합 레이어가 요청을 라우팅하고 트래픽을 관리합니다.

🔑 Key Integration Components

A complete bus integration needs these building blocks:

완전한 버스 통합에는 다음 구성 요소가 필요합니다:

  • Address Decoder — routes requests to the correct target based on address
  • 주소 디코더 — 주소를 기반으로 요청을 올바른 타겟으로 라우팅
  • Arbiter — resolves conflicts when multiple initiators request the same target
  • 중재기 — 여러 이니시에이터가 같은 타겟에 요청할 때 충돌 해결
  • Multiplexers — select which initiator/target gets connected
  • 멀티플렉서 — 어떤 이니시에이터/타겟이 연결될지 선택
  • Response Router — sends target responses back to the correct initiator
  • 응답 라우터 — 타겟 응답을 올바른 이니시에이터로 돌려보냄
  • Pipeline Stages — optional registers to meet timing
  • 파이프라인 스테이지 — 타이밍을 충족하기 위한 선택적 레지스터

2. Address Decoding

The first step in bus integration: figuring out where each request should go. An address decoder examines the address and produces a select signal for the appropriate target.

버스 통합의 첫 번째 단계: 각 요청이 어디로 가야 하는지 파악하는 것입니다. 주소 디코더는 주소를 검사하고 적절한 타겟에 대한 선택 신호를 생성합니다.

// Address decoder — maps address ranges to target selects
module addr_decoder #(
    parameter ADDR_W = 32,
    parameter N_TARGETS = 3
)(
    input  logic [ADDR_W-1:0] addr,
    input  logic                valid,
    output logic [N_TARGETS-1:0] target_sel,
    output logic                addr_error
);

    always_comb begin
        target_sel = '0;
        addr_error = 1'b0;

        if (valid) begin
            casez (addr[31:28])  // Decode upper 4 bits
                4'h0:    target_sel[0] = 1'b1;  // 0x0xxx_xxxx → Memory
                4'h4:    target_sel[1] = 1'b1;  // 0x4xxx_xxxx → UART
                4'h8:    target_sel[2] = 1'b1;  // 0x8xxx_xxxx → GPIO
                default: addr_error    = 1'b1;  // Unmapped!
            endcase
        end
    end

endmodule

💡 Design Tip

Always handle unmapped addresses! An addr_error signal lets the system respond with a bus error instead of silently dropping the transaction. In AXI, this becomes a DECERR response.

매핑되지 않은 주소를 항상 처리하세요! addr_error 신호를 사용하면 트랜잭션을 조용히 무시하는 대신 버스 에러로 응답할 수 있습니다. AXI에서는 DECERR 응답이 됩니다.

3. Request Multiplexer with Arbitration

When multiple initiators want the same target, we need an arbiter to pick one and a mux to route its signals. Here's how they work together:

여러 이니시에이터가 같은 타겟을 원할 때, 하나를 선택하는 중재기와 그 신호를 라우팅하는 멀티플렉서가 필요합니다. 함께 작동하는 방법입니다:

// Request path: N initiators → 1 target
module req_mux #(
    parameter N_INIT = 2,
    parameter DATA_W = 32,
    parameter ADDR_W = 32
)(
    input  logic                clk,
    input  logic                rst_n,

    // From initiators
    input  logic [N_INIT-1:0]   init_valid,
    output logic [N_INIT-1:0]   init_ready,
    input  logic [ADDR_W-1:0]  init_addr  [N_INIT],
    input  logic [DATA_W-1:0]  init_data  [N_INIT],
    input  logic               init_wr    [N_INIT],

    // To target
    output logic                tgt_valid,
    input  logic                tgt_ready,
    output logic [ADDR_W-1:0]  tgt_addr,
    output logic [DATA_W-1:0]  tgt_data,
    output logic                tgt_wr,
    output logic [$clog2(N_INIT)-1:0] tgt_id  // Which initiator won
);

    logic [N_INIT-1:0] grant;
    logic [$clog2(N_INIT)-1:0] grant_idx;

    // Round-robin arbiter (from Day 28!)
    rr_arbiter #(.N(N_INIT)) u_arb (
        .clk     (clk),
        .rst_n   (rst_n),
        .req     (init_valid),
        .grant   (grant),
        .advance (tgt_valid & tgt_ready)  // Rotate on handshake
    );

    // Encode grant to index
    always_comb begin
        grant_idx = '0;
        for (int i = 0; i < N_INIT; i++)
            if (grant[i]) grant_idx = i[$clog2(N_INIT)-1:0];
    end

    // Mux: route the winning initiator to the target
    assign tgt_valid = |grant;
    assign tgt_addr  = init_addr[grant_idx];
    assign tgt_data  = init_data[grant_idx];
    assign tgt_wr    = init_wr[grant_idx];
    assign tgt_id    = grant_idx;

    // Ready: only the granted initiator sees ready
    always_comb begin
        init_ready = '0;
        init_ready[grant_idx] = tgt_ready & grant[grant_idx];
    end

endmodule

4. Response Routing

Responses must travel back to the correct initiator. We use the transaction ID (tgt_id) that was stored with the request to route the response.

응답은 올바른 이니시에이터로 돌아가야 합니다. 요청과 함께 저장된 트랜잭션 ID(tgt_id)를 사용하여 응답을 라우팅합니다.

// Response demux: 1 target → N initiators
module resp_demux #(
    parameter N_INIT = 2,
    parameter DATA_W = 32
)(
    // From target
    input  logic                tgt_resp_valid,
    output logic                tgt_resp_ready,
    input  logic [DATA_W-1:0]  tgt_resp_data,
    input  logic                tgt_resp_err,
    input  logic [$clog2(N_INIT)-1:0] tgt_resp_id,

    // To initiators
    output logic [N_INIT-1:0]   init_resp_valid,
    input  logic [N_INIT-1:0]   init_resp_ready,
    output logic [DATA_W-1:0]  init_resp_data,
    output logic                init_resp_err
);

    // Data/error broadcast to all — only valid is selective
    assign init_resp_data = tgt_resp_data;
    assign init_resp_err  = tgt_resp_err;

    // Steer valid to the correct initiator
    always_comb begin
        init_resp_valid = '0;
        if (tgt_resp_valid)
            init_resp_valid[tgt_resp_id] = 1'b1;
    end

    // Ready from the correct initiator
    assign tgt_resp_ready = init_resp_ready[tgt_resp_id];

endmodule

🔑 Transaction IDs Are Essential

The tgt_id field tags each request with its source. When the target responds, this ID routes the response back. Without it, you wouldn't know which initiator to send the response to. In AXI, this is the AWID/ARID field.

tgt_id 필드는 각 요청에 출처를 태그합니다. 타겟이 응답할 때 이 ID가 응답을 올바르게 라우팅합니다. 이것이 없으면 어떤 이니시에이터에게 응답을 보내야 할지 알 수 없습니다. AXI에서는 AWID/ARID 필드입니다.

5. Putting It All Together: Simple Bus Interconnect

Now let's connect everything into a top-level bus interconnect — 2 initiators, 3 targets:

이제 모든 것을 최상위 버스 인터커넥트로 연결합시다 — 2개의 이니시에이터, 3개의 타겟:

module simple_bus #(
    parameter ADDR_W    = 32,
    parameter DATA_W    = 32,
    parameter N_INIT    = 2,
    parameter N_TARGETS = 3
)(
    input  logic clk, rst_n,

    // Initiator interfaces (ready/valid)
    input  logic [N_INIT-1:0]  i_valid,
    output logic [N_INIT-1:0]  i_ready,
    input  logic [ADDR_W-1:0] i_addr [N_INIT],
    input  logic [DATA_W-1:0] i_wdata[N_INIT],
    input  logic              i_wr   [N_INIT],

    // Target interfaces
    output logic [N_TARGETS-1:0] t_valid,
    input  logic [N_TARGETS-1:0] t_ready,
    output logic [ADDR_W-1:0]    t_addr,
    output logic [DATA_W-1:0]    t_wdata,
    output logic                  t_wr
);

    // Internal signals
    logic [N_TARGETS-1:0] target_sel;
    logic                addr_error;
    logic                arb_valid;
    logic                arb_ready;
    logic [ADDR_W-1:0]  arb_addr;
    logic [DATA_W-1:0]  arb_wdata;
    logic                arb_wr;

    // Step 1: Arbitrate among initiators
    req_mux #(.N_INIT(N_INIT)) u_req_mux (
        .clk(clk), .rst_n(rst_n),
        .init_valid(i_valid), .init_ready(i_ready),
        .init_addr(i_addr),   .init_data(i_wdata),
        .init_wr(i_wr),
        .tgt_valid(arb_valid), .tgt_ready(arb_ready),
        .tgt_addr(arb_addr),   .tgt_data(arb_wdata),
        .tgt_wr(arb_wr),       .tgt_id()
    );

    // Step 2: Decode address → target select
    addr_decoder #(.ADDR_W(ADDR_W)) u_dec (
        .addr(arb_addr), .valid(arb_valid),
        .target_sel(target_sel), .addr_error(addr_error)
    );

    // Step 3: Route to selected target
    assign t_valid = target_sel & {N_TARGETS{arb_valid}};
    assign t_addr  = arb_addr;
    assign t_wdata = arb_wdata;
    assign t_wr    = arb_wr;

    // Step 4: Collect ready from selected target
    assign arb_ready = |(target_sel & t_ready);

endmodule

6. Integration Checklist: Connecting Any Two Modules

When you need to connect modules in practice, follow this systematic checklist:

실제로 모듈을 연결해야 할 때 이 체계적인 체크리스트를 따르세요:

# Step 단계 Details 세부사항
1 Define the interface 인터페이스 정의 What signals? Ready/valid? Address width? Data width? 어떤 신호? Ready/valid? 주소 폭? 데이터 폭?
2 Check clock domains 클럭 도메인 확인 Same clock? If not → add synchronizers (Week 4!) 같은 클럭? 아니면 → 동기화기 추가 (Week 4!)
3 Match data widths 데이터 폭 맞추기 Width converter if widths differ (e.g., 64→32) 폭이 다르면 변환기 필요 (예: 64→32)
4 Add arbitration if N:1 N:1이면 중재 추가 Round-robin or priority arbiter for shared resources 공유 리소스에 라운드로빈 또는 우선순위 중재기
5 Buffer if needed 필요시 버퍼 추가 FIFO between producer/consumer at different rates 다른 속도의 생산자/소비자 사이에 FIFO
6 Pipeline for timing 타이밍을 위한 파이프라인 Add register stages on long paths 긴 경로에 레지스터 스테이지 추가
7 Handle errors 에러 처리 Unmapped addresses, timeouts, protocol violations 매핑되지 않은 주소, 타임아웃, 프로토콜 위반

7. Real-World Example: Register Block Integration

One of the most common bus integration tasks: connecting a configuration register block to the bus. Let's build a simple one with ready/valid interface:

가장 흔한 버스 통합 작업 중 하나: 구성 레지스터 블록을 버스에 연결하기. Ready/valid 인터페이스로 간단한 것을 만들어 봅시다:

// Simple register block — bus target
module reg_block #(
    parameter ADDR_W = 8,
    parameter DATA_W = 32
)(
    input  logic               clk,
    input  logic               rst_n,

    // Bus interface (target side)
    input  logic               req_valid,
    output logic               req_ready,
    input  logic [ADDR_W-1:0] req_addr,
    input  logic [DATA_W-1:0] req_wdata,
    input  logic               req_wr,

    // Response
    output logic               resp_valid,
    input  logic               resp_ready,
    output logic [DATA_W-1:0] resp_rdata,

    // Register outputs (functional)
    output logic [DATA_W-1:0] ctrl_reg,
    output logic [DATA_W-1:0] cfg_reg,
    input  logic [DATA_W-1:0] status_reg  // Read-only from HW
);

    // Register map
    localparam CTRL_ADDR   = 8'h00;
    localparam CFG_ADDR    = 8'h04;
    localparam STATUS_ADDR = 8'h08;

    // Always ready — single-cycle access
    assign req_ready = 1'b1;

    // Write logic
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            ctrl_reg <= '0;
            cfg_reg  <= '0;
        end else if (req_valid & req_ready & req_wr) begin
            case (req_addr)
                CTRL_ADDR: ctrl_reg <= req_wdata;
                CFG_ADDR:  cfg_reg  <= req_wdata;
                // STATUS_ADDR is read-only — write ignored
                default:   ; // Ignore writes to unknown addresses
            endcase
        end
    end

    // Read logic — 1-cycle response
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            resp_valid <= 1'b0;
            resp_rdata <= '0;
        end else begin
            resp_valid <= req_valid & req_ready & !req_wr;
            case (req_addr)
                CTRL_ADDR:   resp_rdata <= ctrl_reg;
                CFG_ADDR:    resp_rdata <= cfg_reg;
                STATUS_ADDR: resp_rdata <= status_reg;
                default:     resp_rdata <= 32'hDEAD_BEEF;
            endcase
        end
    end

endmodule

⚠️ Common Integration Mistakes

  • Forgetting to connect ready/valid correctly — A dangling ready (not driven) keeps the initiator stalled forever. Always check both directions.
  • Ready/valid를 올바르게 연결하지 않음 — 연결되지 않은 ready는 이니시에이터를 영원히 정지시킵니다. 항상 양방향을 확인하세요.
  • Missing default in address decode — Unmapped address accesses hang the bus. Always have a default path.
  • 주소 디코드에서 default 누락 — 매핑되지 않은 주소 접근이 버스를 멈춥니다. 항상 기본 경로를 만드세요.
  • ID width mismatch — If you have 4 initiators, you need at least 2-bit IDs. Off-by-one errors here cause wrong responses.
  • ID 폭 불일치 — 4개의 이니시에이터가 있으면 최소 2비트 ID가 필요합니다. 여기서의 오프바이원 에러는 잘못된 응답을 유발합니다.
  • Combinational loops — If ready depends on valid which depends on ready... deadlock! Break loops with registers.
  • 조합 논리 루프 — ready가 valid에 의존하고 valid가 ready에 의존하면... 교착상태! 레지스터로 루프를 끊으세요.
