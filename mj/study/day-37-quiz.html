Day 37 Quiz

FIFO Full/Empty Flags Quiz FIFO Full/Empty 플래그 퀴즈

Test your understanding of full/empty detection in FIFO design.

FIFO 설계에서 full/empty 감지에 대한 이해를 테스트하세요.

Question 1: The MSB Trick 질문 1: MSB 트릭

For an 8-entry FIFO, how many bits should each pointer have?

8-entry FIFO의 경우, 각 포인터는 몇 비트를 가져야 하나요?

A) 3 bits (to address 8 locations)
B) 4 bits (3 for address + 1 for wrap detection)
C) 8 bits (one per entry)
D) 2 bits (binary encoding)
Answer: B) 4 bits 정답: B) 4비트

You need 3 bits to address 8 locations (0-7), plus 1 extra MSB to track wraparound. The MSB toggles each time the pointer wraps, allowing you to distinguish full from empty.

8개 위치(0-7)를 주소 지정하려면 3비트가 필요하고, wraparound를 추적하기 위해 1개의 추가 MSB가 필요합니다. MSB는 포인터가 wrap할 때마다 토글되어 full과 empty를 구분할 수 있게 합니다.

Question 2: Empty Condition 질문 2: Empty 조건

When is a FIFO empty?

FIFO는 언제 empty인가요?

A) When write_ptr MSB differs from read_ptr MSB
B) When write_ptr == read_ptr (all bits match)
C) When write_ptr > read_ptr
D) When write_ptr < read_ptr
Answer: B) When write_ptr == read_ptr 정답: B) write_ptr == read_ptr일 때

Empty occurs when the write pointer catches up to the read pointer with the same wrap count. All bits (including MSB) are equal. This is different from full, where only the lower bits match.

Empty는 write 포인터가 같은 wrap count로 read 포인터를 따라잡을 때 발생합니다. 모든 비트(MSB 포함)가 같습니다. 이는 하위 비트만 일치하는 full과 다릅니다.

Question 3: Full Condition 질문 3: Full 조건

For a FIFO with 4-bit pointers (ADDR_WIDTH=3), which condition indicates FULL?

4비트 포인터(ADDR_WIDTH=3)를 가진 FIFO에서 어떤 조건이 FULL을 나타내나요?

A) wr_ptr == rd_ptr
B) wr_ptr[2:0] == rd_ptr[2:0] && wr_ptr[3] != rd_ptr[3]
C) wr_ptr > rd_ptr
D) wr_ptr[3] == rd_ptr[3]
Answer: B) Lower bits match, MSBs differ 정답: B) 하위 비트는 일치, MSB는 다름

Full occurs when write has wrapped one more time than read. The addresses (lower bits) align, but the MSBs differ because write has cycled through the FIFO one extra time.

Full은 write가 read보다 한 번 더 wrap했을 때 발생합니다. 주소(하위 비트)는 일치하지만 MSB는 다릅니다 — write가 FIFO를 한 번 더 순환했기 때문입니다.

Question 4: Pointer State Analysis 질문 4: 포인터 상태 분석

Given: wr_ptr = 4'b1010, rd_ptr = 4'b0010. What is the FIFO state?

주어짐: wr_ptr = 4'b1010, rd_ptr = 4'b0010. FIFO 상태는?

A) Empty
B) Full
C) Partially full (8 entries)
D) Cannot determine
Answer: B) Full 정답: B) Full

Lower 3 bits match (010 == 010), but MSBs differ (1 != 0). This means write has wrapped around and caught up to read — the FIFO is full. With 3 address bits, this represents 8 entries.

하위 3비트가 일치(010 == 010)하지만 MSB는 다릅니다(1 != 0). 이는 write가 wrap around되어 read를 따라잡았음을 의미 — FIFO는 full입니다. 3개 주소 비트로 8개 entry를 나타냅니다.

Question 5: Write Protection 질문 5: 쓰기 보호

What happens if you write to a FIFO when it's full?

FIFO가 full일 때 쓰기를 하면 어떻게 되나요?

A) The write is ignored (no data written)
B) The oldest data is overwritten
C) The FIFO overflows and data is lost
D) It depends on the implementation
Answer: D) It depends on the implementation 정답: D) 구현에 따라 다름

Well-designed FIFOs guard writes with if (wr_en && !full), ignoring the write. However, unprotected writes could overwrite data or corrupt pointers. Always check the full flag!

잘 설계된 FIFO는 if (wr_en && !full)로 쓰기를 보호하여 쓰기를 무시합니다. 하지만 보호되지 않은 쓰기는 데이터를 덮어쓰거나 포인터를 손상시킬 수 있습니다. 항상 full 플래그를 확인하세요!

Question 6: Code Bug 질문 6: 코드 버그

What's wrong with this full detection logic?

이 full 감지 로직의 문제는 무엇인가요?

assign full = (wr_ptr[2:0] == rd_ptr[2:0]);
A) Nothing, this is correct
B) It can't distinguish full from empty
C) The bit range is wrong
D) It should use > instead of ==
Answer: B) It can't distinguish full from empty 정답: B) full과 empty를 구분할 수 없음

This condition is also true when the FIFO is empty (both pointers point to the same address). You MUST compare the MSBs to distinguish: full = addresses match AND MSBs differ.

이 조건은 FIFO가 empty일 때도 참입니다(두 포인터가 같은 주소를 가리킴). 구분하려면 MSB를 비교해야 합니다: full = 주소가 일치 AND MSB가 다름.

Question 7: FIFO Depth 질문 7: FIFO 깊이

With the MSB trick, what's the maximum usable depth of a FIFO with 4-bit pointers?

MSB 트릭을 사용하면 4비트 포인터로 FIFO의 최대 사용 가능 깊이는 얼마인가요?

A) 16 entries
B) 15 entries
C) 8 entries
D) 7 entries
Answer: C) 8 entries 정답: C) 8개 entry

With 4-bit pointers, 1 bit is used for the wrap flag, leaving 3 bits for addressing. 2³ = 8 addressable locations. The MSB trick "costs" you half the address space.

4비트 포인터에서 1비트는 wrap 플래그에 사용되고 3비트는 주소 지정에 남습니다. 2³ = 8개의 주소 지정 가능 위치. MSB 트릭은 주소 공간의 절반을 "비용"으로 합니다.

Question 8: Simultaneous Read/Write 질문 8: 동시 읽기/쓰기

What happens if both wr_en and rd_en are asserted when the FIFO is full?

FIFO가 full일 때 wr_en과 rd_en이 모두 assert되면 어떻게 되나요?

A) Both operations succeed (write then read)
B) Only the read succeeds, write is blocked
C) Only the write succeeds, read is blocked
D) Both operations are blocked
Answer: B) Only the read succeeds, write is blocked 정답: B) 읽기만 성공, 쓰기는 차단됨

At the start of the cycle, full=1 so the write is blocked. The read proceeds (if not empty), freeing a slot. Some FIFO designs allow both in the same cycle — this depends on your specification. The safest approach: read first, then write.

사이클 시작 시 full=1이므로 쓰기가 차단됩니다. 읽기는 진행됩니다(empty가 아니라면), 슬롯을 비웁니다. 일부 FIFO 설계에서는 같은 사이클에 둘 다 허용합니다 — 이는 사양에 따라 다릅니다. 가장 안전한 접근: 먼저 읽기, 그 다음 쓰기.

Question 9: Reset State 질문 9: 리셋 상태

After reset, what are the initial values of wr_ptr and rd_ptr?

리셋 후 wr_ptr과 rd_ptr의 초기값은 무엇인가요?

A) Both are X (unknown)
B) wr_ptr = 0, rd_ptr = DEPTH-1
C) Both are 0
D) Both are 1
Answer: C) Both are 0 정답: C) 둘 다 0

Both pointers start at 0, making wr_ptr == rd_ptr, which correctly indicates empty. This is the natural reset state for a FIFO.

두 포인터 모두 0에서 시작하여 wr_ptr == rd_ptr이 되어, 이는 empty를 올바르게 나타냅니다. 이것이 FIFO의 자연스러운 리셋 상태입니다.

Question 10: Almost-Full Purpose 질문 10: Almost-Full 목적

Why would you implement an "almost_full" flag instead of just using "full"?

왜 "full"만 사용하는 대신 "almost_full" 플래그를 구현하나요?

A) To reduce power consumption
B) For flow control — to prevent overflow in multi-cycle paths
C) Because full detection is unreliable
D) To increase FIFO capacity
Answer: B) For flow control — to prevent overflow in multi-cycle paths 정답: B) flow control — 멀티사이클 경로에서 오버플로우 방지

Almost-full gives upstream logic early warning to stop sending data before it's too late. This is crucial when crossing clock domains or when there's latency in the backpressure path.

Almost-full은 업스트림 로직에 너무 늦기 전에 데이터 전송을 중지하라는 조기 경고를 제공합니다. 이는 clock domain crossing 시나 backpressure 경로에 지연이 있을 때 중요합니다.
