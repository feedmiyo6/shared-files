Exercise 1: Basic TestbenchEasy 연습 1: 기본 테스트벤치

Write a testbench for this 4-bit counter. Generate a 100MHz clock, apply reset, enable counting, and use $monitor to observe the output.

이 4비트 카운터에 대한 테스트벤치를 작성하세요. 100MHz 클록을 생성하고, 리셋을 적용하고, 카운팅을 활성화하고, $monitor로 출력을 관찰하세요.

Design Code (left panel):

설계 코드 (왼쪽 패널):

module counter (
    input  logic       clk,
    input  logic       rst_n,
    input  logic       enable,
    output logic [3:0] count
);
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            count <= 4'b0;
        else if (enable)
            count <= count + 1;
    end
endmodule

Your task — write the testbench (right panel):

과제 — 테스트벤치 작성 (오른쪽 패널):

  1. Declare signals: clk, rst_n, enable, count
  2. 신호 선언: clk, rst_n, enable, count
  3. Instantiate the counter as dut
  4. 카운터를 dut로 인스턴스화
  5. Generate a 100MHz clock (10ns period)
  6. 100MHz 클록 생성 (10ns 주기)
  7. Reset for 25ns, then release and enable counting for 160ns
  8. 25ns 동안 리셋, 그 후 해제하고 160ns 동안 카운팅 활성화
  9. Add $monitor, $dumpfile/$dumpvars, and $finish
  10. $monitor, $dumpfile/$dumpvars, $finish 추가

🔍 Hint: The counter should wrap around from 15 (4'hF) back to 0. You should see this in 160ns of counting (16 clock cycles at 100MHz).

🔍 힌트: 카운터는 15(4'hF)에서 0으로 롤오버해야 합니다. 160ns 카운팅(100MHz에서 16 클록 사이클)에서 이를 확인할 수 있습니다.

👀 Show Solution 👀 정답 보기 
`timescale 1ns / 1ps

module tb_counter;
    logic       clk, rst_n, enable;
    logic [3:0] count;

    counter dut (
        .clk(clk), .rst_n(rst_n),
        .enable(enable), .count(count)
    );

    initial clk = 0;
    always #5 clk = ~clk;

    initial
        $monitor("[%0t] rst_n=%b en=%b count=%4b (%0d)",
                 $time, rst_n, enable, count, count);

    initial begin
        rst_n = 0; enable = 0;
        #25;
        rst_n = 1;
        #10;
        enable = 1;
        #160;
        $display("Simulation complete");
        $finish;
    end

    initial begin
        $dumpfile("counter.vcd");
        $dumpvars(0, tb_counter);
    end
endmodule

Exercise 2: Self-Checking TestbenchMedium 연습 2: 자체 검증 테스트벤치

Upgrade your testbench to automatically verify correctness using assert. Test these scenarios:

테스트벤치를 assert를 사용하여 자동으로 정확성을 검증하도록 업그레이드하세요. 다음 시나리오를 테스트하세요:

  1. Reset check: After reset, count must be 0
  2. 리셋 확인: 리셋 후 count는 0이어야 함
  3. Count check: After 5 clocks with enable=1, count must be 5
  4. 카운트 확인: enable=1로 5클록 후 count는 5여야 함
  5. Pause check: With enable=0, count must not change for 3 clocks
  6. 일시정지 확인: enable=0일 때 count가 3클록 동안 변하지 않아야 함
  7. Wrap check: Count must wrap from 15 back to 0
  8. 랩 확인: count가 15에서 0으로 롤오버해야 함

🔍 Hint: Use repeat(N) @(posedge clk); #1; to wait N cycles then check. The #1 delay lets the output settle after the clock edge.

🔍 힌트: repeat(N) @(posedge clk); #1;을 사용하여 N사이클 대기 후 확인하세요. #1 지연은 클록 에지 후 출력이 안정되게 합니다.

👀 Show Solution 👀 정답 보기 
`timescale 1ns / 1ps

module tb_counter_check;
    logic       clk, rst_n, enable;
    logic [3:0] count;
    integer     pass_count = 0;
    integer     fail_count = 0;

    counter dut (.*);

    initial clk = 0;
    always #5 clk = ~clk;

    initial begin
        // Test 1: Reset
        rst_n = 0; enable = 0;
        #25; rst_n = 1; #1;
        assert (count == 0) begin
            $display("PASS: Reset → count=0");
            pass_count++;
        end else begin
            $error("FAIL: Reset → count=%0d", count);
            fail_count++;
        end

        // Test 2: Count to 5
        enable = 1;
        repeat(5) @(posedge clk); #1;
        assert (count == 5) begin
            $display("PASS: Count reached 5");
            pass_count++;
        end else begin
            $error("FAIL: expected 5, got %0d", count);
            fail_count++;
        end

        // Test 3: Pause (enable=0)
        enable = 0;
        repeat(3) @(posedge clk); #1;
        assert (count == 5) begin
            $display("PASS: Paused at 5");
            pass_count++;
        end else begin
            $error("FAIL: expected 5, got %0d", count);
            fail_count++;
        end

        // Test 4: Wrap from 15 → 0
        enable = 1;
        repeat(11) @(posedge clk); #1;
        assert (count == 0) begin
            $display("PASS: Wrapped to 0");
            pass_count++;
        end else begin
            $error("FAIL: expected 0, got %0d", count);
            fail_count++;
        end

        $display("=== Results: %0d PASS, %0d FAIL ===",
                 pass_count, fail_count);
        $finish;
    end

    initial begin
        $dumpfile("check.vcd");
        $dumpvars(0, tb_counter_check);
    end
endmodule

Exercise 3: D Flip-Flop TestbenchMedium 연습 3: D 플립플롭 테스트벤치

Write both the design AND testbench for a D flip-flop with async reset. Verify that:

비동기 리셋이 있는 D 플립플롭의 설계와 테스트벤치를 모두 작성하세요. 다음을 검증하세요:

  1. Reset forces Q to 0 regardless of clock
  2. 리셋은 클록에 관계없이 Q를 0으로 강제
  3. Q follows D on the rising clock edge
  4. Q는 상승 클록 에지에서 D를 따름
  5. Q does NOT change between clock edges
  6. Q는 클록 에지 사이에서 변하지 않음

🔍 Hint: Drive D to different values between clock edges and verify Q only updates at posedge clk. Use $display at strategic points to trace behavior.

🔍 힌트: 클록 에지 사이에서 D를 다른 값으로 구동하고 Q가 posedge clk에서만 업데이트되는지 확인하세요. 전략적 위치에서 $display를 사용하여 동작을 추적하세요.

👀 Show Solution 👀 정답 보기

Design (left panel):

설계 (왼쪽 패널):

module dff (
    input  logic clk,
    input  logic rst_n,
    input  logic d,
    output logic q
);
    always_ff @(posedge clk or negedge rst_n)
        if (!rst_n) q <= 1'b0;
        else         q <= d;
endmodule

Testbench (right panel):

테스트벤치 (오른쪽 패널):

`timescale 1ns / 1ps

module tb_dff;
    logic clk, rst_n, d, q;

    dff dut (.*);

    initial clk = 0;
    always #5 clk = ~clk;

    initial begin
        // Test 1: Reset
        rst_n = 0; d = 1;
        #15;
        assert (q == 0)
            $display("PASS: Reset holds Q=0 even with D=1");
        else
            $error("FAIL: Q=%b during reset", q);

        // Test 2: Q follows D after reset release
        rst_n = 1; d = 1;
        @(posedge clk); #1;
        assert (q == 1)
            $display("PASS: Q captured D=1");
        else
            $error("FAIL: Q=%b, expected 1", q);

        // Test 3: Q doesn't change mid-cycle
        d = 0;  // Change D between edges
        #2;  // Still before next posedge
        assert (q == 1)
            $display("PASS: Q stable mid-cycle");
        else
            $error("FAIL: Q changed mid-cycle!");

        // Test 4: Q updates at next posedge
        @(posedge clk); #1;
        assert (q == 0)
            $display("PASS: Q captured D=0");
        else
            $error("FAIL: Q=%b, expected 0", q);

        $display("=== All tests complete ===");
        $finish;
    end

    initial begin
        $dumpfile("dff.vcd");
        $dumpvars(0, tb_dff);
    end
endmodule

Exercise 4: Debug the Testbench 🐛Hard 연습 4: 테스트벤치 디버깅 🐛

This testbench has 4 bugs. Find and fix them all!

이 테스트벤치에는 4개의 버그가 있습니다. 모두 찾아서 수정하세요!

module tb_buggy;
    logic       clk, rst_n, enable;
    logic [3:0] count;

    counter dut (
        .clk(clk), .rst_n(rst_n),
        .enable(enable), .count(count)
    );

    // Bug 1: Clock generation
    always #5 clk = ~clk;

    // Bug 2: Multiple monitors
    initial $monitor("rst=%b", rst_n);
    initial $monitor("count=%d", count);

    initial begin
        rst_n = 0;
        enable = 0;
        #20;
        rst_n = 1;
        enable = 1;
        #100;

        // Bug 3: Check immediately after clock edge
        @(posedge clk);
        assert(count == 4'd10);

        // Bug 4: Missing $finish
    end
endmodule
👀 Show Answer 👀 정답 보기
  1. Bug 1: clk is never initialized! It starts as X, and ~X = X. Fix: add initial clk = 0;
  2. 버그 1: clk이 초기화되지 않음! X로 시작하고 ~X = X. 수정: initial clk = 0; 추가
  3. Bug 2: Two $monitor calls — the second replaces the first. Fix: combine into one: $monitor("rst=%b count=%d", rst_n, count);
  4. 버그 2: 두 개의 $monitor 호출 — 두 번째가 첫 번째를 대체. 수정: 하나로 합치기
  5. Bug 3: Assert right at posedge — output hasn't settled yet! Fix: add #1; before the assert
  6. 버그 3: posedge 직후에 assert — 출력이 아직 안정되지 않음! 수정: assert 전에 #1; 추가
  7. Bug 4: No $finish — simulation runs forever. Fix: add $finish; at the end
  8. 버그 4: $finish 없음 — 시뮬레이션이 영원히 실행. 수정: 끝에 $finish; 추가
