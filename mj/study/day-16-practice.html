Exercise 1: Basic 2-Flop Synchronizer

Implement a 2-flop synchronizer for a single-bit asynchronous input. This is the most common CDC circuit you'll encounter.

단일 비트 비동기 입력을 위한 2-플립플롭 동기화기를 구현하세요. 이것은 가장 흔한 CDC 회로입니다.

📋 Requirements

  • Inputs: clk, rst_n (active-low async reset), async_in
  • 입력: clk, rst_n (액티브 로우 비동기 리셋), async_in
  • Output: sync_out
  • 출력: sync_out
  • Two flip-flop stages, both clocked by clk
  • 두 플립플롭 단계, 둘 다 clk으로 클록
  • No logic between the flip-flops!
  • 플립플롭 사이에 로직 없음!
💡 Hint: Use a single always_ff block with two registers: meta (stage 1) and sync_out (stage 2). The key is meta <= async_in; sync_out <= meta; 두 레지스터가 있는 단일 always_ff 블록을 사용하세요: meta (1단계)와 sync_out (2단계). 핵심은 meta <= async_in; sync_out <= meta; 
module sync_2ff (
    input  logic clk,
    input  logic rst_n,
    input  logic async_in,
    output logic sync_out
);

    logic meta;  // First stage - may go metastable

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            meta     <= 1'b0;
            sync_out <= 1'b0;
        end else begin
            meta     <= async_in;  // Capture - might be metastable
            sync_out <= meta;      // Resolve - almost certainly stable
        end
    end

endmodule

Exercise 2: Parameterized N-Stage Synchronizer

Create a synchronizer with a configurable number of stages. Some high-frequency designs need 3 or even 4 stages.

구성 가능한 단계 수를 가진 동기화기를 만드세요. 일부 고주파 설계에서는 3단계 또는 4단계가 필요합니다.

📋 Requirements

  • Parameter STAGES with default value of 2
  • 기본값 2인 매개변수 STAGES
  • Use a shift register of width STAGES
  • 폭이 STAGES인 시프트 레지스터 사용
  • Output comes from the last stage
  • 출력은 마지막 단계에서 나옴
  • Minimum STAGES should be 2
  • 최소 STAGES는 2여야 함
💡 Hint: Declare logic [STAGES-1:0] sync_pipe; and shift: sync_pipe <= {sync_pipe[STAGES-2:0], async_in};. Output is sync_pipe[STAGES-1]. logic [STAGES-1:0] sync_pipe;를 선언하고 시프트: sync_pipe <= {sync_pipe[STAGES-2:0], async_in};. 출력은 sync_pipe[STAGES-1]. 
module sync_nff #(
    parameter int STAGES = 2  // Minimum 2
) (
    input  logic clk,
    input  logic rst_n,
    input  logic async_in,
    output logic sync_out
);

    // Shift register for synchronizer pipeline
    logic [STAGES-1:0] sync_pipe;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            sync_pipe <= '0;
        end else begin
            sync_pipe <= {sync_pipe[STAGES-2:0], async_in};
        end
    end

    assign sync_out = sync_pipe[STAGES-1];

endmodule

Exercise 3: Synchronizer Testbench

Write a testbench that drives an asynchronous signal into your 2-flop synchronizer. Verify the output appears 2 clock cycles later.

2-플립플롭 동기화기에 비동기 신호를 구동하는 테스트벤치를 작성하세요. 출력이 2 클록 사이클 후에 나타나는지 확인하세요.

📋 Requirements

  • Generate a 100 MHz clock
  • 100 MHz 클록 생성
  • Toggle async_in at non-clock-aligned times (e.g., #7, #13)
  • async_in을 클록과 정렬되지 않은 시간에 토글 (예: #7, #13)
  • Monitor sync_out and verify it follows async_in with 2-cycle latency
  • sync_out를 모니터링하고 2 사이클 지연으로 async_in을 따르는지 확인
  • Use $display to show the signal values over time
  • $display를 사용하여 시간에 따른 신호 값 표시
💡 Hint: Use #7 and #13 delays to ensure transitions happen at non-clock-edge times. This simulates real asynchronous behavior. Check sync_out after @(posedge clk); @(posedge clk); — it should reflect the input. #7과 #13 지연을 사용하여 전환이 클록 에지가 아닌 시간에 발생하도록 하세요. 이것은 실제 비동기 동작을 시뮬레이션합니다. @(posedge clk); @(posedge clk); 후에 sync_out을 확인하세요 — 입력을 반영해야 합니다. 
module tb_sync_2ff;

    logic clk, rst_n, async_in, sync_out;

    // Instantiate DUT
    sync_2ff dut (
        .clk(clk),
        .rst_n(rst_n),
        .async_in(async_in),
        .sync_out(sync_out)
    );

    // 100 MHz clock (10ns period)
    initial clk = 0;
    always #5 clk = ~clk;

    // Monitor signals
    initial begin
        $monitor("t=%0t  async_in=%b  meta=%b  sync_out=%b",
                $time, async_in, dut.meta, sync_out);
    end

    initial begin
        // Initialize
        rst_n    = 0;
        async_in = 0;
        #20;
        rst_n = 1;

        // Test 1: Assert async_in at non-aligned time
        #7;  // NOT aligned to clock edge
        async_in = 1;
        $display("\n--- async_in asserted at t=%0t ---", $time);

        // Wait 2 clock cycles — sync_out should be 1
        @(posedge clk);  // meta captures
        @(posedge clk);  // sync_out captures meta
        #1;
        if (sync_out === 1'b1)
            $display("PASS: sync_out = 1 after 2 cycles");
        else
            $display("FAIL: sync_out = %b (expected 1)", sync_out);

        // Test 2: Deassert at non-aligned time
        #13;
        async_in = 0;
        $display("\n--- async_in deasserted at t=%0t ---", $time);

        @(posedge clk);
        @(posedge clk);
        #1;
        if (sync_out === 1'b0)
            $display("PASS: sync_out = 0 after 2 cycles");
        else
            $display("FAIL: sync_out = %b (expected 0)", sync_out);

        // Test 3: Rapid toggles
        #3;
        async_in = 1;
        #4;
        async_in = 0;  // Pulse shorter than clock period
        #3;
        async_in = 1;
        $display("\n--- Rapid toggles at t=%0t ---", $time);

        #50;
        $display("\n=== Simulation complete ===");
        $finish;
    end

endmodule

Exercise 4: Edge Detector with Synchronizer

A common pattern: synchronize an asynchronous signal, then detect its rising edge. Build a module that outputs a single-cycle pulse when the synchronized signal transitions from 0 to 1.

일반적인 패턴: 비동기 신호를 동기화한 다음 상승 에지를 감지합니다. 동기화된 신호가 0에서 1로 전환될 때 단일 사이클 펄스를 출력하는 모듈을 만드세요.

📋 Requirements

  • First: synchronize with 2-flop synchronizer
  • 먼저: 2-플립플롭 동기화기로 동기화
  • Then: detect rising edge (compare current vs previous value)
  • 그 다음: 상승 에지 감지 (현재 값과 이전 값 비교)
  • Output: pulse_out — high for exactly one clock cycle
  • 출력: pulse_out — 정확히 한 클록 사이클 동안 하이
  • Total latency: 3 clock cycles (2 sync + 1 edge detect)
  • 총 지연: 3 클록 사이클 (2 동기화 + 1 에지 감지)
💡 Hint: After the synchronizer, add a third flip-flop: sync_delay <= sync_out;. The rising edge is: pulse_out = sync_out & ~sync_delay; 동기화기 후에 세 번째 플립플롭을 추가하세요: sync_delay <= sync_out;. 상승 에지는: pulse_out = sync_out & ~sync_delay; 
module async_edge_detect (
    input  logic clk,
    input  logic rst_n,
    input  logic async_in,
    output logic pulse_out    // Single-cycle pulse on rising edge
);

    logic meta, sync, sync_d;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            meta   <= 1'b0;
            sync   <= 1'b0;
            sync_d <= 1'b0;
        end else begin
            meta   <= async_in;   // Stage 1: capture
            sync   <= meta;       // Stage 2: resolve
            sync_d <= sync;       // Stage 3: delay for edge detect
        end
    end

    // Rising edge: sync is high, previous was low
    assign pulse_out = sync & ~sync_d;

endmodule

🌟 Bonus: MTBF Calculator

Calculate the MTBF for these scenarios (use the formula from the lesson):

이 시나리오에 대한 MTBF를 계산하세요 (레슨의 공식 사용):

Scenario A

  • τ = 25 ps, Tw = 50 ps
  • fclk = 200 MHz, fdata = 50 MHz
  • 2-flop synchronizer (tres = 1 clock period = 5 ns)
  • 2-플립플롭 동기화기 (tres = 1 클록 주기 = 5 ns)

Scenario B

  • τ = 25 ps, Tw = 50 ps
  • fclk = 1 GHz, fdata = 500 MHz
  • 2-flop synchronizer (tres = 1 ns)
  • 2-플립플롭 동기화기 (tres = 1 ns)

Scenario A Answer

MTBF = e(5000ps / 25ps) / (50e-12 × 200e6 × 50e6)
     = e200 / (50e-12 × 1e16)
     = e200 / 500000
     ≈ 7.2 × 1080 seconds
     ≈ 2.3 × 1073 years  // Incomprehensibly long!

Scenario B Answer

MTBF = e(1000ps / 25ps) / (50e-12 × 1e9 × 500e6)
     = e40 / (50e-12 × 5e17)
     = e40 / 25000000
     ≈ 2.35 × 1017 / 2.5e7
     ≈ 9.4 × 109 seconds
     ≈ ~300 years  // Okay for some apps, but consider 3 stages!

Notice how Scenario B has much shorter MTBF! At 1 GHz with only 1ns resolution time, you should consider a 3-flop synchronizer to increase MTBF dramatically.

시나리오 B의 MTBF가 훨씬 짧은 것에 주목하세요! 1 GHz에서 1ns 해결 시간만으로는 MTBF를 극적으로 증가시키기 위해 3-플립플롭 동기화기를 고려해야 합니다.
