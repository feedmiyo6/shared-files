Exercise 1: Moore "110" Detector

Design a Moore FSM that outputs detected = 1 when it sees the sequence "110" on a serial input din. The detector should be overlapping (after detecting "110", it can immediately start looking for a new "110" pattern).

직렬 입력 din에서 "110" 시퀀스를 감지하면 detected = 1을 출력하는 Moore FSM을 설계하세요. 감지기는 중첩 방식이어야 합니다 ("110" 감지 후 즉시 새로운 "110" 패턴을 찾을 수 있음).

Requirements

요구사항

  • States: IDLE, SAW_1, SAW_11, SAW_110
  • Output detected is HIGH only in SAW_110
  • Overlapping: from SAW_110, if din=1, go to SAW_1 (not IDLE)
  • Active-low async reset rst_n
  • 상태: IDLE, SAW_1, SAW_11, SAW_110
  • 출력 detected는 SAW_110에서만 HIGH
  • 중첩: SAW_110에서 din=1이면 SAW_1로 이동 (IDLE이 아님)
  • 액티브-로우 비동기 리셋 rst_n
💬 Hint: Draw the state diagram first! Think about what happens in each state for din=0 and din=1. Remember: in Moore, the output is tied to the state, not the transition. 먼저 상태 다이어그램을 그려보세요! 각 상태에서 din=0과 din=1일 때 무엇이 일어나는지 생각하세요. Moore에서 출력은 전이가 아닌 상태에 연결됩니다. 
module moore_110_detector (
    input  logic clk, rst_n, din,
    output logic detected
);

    typedef enum logic [1:0] {
        IDLE    = 2'b00,
        SAW_1   = 2'b01,
        SAW_11  = 2'b10,
        SAW_110 = 2'b11
    } state_t;

    state_t state, next_state;

    // State register
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    // Next state logic
    always_comb begin
        case (state)
            IDLE:    next_state = din ? SAW_1   : IDLE;
            SAW_1:   next_state = din ? SAW_11  : IDLE;
            SAW_11:  next_state = din ? SAW_11  : SAW_110;
            SAW_110: next_state = din ? SAW_1   : IDLE;
            default: next_state = IDLE;
        endcase
    end

    // Moore output — state only
    assign detected = (state == SAW_110);

endmodule

Key points: From SAW_11 with din=1, we stay in SAW_11 (still "11"). From SAW_110 with din=1, we go to SAW_1 (overlapping — the "0" breaks the streak, but the new "1" starts a fresh match).

핵심 포인트: SAW_11에서 din=1이면 SAW_11에 머뭅니다 (여전히 "11"). SAW_110에서 din=1이면 SAW_1로 이동합니다 (중첩 — "0"이 연속을 끊지만, 새 "1"이 새로운 매칭을 시작).

Exercise 2: Mealy "110" Detector

Now implement the same "110" detector as a Mealy machine. You should need fewer states!

이번에는 같은 "110" 감지기를 Mealy 머신으로 구현하세요. 더 적은 상태가 필요할 것입니다!

Requirements

요구사항

  • Should need only 3 states (vs Moore's 4)
  • Output goes high in the SAME cycle the '0' arrives (completing "110")
  • Still overlapping
  • 3개 상태만 필요 (Moore의 4개 대비)
  • '0'이 도착하는 같은 사이클에 출력이 올라감 ("110" 완성)
  • 여전히 중첩
💬 Hint: You don't need a SAW_110 state — the Mealy output can fire from SAW_11 when din=0. The output expression will be: (state == SAW_11) && !din. SAW_110 상태가 필요 없습니다 — din=0일 때 SAW_11에서 Mealy 출력을 발생시킬 수 있습니다. 출력 표현식: (state == SAW_11) && !din. 
module mealy_110_detector (
    input  logic clk, rst_n, din,
    output logic detected
);

    typedef enum logic [1:0] {
        IDLE   = 2'b00,
        SAW_1  = 2'b01,
        SAW_11 = 2'b10
    } state_t;            // Only 3 states!

    state_t state, next_state;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    always_comb begin
        case (state)
            IDLE:   next_state = din ? SAW_1  : IDLE;
            SAW_1:  next_state = din ? SAW_11 : IDLE;
            SAW_11: next_state = din ? SAW_11 : IDLE;
            default: next_state = IDLE;
        endcase
    end

    // Mealy output — state AND input
    assign detected = (state == SAW_11) && !din;

endmodule

Compare: Moore needed 4 states, Mealy needs 3. The detection happens one cycle earlier. But note: from SAW_11 with din=0, we go to IDLE (not SAW_1, since '0' doesn't start "110"). For overlapping after detection, the next din=1 from IDLE starts fresh.

비교: Moore는 4개 상태, Mealy는 3개만 필요합니다. 감지가 한 사이클 더 일찍 발생합니다. 단, SAW_11에서 din=0이면 IDLE로 갑니다 ('0'은 "110"을 시작하지 않으므로).

Exercise 3: Registered Mealy with Testbench

Take your Mealy "110" detector and add a registered output. Then write a testbench to verify it detects "110" patterns in the input stream 1,1,0,1,1,1,0,0.

Mealy "110" 감지기에 레지스터된 출력을 추가하세요. 그런 다음 입력 스트림 1,1,0,1,1,1,0,0에서 "110" 패턴을 감지하는지 확인하는 테스트벤치를 작성하세요.

Expected Output Timing

예상 출력 타이밍

Cycle:  1   2   3   4   5   6   7   8
din:    1   1   0   1   1   1   0   0
Mealy:  0   0   1   0   0   0   1   0   (combinational)
Reg'd:  0   0   0   1   0   0   0   1   (one cycle delayed)

module reg_mealy_110_detector (
    input  logic clk, rst_n, din,
    output logic detected
);

    typedef enum logic [1:0] {
        IDLE   = 2'b00,
        SAW_1  = 2'b01,
        SAW_11 = 2'b10
    } state_t;

    state_t state, next_state;
    logic mealy_out;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    always_comb begin
        case (state)
            IDLE:   next_state = din ? SAW_1  : IDLE;
            SAW_1:  next_state = din ? SAW_11 : IDLE;
            SAW_11: next_state = din ? SAW_11 : IDLE;
            default: next_state = IDLE;
        endcase
    end

    // Raw Mealy output
    assign mealy_out = (state == SAW_11) && !din;

    // Registered output — glitch-free!
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            detected <= 1'b0;
        else
            detected <= mealy_out;
    end

endmodule

Testbench:

테스트벤치:

module tb_reg_mealy_110;
    logic clk, rst_n, din, detected;

    reg_mealy_110_detector dut (.*);

    // 10ns clock
    always #5 clk = ~clk;

    // Input pattern: 1,1,0,1,1,1,0,0
    logic [7:0] pattern = 8'b11011100;

    initial begin
        clk = 0;
        rst_n = 0;
        din = 0;

        // Release reset
        #12 rst_n = 1;

        // Apply pattern MSB first
        for (int i = 7; i >= 0; i--) begin
            @(posedge clk);
            din = pattern[i];
            $display("t=%0t din=%b detected=%b",
                     $time, din, detected);
        end

        // Extra cycles to see delayed output
        repeat(2) @(posedge clk);
        $display("t=%0t detected=%b (should be 1)",
                 $time, detected);

        #20 $finish;
    end

endmodule

Take the Moore "110" detector (Exercise 1) and trace through the input 1,1,0,1,1,0. Fill in the table below on paper, then verify with the Mealy version. Note where Mealy detects one cycle earlier.

Moore "110" 감지기(문제 1)로 입력 1,1,0,1,1,0을 추적하세요. 아래 표를 종이에 채운 후 Mealy 버전으로 검증하세요. Mealy가 한 사이클 더 일찍 감지하는 곳을 확인하세요.

Cycle:   1    2    3    4    5    6
din:     1    1    0    1    1    0
Moore:   __   __   __   __   __   __
Mealy:   __   __   __   __   __   __

Cycle:   1    2    3    4    5    6
din:     1    1    0    1    1    0

분석: Mealy는 사이클 3과 6에서 감지 ('0' 완성과 동시). Moore는 사이클 4에서 감지 (첫 패턴보다 한 사이클 늦음). 이것이 1사이클 지연 차이를 완벽히 보여줍니다!
