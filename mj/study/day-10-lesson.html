🚦 Project 1: Traffic Light Controller

A classic FSM problem. We'll build a controller for a simple intersection with North-South and East-West lights.

클래식한 FSM 문제입니다. 남북/동서 방향 신호등이 있는 간단한 교차로 컨트롤러를 만들겠습니다.

📋 Specification

States: GREEN_NS → YELLOW_NS → GREEN_EW → YELLOW_EW → (repeat)

상태: GREEN_NS → YELLOW_NS → GREEN_EW → YELLOW_EW → (반복)

  • Green lasts 10 cycles
  • Yellow lasts 3 cycles
  • When one direction is green/yellow, the other is red
  • Emergency input → both directions go red
  • 초록불은 10 사이클 유지
  • 노란불은 3 사이클 유지
  • 한 방향이 초록/노란불일 때 다른 방향은 빨간불
  • 비상 입력 → 양방향 모두 빨간불

State Diagram

Think of it as a circular FSM with a timer-based transition and an emergency override:

타이머 기반 전환과 비상 오버라이드가 있는 순환 FSM으로 생각하세요:

// State Encoding — using one-hot for clarity
typedef enum logic [4:0] {
    GREEN_NS   = 5'b00001,
    YELLOW_NS  = 5'b00010,
    GREEN_EW   = 5'b00100,
    YELLOW_EW  = 5'b01000,
    EMERGENCY  = 5'b10000
} state_t;

Full Implementation

module traffic_light (
    input  logic       clk,
    input  logic       rst_n,
    input  logic       emergency,
    output logic [2:0] ns_light,  // {red, yellow, green}
    output logic [2:0] ew_light   // {red, yellow, green}
);

    // Light encoding
    localparam logic [2:0] RED    = 3'b100;
    localparam logic [2:0] YELLOW = 3'b010;
    localparam logic [2:0] GREEN  = 3'b001;

    typedef enum logic [2:0] {
        S_GREEN_NS,
        S_YELLOW_NS,
        S_GREEN_EW,
        S_YELLOW_EW,
        S_EMERGENCY
    } state_t;

    state_t state, next_state;
    logic [3:0] timer, next_timer;

    // State register
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            state <= S_GREEN_NS;
            timer <= 4'd0;
        end else begin
            state <= next_state;
            timer <= next_timer;
        end
    end

    // Next state logic
    always_comb begin
        next_state = state;
        next_timer = timer + 4'd1;

        if (emergency) begin
            next_state = S_EMERGENCY;
            next_timer = 4'd0;
        end else begin
            case (state)
                S_GREEN_NS: if (timer == 4'd9) begin
                    next_state = S_YELLOW_NS;
                    next_timer = 4'd0;
                end

                S_YELLOW_NS: if (timer == 4'd2) begin
                    next_state = S_GREEN_EW;
                    next_timer = 4'd0;
                end

                S_GREEN_EW: if (timer == 4'd9) begin
                    next_state = S_YELLOW_EW;
                    next_timer = 4'd0;
                end

                S_YELLOW_EW: if (timer == 4'd2) begin
                    next_state = S_GREEN_NS;
                    next_timer = 4'd0;
                end

                S_EMERGENCY: if (!emergency) begin
                    next_state = S_GREEN_NS;
                    next_timer = 4'd0;
                end

                default: begin
                    next_state = S_GREEN_NS;
                    next_timer = 4'd0;
                end
            endcase
        end
    end

    // Output logic (Moore — outputs depend only on state)
    always_comb begin
        case (state)
            S_GREEN_NS:  begin ns_light = GREEN;  ew_light = RED;    end
            S_YELLOW_NS: begin ns_light = YELLOW; ew_light = RED;    end
            S_GREEN_EW:  begin ns_light = RED;    ew_light = GREEN;  end
            S_YELLOW_EW: begin ns_light = RED;    ew_light = YELLOW; end
            S_EMERGENCY: begin ns_light = RED;    ew_light = RED;    end
            default:     begin ns_light = RED;    ew_light = RED;    end
        endcase
    end

endmodule

💡 Design Patterns Used

  • Timer counter — separate counter register avoids complex state explosion
  • Emergency override — checked before the case statement (highest priority)
  • Moore outputs — clean, glitch-free output from registered state
  • Default case — safe recovery from illegal states (Day 9!)
  • 타이머 카운터 — 별도 카운터 레지스터로 복잡한 상태 폭발 방지
  • 비상 오버라이드 — case문 전에 체크 (최우선 순위)
  • Moore 출력 — 등록된 상태에서 깔끔하고 글리치 없는 출력
  • Default case — 불법 상태에서의 안전한 복구 (9일차!)

🔍 Project 2: Sequence Detector (1011)

Detects the pattern 1011 on a serial input. We'll build both overlapping and non-overlapping versions.

직렬 입력에서 패턴 1011을 감지합니다. 오버래핑과 논오버래핑 버전을 모두 만들겠습니다.

🔄 Overlapping vs Non-Overlapping

Input: 1 0 1 1 0 1 1

입력: 1 0 1 1 0 1 1

TypeDetectionsExplanation
Non-overlapping1 (at position 4)Resets to idle after detection
논오버래핑1회 (위치 4)감지 후 초기 상태로 리셋
Overlapping2 (at positions 4, 7)Reuses matched bits for next pattern
오버래핑2회 (위치 4, 7)매치된 비트를 다음 패턴에 재사용

Overlapping Sequence Detector (Mealy)

module seq_detector_1011 (
    input  logic clk,
    input  logic rst_n,
    input  logic din,
    output logic detected
);

    typedef enum logic [2:0] {
        IDLE,    // Waiting for '1'
        GOT_1,   // Seen "1"
        GOT_10,  // Seen "10"
        GOT_101  // Seen "101"
    } state_t;

    state_t state, next_state;

    // State register
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    // Next state + output (Mealy: output depends on state AND input)
    always_comb begin
        next_state = IDLE;
        detected  = 1'b0;

        case (state)
            IDLE: begin
                next_state = din ? GOT_1 : IDLE;
            end

            GOT_1: begin
                next_state = din ? GOT_1 : GOT_10;
            end

            GOT_10: begin
                next_state = din ? GOT_101 : IDLE;
            end

            GOT_101: begin
                if (din) begin
                    detected  = 1'b1;    // Pattern found!
                    next_state = GOT_1;  // Overlap: "1" can start new match
                end else begin
                    next_state = GOT_10; // "1010" — reuse "10"
                end
            end

            default: next_state = IDLE;
        endcase
    end

endmodule

⚠️ Mealy vs Moore Tradeoff

This is a Mealy machine — detected depends on both state AND din. This gives us one cycle earlier detection, but the output can glitch if din changes asynchronously. For safer designs, register the output:

이것은 Mealy 머신입니다 — detected가 상태와 din 모두에 의존합니다. 한 사이클 빨리 감지하지만, din이 비동기적으로 변하면 출력이 글리치할 수 있습니다. 안전한 설계를 위해 출력을 레지스터링하세요:

// Registered Mealy output — no glitches
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        detected_reg <= 1'b0;
    else
        detected_reg <= detected;
end

🧪 Testbench Techniques

Good testbenches are just as important as the design. Here's how to verify our FSMs:

좋은 테스트벤치는 설계만큼 중요합니다. FSM을 검증하는 방법입니다:

module tb_seq_detector;
    logic clk, rst_n, din, detected;

    seq_detector_1011 dut (.*);

    // Clock generation
    always #5 clk = ~clk;

    // Test sequence
    task send_bit(input logic bit_val);
        @(posedge clk);
        din = bit_val;
    endtask

    initial begin
        clk = 0; rst_n = 0; din = 0;
        #20 rst_n = 1;

        // Send: 1 0 1 1 → should detect
        send_bit(1);
        send_bit(0);
        send_bit(1);
        send_bit(1);
        @(posedge clk);
        assert(detected) else $error("Missed 1011!");

        // Test overlapping: continue with 0 1 1
        send_bit(0);
        send_bit(1);
        send_bit(1);
        @(posedge clk);
        assert(detected) else $error("Missed overlap!");

        $display("All tests passed!");
        $finish;
    end
endmodule

🎯 Interview Tips: FSM Questions

  • "Design a traffic light controller" — always add emergency state and timer
  • "Design a sequence detector" — ask: overlapping or non-overlapping? Mealy or Moore?
  • Draw the state diagram first — interviewers want to see your thought process
  • Don't forget the default case — shows you think about safety
  • "신호등 컨트롤러 설계" — 항상 비상 상태와 타이머 추가
  • "시퀀스 디텍터 설계" — 질문: 오버래핑? 논오버래핑? Mealy? Moore?
  • 상태 다이어그램을 먼저 그리세요 — 면접관은 사고 과정을 보고 싶어합니다
  • default case를 잊지 마세요 — 안전성을 고려한다는 것을 보여줍니다
