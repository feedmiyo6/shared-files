📅 Day 9: Safe FSM Design

📝 Quiz 💻 Practice

Yesterday we learned about state encoding (binary, one-hot, gray). Today we focus on making FSMs robust and safe — handling illegal states, adding default transitions, and designing for reliability in real silicon.

어제 상태 인코딩(바이너리, 원-핫, 그레이)을 배웠습니다. 오늘은 FSM을 견고하고 안전하게 만드는 방법 — 불법 상태 처리, 기본 전이 추가, 실제 실리콘에서의 안정성 설계에 집중합니다.

1. Why FSMs Need Safety

In theory, an FSM only visits defined states. In reality, several things can go wrong:

이론적으로 FSM은 정의된 상태만 방문합니다. 하지만 실제로는 여러 문제가 발생할 수 있습니다:

🔍 Sources of Illegal States

  • Power-on reset issues: Flip-flops can start in any state if reset is not applied properly
  • 전원 리셋 문제: 리셋이 제대로 적용되지 않으면 플립플롭이 임의의 상태로 시작할 수 있음
  • Radiation (SEU): Single-event upsets can flip bits in state registers
  • 방사선 (SEU): 단일 이벤트 업셋이 상태 레지스터의 비트를 뒤집을 수 있음
  • Metastability: Asynchronous inputs can cause undefined state values
  • 메타안정성: 비동기 입력이 정의되지 않은 상태 값을 유발할 수 있음
  • One-hot corruption: If using one-hot encoding, a bit flip creates an illegal state
  • 원-핫 손상: 원-핫 인코딩 사용 시 비트 플립이 불법 상태를 생성

2. The default Case — Your Safety Net

The most fundamental safety mechanism is the default case in your state machine's case statement. It catches any state value not explicitly handled.

가장 기본적인 안전 메커니즘은 상태 머신의 case 문에서 default 케이스입니다. 명시적으로 처리되지 않은 모든 상태 값을 잡아냅니다.

⚠️ Common Mistake: Missing default

Without a default case, if the FSM enters an illegal state, it may stay stuck there forever — or worse, the synthesis tool may infer a latch!

default 케이스가 없으면 FSM이 불법 상태에 진입했을 때 영원히 멈추거나, 더 나쁜 경우 합성 도구가 래치를 유추할 수 있습니다!

❌ Unsafe FSM (No Recovery)

module unsafe_fsm (
    input  logic clk, rst_n, go,
    output logic done
);
    typedef enum logic [1:0] {
        IDLE  = 2'b00,
        RUN   = 2'b01,
        DONE  = 2'b10
    } state_t;

    state_t state, next_state;

    always_comb begin
        next_state = state;
        done = 1'b0;
        case (state)
            IDLE: if (go) next_state = RUN;
            RUN:  next_state = DONE;
            DONE: begin
                done = 1'b1;
                next_state = IDLE;
            end
            // No default! State 2'b11 = STUCK FOREVER
        endcase
    end
endmodule

✅ Safe FSM (With Recovery)

module safe_fsm (
    input  logic clk, rst_n, go,
    output logic done,
    output logic err_flag  // signals illegal state was hit
);
    typedef enum logic [1:0] {
        IDLE  = 2'b00,
        RUN   = 2'b01,
        DONE  = 2'b10
    } state_t;

    state_t state, next_state;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= IDLE;
        else
            state <= next_state;
    end

    always_comb begin
        next_state = state;
        done       = 1'b0;
        err_flag   = 1'b0;
        case (state)
            IDLE: if (go) next_state = RUN;
            RUN:  next_state = DONE;
            DONE: begin
                done = 1'b1;
                next_state = IDLE;
            end
            default: begin
                next_state = IDLE;  // recover to known state
                err_flag   = 1'b1;  // report the error
            end
        endcase
    end
endmodule

💡 Key Principle

Always include a default case that transitions to a known safe state (usually IDLE or a RESET state). Optionally flag the error so upstream logic can log or respond to it.

항상 알려진 안전 상태(보통 IDLE 또는 RESET 상태)로 전이하는 default 케이스를 포함하세요. 선택적으로 오류를 플래그하여 상위 로직이 로그하거나 대응할 수 있게 합니다.

3. Reset Strategy

A proper reset is the first line of defense. Every FSM must reset to a known state.

적절한 리셋은 첫 번째 방어선입니다. 모든 FSM은 알려진 상태로 리셋되어야 합니다.

Reset Type Pros장점 Cons단점
Synchronous
if (!rst_n) inside always_ff		 Clean timing, synthesis-friendly깨끗한 타이밍, 합성 친화적 Needs active clock to reset리셋에 활성 클럭 필요
Asynchronous
posedge clk or negedge rst_n		 Works without clock, instant클럭 없이 작동, 즉각적 Can cause metastability on release릴리스 시 메타안정성 유발 가능
Async assert, sync deassert Best of both — industry standard둘 다의 장점 — 업계 표준 Requires reset synchronizer circuit리셋 동기화 회로 필요

Reset Synchronizer Pattern

// Async assert, sync deassert reset
module reset_sync (
    input  logic clk,
    input  logic rst_n_async,  // raw async reset
    output logic rst_n_sync   // clean sync reset
);
    logic rst_meta;

    always_ff @(posedge clk or negedge rst_n_async) begin
        if (!rst_n_async) begin
            rst_meta   <= 1'b0;  // assert immediately
            rst_n_sync <= 1'b0;
        end else begin
            rst_meta   <= 1'b1;  // deassert through 2 flops
            rst_n_sync <= rst_meta;
        end
    end
endmodule

4. One-Hot Safety Techniques

One-hot encoding is especially vulnerable because any single bit flip creates an invalid state. Here are techniques to protect one-hot FSMs:

원-핫 인코딩은 단일 비트 플립으로 유효하지 않은 상태가 만들어지므로 특히 취약합니다. 원-핫 FSM을 보호하는 기법들입니다:

Technique 1: Parity Check

// One-hot should have exactly one bit set
logic state_valid;
assign state_valid = ($countones(state) == 1);

always_ff @(posedge clk) begin
    if (!state_valid)
        state <= IDLE;  // force recovery
end

Technique 2: Hamming Distance Encoding

🧠 Hamming Distance

Instead of one-hot, use encodings where adjacent states differ by ≥2 bits. This way, a single bit flip doesn't land on another valid state — it's always detected as an error.

원-핫 대신, 인접 상태가 최소 2비트 이상 다른 인코딩을 사용합니다. 이렇게 하면 단일 비트 플립이 다른 유효한 상태에 도달하지 않고 항상 오류로 감지됩니다.

5. Synthesis Directives for Safety

Synthesis tools have special attributes to control FSM behavior:

합성 도구에는 FSM 동작을 제어하는 특별한 속성이 있습니다:

// Synopsys: force safe FSM implementation
(* fsm_encoding = "safe" *)
state_t state;

// Xilinx: safe implementation attribute
(* SAFE_IMPLEMENTATION = "yes" *)
(* FSM_SAFE_STATE = "reset_state" *)
state_t state;

// These tell synthesis to add recovery logic
// even if the tool would optimize it away

⚠️ Synthesis Can Remove Your Safety!

By default, synthesis tools may optimize away your default case if they determine the unused states are unreachable. Use full_case / parallel_case carefully, and add synthesis attributes to preserve safety logic.

기본적으로 합성 도구는 미사용 상태가 도달 불가능하다고 판단하면 default 케이스를 최적화하여 제거할 수 있습니다. full_case / parallel_case를 주의해서 사용하고, 안전 로직을 보존하기 위해 합성 속성을 추가하세요.

6. Full Safe FSM Template

Here's a production-quality safe FSM template you can use as a starting point:

시작점으로 사용할 수 있는 프로덕션 수준의 안전한 FSM 템플릿입니다:

module safe_fsm_template #(
    parameter int TIMEOUT_CYCLES = 1000
)(
    input  logic clk,
    input  logic rst_n,
    input  logic start,
    input  logic data_valid,
    output logic busy,
    output logic done,
    output logic error
);

    typedef enum logic [2:0] {
        S_IDLE    = 3'b000,
        S_WAIT    = 3'b001,
        S_PROCESS = 3'b010,
        S_DONE    = 3'b100
    } state_t;

    state_t state, next_state;
    logic [9:0] timeout_cnt;
    logic timeout;

    // ── Timeout watchdog ──
    assign timeout = (timeout_cnt >= TIMEOUT_CYCLES);

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            timeout_cnt <= '0;
        else if (state == S_IDLE)
            timeout_cnt <= '0;
        else
            timeout_cnt <= timeout_cnt + 1;
    end

    // ── State register ──
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            state <= S_IDLE;
        else
            state <= next_state;
    end

    // ── Next-state logic ──
    always_comb begin
        next_state = state;
        busy       = 1'b0;
        done       = 1'b0;
        error      = 1'b0;

        case (state)
            S_IDLE: begin
                if (start)
                    next_state = S_WAIT;
            end

            S_WAIT: begin
                busy = 1'b1;
                if (timeout) begin
                    next_state = S_IDLE;
                    error      = 1'b1;
                end else if (data_valid)
                    next_state = S_PROCESS;
            end

            S_PROCESS: begin
                busy = 1'b1;
                next_state = S_DONE;
            end

            S_DONE: begin
                done = 1'b1;
                next_state = S_IDLE;
            end

            default: begin
                next_state = S_IDLE;  // RECOVER
                error      = 1'b1;  // REPORT
            end
        endcase
    end

endmodule

🎯 Safety Features in This Template

  1. Async reset — guaranteed return to IDLE
  2. 비동기 리셋 — IDLE로의 복귀 보장
  3. default case — illegal states recover to IDLE
  4. default 케이스 — 불법 상태가 IDLE로 복구
  5. Error flag — upstream logic knows something went wrong
  6. 에러 플래그 — 상위 로직이 문제 발생을 인지
  7. Timeout watchdog — prevents getting stuck in wait states
  8. 타임아웃 워치독 — 대기 상태에서 멈추는 것을 방지

7. Assertions for Verification

In simulation, use SystemVerilog assertions to catch illegal states early:

시뮬레이션에서 SystemVerilog 어설션을 사용하여 불법 상태를 조기에 잡습니다:

// Check that state is always valid
assert_valid_state: assert property (
    @(posedge clk) disable iff (!rst_n)
    state inside {S_IDLE, S_WAIT, S_PROCESS, S_DONE}
) else $error("Illegal state: %b", state);

// Check one-hot property (if using one-hot)
assert_one_hot: assert property (
    @(posedge clk) disable iff (!rst_n)
    $onehot(state)
) else $error("State not one-hot: %b", state);

// Check no stuck states (liveness)
assert_no_stuck: assert property (
    @(posedge clk) disable iff (!rst_n)
    (state != S_IDLE) |-> ##[1:1000] (state == S_IDLE)
) else $error("FSM stuck — never returned to IDLE");
