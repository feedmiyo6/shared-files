Registers vs Wires 레지스터 vs 와이어

📝 Quiz 💻 Practice ← Day 3

1. The Old World: reg and wire 1. 과거의 방식: reg와 wire

In original Verilog, you had two main data types: wire and reg. Despite the name, reg does NOT always mean a hardware register — it just means "a variable that can hold a value in simulation."

기존 Verilog에서는 두 가지 주요 데이터 타입이 있었습니다: wire와 reg. 이름과 달리 reg는 항상 하드웨어 레지스터를 의미하지 않습니다 — 단지 "시뮬레이션에서 값을 저장할 수 있는 변수"를 의미합니다.

🔌 wire — Continuous Connection 🔌 wire — 연속적 연결

A wire represents a physical connection. It must be continuously driven — you cannot assign it inside an always block. Think of it as an actual copper trace on a PCB.

wire는 물리적 연결을 나타냅니다. 연속적으로 구동되어야 하며 always 블록 안에서 할당할 수 없습니다. PCB 위의 실제 구리 배선이라고 생각하세요.

wire [7:0] data_bus;           // Declaration
assign data_bus = a & b;    // Continuous assignment

📦 reg — Procedural Variable 📦 reg — 절차적 변수

A reg can be assigned inside always, initial, task, and function blocks. It holds its value until the next assignment. It may or may not become a hardware register — that depends on the context.

reg는 always, initial, task, function 블록 안에서 할당할 수 있습니다. 다음 할당까지 값을 유지합니다. 하드웨어 레지스터가 될 수도 있고 아닐 수도 있습니다 — 문맥에 따라 다릅니다.

reg [7:0] counter;

always @(posedge clk) begin
    counter <= counter + 1;  // This WILL be a register
end

reg [7:0] mux_out;

always @(*) begin
    case (sel)
        2'b00: mux_out = a;     // This is combinational (NOT a register!)
        2'b01: mux_out = b;
        default: mux_out = 0;
    endcase
end

⚠️ The Naming Trap

The biggest source of confusion in Verilog: reg ≠ register! A reg used in an always @(*) block synthesizes to combinational logic, not a flip-flop. Only reg used with a clock edge becomes a real register.

Verilog에서 가장 큰 혼란의 원인: reg ≠ 레지스터! always @(*) 블록에서 사용된 reg는 플립플롭이 아닌 조합 논리로 합성됩니다. 클럭 에지와 함께 사용된 reg만 실제 레지스터가 됩니다.

2. The New World: logic (SystemVerilog) 2. 새로운 방식: logic (SystemVerilog)

SystemVerilog introduced logic to end the confusion. It can be used everywhere — in continuous assignments, procedural blocks, module ports. One type to rule them all.

SystemVerilog은 혼란을 해소하기 위해 logic을 도입했습니다. 어디서든 사용할 수 있습니다 — 연속 할당, 절차적 블록, 모듈 포트. 하나의 타입으로 모든 것을 해결합니다.

module example (
    input  logic       clk,
    input  logic       rst_n,
    input  logic [7:0] data_in,
    output logic [7:0] data_out   // No more wire vs reg decision!
);

logic [7:0] internal_sig;  // Works anywhere

// Combinational — synthesizes to mux
always_comb begin
    internal_sig = data_in + 8'd1;
end

// Sequential — synthesizes to flip-flop
always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        data_out <= 8'd0;
    else
        data_out <= internal_sig;
end

endmodule

💡 Modern Best Practice 💡 최신 모범 사례

In SystemVerilog, use logic for almost everything. The block type (always_ff vs always_comb) determines whether hardware is sequential or combinational — not the variable type. This is much clearer!

SystemVerilog에서는 거의 모든 곳에 logic을 사용하세요. 하드웨어가 순차적인지 조합적인지는 변수 타입이 아니라 블록 타입(always_ff vs always_comb)이 결정합니다. 훨씬 명확합니다!

3. When You Still Need wire 3. wire가 여전히 필요한 경우

There's one case where logic doesn't work: multiple drivers. If a signal needs to be driven by more than one source (like a bidirectional bus), you need wire.

logic이 작동하지 않는 경우가 하나 있습니다: 다중 드라이버. 신호가 둘 이상의 소스에서 구동되어야 하는 경우(양방향 버스 등), wire가 필요합니다.

// Multiple drivers → must use wire
wire [7:0] shared_bus;

assign shared_bus = enable_a ? data_a : 8'bz;  // Tri-state driver A
assign shared_bus = enable_b ? data_b : 8'bz;  // Tri-state driver B

// logic would cause a compile error here!
// logic can only have ONE driver

📋 Rule of Thumb 📋 경험 법칙

SituationUseWhy
Module portslogicClean, modern
Internal signalslogicWorks in any block
Tri-state / multi-driverwireOnly wire supports multiple drivers
Connecting module instanceslogic or wireBoth work for single-driver nets

4. Four-State vs Two-State Types 4. 4상태 vs 2상태 타입

SystemVerilog also distinguishes between four-state types (0, 1, X, Z) and two-state types (0, 1 only). This matters for simulation.

SystemVerilog은 4상태 타입(0, 1, X, Z)과 2상태 타입(0, 1만)도 구분합니다. 이는 시뮬레이션에서 중요합니다.

TypeStatesDefault ValueUse Case
logic / reg / wire4-state (0, 1, X, Z)X (unknown)RTL design, synthesis
bit2-state (0, 1)0Testbenches, fast sim
int2-state0Testbenches, loops
integer4-stateXLegacy Verilog

⚠️ Why X Matters

logic initializes to X (unknown). This is a feature, not a bug! It helps you catch uninitialized signals in simulation. If you see X propagating in your waveform, something isn't being driven or reset properly.

logic은 X(미지)로 초기화됩니다. 이것은 버그가 아니라 기능입니다! 시뮬레이션에서 초기화되지 않은 신호를 잡는 데 도움이 됩니다. 파형에서 X가 전파되는 것을 보면 무언가가 제대로 구동되거나 리셋되지 않은 것입니다.

6. Common Mistakes 6. 흔한 실수

❌ Mistake 1: Using reg for Module Input

// WRONG — inputs cannot be reg
module bad_example (
    input reg [7:0] data   // ❌ Error!
);

// CORRECT — use wire or logic
module good_example (
    input logic [7:0] data   // ✅
);

❌ Mistake 2: Thinking reg = Flip-Flop

reg y;
always @(*) begin
    y = a & b;  // This is an AND gate, NOT a flip-flop!
end

// Only this creates a flip-flop:
reg q;
always @(posedge clk) begin
    q <= d;     // THIS is a real register
end

❌ Mistake 3: Multiple Drivers on logic

logic shared;
assign shared = a;   // Driver 1
assign shared = b;   // Driver 2 — ❌ Compile error!

// Fix: use wire for multi-driver nets
wire shared;
assign shared = enable_a ? a : 1'bz;
assign shared = enable_b ? b : 1'bz;

7. Key Takeaways 7. 핵심 요약

🎯 Remember These

  1. logic replaces both wire and reg in 99% of SystemVerilog code
  2. logic은 SystemVerilog 코드의 99%에서 wire와 reg를 대체합니다
  3. reg ≠ register — the block type determines hardware, not the variable type
  4. reg ≠ 레지스터 — 변수 타입이 아닌 블록 타입이 하드웨어를 결정합니다
  5. wire is still needed for tri-state and multi-driver nets
  6. wire는 여전히 필요합니다 — 트라이스테이트와 다중 드라이버 넷에서
  7. logic initializes to X — this helps catch bugs
  8. logic은 X로 초기화 — 버그를 잡는 데 도움이 됩니다
  9. always_ff / always_comb make intent explicit — use them!
  10. always_ff / always_comb은 의도를 명확히 합니다 — 사용하세요!
