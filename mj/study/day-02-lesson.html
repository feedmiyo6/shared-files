All digital hardware is built from two fundamental types of logic:

⚡ always_comb — Combinational Logicalways_comb — 조합 논리

Use always_comb when the output should update immediately whenever any input changes. Think of it like a pure function — same inputs always produce same outputs.

always_comb는 입력이 변경될 때마다 출력이 즉시 업데이트되어야 할 때 사용합니다. 순수 함수처럼 생각하세요 — 같은 입력은 항상 같은 출력을 생성합니다.

Example: 4-to-1 Multiplexer

예제: 4대1 멀티플렉서

module mux4to1 (
    input  logic [1:0] sel,
    input  logic [7:0] a, b, c, d,
    output logic [7:0] y
);
    always_comb begin
        case (sel)
            2'b00: y = a;
            2'b01: y = b;
            2'b10: y = c;
            2'b11: y = d;
        endcase
    end
endmodule

💡 Key Properties of always_comb

💡 always_comb의 주요 특성

  • No clock! — Sensitivity list is automatic (all read signals)
  • 클럭 없음! — 감도 목록이 자동 (모든 읽기 신호)
  • Executes at time 0 — Runs once at simulation start
  • 시간 0에 실행 — 시뮬레이션 시작 시 한 번 실행
  • Cannot have feedback — Output cannot depend on itself
  • 피드백 불가 — 출력이 자기 자신에 의존할 수 없음
  • Must assign all outputs in all paths — Or you get latches!
  • 모든 경로에서 모든 출력 할당 필수 — 아니면 래치 발생!

Example: Priority Encoder

예제: 우선순위 인코더

module priority_encoder (
    input  logic [3:0] req,
    output logic [1:0] grant,
    output logic        valid
);
    always_comb begin
        valid = 1'b1;    // Default assignment
        if (req[3])
            grant = 2'd3;
        else if (req[2])
            grant = 2'd2;
        else if (req[1])
            grant = 2'd1;
        else if (req[0])
            grant = 2'd0;
        else begin
            grant = 2'd0;  // Must assign even in else!
            valid = 1'b0;
        end
    end
endmodule

🔄 always_ff — Sequential Logicalways_ff — 순차 논리

Use always_ff when you need to store values and update them on clock edges. This creates flip-flops — the building blocks of memory.

always_ff는 값을 저장하고 클럭 에지에서 업데이트해야 할 때 사용합니다. 이것은 플립플롭을 생성합니다 — 메모리의 기본 구성 요소입니다.

Example: Simple 8-bit Register

예제: 간단한 8비트 레지스터

module register (
    input  logic        clk,
    input  logic        rst_n,    // Active-low reset
    input  logic        en,
    input  logic [7:0] d,
    output logic [7:0] q
);
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            q <= 8'h00;    // Asynchronous reset
        else if (en)
            q <= d;       // Capture input on clock edge
        // else: q keeps its value (implied)
    end
endmodule

💡 Key Properties of always_ff

💡 always_ff의 주요 특성

  • Requires clock edge — posedge clk or negedge clk
  • 클럭 에지 필요 — posedge clk 또는 negedge clk
  • Use non-blocking assignments — Always <=, never =
  • 논블로킹 할당 사용 — 항상 <=, 절대 = 아님
  • Holds value between clocks — That's the "memory"
  • 클럭 사이에 값 유지 — 이것이 "메모리"
  • Reset is optional but recommended — For known initial state
  • 리셋은 선택이지만 권장 — 알려진 초기 상태를 위해

Example: 4-bit Counter with Enable

예제: 인에이블이 있는 4비트 카운터

module counter (
    input  logic       clk,
    input  logic       rst_n,
    input  logic       en,
    input  logic       load,
    input  logic [3:0] data,
    output logic [3:0] count
);
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            count <= 4'd0;
        else if (load)
            count <= data;
        else if (en)
            count <= count + 1;  // count on left = next value
                                  // count on right = current value
    end
endmodule

⚠️ Common Mistakes일반적인 실수

❌ Mistake 1: Missing assignment creates latch

❌ 실수 1: 할당 누락으로 래치 생성

// BAD: 'y' not assigned when sel=2'b11
always_comb begin
    case (sel)
        2'b00: y = a;
        2'b01: y = b;
        2'b10: y = c;
        // Missing 2'b11 case! → Latch inferred
    endcase
end

// GOOD: Use default or cover all cases
always_comb begin
    case (sel)
        2'b00: y = a;
        2'b01: y = b;
        2'b10: y = c;
        default: y = d;  // ✓ All cases covered
    endcase
end

❌ Mistake 2: Using blocking in always_ff

❌ 실수 2: always_ff에서 블로킹 사용

// BAD: Blocking assignment in sequential logic
always_ff @(posedge clk) begin
    a = b;    // ✗ Wrong!
    c = a;    // Gets new value of 'a' immediately
end

// GOOD: Non-blocking assignment
always_ff @(posedge clk) begin
    a <= b;   // ✓ Correct!
    c <= a;   // Gets OLD value of 'a'
end

❌ Mistake 3: Using always_comb for state

❌ 실수 3: 상태에 always_comb 사용

// BAD: Trying to hold state in combinational block
always_comb begin
    if (en)
        count = count + 1;  // ✗ Combinational feedback!
end

// GOOD: Use always_ff for anything that holds state
always_ff @(posedge clk) begin
    if (en)
        count <= count + 1;  // ✓ Registered counter
end

💼 Real Design Pattern: Register + Combinational실제 설계 패턴: 레지스터 + 조합

Most real modules combine both types. Here's a typical pattern — registered outputs with combinational next-state logic:

대부분의 실제 모듈은 두 유형을 결합합니다. 여기 일반적인 패턴이 있습니다 — 조합 논리의 다음 상태와 레지스터 출력:

module alu_with_register (
    input  logic        clk,
    input  logic        rst_n,
    input  logic [7:0] a, b,
    input  logic [1:0] op,
    input  logic        valid_in,
    output logic [7:0] result,
    output logic        valid_out
);
    // Internal wire for combinational result
    logic [7:0] alu_result;

    // Combinational: ALU operation
    always_comb begin
        case (op)
            2'b00: alu_result = a + b;
            2'b01: alu_result = a - b;
            2'b10: alu_result = a & b;
            2'b11: alu_result = a | b;
        endcase
    end

    // Sequential: Register the output
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            result    <= 8'd0;
            valid_out <= 1'b0;
        end else begin
            result    <= alu_result;  // Register comb output
            valid_out <= valid_in;    // Pipeline valid signal
        end
    end
endmodule

🎯 Why This Pattern?

🎯 왜 이 패턴을 사용하나요?

  • Clean separation: Easy to read, debug, modify
  • 깔끔한 분리: 읽기, 디버그, 수정이 쉬움
  • Timing closure: Registered outputs are timing-friendly
  • 타이밍 클로저: 레지스터 출력은 타이밍에 유리
  • Pipeline ready: Easy to add more stages later
  • 파이프라인 준비: 나중에 더 많은 단계 추가가 쉬움

✅ Key Takeaways핵심 요약

  • always_comb = No clock, no memory, output tracks inputs instantly
  • always_comb = 클럭 없음, 메모리 없음, 출력이 입력을 즉시 추적
  • always_ff = Clock-driven, creates flip-flops, holds state
  • always_ff = 클럭 기반, 플립플롭 생성, 상태 유지
  • Use = in always_comb, <= in always_ff
  • always_comb에서 =, always_ff에서 <= 사용
  • Always assign all outputs in all paths of always_comb
  • always_comb의 모든 경로에서 항상 모든 출력 할당
  • Combine both in real designs: comb for logic, ff for storage
  • 실제 설계에서 둘을 결합: comb는 논리용, ff는 저장용
