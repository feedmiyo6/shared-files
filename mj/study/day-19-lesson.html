1. The Multi-Bit CDC Problem

In Day 17, we learned the 2-flop synchronizer for single-bit signals. But what about multi-bit values like counters or addresses? You cannot simply synchronize each bit independently.

17일차에서 단일 비트 신호를 위한 2-플립플롭 동기화기를 배웠습니다. 하지만 카운터나 주소 같은 멀티비트 값은 어떨까요? 각 비트를 독립적으로 동기화할 수 없습니다.

⚠️ The Binary Counter Disaster

When a binary counter transitions from 0111 → 1000, all 4 bits change simultaneously. If the receiving clock samples during this transition, it could capture any combination: 0000, 1111, 0100, etc. — completely wrong values!

바이너리 카운터가 0111 → 1000으로 전환될 때, 4개의 비트가 모두 동시에 변경됩니다. 수신 클록이 이 전환 중에 샘플링하면, 0000, 1111, 0100 등 — 완전히 잘못된 값을 캡처할 수 있습니다!

Binary Counter Transition: 7 → 8

  Bit3: 0 ──────────┐1
  Bit2: 1 ┐──────── 0    ← All 4 bits change!
  Bit1: 1 ┘──────── 0
  Bit0: 1 ┘──────── 0
          ─────────────
          0111     1000

  Possible sampled values during transition:
  0111, 0110, 0100, 0000, 1000, 1100, 1110, 1111 ...
  Any combo of old/new bits is possible! 💀

2. Gray Code to the Rescue

Gray code is an encoding where only one bit changes between consecutive values. This means during any transition, the receiving clock either captures the old value or the new value — never garbage.

그레이 코드는 연속된 값 사이에서 하나의 비트만 변경되는 인코딩입니다. 이는 전환 중에 수신 클록이 이전 값 또는 새로운 값만 캡처한다는 것을 의미합니다 — 절대 잘못된 값이 아닙니다.

🔑 Gray Code Property

Adjacent values differ in exactly one bit. This makes Gray code safe to synchronize across clock domains because metastability on a single bit can only resolve to the old or new value.

인접한 값은 정확히 하나의 비트만 다릅니다. 이는 단일 비트의 메타안정성이 이전 값 또는 새 값으로만 해결될 수 있기 때문에 클록 도메인 간 동기화에 안전합니다.

3. Binary ↔ Gray Conversion

Binary to Gray Code

The formula is simple: XOR each bit with the bit above it. The MSB stays the same.

공식은 간단합니다: 각 비트를 위의 비트와 XOR합니다. MSB는 그대로 유지됩니다.

// Binary to Gray Code conversion
// gray = binary XOR (binary >> 1)
function logic [3:0] bin2gray(input logic [3:0] bin);
    return bin ^ (bin >> 1);
endfunction

// Example: binary 0110 (6)
//   0110       (binary)
// ^ 0011       (binary >> 1)
// ------
//   0101       (gray code for 6) ✅

Gray Code to Binary

The reverse is a cascade of XORs. Each binary bit depends on all higher Gray bits.

역변환은 XOR의 캐스케이드입니다. 각 바이너리 비트는 모든 상위 그레이 비트에 의존합니다.

// Gray to Binary conversion
function logic [3:0] gray2bin(input logic [3:0] gray);
    logic [3:0] bin;
    bin[3] = gray[3];                         // MSB same
    bin[2] = gray[3] ^ gray[2];                // XOR with above
    bin[1] = gray[3] ^ gray[2] ^ gray[1];   // XOR chain
    bin[0] = gray[3] ^ gray[2] ^ gray[1] ^ gray[0];
    return bin;
endfunction

// Compact version using a loop:
function logic [3:0] gray2bin_v2(input logic [3:0] gray);
    logic [3:0] bin;
    bin[3] = gray[3];
    for (int i = 2; i >= 0; i--)
        bin[i] = bin[i+1] ^ gray[i];
    return bin;
endfunction

4. Gray Code Counter Design

A Gray code counter doesn't count directly in Gray — it maintains a binary counter internally and converts the output to Gray code. This is the standard pattern used in async FIFOs.

그레이 코드 카운터는 그레이 코드로 직접 카운트하지 않습니다 — 내부적으로 바이너리 카운터를 유지하고 출력을 그레이 코드로 변환합니다. 이것이 비동기 FIFO에서 사용되는 표준 패턴입니다.

module gray_counter #(
    parameter int WIDTH = 4
)(
    input  logic               clk,
    input  logic               rst_n,
    input  logic               enable,
    output logic [WIDTH:0]     gray_count,  // Extra bit for full/empty
    output logic [WIDTH:0]     bin_count    // Binary version (local use)
);

    logic [WIDTH:0] bin_next;
    logic [WIDTH:0] gray_next;

    // Binary counter logic
    assign bin_next  = bin_count + (enable ? 1 : 0);

    // Binary to Gray conversion
    assign gray_next = bin_next ^ (bin_next >> 1);

    // Register both values
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            bin_count  <= '0;
            gray_count <= '0;
        end else begin
            bin_count  <= bin_next;
            gray_count <= gray_next;
        end
    end

endmodule

💡 Why WIDTH+1 Bits?

In async FIFOs, we use an extra bit on the counter. For a FIFO with 2N entries, we use N+1 bit pointers. The extra MSB lets us distinguish between full and empty — both conditions occur when the read and write pointers are "equal" at the FIFO address level, but the MSB differs when full.

비동기 FIFO에서는 카운터에 추가 비트를 사용합니다. 2N개 엔트리의 FIFO에는 N+1 비트 포인터를 사용합니다. 추가 MSB로 full과 empty를 구분할 수 있습니다 — 두 조건 모두 읽기/쓰기 포인터가 FIFO 주소 레벨에서 "같은" 경우에 발생하지만, full일 때 MSB가 다릅니다.

5. Synchronizing Gray Code Across Domains

Once we have a Gray-coded counter, we can safely synchronize it to another clock domain using a simple 2-flop synchronizer on each bit — because only one bit changes at a time!

그레이 코드 카운터가 있으면, 각 비트에 간단한 2-플립플롭 동기화기를 사용하여 다른 클록 도메인으로 안전하게 동기화할 수 있습니다 — 한 번에 하나의 비트만 변경되기 때문입니다!

module gray_sync #(
    parameter int WIDTH = 5
)(
    input  logic              clk_dest,    // Destination clock
    input  logic              rst_n,
    input  logic [WIDTH-1:0]  gray_in,     // From source domain
    output logic [WIDTH-1:0]  gray_out     // Synchronized output
);

    logic [WIDTH-1:0] sync_ff1, sync_ff2;

    always_ff @(posedge clk_dest or negedge rst_n) begin
        if (!rst_n) begin
            sync_ff1 <= '0;
            sync_ff2 <= '0;
        end else begin
            sync_ff1 <= gray_in;   // First flop
            sync_ff2 <= sync_ff1; // Second flop
        end
    end

    assign gray_out = sync_ff2;

endmodule

💡 The Complete CDC Flow

Source domain: Binary counter → convert to Gray → register the Gray value
Cross domain: 2-flop synchronizer on the Gray value
Destination domain: Convert synchronized Gray back to binary for address use

소스 도메인: 바이너리 카운터 → 그레이로 변환 → 그레이 값 레지스터
크로스 도메인: 그레이 값에 2-플립플롭 동기화기
목적지 도메인: 동기화된 그레이를 주소 사용을 위해 바이너리로 역변환

⚠️ Common Mistakes

  • Don't synchronize binary counters! Multiple bits changing = guaranteed corruption
  • 바이너리 카운터를 동기화하지 마세요! 여러 비트 변경 = 확실한 데이터 손상
  • Don't convert Gray→Binary before synchronizing. Convert AFTER the 2-flop sync
  • 동기화 전에 그레이→바이너리 변환하지 마세요. 2-플립플롭 동기화 후에 변환
  • Don't forget the extra MSB for full/empty detection in FIFOs
  • FIFO에서 full/empty 감지를 위한 추가 MSB를 잊지 마세요
  • Gray code only works for power-of-2 depths. Non-power-of-2 FIFOs need special handling
  • 그레이 코드는 2의 거듭제곱 깊이에서만 작동합니다. 2의 거듭제곱이 아닌 FIFO는 특별한 처리가 필요합니다

7. Key Takeaways

📝 Summary

  1. Binary counters across clock domains = broken. Multiple bits change simultaneously
  2. 클록 도메인 간 바이너리 카운터 = 고장. 여러 비트가 동시에 변경
  3. Gray code: only 1 bit changes per increment → safe to synchronize
  4. 그레이 코드: 증가당 1비트만 변경 → 동기화에 안전
  5. Conversion: gray = bin ^ (bin >> 1) — dead simple in hardware (just XOR gates)
  6. 변환: gray = bin ^ (bin >> 1) — 하드웨어에서 매우 간단 (XOR 게이트만)
  7. Pattern: Count in binary, convert to Gray, synchronize, convert back
  8. 패턴: 바이너리로 카운트, 그레이로 변환, 동기화, 다시 변환
  9. This is the foundation of async FIFO design (Day 20)
  10. 이것은 비동기 FIFO 설계의 기초입니다 (20일차)
