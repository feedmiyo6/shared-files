1. What Is Setup Time?

📌 Definition

Setup time (Tsu) is the minimum amount of time the data input must be stable before the active clock edge arrives. If data changes too close to the clock edge, the flip-flop may capture the wrong value or enter a metastable state.

셋업 타임 (Tsu)은 클럭의 유효 에지가 도착하기 전에 데이터 입력이 안정되어 있어야 하는 최소 시간입니다. 데이터가 클럭 에지에 너무 가깝게 변하면, 플립플롭이 잘못된 값을 잡거나 메타스테이블 상태에 빠질 수 있습니다.

Think of it like a traffic signal: you need to be in your lane before the light turns green. If you're still changing lanes when the light changes, you'll end up in the wrong lane.

신호등을 생각해 보세요: 신호가 바뀌기 전에 차선에 있어야 합니다. 신호가 바뀔 때 아직 차선을 변경하고 있다면, 잘못된 차선에 있게 됩니다.

💡 Key Insight

Setup time is a property of the flip-flop, determined by the silicon technology. You can't change it — you can only ensure your design meets it. Typical values: 50-200ps in modern processes.

셋업 타임은 실리콘 기술에 의해 결정되는 플립플롭의 속성입니다. 이를 변경할 수 없고, 설계가 이를 충족하도록 해야 합니다. 최신 공정의 일반적인 값: 50-200ps.

3. The Setup Time Equation

The fundamental timing relationship that every digital designer must know:

모든 디지털 설계자가 알아야 하는 기본 타이밍 관계식:

📌 Setup Time Constraint

// The data must arrive before the setup time window

T_clk  ≥  T_cq  +  T_comb  +  T_su

// Where:
//   T_clk  = Clock period (1/frequency)
//   T_cq   = Clock-to-Q delay of source flip-flop
//   T_comb = Combinational logic delay between flip-flops
//   T_su   = Setup time of destination flip-flop

This is often rearranged to find the maximum frequency:

이것은 종종 최대 주파수를 찾기 위해 재배열됩니다:

// Maximum operating frequency
F_max = 1 / (T_cq + T_comb + T_su)

// Example:
//   T_cq   = 100ps
//   T_comb = 600ps (longest combinational path)
//   T_su   = 50ps
//
//   F_max = 1 / (100ps + 600ps + 50ps)
//         = 1 / 750ps
//         = 1.33 GHz

4. Setup Violation — What Happens?

⚠️ Setup Time Violation

A setup violation occurs when data arrives too late — the combinational logic path is too slow for the clock frequency. The result: the flip-flop may capture the wrong value or enter metastability (output oscillates between 0 and 1).

셋업 위반은 데이터가 너무 늦게 도착할 때 발생합니다 — 조합 논리 경로가 클럭 주파수에 비해 너무 느립니다. 결과: 플립플롭이 잘못된 값을 잡거나 메타스테이빌리티(출력이 0과 1 사이에서 진동)에 빠질 수 있습니다.

✅ GOOD: Data stable before T_su CLK ___↑___ DATA ══════╗ ║ stable T_su ◄──► ╚══════ ❌ BAD: Data changes within T_su window CLK ___↑___ DATA ───╱╲─── ↕ changing! T_su ◄──► VIOLATION!

6. Setup Time in SystemVerilog

While setup time is a physical property, SystemVerilog lets you model and check it in simulation:

셋업 타임은 물리적 속성이지만, SystemVerilog에서 시뮬레이션으로 모델링하고 확인할 수 있습니다:

module dff_with_timing (
    input  logic clk,
    input  logic d,
    output logic q
);

    // Behavioral model with timing check
    always_ff @(posedge clk) begin
        q <= d;
    end

    // Setup time assertion (simulation only!)
    // $setup(data_signal, reference_event, setup_time)
    specify
        $setup(d, posedge clk, 50);  // 50 time units setup
    endspecify

endmodule

A Practical Example: Pipeline Register

실용 예제: 파이프라인 레지스터

Here's a common pattern — when combinational logic is too slow, insert a pipeline register to split the critical path:

일반적인 패턴입니다 — 조합 논리가 너무 느릴 때, 파이프라인 레지스터를 삽입하여 크리티컬 패스를 분할합니다:

// BEFORE: Long combinational path — may violate setup time
module slow_adder (
    input  logic        clk,
    input  logic [31:0] a, b, c, d,
    output logic [31:0] result
);
    logic [31:0] sum;

    // All additions in one cycle — LONG path!
    always_comb begin
        sum = a + b + c + d;  // 3 chained adders
    end

    always_ff @(posedge clk)
        result <= sum;
endmodule

// AFTER: Pipelined — shorter combinational paths
module fast_adder (
    input  logic        clk,
    input  logic [31:0] a, b, c, d,
    output logic [31:0] result
);
    logic [31:0] sum_ab, sum_cd;  // Pipeline register

    // Stage 1: Two parallel additions
    always_ff @(posedge clk) begin
        sum_ab <= a + b;  // 1 adder
        sum_cd <= c + d;  // 1 adder (parallel!)
    end

    // Stage 2: Final addition
    always_ff @(posedge clk)
        result <= sum_ab + sum_cd;  // 1 adder
endmodule

// Trade-off: 2 cycles latency instead of 1
// But each stage is faster → higher clock frequency!

7. Real-World Context

🏭 In Industry

Setup time analysis is done by Static Timing Analysis (STA) tools like Synopsys PrimeTime or Cadence Tempus. These tools check every path in the design without running simulation. When the tool reports a negative slack on a path, that's a setup violation — the data arrives too late.

셋업 타임 분석은 Synopsys PrimeTime이나 Cadence Tempus와 같은 정적 타이밍 분석(STA) 도구에 의해 수행됩니다. 이 도구들은 시뮬레이션 없이 설계의 모든 경로를 확인합니다. 도구가 경로에 음의 슬랙(negative slack)을 보고하면, 이것이 셋업 위반입니다 — 데이터가 너무 늦게 도착합니다.

// Reading an STA timing report (conceptual)
//
// Startpoint: reg_a (rising edge-triggered flip-flop)
// Endpoint:   reg_b (rising edge-triggered flip-flop)
//
// Path Type: max (setup check)
//
//   T_cq (reg_a)        :  0.10 ns
//   combinational logic  :  0.65 ns
//   net delay            :  0.03 ns
//   ─────────────────────────────
//   Data arrival time    :  0.78 ns
//
//   Clock period         :  1.00 ns
//   Setup time (reg_b)   : -0.05 ns
//   ─────────────────────────────
//   Data required time   :  0.95 ns
//
//   Slack = 0.95 - 0.78 = +0.17 ns  ✅ (positive = PASS)

8. Summary

🎯 Key Takeaways

🎯 핵심 요약

  • Setup time = minimum time data must be stable BEFORE the clock edge
  • 셋업 타임 = 클럭 에지 전에 데이터가 안정되어야 하는 최소 시간
  • T_clk ≥ T_cq + T_comb + T_su — the fundamental timing equation
  • T_clk ≥ T_cq + T_comb + T_su — 기본 타이밍 방정식
  • Violation → wrong data captured or metastability
  • 위반 → 잘못된 데이터 캡처 또는 메타스테이빌리티
  • Fix: pipeline, optimize logic, reduce frequency, or use faster cells
  • 해결: 파이프라이닝, 로직 최적화, 주파수 감소, 또는 빠른 셀 사용
  • STA tools check setup time on every path — negative slack = violation
  • STA 도구는 모든 경로에서 셋업 타임을 확인 — 음의 슬랙 = 위반
