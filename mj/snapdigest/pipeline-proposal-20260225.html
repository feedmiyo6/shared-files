🟢 New Architecture 🟢 새로운 아키텍처

SERVER (runs every 4 hours via cron):
Brave Search (4 categories × 3 queries) → Deduplicate → AI Score (nano) → AI Enhance (mini) → AI Translate (mini) → Store in Supabase

CLIENT (user opens app):
Query Supabase → Show Articles ⚡
⏱️ <1 second  |  💸 $0 per user per open 서버 (4시간마다 cron 실행):
Brave Search (4개 카테고리 × 3개 쿼리) → 중복제거 → AI 점수매기기 (nano) → AI 요약 (mini) → AI 번역 (mini) → Supabase 저장

클라이언트 (앱 열기):
Supabase 쿼리 → 기사 표시 ⚡
⏱️ 1초 미만  |  💸 사용자당 $0

⚡ Pipeline Detail: Brave Search Edge Function ⚡ 파이프라인 상세: Brave Search Edge Function

Step 1: Brave Search Queries1단계: Brave Search 쿼리

Targeted queries per category with freshness=pd (past day): 카테고리별 타겟 쿼리, freshness=pd (24시간 이내):

  • 💻 Technology: "top technology news today", "AI artificial intelligence news", "tech industry latest developments"
  • 🌍 World: "breaking world news today", "international news today", "major global events today"
  • 💰 Finance: "stock market news today", "financial markets today", "economy news latest"
  • 💼 Business: "business news today", "corporate news acquisitions", "startup news funding"

~12 Brave API calls per run × 10 results each = ~120 raw articles 실행당 Brave API 호출 ~12회 × 결과 10개 = 원시 기사 ~120개

Step 2: Deduplicate2단계: 중복 제거

Remove duplicates by URL + title similarity (>50% word overlap = dupe). Also skip articles already in DB from prior runs. URL + 제목 유사도로 중복 제거 (50% 이상 단어 겹침 = 중복). 이전 실행에서 이미 DB에 있는 기사도 건너뜀.

Step 3: AI Score (gpt-4.1-nano) — ~$0.002/run3단계: AI 점수매기기 (gpt-4.1-nano) — 실행당 ~$0.002

Same scoring prompt as current. Classify: breaking / significant / standard / minor / noise. Filter out noise. Keep top ~40-50 articles. 현재와 동일한 점수매기기 프롬프트. 분류: 속보 / 중요 / 보통 / 사소 / 노이즈. 노이즈 필터링. 상위 ~40-50개 기사 유지.

Step 4: AI Enhance (gpt-4.1-mini) — ~$0.01/run4단계: AI 강화 (gpt-4.1-mini) — 실행당 ~$0.01

Generate: 2-3 sentence summary, teaser, 3 key takeaways for each article. Batch process in groups of 5. 생성: 기사별 2-3문장 요약, 티저, 핵심 포인트 3개. 5개씩 배치 처리.

Step 5: AI Translate (gpt-4.1-mini) — ~$0.008/run5단계: AI 번역 (gpt-4.1-mini) — 실행당 ~$0.008

Korean translations for title + summary. Stored in title_ko, summary_ko columns. 제목 + 요약 한국어 번역. title_ko, summary_ko 컬럼에 저장.

Step 6: Generate Briefing (gpt-4.1-mini) — ~$0.002/run6단계: 브리핑 생성 (gpt-4.1-mini) — 실행당 ~$0.002

Morning briefing intro from top 5 articles. Stored in daily_briefings table. 상위 5개 기사로 모닝 브리핑 생성. daily_briefings 테이블에 저장.

Step 7: Store + Cleanup7단계: 저장 + 정리

Upsert articles into Supabase (unique on source_url). Create/update daily digest record. Delete articles older than 7 days. Supabase에 기사 upsert (source_url 기준 고유). 일간 다이제스트 레코드 생성/업데이트. 7일 이상 된 기사 삭제.

⚠️ Risks & Mitigations ⚠️ 리스크 및 대응

  • Brave free tier limit: ~2,160 queries/month needed at 6 runs/day. Mitigation: start at 4 runs/day (1,440/month = safe). Upgrade to $5/mo plan if needed. Brave 무료 티어 제한: 일 6회 시 월 ~2,160 쿼리 필요. 대응: 일 4회로 시작 (1,440/월 = 안전). 필요시 $5/월 플랜 업그레이드.
  • Edge Function timeout: Supabase has 60s default timeout. Full pipeline may exceed this. Mitigation: batch AI calls, or split into 2 functions (fetch+score → enhance+store). Edge Function 타임아웃: Supabase 기본 60초. 전체 파이프라인 초과 가능. 대응: AI 호출 배치 처리, 또는 2개 함수로 분리.
  • Pipeline fails silently: Mitigation: pipeline_runs table tracks every run. Can add alerting later. 파이프라인 무음 실패: 대응: pipeline_runs 테이블에 모든 실행 기록. 나중에 알림 추가 가능.
  • No articles between runs: If last run was 3.5 hours ago, that's fine — articles stay in DB. Fresh batch comes every 4 hours. 실행 사이 기사 없음: 마지막 실행 3.5시간 전이어도 괜찮 — 기사는 DB에 유지. 4시간마다 새 배치.
